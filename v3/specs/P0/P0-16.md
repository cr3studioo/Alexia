# P0-16: CI: v3 workflow, no-plugins run, invariant script

Model: sonnet
Depends on: P0-15
Feature IDs: EX-01, SP-11

## Goal
After this task every push runs v3's checks on `windows-latest`: fmt, clippy and the whole
workspace test suite **with `plugins/` moved away** (invariant 2: core runs with plugins
empty), a script that fails if any v3 source names a plugin, hard-codes a path, or adds a crate
dependency edge not in INTERFACES.md §1.1, and a separate job that runs the v2 conformance test
against the real plugins. This is the last line of P0's done-when: "CI runs core with
`plugins/` empty."

## Touch only these paths
- `.github/workflows/v3.yml`   (create)
- `v3/ci/invariants.mjs`   (create)

**This task is explicitly allowed to create `.github/workflows/v3.yml`** (CEO: the builder
prompt's "don't edit .github/workflows/" rule is lifted for this one file).

## Must not touch
`.github/workflows/ci.yml`, `.github/workflows/release.yml` and every other existing workflow;
anything in `v3/crates/`; `plugins/`, `packages/`, `src-tauri/`, `connect/`. The workflow and
the script must never mention `tauri.dev.conf.json`, `scripts/dev-app.mjs`, `ALEXIA_DEV_NAME`
or `ALEXIA_KEYCHAIN`. No secrets: the workflow uses no `secrets.*` at all.

## Interfaces
`v3/ci/invariants.mjs` (Node 24, ESM, no dependencies, run from the repo root):

```
node v3/ci/invariants.mjs            # exit 0 = all checks pass; 1 = a check failed (each hit printed)
node v3/ci/invariants.mjs --self-test  # proves each check catches a planted violation; exit 0/1
```

Checks (INTERFACES.md §7, adjusted as PHASE.md explains):
1. **No crate names a plugin.** For every folder name under `plugins/`, scan
   `v3/crates/*/src/**/*.rs`. A hit is the id **quoted** (`"id"`, `'id'`) or as a path segment
   after `plugins/` or `plugins\\` — v2's rule (`packages/core/test/invariants/01-core-names-no-plugin.test.ts`),
   not a bare word, because `memory` and `media` are English. Also a hit: any
   `plugins/` or `plugins\\` string in v3 `src/`. Exception: files under
   `v3/crates/alexia-gateway/src/channels/` may name the service they speak to (INTERFACES.md
   §8.1). Fails if `plugins/` has no folders (the check would be vacuous).
2. **Dependency graph.** `cargo metadata --format-version 1 --no-deps --manifest-path v3/Cargo.toml`;
   every internal edge (normal and dev) must be in this table, else fail naming the edge:
   `alexia-mcp → alexia-store`; `alexia-core → alexia-store, alexia-mcp`;
   `alexia-gateway → alexia-store, alexia-core`; `alexia-scheduler → alexia-store, alexia-core`;
   `alexia-hub → all five libs`; `alexia-limb → alexia-mcp`. Also every package's `license` is
   `AGPL-3.0-only` and every `.rs` file under `v3/crates` starts with
   `// SPDX-License-Identifier: AGPL-3.0-only`.
3. **No hard-coded paths** (check 7): no `C:\\`, `C:/`, `/home/`, `/Users/` in
   `v3/crates/*/src/**/*.rs`.

`.github/workflows/v3.yml`:

```yaml
name: v3
on:
  push:
    branches: ["cr3studioo/v3", "cr3studioo/v3-*"]
  pull_request:
    paths: ["v3/**", ".github/workflows/v3.yml"]
jobs:
  core:                 # fmt, clippy, invariants, then tests with plugins/ moved away
    runs-on: windows-latest
  v2-conformance:       # the real v2 plugins through the Rust host
    runs-on: windows-latest
```

## Steps
1. Write `invariants.mjs` with the three checks and `--self-test` (plant a quoted id, a
   `plugins/x` path, a bad edge and a `C:\\` in in-memory strings and assert each check reports
   it; no files written).
2. Job `core` (`shell: bash` for every step): checkout; `actions/setup-node` (Node 24, no
   cache needed); `dtolnay/rust-toolchain@stable` with `rustfmt, clippy`; cache `v3/target`
   with `Swatinem/rust-cache` (`workspaces: v3`); `node v3/ci/invariants.mjs --self-test`;
   `node v3/ci/invariants.mjs`; in `v3/`: `cargo fmt --all --check`,
   `cargo clippy --workspace --all-targets --locked -- -D warnings`; then
   `mv plugins "$RUNNER_TEMP/plugins"`, `mkdir "$RUNNER_TEMP/empty-plugins"`, and with env
   `ALEXIA_PLUGINS_DIR=$RUNNER_TEMP/empty-plugins` and `ALEXIA_SECRETS_IN_MEMORY` **unset** (so
   the Credential Manager test in P0-06 runs for real): `cargo build --workspace --bins --locked`
   and `cargo test --workspace --locked`.
3. Job `v2-conformance`: checkout; `pnpm/action-setup`; `actions/setup-node` (Node 24,
   `cache: pnpm`); rust toolchain + cache as above; `pnpm install --frozen-lockfile`;
   `pnpm typecheck`; in `v3/`: `cargo test -p alexia-hub --features v2-conformance --test
   v2_plugins --locked -- --nocapture` with `ALEXIA_V2_PLUGINS: ${{ github.workspace }}\plugins`.
4. Use the same action major versions `.github/workflows/ci.yml` uses (read it; don't change
   it).
5. Run the script locally (`node v3/ci/invariants.mjs` and `--self-test`), run `pnpm check`,
   then push the task branch and confirm the workflow's two jobs are green on GitHub
   (`gh run list --workflow v3.yml --branch cr3studioo/v3-P0-16`, then `gh run view <id>`).

## Tests
- `node v3/ci/invariants.mjs --self-test`: each of the three checks catches its planted
  violation (this is the script's own test, and CI runs it before the real check).
- The workflow itself: both jobs green on the task branch.

## Done when
- `cargo fmt --all --check` passes in v3/
- `cargo clippy --workspace --all-targets -- -D warnings` passes in v3/
- `cargo test --workspace` passes in v3/
- `node v3/ci/invariants.mjs` exits 0 at the repo root
- `node v3/ci/invariants.mjs --self-test` exits 0
- `pnpm check` passes at repo root (ESLint lints `v3/ci/*.mjs` too)
- `gh run list --workflow v3.yml --branch cr3studioo/v3-P0-16 --limit 1` shows `completed
  success` for both jobs
- `git grep -nE "tauri.dev.conf|dev-app.mjs|ALEXIA_DEV_NAME|ALEXIA_KEYCHAIN|secrets\\." .github/workflows/v3.yml`
  prints nothing

## Notes for the worker
- Pushing the task branch is needed to see the workflow run; push only `cr3studioo/v3-P0-16`,
  never `main`, never `cr3studioo/v3`. Don't run or touch the `release` workflow.
- Moving `plugins/` away is v2's no-plugins job pattern (`.github/workflows/ci.yml`,
  `no-plugins`). Host tests use `mcp-fixture`, so nothing in `cargo test --workspace` should
  notice; if something does, that's an invariant bug to report, not to paper over.
- The invariant script runs **before** `plugins/` is moved (check 1 needs the folder names).
- ESLint config is the repo root's `eslint.config.js`; follow the style of `scripts/*.mjs`.
- Windows runner: `shell: bash` is Git Bash; `mv` and `$RUNNER_TEMP` work there. Paths passed to
  cargo via env are Windows paths; `$RUNNER_TEMP` in bash is a Windows path already.
