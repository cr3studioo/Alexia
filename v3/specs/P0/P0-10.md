# P0-10: Plugin process and JSON-RPC connection

Model: opus
Depends on: P0-08, P0-09
Feature IDs: SP-11, EX-01

## Goal
After this task the host can spawn one plugin the way INTERFACES.md §3.2 says (resolved command,
scrubbed env, own-dir cwd, no console window, inside a kill-on-close Job Object), talk JSON-RPC
to it over stdio in both directions with out-of-order answers, progress and cancellation, keep
its last 500 stderr lines redacted, and stop it cleanly. `McpHost` (P0-11) is built from these
two pieces.

```rust
// process.rs
pub(crate) struct Proc {
    pub child: tokio::process::Child,   // stdin/stdout taken by Conn
    pub pid: u32,
    pub stderr: StderrLog,
    job: crate::job::Job,                // dropping it kills the whole tree (Windows)
}
#[derive(Clone, Default)]
pub(crate) struct StderrLog(Arc<Mutex<VecDeque<String>>>);
impl StderrLog {
    pub fn lines(&self) -> Vec<String>;          // oldest first, at most 500
}
/// INTERFACES.md §3.2. `secrets` are values to redact from stderr (the plugin's password
/// settings, read by the caller); never logged themselves.
pub(crate) fn spawn(dir: &PluginDir, layout: &Layout, node: &Path, secrets: Vec<String>) -> Result<Proc, Error>;
/// Close stdin, wait `grace`, then kill (the Job Object on Windows, `start_kill` elsewhere).
pub(crate) async fn stop(proc: Proc, grace: Duration) -> Option<i32>;   // exit code if any

// job.rs  (#![allow(unsafe_code)] at module level, the only unsafe in the crate)
pub(crate) struct Job { /* HANDLE on Windows; unit elsewhere */ }
impl Job {
    pub fn new() -> std::io::Result<Job>;                     // JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE
    pub fn assign(&self, pid: u32) -> std::io::Result<()>;
    pub fn kill(&self);
}

// conn.rs
#[async_trait::async_trait]
pub(crate) trait Incoming: Send + Sync {
    /// A request from the plugin (alexia/*, roots/list, sampling/…, ping is answered by Conn).
    async fn request(&self, method: String, params: Option<Value>) -> Result<Value, RpcError>;
    /// A notification from the plugin other than progress and cancelled.
    async fn notification(&self, method: String, params: Option<Value>);
}
pub(crate) struct Conn { /* writer, pending map, progress sinks, closed token */ }
impl Conn {
    pub fn start(stdin: ChildStdin, stdout: ChildStdout, incoming: Arc<dyn Incoming>) -> Conn;
    /// Ids count from 1 per Conn. With `progress`, sets `params._meta.progressToken` to the id
    /// and forwards matching `notifications/progress` there. On `cancel`: sends
    /// `notifications/cancelled {requestId}` and returns `CallError::Cancelled`. On timeout:
    /// sends the same and returns `CallError::Timeout`. Stdout EOF → `CallError::Gone`.
    pub async fn request(&self, method: &str, params: Option<Value>, progress: Option<ProgressSink>,
                         cancel: &CancellationToken, timeout: Duration) -> Result<Value, CallError>;
    pub async fn notify(&self, method: &str, params: Option<Value>) -> std::io::Result<()>;
    /// Cancelled when stdout reaches EOF or the reader fails.
    pub fn closed(&self) -> CancellationToken;
    /// Millis since the plugin last sent anything (for idle and heartbeat, P0-12).
    pub fn quiet_ms(&self) -> u64;
}
```

## Steps
1. `Cargo.toml`: `[target.'cfg(windows)'.dependencies] windows-sys` with the features for
   `Win32_System_JobObjects`, `Win32_System_Threading`, `Win32_Foundation`, `Win32_Security`
   (why: Job Objects have no std or tokio API, and without one a plugin's own children outlive
   it on Windows).
2. `spawn`: command = `entry.run`, `"node"` → `node`; otherwise, and for every arg naming an
   existing file in the plugin folder, made absolute against the folder. cwd =
   `layout.own_dir(id)`, created first. `env_clear()` then only the §3.2 list (those present)
   plus `ALEXIA_PLUGIN_DIR`. Windows: `creation_flags(CREATE_NO_WINDOW)`, assign to a new `Job`
   right after spawn. stdin/stdout/stderr piped; a task reads stderr lines into `StderrLog`
   (ring of 500), each line redacted: every `secrets` value replaced by `•••`, plus the
   patterns in v2's `packages/core/src/redact.ts` `redactSecrets` (port the patterns, not the
   whole file).
3. `Conn`: one reader task parses each stdout line as `jsonrpc::Message`; a line that doesn't
   parse is logged to the `StderrLog` as `[not json] …` (truncated to 200 chars) and skipped.
   Responses resolve the pending entry by id; requests from the plugin are handled on their own
   task (so a plugin can make requests while the host waits on one of its tools); `ping` is
   answered `{}` by `Conn` itself; `notifications/progress` goes to the sink; plugin-sent
   `notifications/cancelled` cancels that incoming request's task. One writer task serialises
   writes (`\n` terminated).
4. `stop`: drop stdin, wait up to `grace` for exit, then kill.
5. Write the tests against `mcp-fixture` (`env!("CARGO_BIN_EXE_mcp-fixture")` in a manifest
   written to a temp folder).

## Tests
`tests/conn.rs`:
- `spawns_and_lists_tools`: `greet` fixture: initialize, `notifications/initialized`,
  `tools/list` returns `greet`.
- `out_of_order_answers`: two `slow` calls in `vanish` mode (300 ms then 50 ms) resolve to the
  right callers.
- `progress_is_forwarded`: `greet {who:"progress"}` delivers two frames to the sink before the
  result.
- `plugin_requests_reach_incoming`: `greet {who:"ask"}` → `Incoming::request` receives
  `alexia/settings/get`, the test answers `{"settings":{"a":1}}`, and the tool's text contains it.
- `cancel_sends_cancelled`: cancel a `slow` call → `CallError::Cancelled`, and the fixture still
  answers `ping` afterwards.
- `timeout_is_timeout`: `slow {ms:2000}` with a 100 ms timeout → `CallError::Timeout`.
- `exit_mid_call_is_gone`: `exit` mode → `CallError::Gone`, `closed()` fires.
- `junk_is_skipped_and_logged`: `junk` mode still answers `tools/list`; `StderrLog` holds at
  most 500 lines.
- `env_is_scrubbed_and_cwd_is_own_dir`: set `ALEXIA_TEST_LEAK=x` in the test process, then
  `spawn` a manifest whose entry is `cmd /C "set & cd"` on Windows (`sh -c "env; pwd"`
  elsewhere) and read its stdout from `Proc.child`: `ALEXIA_TEST_LEAK` is absent,
  `ALEXIA_PLUGIN_DIR` is the plugin folder, and the printed cwd is `layout.own_dir(id)`.
- `redacts_secrets_in_stderr`: a manifest whose entry prints a given secret to stderr
  (`cmd /C echo` on Windows, `sh -c` elsewhere); `lines()` shows `•••`, never the value.
- `job_kills_children` (`#[cfg(windows)]`): spawn `cmd /C start /B ping -n 30 127.0.0.1`
  through `spawn`, `stop` it, and the child `ping` is gone (check with `tasklist /FI "PID eq …"`
  or by its pid via `OpenProcess`-free means such as `tasklist`).

## Notes for the worker
- Windows can't delete a running process's cwd, which is why cwd is the own dir and never the
  plugin folder (INTERFACES.md §3.2). The vanisher test (P0-12) depends on this.
- Windows has no SIGTERM: closing stdin is the polite stop, the Job Object the hard one.
- `tokio::process::Command::creation_flags` exists on Windows; `CREATE_NO_WINDOW` is
  `0x0800_0000`.
- Don't hold the pending-map lock across an `.await`.
- v2's equivalent: `packages/core/src/plugins.ts` and `host.ts` (spawn, env list, stderr), and
  the MCP SDK's stdio transport. Behaviour must match what v2 plugins expect.
