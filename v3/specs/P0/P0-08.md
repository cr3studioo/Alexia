# P0-08: Manifest parsing, compatibility, discovery

Model: opus
Depends on: P0-03
Feature IDs: SP-11, EX-01

## Goal
After this task the host can read any v2 `plugin.json` exactly as strictly as v2 does, decide
whether this build may run it (with the sentence the owner reads if not), and find every plugin
folder in a directory without spawning anything. This ports v2's manifest checks from TypeScript,
because a plugin v2 accepts must load here and one v2 refuses must be refused here.

## Touch only these paths
- `v3/crates/alexia-mcp/src/lib.rs`   (change: `pub mod manifest;` and the re-exports)
- `v3/crates/alexia-mcp/src/manifest.rs`   (create)
- `v3/crates/alexia-mcp/tests/manifest.rs`   (create)

## Must not touch
`plugins/` (read the manifests for reference; tests must not read them, INTERFACES.md §7 check
2), `packages/protocol/` (read only), `jsonrpc.rs`, `types.rs`, `alexia.rs`, other crates.

## Interfaces
From INTERFACES.md §2.2, verbatim: `Manifest`, `Entry`, `Require`, `Setting`, `StorageDecl`,
`Command`, `Lifetime`, `ComputeDecl`, `ComputeOp`, `Manifest::parse`, `Manifest::compatible`,
`PluginDir`, `discover`.

Defined here:

```rust
#[derive(Clone, Debug, PartialEq, Eq, thiserror::Error)]
#[error("{sentence}")]
pub struct ManifestError {
    /// What the owner reads, e.g. "The plugin in “foo” has a manifest with an unknown field “tols”."
    pub sentence: String,
}

impl Manifest {
    /// `lifetime` with v2's default (`Lazy` when absent).
    pub fn lifetime(&self) -> Lifetime;
    /// Keys of settings whose `kind == "password"`.
    pub fn password_keys(&self) -> Vec<String>;
}
```

`lib.rs` re-exports `manifest::{discover, Manifest, ManifestError, PluginDir}`.

## Steps
1. Read `docs/spec/manifest.md` (normative), `packages/protocol/src/manifest.ts` (the zod shape
   at `ManifestShape` and every rule in the `superRefine` at `Manifest`), `versionVerdict`,
   `mcpRefusal`, and `packages/protocol/src/capabilities.ts` (`PERMISSIONS`, capability syntax).
2. Port to `Manifest::parse`: serde for the shape (`deny_unknown_fields` at the top level, as
   INTERFACES.md fixes it), then every cross-field rule from the `superRefine` that concerns
   fields the struct has. v2's code is the authority; the list below is what to expect, and a
   rule below that v2 does not have is dropped (say so in the report): `manifest_version == 1`; id syntax; `storage.namespace == id`; table
   names are idents; capability syntax in `requires`/`provides`; a `requires` cap that is
   neither a permission in `PERMISSIONS` nor capability syntax is an error; duplicate setting
   keys, commands, provides; `password` settings have no `default`; `min_tier` in `T0..T3`;
   compute ops' caps are in `provides`. Rules about `panel`/`page`/widget fields stay with v2's
   UI and are **not** ported (those fields are raw JSON here). List in your report every v2 rule
   you ported and every one you deliberately didn't.
3. Port `compatible()`: `alexia_protocol` within `ALEXIA_PROTOCOL_MIN..=ALEXIA_PROTOCOL_MAX`;
   `mcp_protocol` in `MCP_REVISIONS` (else v2's `mcpRefusal` sentence); `min_app`/`max_app`
   compared to `APP_VERSION` as v2's `versionVerdict` does. Each failure returns v2's sentence,
   with the app version reading `3.0.0`.
4. `discover(dir)`: every immediate subfolder with a `plugin.json`; read and parse it; a missing
   `dir` returns an empty `Vec`; a folder without `plugin.json` is skipped silently; a parse
   failure is `Err((folder, ManifestError))`. Sorted by folder name. Nothing is spawned.
5. Write the tests.

## Tests
`tests/manifest.rs`, manifests written inline as JSON strings (shaped like the v2 ones, ids such
as `sample`, `two-words`; never read `plugins/`):
- `parses_a_full_manifest`: every field of §2.2 including `settings` with widget fields,
  `panel`, `page`, `compute`, `lifetime: "resident"`.
- `unknown_top_level_key_is_an_error`: `"tols": []` fails with a sentence naming `tols`.
- `widget_fields_are_kept`: a `choice` setting's `options` and `hint` land in `Setting.widget`.
- `cross_field_rules`: one assertion per ported rule (namespace ≠ id, bad id, bad table name,
  bad cap syntax, unknown permission, duplicate setting key, password with default,
  `manifest_version: 2`, compute op cap not provided).
- `compatible_protocol_window`: `alexia_protocol` 1 and 16 refused, 2 and 15 accepted.
- `compatible_mcp_revision`: `2025-11-25` accepted, `2026-07-28` refused with v2's sentence.
- `compatible_app_range`: `min_app: "4.0.0"` refused, `max_app: "2.9.0"` refused,
  `min_app: "3.0.0"` accepted.
- `lifetime_defaults_to_lazy` and `password_keys_lists_password_settings`.
- `discover_reports_failures_without_stopping`: a temp dir with one good folder, one bad
  manifest, one folder without `plugin.json`, and a stray file; returns one `Ok`, one `Err`.
- `discover_missing_dir_is_empty`.

## Notes for the worker
- If a v2 manifest in `plugins/` fails to parse here, the port is wrong, not the manifest:
  v2 plugins must run unchanged (SP-11).
- `"$schema"` is a legal top-level key (it is in every v2 manifest).
- Sentences: full sentences, curly quotes as v2 uses them; copy v2's wording where v2 has one.
- No plugin id literal in `src/` (check 1, P0-16). Test files may use made-up ids.
