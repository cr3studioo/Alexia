# P0-22: Close the idle-stop vs incoming-call race

Model: opus
Depends on: P0-21
Feature IDs: none

## Goal
A call that arrives just as a lazy plugin reaches its idle timeout can get CallError::Gone,
because the idle check and the Busy guard are not under the same lock. After this task a call
either runs on the live process or starts a new one; it never sees Gone from an idle stop.

## Touch only these paths
- v3/crates/alexia-mcp/src/host.rs   (change)
- v3/crates/alexia-mcp/src/supervise.rs   (change)
- v3/crates/alexia-mcp/tests/supervise.rs   (change)

## Must not touch
Other crates, the purge code P0-21 changed, the public API.

## Interfaces
No public signature changes.

## Steps
1. supervise.rs ~163-167 checks idle outside the spawn lock. host.rs ~406-407 enters Busy only after
   ensure_running released that lock.
2. Take the Busy guard inside ensure_running while the spawn lock is held, and hand it to the caller.
3. stop_with(Idle) re-checks idle (no Busy, last-use older than the timeout) under the same lock and
   does nothing if the plugin became busy.
4. tests/supervise.rs ~401 hang_is_killed_by_heartbeat matches Stopped{..} only. Assert
   StopReason::Heartbeat.

## Tests
- call_at_idle_deadline_never_gone: a short idle timeout; fire calls timed around the deadline many
  times (for example 50 loops); none returns CallError::Gone and every one gets its result.
- hang_is_killed_by_heartbeat asserts the Heartbeat reason.
