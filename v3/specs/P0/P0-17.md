# P0-17: Purge and settings parity follow-ups from the P0-13 review

Model: opus
Depends on: P0-13
Feature IDs: SP-11

## Goal
The P0-13 review found four small gaps between the Rust host and v2. After this task, purge
leaves no half-deleted plugin when the keychain refuses, purge switches the plugin off first so
a late call cannot respawn it, a stored JSON null falls back to the setting's default as in v2,
and the guessed `_core/provenance` read is gone.

## Touch only these paths
- v3/crates/alexia-mcp/src/host.rs   (change)
- v3/crates/alexia-mcp/src/serve.rs   (change)
- v3/crates/alexia-mcp/tests/purge.rs   (change)
- v3/crates/alexia-mcp/tests/alexia_layer.rs   (change)

## Must not touch
Every other crate, `src/bin/mcp-fixture.rs`, `plugins/`, `packages/`, `v3/specs/`.

## Interfaces
No public signature changes. Purge keeps its current signature and return type.

## Steps
1. Purge (host.rs, around line 565-577): disable the plugin (the same path `set_enabled(false)`
   uses, so it is stopped and will not be lazily respawned) before deleting anything. v2 does
   this at packages/core/src/plugins.ts:903.
2. Purge: if deleting the plugin's keychain secrets fails, log it (no secret values in the log)
   and carry on removing the plugin's own dir and cache; return the keychain error only after
   everything else was removed. v2 does this at packages/core/src/plugins.ts:914-923.
3. Settings read (serve.rs, around line 255): a stored JSON null must fall back to the
   manifest default, matching v2's `??` at packages/core/src/host.ts:320.
4. Remove the `installed_at()` provenance guess (host.rs around line 487) and its call.
   Capability ties are broken by plugin id order, as the P0-13 spec already says. v2 has no
   `_core/provenance` key.

## Tests
- `purge_disables_before_deleting` (tests/purge.rs): after purge, a call_tool to that plugin
  fails as disabled and the plugin's own dir is not recreated.
- `purge_finishes_when_keychain_fails` (tests/purge.rs): with a secret delete that fails (use
  whatever injection the store or host already offers; if none exists, stop and report),
  own dir and cache are still removed and the error is returned.
- `stored_null_setting_uses_default` (tests/alexia_layer.rs): a setting stored as JSON null
  reads back as the manifest default.
- Existing capability tie-break test still passes with id order.
