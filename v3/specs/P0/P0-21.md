# P0-21: Purge keeps going when one step fails

Model: sonnet
Depends on: P0-17
Feature IDs: none

## Goal
Purging a plugin stops at the first failure today, leaving later secrets and the cache dir behind.
After this task purge tries every step and returns the first error it saw.

## Touch only these paths
- v3/crates/alexia-store/src/secrets.rs   (change)
- v3/crates/alexia-mcp/src/host.rs   (change, purge only)
- v3/crates/alexia-mcp/tests/purge.rs   (change)

## Must not touch
Other host.rs functions, supervise.rs, other crates.

## Interfaces
No signature changes.

## Steps
1. secrets.rs:56: the purge loop uses try_for_each and stops at the first key the keychain refuses.
   Try every key; return the first error after the loop.
2. host.rs ~562-566: purge returns on the first remove_dir_all error, skipping the cache dir and
   dropping the secrets error. Try the secrets, the data dir and the cache dir, every one; return the
   first error. A dir that does not exist is not an error.
3. The keychain cannot be atomic; do not try.

## Tests
- purge_continues_after_a_secret_fails: a secrets backend that refuses one key; every other key is
  gone and the error is returned (use the in-memory/test backend the crate already has).
- purge_removes_cache_dir_when_data_dir_fails: make the data dir removal fail (for example a file
  held open, or a read-only file on Windows); the cache dir is still removed and the error returned.
