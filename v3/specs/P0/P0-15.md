# P0-15: v2 plugins conformance test

Model: sonnet
Depends on: P0-14
Feature IDs: SP-11, EX-01

## Goal
After this task one test spawns every v2 plugin found in a v2 checkout's `plugins/` folder
through the Rust `McpHost` and lists its tools, and checks the `hello`-style capability round
trip and the crasher/vanisher behaviour against real Node plugins. This is the proof of P0's
"lists the v2 plugins' tools" and of SP-11 ("every v2 plugin runs unchanged"). It is a separate
test target behind a cargo feature, so `cargo test --workspace` stays free of `plugins/` and Node
(invariant check 2).

## Touch only these paths
- `v3/crates/alexia-hub/Cargo.toml`   (change: feature + test target)
- `v3/crates/alexia-hub/tests/v2_plugins.rs`   (create)

## Must not touch
`plugins/` (read only; never modify a v2 plugin to make it pass, that would break SP-11),
`packages/`, every library crate, `src/main.rs`, `.github/`.

## Interfaces
`Cargo.toml`:

```toml
[features]
# Runs tests/v2_plugins.rs. Needs Node and a built v2 checkout; never on in `cargo test --workspace`.
v2-conformance = []

[[test]]
name = "v2_plugins"
required-features = ["v2-conformance"]
```

Environment the test reads:
- `ALEXIA_V2_PLUGINS`: absolute path of a v2 checkout's `plugins` folder. **Required**: with the
  feature on and this unset, the test panics with "Set ALEXIA_V2_PLUGINS to a built v2
  checkout's plugins folder." (no silent pass).
- `ALEXIA_NODE`: optional, as in the hub.

Uses `alexia_mcp::{McpHost, HostConfig, Timings, NoUpcalls, PluginId, PluginState, discover,
CallCtx}`, `alexia_store::{Store, Layout}`.

## Steps
1. Add the feature and `[[test]]` entry; add `alexia-mcp`/`alexia-store` dev-dependencies only
   if the normal dependencies don't already cover them (they do, via P0-01).
2. `tests/v2_plugins.rs`: build a host with `plugin_dirs = [ALEXIA_V2_PLUGINS]`, a temp
   `Layout`, `Store::open_in_memory()`, every discovered id enabled, `ALEXIA_SECRETS_IN_MEMORY=1`.
   Plugin ids come only from `discover`; the test names none except where a step below says
   it uses a capability or a manifest property.
3. Write the tests.

## Tests
`tests/v2_plugins.rs`:
- `every_v2_plugin_lists_its_tools`: `discover` finds at least one plugin and every manifest
  parses (`Ok`). `host.tools()` is called once; then for every discovered plugin, either it has
  at least one `HostedTool`, or its `PluginStatus.state` is `Refused`/`Unhealthy` **and** its
  `sentence` is set, in which case the test fails listing `id: sentence` for every such plugin.
  In other words: on Windows every v2 plugin must start and list tools. Print a table
  `id  tools  state` to stdout for the CI log.
- `capability_round_trip`: `host.call_capability("demo.greet", {"who":"Sam"}, CallCtx::default())`
  (core calling, so no `requires` check; that check is P0-13's) returns text containing `Sam`.
  The provider is whichever plugin's tool lists `demo.greet`; if none does, the test fails
  saying so.
- `a_crashing_plugin_is_contained`: pick the plugin whose tool list has a tool named `exit`
  and whose description says it exits (selected by tool, not by id); calling it returns
  `CallError::Gone`, and `tools()` still lists the others.
- `a_vanishing_plugin_is_removed`: find the plugin with a tool named `slow`; copy its folder's
  files except `node_modules` into a temp plugin dir and make `node_modules` there a directory
  junction to the original's (`cmd /C mklink /J`, Windows; a symlink elsewhere), so the
  original is never touched. Start `slow {ms:5000}`, delete the copy (`remove_dir_all`; the
  junction is removed, not followed), and the call ends with `CallError::Gone` and the plugin
  leaves `tools()`.

## Done when
- `cargo fmt --all --check` passes in v3/
- `cargo clippy --workspace --all-targets -- -D warnings` passes in v3/
- `cargo clippy -p alexia-hub --features v2-conformance --all-targets -- -D warnings` passes
- `cargo test --workspace` passes in v3/ (and does not run `v2_plugins`)
- On the Windows PC: at the repo root `pnpm install --frozen-lockfile` and `pnpm typecheck`,
  then in v3/ `ALEXIA_V2_PLUGINS=<repo>\plugins cargo test -p alexia-hub --features
  v2-conformance --test v2_plugins -- --nocapture` passes; paste the printed table into the
  report
- `pnpm check` passes at repo root (nothing in v2 changed; confirms it)

## Notes for the worker
- If a v2 plugin fails on Windows, find out why and report it with the plugin's stderr
  (`host.log(id)`). The fix goes in the host (P0-10 to P0-13 code) only if the host is wrong; if
  the plugin genuinely can't start on Windows, stop and report: the CEO decides, and the
  plugin is not edited.
- Platform-specific plugins (Apple context, OCR via Vision) should still start and list tools
  on Windows (tools fail at call time, not at listing). Verify that rather than assume it.
- Some plugins import npm packages; `pnpm install` at the repo root provides them. They import
  `@alexia/sdk` from `packages/sdk/dist`, which `pnpm typecheck` (`tsc -b`) builds. INTERFACES.md
  §7 says `pnpm build`; there is no such script.
- The test file is outside `src/`, so invariant check 1 does not apply to it, but keep plugin
  selection by capability or tool anyway: it keeps the test valid when plugins are renamed.
- A resident plugin that long-polls a service (it has no token in a test store) must still
  start; if one blocks `initialize`, report it.
