# P0-14: alexia-hub CLI

Model: sonnet
Depends on: P0-13, P0-07
Feature IDs: SP-11, SP-12, SP-18

## Goal
After this task `alexia-hub.exe` is the one binary that boots the hub on Windows (`run`), lists
every enabled plugin's tools (`tools`), shows plugin status (`plugins`) and imports a v2 data
folder (`import-v2`). These four commands are how the owner checks P0's done-when by hand.

## Touch only these paths
- `v3/crates/alexia-hub/Cargo.toml`   (change)
- `v3/crates/alexia-hub/src/main.rs`   (change)
- `v3/crates/alexia-hub/tests/skeleton.rs`   (delete)
- `v3/crates/alexia-hub/tests/cli.rs`   (create)
- `v3/Cargo.lock`   (change)

## Must not touch
Every library crate (if one lacks something, stop and report), `connect/`, `.github/`,
`plugins/`.

## Interfaces
INTERFACES.md §2.6:

```
alexia-hub run                     start everything; Ctrl+C stops it cleanly
alexia-hub tools                   load plugins, print every enabled plugin's tools, exit
alexia-hub import-v2 <v2-folder>   print the ImportReport
alexia-hub import-v2 --files-only <v2-folder>   repeat the file copy only (§6)
alexia-hub plugins                 print PluginStatus for every plugin found
```

Uses: `alexia_store::{data_dir, Layout, Store, import::{import_v2, import_v2_files}, secrets}`,
`alexia_mcp::{McpHost, HostConfig, Timings, NoUpcalls, PluginId, discover}`,
`alexia_core::{Bus, Event}`.

Environment:
- `ALEXIA_V3_DATA` (via `data_dir()`), `ALEXIA_PLUGINS_DIR` (a second plugin folder after
  `layout.extensions()`), `ALEXIA_NODE` (else `node` resolved on `PATH`, else the literal
  `node`).

Which plugins are enabled: kv `_core` / `enabled` (a JSON array of ids, v2's key, so an import
carries it over). When the key is absent, every discovered plugin is enabled (a fresh hub with
`ALEXIA_PLUGINS_DIR` set shows everything, which is what P0's done-when needs).

Output, one line per item, stable for tests:
- `tools`: `<plugin id>\t<tool name>\t<description first line>`; hidden tools get a trailing
  `\t(hidden)`. Then, per plugin that is refused or unhealthy, `! <id>\t<sentence>` on stderr.
  Exit 0 even when some plugin failed (the line says why); exit 1 only if the hub itself failed.
- `plugins`: `<id>\t<state>\t<version>\t<enabled|disabled>[\t<sentence>]`.
- `import-v2`: `imported <table>\t<rows>` per table, `files\t<n>`, `skipped\t<item>` per
  skipped item, then `secret missing\t<plugin>.<key>` for every `password` setting of every
  discovered plugin whose `secrets::get` is `None`. Refusals print the sentence to stderr, exit 1.
- `run`: `Alexia hub is running. Press Ctrl+C to stop.` then, on Ctrl+C,
  `Stopped.`; each `PluginEvent` is logged with `tracing` at info.

## Steps
1. Dependencies: `tokio`, `tokio-util`, `tracing`, `serde_json` (workspace) and
   `tracing-subscriber` (why: the binary needs somewhere to print `tracing` events; one crate,
   `fmt` feature only, the same `connect/` uses). Argument parsing with `std::env::args`
   (four subcommands don't need a parser crate). `anyhow` is not in the workspace; use
   `Box<dyn std::error::Error>` in `main` or add nothing.
2. Wiring for `run` (§2.6): `Store::open(layout.db())` → `Bus::new(1024)` →
   `McpHost::new(cfg, store, Arc::new(NoUpcalls), sink)` where `sink` publishes
   `Event::Plugin` → `host.start(&enabled)` → wait for `tokio::signal::ctrl_c()` under a root
   `CancellationToken` → `host.shutdown()` → publish `Event::ShuttingDown`.
3. `tools` and `plugins`: same up to `start`, then `tools()` / `plugins()`, print, `shutdown`.
4. `import-v2`: open the store, call `import_v2` (or `import_v2_files`), print, then the secret
   check.
5. Unknown subcommand or none → usage text on stderr, exit 2.
6. Delete `tests/skeleton.rs`; write `tests/cli.rs`.

## Tests
`tests/cli.rs` (run `env!("CARGO_BIN_EXE_alexia-hub")` with `ALEXIA_V3_DATA` = a temp dir and
`ALEXIA_PLUGINS_DIR` = another temp dir; `ALEXIA_SECRETS_IN_MEMORY=1`):
- `no_args_prints_usage_and_exits_2`.
- `tools_with_no_plugins_prints_nothing`: exit 0, empty stdout. (Invariant 2 at the binary.)
- `plugins_with_no_plugins_prints_nothing`.
- `tools_lists_a_fixture_plugin`: a plugin folder whose `entry.run` is the `mcp-fixture`
  binary, found by `fixture_exe()` (see Notes); output contains `\tgreet\t` and a
  `secret_tool` line ending in `(hidden)`.
- `enabled_list_is_respected`: kv `_core/enabled = []` written to the store first → `tools`
  prints nothing for that plugin.
- `import_v2_refuses_a_missing_folder`: exit 1, the sentence on stderr.
- `import_v2_imports_a_v2_file`: a v2 database built with the P0-07 fixture SQL
  (`include_str!("../../alexia-store/tests/fixtures/v2_migrations.sql")`) holding one session
  and one message; output has `imported messages\t1`; a second run exits 1.
- `run_starts_and_stops`: spawn `run` with `ALEXIA_HUB_STOP_ON_EOF=1`, wait for the
  "running" line, close its stdin; it prints `Stopped.` and exits 0 within 10 s. (Sending a real
  Ctrl+C to a child on Windows needs `GenerateConsoleCtrlEvent`, which is unsafe and fragile;
  the env var is a documented test hook that makes stdin EOF behave like Ctrl+C.)

## Notes for the worker
- `fixture_exe()`: `std::env::current_exe()` (the test binary in `target/<profile>/deps/`),
  up one folder, `mcp-fixture` plus `std::env::consts::EXE_SUFFIX`. `cargo test --workspace`
  builds every package's bins before running any test, so it exists; when it doesn't (e.g.
  `cargo test -p alexia-hub` alone), panic with "run `cargo build --workspace --bins` first".
  No new dev-dependency.
- Never print a secret value; `secret missing` lines name the key only.
- The hub must never name a plugin (check 1, P0-16): ids come from manifests at runtime.
- Windows: the hub runs as a console app in P0. The tray and `windows_subsystem = "windows"`
  come later.
