# P0-05: Store: plugin namespaces

Model: opus
Depends on: P0-04
Feature IDs: SP-11, EX-01

## Goal
After this task a plugin's tables (`p_<ns>_<table>`), kv and settings can be created, read,
written and purged through `Store`, exactly as v2's `storage.md` promises, with every value a
bound parameter and every identifier checked. This is what the `alexia/storage/*` methods
(P0-13) sit on, and what makes "purge leaves no residue" (EX-01) provable.

## Touch only these paths
- `v3/crates/alexia-store/src/lib.rs`   (change: `mod namespace;`)
- `v3/crates/alexia-store/src/namespace.rs`   (create)
- `v3/crates/alexia-store/tests/namespace.rs`   (create)

## Must not touch
`db.rs`, `migrations.rs`, `types.rs` (use `Store::conn()` from P0-04). Other crates.
`Cargo.toml` (no new dependencies).

## Interfaces
From INTERFACES.md §2.1, implemented in `namespace.rs` as an `impl Store` block:

```rust
impl Store {
    pub fn create_tables(&self, ns: &str, tables: &[String]) -> Result<()>;
    pub fn insert(&self, ns: &str, table: &str, row: &Row) -> Result<i64>;          // rowid
    pub fn select(&self, ns: &str, table: &str, q: &Select) -> Result<Vec<Row>>;
    pub fn update(&self, ns: &str, table: &str, set: &Row, filter: &Where) -> Result<u64>;  // filter non-empty
    pub fn delete(&self, ns: &str, table: &str, scope: DeleteScope<'_>) -> Result<u64>;
    pub fn count(&self, ns: &str, table: &str, filter: Option<&Where>) -> Result<u64>;
    pub fn raw(&self, ns: &str, sql: &str, params: &[Scalar]) -> Result<Vec<Row>>;
    pub fn purge(&self, plugin: &str, ns: Option<&str>) -> Result<()>;
}
```

Physical name: `p_<ns>_<table>` with every `-` in `ns` replaced by `_`. `ns` must match
`^[a-z][a-z0-9-]*$`; `table` and every column must pass `is_ident` (P0-02). A table that was not
created by `create_tables` for this `ns` → `Error::OutOfNamespace("<table> is not one of this
plugin's tables.")`.

## Steps
1. Name helpers: `physical(ns, table) -> Result<String>`; identifiers are double-quoted after
   validation.
2. `create_tables`: `CREATE TABLE IF NOT EXISTS "<physical>" (rowid INTEGER PRIMARY KEY)` per
   table, and add the table names to kv ns `_core`, key `tables:<ns>` (a JSON array, sorted,
   no duplicates). That record is the only way purge knows which tables are whose (see Notes).
3. `insert`: for each key not yet a column (read `PRAGMA table_info`), `ALTER TABLE … ADD COLUMN`
   with the type from storage.md (§5.2 of INTERFACES.md): integer or bool → `INTEGER`, other
   number → `REAL`, string/object/array → `TEXT` (objects and arrays stored as JSON text),
   null → `TEXT` nullable. Booleans stored as 0/1. A `rowid` key in the row is rejected
   (`Error::Invalid`).
4. `Where` → SQL: AND of `col = ?`, `!= ?`, `< ?`, `<= ?`, `> ?`, `>= ?`, `IN (?, …)`, `LIKE ?`,
   `IS NULL`. Validate each `Operator` (`validate()`). A column not in the table →
   `Error::Invalid`.
5. `select`: `order` columns validated, `limit`/`offset` bound. Rows come back as JSON objects
   with `rowid`; `TEXT` that was written from an object/array is returned as the parsed JSON
   (track which columns hold JSON by trying `serde_json::from_str` only when the text starts
   with `{` or `[`, as v2 does; read v2's `packages/core/src/store.ts` `select` and match it).
6. `update`: empty `filter` → `Error::Invalid("update needs a where.")`; new keys in `set` add
   columns like insert. `delete`: `DeleteScope::Where(w)` with empty `w` → `Error::Invalid`;
   `All` deletes every row.
7. `raw`: always `Error::OutOfNamespace("Raw SQL is not available.")`. This is v2's behaviour
   (`packages/core/src/host.ts`, open question G1); no plugin uses it.
8. `purge(plugin, ns)`: in one transaction, `DROP TABLE IF EXISTS` each table listed in kv
   `_core` / `tables:<ns>` (when `ns` is `Some`), delete that record,
   `DELETE FROM kv WHERE ns = ?plugin`, `DELETE FROM settings WHERE plugin = ?plugin`.
9. Write the tests.

## Tests
`tests/namespace.rs` (all on `Store::open_in_memory()`):
- `insert_grows_columns_with_v2_types`: insert `{"text":"a","n":3,"x":1.5,"b":true,"o":{"k":1},"z":null}`;
  `PRAGMA table_info` shows `INTEGER` for `n` and `b`, `REAL` for `x`, `TEXT` for `text`, `o`;
  select returns `b` as `1`, `o` as `{"k":1}`.
- `where_grammar`: one test per operator (`eq`, bare literal, `ne`, `lt`, `lte`, `gt`, `gte`,
  `in`, `like`, `isNull`) and a two-key AND, each asserting the right rows.
- `order_limit_offset`: `[["n","desc"]]`, limit 2 offset 1 returns the right rows.
- `update_and_delete_need_where`: empty `where` on update and on delete is `Error::Invalid`;
  `DeleteScope::All` deletes everything.
- `undeclared_table_is_out_of_namespace`: insert into a table not created → `OutOfNamespace`.
- `injection_is_refused`: table `x; DROP TABLE kv`, column `a"b`, ns `A`, and a `like` value
  `%' OR 1=1 --` either fail validation or match nothing; `kv` still exists afterwards.
- `hyphenated_namespace`: ns `web-research`, table `pages` becomes `p_web_research_pages`.
- `raw_is_refused`: any SQL → `OutOfNamespace`.
- `purge_removes_tables_kv_settings`: create two plugins' tables, kv and settings; purge one;
  its rows, tables and `tables:<ns>` record are gone, the other's are untouched.
- `purge_does_not_cross_namespaces`: ns `a` with table `b_x` and ns `a-b` with table `y`;
  purging `a-b` leaves `p_a_b_x` in place.

## Notes for the worker
- Normative: `docs/spec/storage.md`. v2's implementation: `packages/core/src/store.ts` (search
  `p_`, `columnType`, `ident`). Match v2's behaviour; P0-07 imports v2 tables and plugins expect
  the same answers.
- **No value from a plugin is ever concatenated into SQL.** Identifiers are validated, then
  quoted; values are always `?` parameters. This is the security boundary between plugins and
  core's tables.
- The `purge` prefix trap: ns `a` with table `b_x` and ns `a-b` with table `x` are both
  `p_a_b_x`, so a name-prefix match cannot tell whose a table is. Hence the record in kv
  `_core` / `tables:<ns>` (step 2): purge drops exactly the tables listed there. P0-07 writes
  the same record for imported tables.
