# P0-07: Store: the v2 importer

Model: opus
Depends on: P0-06
Feature IDs: SP-18

## Goal
After this task `alexia_store::import::import_v2` turns a copy of a v2 data folder into v3's
store: every chat, every plugin's tables (the memory plugin's long-term memory, commitments,
personas), kv, settings, the ledgers, attachments, and the plugins' own dirs, skills and uploads.
It runs once, all or nothing for the database. This is the "has imported v2's chats and memory"
half of P0's done-when.

## Touch only these paths
- `v3/crates/alexia-store/src/lib.rs`   (change: `pub mod import;`)
- `v3/crates/alexia-store/src/import.rs`   (create)
- `v3/crates/alexia-store/tests/import.rs`   (create)
- `v3/crates/alexia-store/tests/fixtures/v2_migrations.sql`   (create)

## Must not touch
`packages/core/src/store.ts` (copy from it, never edit it), `db.rs`, `migrations.rs`,
`namespace.rs`, `secrets.rs`, other crates.

## Interfaces
From INTERFACES.md §2.1:

```rust
pub mod import {
    #[derive(Clone, Debug, PartialEq, serde::Serialize, serde::Deserialize)]
    pub struct ImportReport { pub v2_schema: i64, pub rows: Vec<(String, u64)>, pub files: u64, pub skipped: Vec<String> }
    /// `v2_root` is a v2 data folder (copied whole, with v2 quit). Refuses if `store` already
    /// holds an import or any session.
    pub fn import_v2(store: &super::Store, v2_root: &Path, v3: &super::Layout) -> super::Result<ImportReport>;
}
```

Added here (INTERFACES.md §6 names `--files-only`):

```rust
pub mod import {
    /// The file half only, for repeating after a copy failure. Never touches the database.
    pub fn import_v2_files(v2_root: &Path, v3: &super::Layout) -> super::Result<u64>;   // files copied
}
```

Behaviour: INTERFACES.md §6, all of it (checks in order, the table mapping, the file mapping,
the `imports` row), with two additions:
- For every imported `p_<ns>_<table>`, write the kv `_core` / `tables:<ns>` record P0-05 uses
  for purge. `ns` comes from the plugin's own kv/settings rows or, failing that, the table name
  is listed in `skipped` as "not attributable" and still copied.

  To attribute a table: a v2 table is `p_<ns>_<table>` where `<ns>` is a plugin id with `-` as
  `_`. Use the set of plugin ids that appear as `kv.ns` or `settings.plugin` in the v2 file plus
  the folder names under `<v2_root>/plugins/` and `<v2_root>/extensions/`; pick the longest id
  whose `p_<id with _>_` prefix matches.
- Secrets are never read or written by the importer. Which `password` settings have no secret
  on this machine needs the manifests, so the hub reports that after importing (P0-14).

## Steps
1. Fixture `tests/fixtures/v2_migrations.sql`: v2's eleven migrations from
   `packages/core/src/store.ts` `MIGRATIONS`, concatenated in order, each followed by
   `PRAGMA user_version = n;`. Add a header comment naming the source file and the date copied.
2. Checks (each a full sentence in `Error::Refused`):
   1. `<v2_root>/alexia.db` missing → "There is no Alexia database in that folder."
   2. `application_id` ≠ 0 → "That folder holds a v3 database, not a v2 one."
   3. `user_version` not in 1..=11 → "This v2 data is from a newer Alexia than the importer
      knows." (0 → "That database is empty.")
   4. v3 store has a row in `imports` or any session → "This hub already has conversations, so
      v2 data was not imported over them."
3. Checkpoint: open the v2 file read-write once, `PRAGMA wal_checkpoint(TRUNCATE)`, close.
   (It is a copy; INTERFACES.md §6.) Then `ATTACH 'file:<path>?mode=ro' AS v2` with URI
   filenames enabled.
4. One transaction: copy each table per §6's table, listing the actual columns of the v2 table
   (`PRAGMA v2.table_info`) and inserting only those, so columns an older v2 lacks become NULL
   or their default. `p_*` tables: `CREATE` from `v2.sqlite_master.sql` (rewritten to the main
   schema), then `INSERT … SELECT *`. Tables not in §6 → `skipped`. Messages whose `body` fails
   to parse as `MessageBody` are still copied and listed in `skipped` by id.
5. Insert the `imports` row (report as JSON) in the same transaction; commit; `DETACH`.
6. Files: `import_v2_files` copies (never moves) `plugins/<id>/` → `layout.own_dir(id)`,
   `extensions/<id>/` → `layout.extensions()/<id>`, `skills/` → `layout.skills()`,
   `uploads/` → `layout.uploads()`; `cache/` is not copied. Existing destination files are left
   alone and listed in `skipped`. `import_v2` calls it after commit; a copy error after commit is
   returned as `Error::Io` and the report row is already written (re-run with `--files-only`).
7. Write the tests.

## Tests
`tests/import.rs`, each in a temp dir, building the v2 file from the fixture SQL:
- `imports_a_full_v2_file`: v2 file at version 11 with 2 sessions, 5 messages (string and parts
  content, one tool call with `callId`), kv rows in `_core` and `memory`, settings rows,
  `usage`, `tries`, `seen`, `runs`, `provider_usage`, one `attachments` row, one
  `attachment_leases` row, and `p_memory_notes` with 3 rows (the memory plugin's table,
  INTERFACES.md §6 done-when). After import: every row count matches `ImportReport.rows` and the
  v2 counts; `attachment_leases` is empty; one message body round-trips byte for byte;
  `store.history(session, None)` returns the v2 conversation in order; `p_memory_notes` is
  readable through `store.select("memory", "notes", …)`; kv `_core` / `tables:memory` lists
  `notes`.
- `imports_an_old_v2_file`: a v2 file built from migrations 1..=4 only: import succeeds, missing
  columns are NULL, `image_ordinal` is 0.
- `refuses_in_order`: missing db, a v3 file, user_version 12, and a v3 store with a session each
  give their sentence.
- `second_import_is_refused`: importing twice → the "already has conversations" sentence.
- `bad_body_is_copied_and_listed`: a message with `body` = `not json` is copied and its id is in
  `skipped`.
- `copies_files_not_moves`: `plugins/memory/x.txt`, `skills/a/SKILL.md`, `uploads/1/p.png`,
  `cache/c` in v2; after import the first three exist in v3 and still in v2, `cache` does not.
- `files_only_repeats_the_copy`: after deleting a copied file, `import_v2_files` puts it back.
- `wal_is_checkpointed`: a v2 file left with an un-checkpointed WAL (write with a second
  connection held open, then copy the db and `-wal` file) imports every row.

## Notes for the worker
- The fixture is the only v2 schema source the tests use; never read `packages/` at test time.
- `ATTACH` with `mode=ro` needs `SQLITE_OPEN_URI`; rusqlite's bundled SQLite supports it, set
  the flag on the connection or use `sqlite3_db_config`. Paths on Windows in a `file:` URI use
  forward slashes and a leading `/` before the drive (`file:/C:/…`); build it from the `Path`.
- Plugin ids are data here, read from the v2 file. Never write a plugin id literal in
  `import.rs` (check 1, P0-16). The test file may use `memory` as a fixture name: tests are
  outside `src/`.
- v2's data folder layout: `docs/spec/storage.md` (*The plugin's directory*) and
  `packages/core/src/store.ts` `dataDir`.
- Do not import `cache/` and never touch v2's live folder.
