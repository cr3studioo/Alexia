# P0-11: McpHost: start, handshake, tools, call_tool

Model: opus
Depends on: P0-10, P0-04
Feature IDs: SP-11

## Goal
After this task `McpHost` exists: it scans the plugin folders, loads manifests, refuses
incompatible plugins with a sentence, creates declared tables, spawns plugins on demand with the
§3.2 handshake, lists every enabled plugin's tools (following `nextCursor`) and calls them. This
is the piece the hub's `tools` command and the v2 conformance test stand on. Supervision
(heartbeat, idle, backoff, vanish) is P0-12; the `alexia/*` layer is P0-13.

- `v3/crates/alexia-mcp/tests/host.rs`   (create)

## Steps
1. State: per plugin id, `{ dir: PluginDir, enabled, state: PluginState, sentence, running:
   Option<Running { proc, conn }>, tools: Option<Vec<HostedTool>> }` behind one
   `std::sync::Mutex` (never held across `.await`); a per-plugin `tokio::sync::Mutex<()>` for
   spawn so two callers don't spawn twice.
2. `start(enabled)`: for each folder in `plugin_dirs` in order, `discover`; the first folder
   holding an id wins (later duplicates ignored, logged). Failed manifests → `Refused` event with
   the sentence (no id known: use the folder name only in the log, never as a `PluginId`).
   `compatible()` failure → state `Refused`, `PluginEvent::Refused`. Loaded → `Loaded` event.
   For enabled plugins with `storage`, `store.create_tables(ns, tables)`. Spawn enabled
   `Resident` plugins now; `Lazy` ones wait for first use.
3. Spawn + handshake (§3.2): `process::spawn` (secrets for redaction: the plugin's password
   values via `alexia_store::secrets::get`), `Conn::start`, `initialize` with
   `Upcalls::offers(id)` and `clientInfo {name:"Alexia", version: APP_VERSION}` within
   `timings.start_ms`; a returned `protocolVersion` ≠ the manifest's `mcp_protocol` → stop the
   process, state `Refused` with v2's sentence; then `notifications/initialized`; emit
   `Started { pid }`.
4. `tools()`: for every enabled, not-refused plugin, spawn if needed and `tools/list` (follow
   `nextCursor`), cache; build `HostedTool` with `provides` from `_meta["alexia/provides"]` and
   `hidden` = `_meta` has `alexia/compute` or `alexia/editor`. A plugin that fails to start is
   left out (its state says why); the call never fails as a whole. Run the plugins concurrently
   (`futures`-free: `tokio::task::JoinSet`).
5. `call_tool`: unknown id → `CallError::Off { sentence }`; disabled/refused → `Off` with its
   sentence; spawn if needed; `tools/call` with `_meta["alexia/call-context"] =
   {"conversationId": …}` when `ctx.conversation` is set, `ctx.meta` merged in; `ctx.progress`
   and `ctx.cancel` passed to `Conn::request` with `timings.call_ms`. Result parsed as
   `CallToolResult`; a JSON-RPC error → `CallError::Rpc`.
6. `stop` (D213: not a crash, next call respawns) → `process::stop` with `exit_grace_ms`,
   `Stopped { reason: Disabled }` is for `set_enabled(false)`; `stop()` emits
   `Stopped { reason: Shutdown }`. `shutdown` stops all. `set_enabled` updates state; `true`
   creates tables and spawns if resident. Persisting `enabled` is the hub's job (kv
   `_core.enabled`), not the host's.
7. `plugins()`: a `PluginStatus` per loaded plugin, sorted by id.
8. Write the tests.

## Tests
`tests/host.rs` (temp dirs; plugin folders hold a `plugin.json` whose `entry.run` is
`env!("CARGO_BIN_EXE_mcp-fixture")` and args the mode; `Store::open_in_memory()`; an
`EventSink` that pushes into a `Mutex<Vec<PluginEvent>>`):
- `starts_with_no_plugins`: empty dir and a missing dir → `start` Ok, `plugins()` empty,
  `tools()` empty. (Invariant 2's host half.)
- `lists_tools_lazily`: a lazy `greet` plugin has no pid after `start`; `tools()` spawns it,
  returns `greet` (provides `["demo.greet"]`, not hidden) and `secret_tool` (hidden), and a
  second `tools()` call doesn't respawn (same pid).
- `resident_spawns_at_start`.
- `call_tool_round_trip`: `greet {who:"Sam"}` → `Hello, Sam.`; with `ctx.conversation =
  Some("7")` the request carries `alexia/call-context` (assert via `host.log(id)`: the fixture's
  `got …` stderr line holds the `_meta` it received).
- `incompatible_is_refused_without_a_process`: `alexia_protocol: 99` → `PluginState::Refused`,
  a `Refused` event with a sentence, no pid, left out of `tools()`.
- `wrong_protocol_answer_is_refused`: a fixture launched with `--protocol 2026-07-28` →
  `Refused` with a sentence, process stopped, left out of `tools()`.
- `disabled_plugin_is_off`: `call_tool` on a disabled plugin → `CallError::Off`.
- `first_folder_wins`: the same id in two `plugin_dirs` → the first folder's manifest is used.
- `declared_tables_are_created`: a manifest with `storage {namespace, tables:["notes"]}` →
  after `start`, `store.count(ns, "notes", None)` is `Ok(0)`.
- `shutdown_stops_everything`: after `shutdown`, `pid()` is `None` for all and the processes
  have exited.

## Notes for the worker
- The invariant: no plugin id literal in `src/` (check 1). Plugins are only `PluginId`s read from
  manifests.
- Capability resolution and the alexia/* answers are P0-13; don't build them here beyond the
  stubs listed.
- The hub calls `tools()` once and exits (`alexia-hub tools`), so a slow plugin start bounds
  that command: respect `start_ms` per plugin and run them concurrently.
- `HostConfig.node` resolution (`ALEXIA_NODE` / PATH) is the hub's (P0-14); the host uses the
  path it is given.
- Behaviour reference: `packages/core/src/plugins.ts`, `handshake.ts`, `host.ts`.
