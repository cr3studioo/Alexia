# P0-03: MCP wire types, host types, core bus

Model: opus
Depends on: P0-02
Feature IDs: SP-11, EX-01

## Goal
After this task the plugin wire exists as Rust types (`jsonrpc`, `types`, `alexia`), the types
the host exposes to the crates above it exist (`PluginId`, `PluginEvent`, `Upcalls`, `CallError`,
`HostConfig`, …), and `alexia-core` has its event bus. No process, no I/O. Every later host task
and the hub build on these, so they are fixed first, in one place.

Defined here:

```rust
// alexia-mcp/src/error.rs
#[derive(Debug, thiserror::Error)]
pub enum Error {
    #[error(transparent)] Store(#[from] alexia_store::Error),
    #[error(transparent)] Io(#[from] std::io::Error),
    #[error("No plugin with that id is installed.")] UnknownPlugin(PluginId),
    /// A sentence the owner reads (incompatible, switched off, unhealthy).
    #[error("{0}")] Refused(String),
}
pub type Result<T> = std::result::Result<T, Error>;

// alexia-core/src/lib.rs
#[derive(Debug, thiserror::Error)]
pub enum Error {
    #[error(transparent)] Store(#[from] alexia_store::Error),
    #[error(transparent)] Mcp(#[from] alexia_mcp::Error),
}
pub type Result<T> = std::result::Result<T, Error>;
```

## Steps
1. Add the dependencies.
2. Write the four mcp modules and the core bus as above. `lib.rs` of mcp declares
   `pub mod jsonrpc; pub mod types; pub mod alexia; mod error;` and `pub use error::{Error, Result};`.
3. `AlexiaCall::parse(method, params)`: not starting with `alexia/` → `Ok(None)`; an `alexia/`
   method not in the enum → `Ok(None)` (the host answers METHOD_NOT_FOUND); `params: None` is
   treated as `{}`; unknown keys inside params (notably `_meta`) are ignored; bad params →
   `Err(RpcError { code: INVALID_PARAMS, .. })` with a sentence naming the method.
4. `Bus::publish` ignores the send error when there are no receivers.
5. Write the tests.

## Tests
`alexia-mcp/tests/wire.rs`:
- `v2_marker_round_trip`: `V2` serializes to `"2.0"`; `"1.0"` fails to deserialize.
- `message_classifies_lines`: a line with `id`+`method` is `Request`, `id`+`result` and
  `id`+`error` are `Response`, `method` alone is `Notification`; string and integer ids survive.
- `initialize_shapes_match_spec`: the §3.2 `initialize` request and result JSON parse into
  `InitializeParams` / `InitializeResult`, and `InitializeParams` serializes back to the same
  JSON.
- `tool_keeps_meta_and_annotations`: a tool with `_meta: {"alexia/provides": ["demo.greet"]}`,
  annotations and `outputSchema` round-trips unchanged.
- `call_tool_result_passes_content_through`: unknown content item types are kept.
- `alexia_call_parse`: each of the 20 methods in `AlexiaCall` parses from a sample params object;
  `None` params parse as `{}` for `settings/get` and `host/info`; `tools/list` is `Ok(None)`;
  `alexia/storage/insert` without `table` is `Err` with code `-32602`; `_meta` inside params is
  ignored.
- `select_params_order`: `"order": [["at","desc"]]` parses to `vec![("at".into(), Dir::Desc)]`.
- `no_upcalls_offers_roots_only`: `NoUpcalls.offers(..)` serializes to `{"roots":{}}`.

`alexia-core/src/bus.rs` unit tests:
- `publish_without_subscribers_is_fine`.
- `subscriber_receives_in_order`.
- `lagging_subscriber_gets_lagged_then_continues`: capacity 2, publish 5, the receiver sees
  `RecvError::Lagged(_)` and then the newest events.

## Notes for the worker
- Normative behaviour: `docs/spec/wire-protocol.md` (§3.3 versions, §4 capabilities, §5
  alexia/*). v2's TypeScript shapes: `packages/protocol/src/methods.ts`, `meta.ts`. If
  INTERFACES.md and `docs/spec/` disagree about what a plugin sees, the spec wins: write it the
  spec's way and say so in your report.
- `Outcome` with `#[serde(flatten)]` + `rename_all = "lowercase"` gives `"result"`/`"error"`
  keys; test both directions.
- `#[serde(untagged)] enum Message` tries variants in order; `Request` must come before
  `Notification` or every request parses as a notification.
- `Upcalls` is `dyn`, so it uses `#[async_trait::async_trait]`.
- No `anyhow` in either crate (INTERFACES.md §0.6).
