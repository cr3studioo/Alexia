# P0-20: De-flake idle_lazy_plugin_stops, round 2

Model: sonnet
Depends on: P0-18
Feature IDs: none

## Goal
P0-18 fixed the `host.pid().unwrap()` panic in `idle_lazy_plugin_stops`. The test still
flaked once under load (a parallel cargo build). It panicked at
`v3/crates/alexia-mcp/tests/supervise.rs:455`, which is the
`any(Stopped { reason: Idle })` assertion. By then `host.pid()` was already `None`, but no
`Stopped{Idle}` event had been recorded. It passes alone. Find which of these it is, fix it,
and make the next failure explain itself.
- (a) `host.pid()` clears before the `Stopped` event reaches the test's event collector. The
  test reads the events once and does not wait for them.
- (b) Under load the plugin stops for a reason other than `Idle`, for example a heartbeat or
  other timeout.

## Touch only these paths
- v3/crates/alexia-mcp/tests/supervise.rs   (change)

## Must not touch
`v3/crates/alexia-mcp/src/`, the other test files, other crates. If (b) turns out to be a real
host bug (for example an idle plugin being stopped as unresponsive), stop and report it with
file:line. Do not change src/.

## Interfaces
None.

## Steps
1. Read the test, the `Fx` event collector in supervise.rs, and where the host publishes
   `Stopped` relative to clearing the pid (`src/host.rs` and `src/supervise.rs`; read only).
2. Replace the one-shot read of the `Stopped{Idle}` event with an `eventually` wait on it,
   with a generous bound like the rest of the file.
3. If no `Stopped{Idle}` arrives, the panic message must print every recorded event, so a
   future flake shows the real stop reason.
4. Run the test under load 5 times: `cargo test --workspace` in one shell while
   `cargo test -p alexia-mcp --test supervise` loops in another, or the closest you can get.

## Tests
No new tests. The changed test still proves that a lazy plugin stops after idle with
`StopReason::Idle`, that its process is gone, that nothing crashed, and that the next call
starts a new process.

- `cargo fmt --all --check` passes in v3/
- `cargo clippy --workspace --all-targets -- -D warnings` passes in v3/
- `cargo test --workspace` passes in v3/
- 5 loaded runs of `cargo test -p alexia-mcp --test supervise` pass (say how you loaded it)
- The report says whether it was (a) or (b), with evidence from the code
