# P0-09: The mcp-fixture test server

Model: sonnet
Depends on: P0-03
Feature IDs: EX-01

## Goal
After this task `alexia-mcp` has a small MCP server in Rust, `mcp-fixture <mode>`, that host
tests spawn instead of real plugins. It is what lets `cargo test --workspace` exercise spawning,
crashing, hanging, vanishing and storage with `plugins/` empty and no Node installed
(INTERFACES.md §7, the fixture).

## Touch only these paths
- `v3/crates/alexia-mcp/src/bin/mcp-fixture.rs`   (create)
- `v3/crates/alexia-mcp/tests/fixture.rs`   (create)

## Must not touch
`alexia-mcp/src/lib.rs` and every other `src/` module (use the public `jsonrpc` and `types`
modules from P0-03), `Cargo.toml` (the bin is auto-discovered from `src/bin/`), other crates.

## Interfaces
Uses `alexia_mcp::jsonrpc::{Message, Request, Response, Notification, Outcome, RpcError, Id, V2}`
and `alexia_mcp::types::{InitializeResult, Implementation, Tool, ListToolsResult,
CallToolParams, CallToolResult}` from P0-03.

```
mcp-fixture <mode> [--die-on-start] [--protocol <version>]
```

Speaks INTERFACES.md §3.1/§3.2 on stdio: one JSON message per line. Answers `initialize` with
`protocolVersion` = `"2025-11-25"`, `serverInfo {name:"mcp-fixture", version:"0.0.0"}`,
`capabilities {"tools":{"listChanged":true}}`; ignores `notifications/initialized`; answers
`ping` with `{}`; answers `tools/list` with the mode's tools; any other request → `-32601`.
Logs each request it receives to **stderr** as `got <the request JSON>` on one line (never
stdout); host tests read `_meta` from these lines. `--protocol <version>` makes `initialize`
answer that `protocolVersion` instead of `2025-11-25`.

| Mode | Tools | Behaviour |
|---|---|---|
| `greet` | `greet {who}` with `_meta: {"alexia/provides": ["demo.greet"]}`; `secret_tool` with `_meta: {"alexia/compute": {"op": "demo.compute"}}` | `greet` returns `{"content":[{"type":"text","text":"Hello, <who>."}]}`. If `who` is `"progress"`, first sends two `notifications/progress` against the request's `_meta.progressToken`. If `who` is `"ask"`, sends `alexia/settings/get` to the host first and puts the result's JSON into the reply text |
| `exit` | `exit` | `tools/call exit` exits the process with code 3 mid-call |
| `hang` | `hang` | `tools/call hang` stops reading stdin and never answers (including pings) |
| `junk` | `junk` | after `initialize`, writes 1000 lines of non-JSON to stdout, then keeps serving normally |
| `vanish` | `slow {ms}` | answers after `ms` milliseconds; on `notifications/cancelled` for that id, drops it without answering |
| `storage` | `store {key, value}`, `recall {key}`, `remember {text}`, `list` | each sends the matching `alexia/storage/kv/set`, `kv/get`, `insert` (table `notes`), `select` (table `notes`) request **to the host**, waits for the answer, and returns it as text (or `isError: true` with the RPC error's message) |

`--die-on-start` exits with code 1 before reading stdin, in any mode.

## Steps
1. Write `mcp-fixture.rs` (aim for ~200 lines): a blocking stdin line reader thread, a writer
   guarded by a mutex, a map of pending outbound requests (fixture → host ids start at 1000 so
   they never collide with the host's). `std` + `serde_json` only; no tokio needed.
2. Write the tests in `tests/fixture.rs`, driving the binary directly through
   `std::process::Command` with piped stdio at `env!("CARGO_BIN_EXE_mcp-fixture")`.

## Tests
`tests/fixture.rs`:
- `greet_handshake_and_tools`: initialize → `2025-11-25`; `tools/list` returns `greet` with its
  `_meta` and `secret_tool`; `tools/call greet {who:"Sam"}` returns `Hello, Sam.`.
- `ping_is_answered`.
- `protocol_flag_changes_the_answer`: `--protocol 2026-07-28` answers that version.
- `requests_are_logged_to_stderr`: after `tools/call`, stderr has a `got {…}` line holding the
  request's `_meta`.
- `unknown_method_is_method_not_found`.
- `exit_mode_exits_with_3_mid_call`.
- `die_on_start_exits_1`.
- `junk_mode_still_answers_after_the_junk`: after initialize, skip non-JSON lines, then
  `tools/list` is answered.
- `storage_mode_sends_requests_to_the_host`: the test plays the host: after `tools/call store`,
  it reads an `alexia/storage/kv/set` request from the fixture, answers `{}`, and then gets the
  tool result.
- `vanish_mode_honours_cancel`: call `slow {ms:5000}`, send `notifications/cancelled`, then
  `ping` is answered and no result for the cancelled id arrives within 500 ms.

## Notes for the worker
- INTERFACES.md §7 names the modes `hello | crasher-* | vanisher`; this spec renames them on
  purpose: those are plugin folder names, and invariant check 1 fails any quoted plugin id in
  `src/` (P0-16). Use the names in the table above.
- Every test must time out (wrap reads in a thread with a deadline, ~5 s) rather than hang the
  test run when the fixture misbehaves.
- stdout is the wire: no `println!` debugging there.
- Windows: line endings are `\n` only; don't let `writeln!` on a `BufWriter` be the issue, but
  do strip a trailing `\r` on input lines.
