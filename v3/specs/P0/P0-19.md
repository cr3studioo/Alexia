# P0-19: Host display name and unwritten tables (from P0-15)

Model: opus
Depends on: P0-13
Feature IDs: none

## Goal
P0-15's conformance test ran the real v2 plugins through the Rust host and found two bugs
that stop plugins from listing their tools. (1) `NoUpcalls::host_facts` returns an empty
`display_name`. The v2 SDK rejects `alexia/host/info` with an empty `displayName` and the
plugin process exits. That breaks apple-context, computer, media, ocr, voice and web-research,
in the hub too, because `alexia-hub` uses `NoUpcalls`. (2) `select` with `where` or `order` on a
column of a declared table that has never had a row written errors with
"<col> is not a column of <table>". v2 creates declared tables with no columns, and columns
appear on first insert. It treats such a table as empty (commitments and persona hit this).
After this task both work the way v2 does.

## Touch only these paths
- v3/crates/alexia-mcp/src/lib.rs   (change: `NoUpcalls::host_facts` only)
- v3/crates/alexia-mcp/tests/alexia_layer.rs   (change: only if an existing assertion expects the empty name; add the new test here)
- v3/crates/alexia-store/src/namespace.rs   (change)
- v3/crates/alexia-store/tests/namespace.rs   (change: add tests)

## Must not touch

## Interfaces
No signature changes.
- `NoUpcalls::host_facts().display_name` is `"Alexia"`. This matches v2's
  `packages/core/src/host.ts:346`, `displayName: this.options.displayName ?? 'Alexia'`.
- In `alexia-store` namespace.rs, mirror v2 `packages/core/src/store.ts:708-760` (`#unwritten`).
  A declared table that has only the columns `create` itself makes (no row has ever added
  one) is *unwritten*. On an unwritten table:
  - `select` returns `Ok(vec![])` whatever its `where`/`order`/`limit`/`offset`
  - `update` returns `Ok(0)`
  - `delete` returns `Ok(0)`
  - `count` returns `Ok(0)`
  The check goes once, in a shared helper, before the column checks. Identifier validation
  (`check_ident`) still runs first, so a malformed name still errors. On a table that has
  columns, an unknown column still errors with the same message as today. Ownership checks
  (`owned`) still run first, so another namespace's table still errors.

4. Add the tests.

## Tests
In alexia-store/tests/namespace.rs:
- `unwritten_table_selects_empty_with_where_and_order`: declare a table, then select with a
  `where` and an `order` on a column that does not exist yet. The result is `Ok(empty)`.
- `unwritten_table_update_delete_count_are_zero`: each returns `Ok(0)`.
- `written_table_still_rejects_unknown_column`: insert one row, then select ordered by a
  missing column. It errors with "is not a column of".
In alexia-mcp/tests/alexia_layer.rs:
- `host_info_display_name_is_not_empty`: a fixture plugin's `alexia/host/info` (or however the
  existing tests observe host facts) gets `displayName == "Alexia"`.
