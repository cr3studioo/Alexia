# P0-12: Supervision: lazy, idle, heartbeat, backoff, vanish

Model: opus
Depends on: P0-11
Feature IDs: EX-01

## Goal
After this task a plugin that crashes, hangs, floods stdout or has its folder deleted mid-call
takes down only itself: the host restarts it with backoff, gives up after three crashes in
sixty seconds and marks it unhealthy, kills it when it stops answering pings, stops lazy plugins
after five idle minutes, and drops a vanished plugin's tools. These are invariant checks 3 and 4
(INTERFACES.md §7), the Rust half of "delete the folder, nothing breaks".

## Touch only these paths
- `v3/crates/alexia-mcp/src/lib.rs`   (change: `mod supervise;`)
- `v3/crates/alexia-mcp/src/host.rs`   (change: hook the supervisor into spawn/exit/call)

## Must not touch
`process.rs`, `conn.rs`, `job.rs`, `manifest.rs`, the wire modules, the fixture, other crates.

## Interfaces
Uses `Timings`, `PluginState`, `PluginEvent`, `StopReason`, `CallError` (INTERFACES.md §2.2,
P0-03) and the P0-11 host. No new public API. Behaviour:

| Situation | What the host does | Event(s) |
|---|---|---|
| process exits unexpectedly (not via `stop`/`shutdown`/idle) | in-flight calls → `CallError::Gone`; record a crash; respawn on the next use, not before `backoff_ms · 2^(n-1)` (capped at `max_backoff_ms`) after the last crash; a resident plugin is respawned by the supervisor after that delay | `Crashed { exit_code }` |
| `crash_limit` crashes within `crash_window_ms` (a failed start counts) | state `Unhealthy`, sentence "<name> stopped working and was switched off. It can be restarted." (v2's wording if v2 has one); no more respawns until `set_enabled(true)` | `Unhealthy { sentence }` |
| no ping answer within `heartbeat_ms`, pinged every `heartbeat_ms` while running | kill, count as a crash | `Stopped { reason: Heartbeat }` then `Crashed` |
| lazy plugin, `Conn::quiet_ms() ≥ idle_ms` and no call in flight | `process::stop` | `Stopped { reason: Idle }` |
| plugin folder no longer exists (checked on every heartbeat tick and before every call) | kill, in-flight calls → `CallError::Gone`, remove from `plugins()` and `tools()` | `Removed` |
| `notifications/tools/list_changed` | drop tool cache (P0-11) | `ToolsChanged` |

One supervisor task per running plugin (spawned with the process, ended with it) does the ping
and idle checks; it holds the plugin's `CancellationToken` so `stop`/`shutdown` end it.

## Steps
1. `supervise.rs`: `CrashLog` (timestamps within the window, `fn record(now) -> Verdict
   { Retry { after_ms }, Unhealthy }`), the per-plugin supervisor loop, the vanish check
   (`dir.path.join("plugin.json").exists()`).
2. Hook into `host.rs`: exit watcher on `Conn::closed()`; respawn gate on backoff; vanish check
   before `call_tool`/`tools`; `set_enabled(true)` clears `Unhealthy` and the crash log.
3. Make `Timings` fully injectable so tests run in seconds (tests use e.g. `heartbeat_ms: 200`,
   `idle_ms: 300`, `backoff_ms: 50`, `crash_window_ms: 5_000`).
4. Write the tests.

## Tests
`tests/supervise.rs` (fixture plugins as in P0-11, short `Timings`):
- `crasher_exit_is_contained`: `exit` mode: `call_tool exit` → `CallError::Gone`; the host still
  answers `tools()` for a second, healthy `greet` plugin; the next `call_tool` on the crasher
  respawns it (new pid).
- `three_crashes_mark_unhealthy`: three `exit` calls within the window → state `Unhealthy`, an
  `Unhealthy` event, the fourth call → `CallError::Off` with the sentence, no new process;
  `set_enabled(true)` brings it back.
- `backoff_delays_respawn`: second respawn happens no sooner than `backoff_ms · 2` after the
  second crash.
- `die_on_start_counts_as_crashes`: `--die-on-start` → after three attempts, `Unhealthy`.
- `hang_is_killed_by_heartbeat`: `hang` mode: `call_tool hang` returns (`Gone` or `Timeout`)
  within `heartbeat_ms · 3`; a `Stopped { Heartbeat }` event was emitted; the process is gone.
- `junk_does_not_kill_the_host`: `junk` mode: `tools()` still returns `junk`'s tool.
- `idle_lazy_plugin_stops`: after `idle_ms` with no calls, `pid()` is `None` and
  `Stopped { Idle }` was emitted; the next call respawns it.
- `resident_does_not_idle_stop`.
- `vanisher_folder_deleted_mid_call`: `vanish` mode: start `slow {ms:3000}`, delete the plugin
  folder (`std::fs::remove_dir_all`, which must succeed on Windows because the process cwd is
  its own dir), the call ends with `CallError::Gone`, a `Removed` event is emitted, and the
  plugin's tools are gone from `tools()`. (Invariant check 4.)
- `stop_is_not_a_crash`: `host.stop(id)` doesn't count toward `crash_limit`.

## Notes for the worker
- *Why*: `Alexia.md` *Supervision — and the memory objection* and *The load-bearing invariant*.
  v2's equivalent: `packages/core/src/plugins.ts` (backoff, crash window, heartbeat) and the
  invariant tests `packages/core/test/invariants/03-crasher-contained.test.ts`,
  `04-vanisher-replans.test.ts`; port their assertions, not their timings.
- Deleting the folder while the process runs: the process's executable is the fixture binary
  in `target/`, not in the folder, so deletion works. With a real Node plugin, the folder holds
  only scripts, which Windows lets you delete while `node` runs.
- Timing tests flake on loaded CI runners: assert with generous upper bounds and never assert
  "exactly at" a time.
- No locks held across `.await`.
