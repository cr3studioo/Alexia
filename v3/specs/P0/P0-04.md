# P0-04: Store: open, migration 1, history, kv, settings, ledger, sqlite-vec

Model: opus
Depends on: P0-02
Feature IDs: SP-15

## Goal
After this task `Store` opens the one v3 database file, runs migration 1, refuses files that
aren't v3's or are newer than this build, and serves sessions, history, kv, settings and the
router's ledger. sqlite-vec is registered on every connection so vector tables can live in the
same file (SP-15). Plugin namespaces, secrets and the importer follow in P0-05 to P0-07.

`migrations.rs`: `pub(crate) const MIGRATIONS: &[&str] = &[ /* migration 1 */ ];` with migration
1 exactly INTERFACES.md §5.1 (application_id, every table and index, without the trailing

## Steps
1. Add `sqlite-vec` to the crate's `Cargo.toml` (why: SP-15 needs vector search in the one
   file, and neither rusqlite nor the standard library provides it; it compiles the C source
   into the binary, so the hub stays a single file).
2. `db.rs`: `Store` with `Mutex<Connection>`. On every new connection: register sqlite-vec,
   `PRAGMA journal_mode=WAL` (skipped for in-memory), `foreign_keys=ON`, `busy_timeout=5000`.
3. `open`: create the parent folder; read `application_id` and `user_version`. A file with
   `user_version > MIGRATIONS.len()` → `Error::Refused("This database is from a newer Alexia
   than this one.")`. A file with tables whose `application_id` is not `APPLICATION_ID` →
   `Error::Refused("This file is not an Alexia v3 database.")` (an empty new file has 0 and no
   tables, and is migrated). Then run each pending migration in its own transaction with its
   `PRAGMA user_version = n`.
4. Sessions and history: `append` also sets the session's `updated_at`. `body` is stored as
   `serde_json::to_string(&MessageBody)`. `history(limit)` returns the newest `limit` messages in
   ascending id order. `at`/`created_at` come from `SystemTime::now()` as `Ms`.
5. kv and settings store values as JSON text.
6. Ledger: `record_request` increments `provider_usage` for both the `minute` bucket
   (`at / 60_000`) and the `day` bucket (`at / 86_400_000`) with an UPSERT, as v2's
   `packages/core/src/store.ts` does (read it and match the bucket arithmetic exactly).
   `record_usage` and `record_try` are plain INSERTs mapping `Usage.writing_ms` → `writing` and
   `Try.waited_ms` → `waited`.
7. Write the tests.

## Tests
`tests/store.rs`:
- `open_creates_file_and_migrates`: in a temp dir, `open` creates `alexia.db`; `user_version`
  is 1, `application_id` is 1095522355, `journal_mode` is `wal`, every §5.1 table exists.
- `reopen_is_idempotent`: open, close, open again: no error, still version 1.
- `refuses_newer_schema`: set `user_version = 99` on a file, `open` is `Error::Refused`.
- `refuses_foreign_file`: a file with one table and `application_id = 0` (a v2 file) is
  refused.
- `sessions_and_history`: create two sessions, append 5 messages to one, `history(None)` returns
  them oldest first with bodies equal to what went in; `history(Some(2))` returns the last two in
  order; `sessions()` lists the one written to most recently first.
- `delete_session_cascades`: deleting a session removes its messages.
- `kv_and_settings`: set, get, overwrite, delete; `settings("x")` returns only plugin `x`'s keys.
- `ledger_rows`: `record_request` twice in the same minute gives count 2 in the minute bucket
  and in the day bucket; `record_usage` and `record_try` rows read back with every column.
- `sqlite_vec_is_available`: `CREATE VIRTUAL TABLE t USING vec0(v float[3])`, insert two rows,
  a KNN `MATCH` query returns the nearer row first.
- `transaction_rolls_back_on_error`: an `Err` from the closure leaves no row behind.

## Notes for the worker
- Registering sqlite-vec is an FFI call (`rusqlite::ffi::sqlite3_auto_extension` with
  `sqlite_vec::sqlite3_vec_init`, as the sqlite-vec crate's README shows). The workspace denies
  `unsafe_code`; put `#![allow(unsafe_code)]` on the smallest private module that holds that one
  call, with a comment saying why, and register it once (`std::sync::Once`).
- If `sqlite-vec` fails to build on MSVC, stop and report: don't swap in another vector crate.
- v2's schema and ledger code: `packages/core/src/store.ts` (migrations at the top, the ledger
  near `requests`/`usage`). Column names and meanings must match; P0-07 copies rows as-is.
- One connection behind a mutex is deliberate (INTERFACES.md §2.1 `ponytail:` note).
- Timestamps are `Ms = i64` everywhere (INTERFACES.md §0.5).
