# P0-13: The alexia/* layer, capabilities, purge

Model: opus
Depends on: P0-12, P0-06
Feature IDs: SP-11, EX-01

## Goal
After this task the host answers every V3-0 `alexia/*` request a v2 plugin sends (settings,
storage, kv, capability calls, `answers`, host info), resolves capabilities to providers without
ever naming them, sends `alexia/settings/changed` and `alexia/conversation/ended`, and purges a
plugin without residue. v2 plugins that read settings or storage at startup, such as the
resident ones, now run unchanged (SP-11), and invariant check 5 holds (EX-01).

## Touch only these paths
- `v3/crates/alexia-mcp/src/lib.rs`   (change: `mod serve;`)
- `v3/crates/alexia-mcp/src/serve.rs`   (create)
- `v3/crates/alexia-mcp/src/host.rs`   (change: route `alexia/*` to `serve`, fill the P0-11 stubs)
- `v3/crates/alexia-mcp/tests/alexia_layer.rs`   (create)
- `v3/crates/alexia-mcp/tests/purge.rs`   (create)

## Must not touch
`alexia-store` (use its API; if something is missing, stop and report), `process.rs`,
`conn.rs`, `supervise.rs`, the wire modules, the fixture, other crates.

## Interfaces
INTERFACES.md §3.4: the methods table (rows marked V3-0), the notifications table, `HostInfo`,
`HostPaths`, `AlexiaCall`. §2.2: the capability resolution rule, and these `McpHost` methods,
which replace the P0-11 stubs:

```rust
pub async fn call_capability(&self, cap: &str, args: Map<String, Value>, ctx: CallCtx) -> Result<types::CallToolResult, CallError>;
pub fn answers(&self, cap: &str) -> Answers;
pub async fn settings_changed(&self, id: &PluginId, changed: Map<String, Value>);
pub async fn conversation_ended(&self);
pub async fn purge(&self, id: &PluginId) -> Result<(), Error>;
```

Crate-private:

```rust
// serve.rs: one request from plugin `id`, already parsed.
pub(crate) async fn serve(host: &McpHost, id: &PluginId, call: alexia::AlexiaCall) -> Result<Value, RpcError>;
```

Store errors map to wire codes: `Error::OutOfNamespace` → `-32052`, `Error::Invalid` → `-32602`,
anything else → `-32603` with the sentence "Alexia could not read or write that." (never the
SQLite text).

## Steps
1. `settings/get`: every declared setting key → the stored value (`store.settings(id)`) or the
   manifest `default`; `password` settings read from `secrets::get(id, key)` at call time
   (missing → omitted, as v2 does; check `packages/core/src/host.ts`). `settings/set`: only a
   declared `status` key (`-32053` unknown key, `-32602` not a `status`), value ≤ 65 536 bytes
   of JSON.
2. Storage methods → `store.insert/select/update/delete/count/raw` with ns = the manifest's
   `storage.namespace`; a plugin without `storage` → `-32052`. `delete` needs exactly one of
   `where` (non-empty) or `all: true`. kv methods use ns = plugin id; value ≤ 65 536 bytes.
3. `capability/call {cap, arguments}`: the caller's manifest must list `cap` in `requires[]`
   (else `-32051`); resolve per §2.2 (enabled plugin whose running tool lists `cap` in
   `_meta["alexia/provides"]`; ties → lowest `installed_at` in kv `_core`/`provenance`, else id
   order); none → `-32050` with "Nothing installed and switched on can do <cap>."; call that
   tool through `call_tool` with `timings.capability_ms`; return the `CallToolResult` unchanged
   (the provider is never named). A plugin calling a capability it provides itself is allowed.
4. `answers {cap}` → `{answers, here}` from manifests' `provides[]` only, starting nothing
   (`here` = this hub's own plugin, which in P0 is the same as `answers`; limbs arrive at V3-4).
5. `host/info` → `HostInfo`: platform/arch in Node's names (`std::env::consts::OS`
   `windows`→`win32`, `macos`→`darwin`; `x86_64`→`x64`, `aarch64`→`arm64`), `APP_VERSION`,
   `ALEXIA_PROTOCOL_MAX`, `Upcalls::host_facts()`, `paths.own_dir` only when the manifest
   requires `fs.own_dir`, `paths.cache_dir` = `layout.cache().join(id)` (created).
6. `compute/run` and `attachments/*` → `-32050` / `Upcalls::attachments` (V3-2 serves them).
7. `settings_changed` and `conversation_ended` send the §3.4 notifications to running plugins
   only. `purge(id)`: `stop`, `store.purge(id, ns)`, `secrets::delete_all(id, password_keys)`,
   remove `layout.own_dir(id)` and `layout.cache().join(id)`.
8. Write the tests.

## Tests
`tests/alexia_layer.rs` (fixture plugins; `ALEXIA_SECRETS_IN_MEMORY` set):
- `settings_get_merges_defaults_values_and_secrets`: manifest with a text setting (default),
  a choice setting set in the store, and a password setting with a secret in the memory
  backend; `greet {who:"ask"}` returns all three.
- `settings_set_only_status`: through a direct `serve` call, a `status` key is stored; a text key
  is `-32602`; an unknown key is `-32053`.
- `storage_round_trip`: `storage` mode: `remember`, `remember`, `list` returns both rows;
  `store`/`recall` round-trip a kv value.
- `storage_without_declaration_is_out_of_namespace`.
- `kv_value_cap`: a 70 000-byte value → `-32602`.
- `capability_call_resolves_without_naming`: plugin A (`storage` mode manifest that
  `requires demo.greet`) sends `alexia/capability/call {cap:"demo.greet"}` via a direct `serve`
  call; plugin B (`greet`) answers; the result has no field naming B.
- `capability_call_needs_requires`: same call from a plugin without the `requires` → `-32051`.
- `capability_call_without_provider`: B disabled → `-32050` with the sentence.
- `answers_reads_manifests_only`: `answers("demo.greet")` is true with B lazy and not running,
  and no process was started.
- `host_info_shape`: platform is `win32` on Windows; `ownDir` present only with `fs.own_dir`.
- `conversation_ended_reaches_running_plugins_only`: the running fixture's stderr log shows the
  notification; a stopped plugin isn't spawned for it.

`tests/purge.rs` (invariant check 5):
- `purge_leaves_no_residue`: snapshot `sqlite_master` and every table's rows (via `transaction`)
  and the data folder's file list; enable a `storage` plugin with a password setting, use
  insert, kv, a status setting, the secret, and write a file into its own dir; `purge`; the
  snapshot equals the first one exactly, and `secrets::get` is `None`.

- Normative: `docs/spec/wire-protocol.md` (alexia/* layer), `docs/spec/capabilities.md`
  (resolution, `requires`, error codes), `docs/spec/storage.md`. v2's server side:
  `packages/core/src/host.ts` (`alexia/*` switch) and `plugins.ts` (capability resolution).

  plugin sees, the spec wins (say so in the report).

  compares a `PluginId` to a literal.
- Tests that need a direct `serve` call use a `#[doc(hidden)] pub` test hook on `McpHost`
  (`serve_for_test(id, method, params)`), added in `host.rs`.
- `kv _core/provenance` may not exist yet in P0 (the library writes it later); fall back to
  id order.
