# P1-20: Hub: latency offsets and hidden console

Model: sonnet
Depends on: none
Feature IDs: SP-09, HB-12

## Goal
The latency dashboard reads span starts the way the gateway writes them. Today
`latency::turns` (`v3/crates/alexia-hub/src/latency.rs:66`) computes `r.start - at`, treating
`SpanRow.start` as epoch ms, but the gateway writes `start` as ms from the turn's first receipt
(`offset()`, `v3/crates/alexia-gateway/src/gateway.rs:126`). Every offset comes out about
−1.7e12, so `ack_ms` is negative and `alexia-hub latency --check` passes every turn. After this
task the offsets are right, a round-trip test through a real `Gateway` pins the contract, and
INTERFACES.md says what `start` means. Also: the boot check's PowerShell child
(`watchdog.rs:44`) opens a console window when the hub runs from Task Scheduler; it gets
`CREATE_NO_WINDOW` like `alexia-mcp/src/process.rs:134`.

## Touch only these paths
- `v3/crates/alexia-hub/src/latency.rs`   (change; tests stay in its `#[cfg(test)] mod tests`)
- `v3/crates/alexia-hub/src/watchdog.rs`   (change)

INTERFACES.md §2.1, the `SpanRow` block (around line 316), becomes:

```rust
/// (V3-1) `at`: epoch ms of the turn's first receipt. `start`: ms from that receipt (`at`) to
/// the span's start, not an epoch time. `ms`: the span's length.
#[derive(Clone, Debug, PartialEq, Serialize, Deserialize)]
pub struct SpanRow { pub turn: String, pub at: Ms, pub origin: String, pub lane: String,
                     pub name: String, pub start: Ms, pub ms: i64 }
```

## Steps
1. `latency.rs:66`: `.map(|r| (r.name.clone(), r.start, r.ms))`. Keep `at` (min of `r.at`) for
   the row's time column; it no longer enters the offsets.
2. In `mod tests`, rewrite `good()` to relative starts:
   `ack` start 0 ms 100, `first-byte` start 0 ms 500, `deliver` start 500 ms 500 (all with
   the given `at`). `groups_and_offsets` keeps its expectations (deliver at 500, total 1000,
   ack 100). Check every other test that builds rows with absolute starts (`check_fails_*`,
   `html_is_self_contained`, `top3_keeps_deliver`) and make their starts relative too.
3. Add the round-trip test below.
4. `watchdog.rs`, `local_offset_minutes`: build the command as a `mut` binding and, under
   `#[cfg(windows)]`, call `.creation_flags(0x0800_0000)` (CREATE_NO_WINDOW) before
   `.output()`. `std::process::Command` needs `use std::os::windows::process::CommandExt;`
   (inside the `#[cfg(windows)]` block, so non-Windows builds have no unused import).
   Leave the `schtasks` command alone: `install` runs from the owner's terminal.
5. INTERFACES.md as above.

## Tests
In `latency.rs` `mod tests`:
- `groups_and_offsets` and the other existing tests pass with the relative fixture.
- `absolute_start_is_not_subtracted` (`#[test]`): one turn with `at = 1_700_000_000_000` and
  rows `ack` start 0 ms 120, `deliver` start 900 ms 100 → `ack_ms == Some(120)`,
  `total_ms == 1000`, `check(&views, 1)` is empty. With the old code this gives a huge
  negative `ack_ms`.
- `check_fails_slow_ack_with_real_epoch` (`#[test]`): same `at`, `ack` start 0 ms 400 →
  `check` reports `ack took 400 ms`.
- `gateway_spans_round_trip` (`#[tokio::test(flavor = "multi_thread", worker_threads = 4)]`):
  a real `alexia_gateway::Gateway` over `Store::open_in_memory()`, with minimal fakes defined in
  the test module (copy the shapes from `v3/crates/alexia-gateway/tests/gateway.rs`:
  a `Channel` whose `next` hands out one `Inbound` (`kind: InKind::Message`,
  `from_owner: true`, text "hi") and then waits for cancel, whose other methods return `Ok`;
  a `Media` returning `Ok(None)`; a `Brain` that sleeps 50 ms and returns
  `Reply { text: "ok", files: vec![], lane: Lane::Chat, model: None, spans: vec![] }`).
  `GatewayConfig { merge_ms: 20, ..Default::default() }`. Poll (≤ 10 s) until
  `store.last_turns(1)` holds an `ack` row and a `deliver` row, cancel, await `run`. Then
  `turns(&rows)`: one view, `ack_ms` is `Some(a)` with `0 <= a < 300`, every stage offset
  `>= 0`, `50 <= total_ms < 5_000`, and `rows[0].at` is within 10 s of now (it is epoch ms).

## Notes for the worker
- `alexia-hub` is a binary crate, so the tests live in `latency.rs`'s inline test module; it
  already depends on `alexia-core`, `alexia-gateway`, `async-trait`, `tokio` (with `macros`,
  `rt-multi-thread`) and `tokio-util`, so no `Cargo.toml` change is needed. If one is, stop and
  report (P1-17 owns that file).
- The ack can be recorded in the turn's own `record_spans` call or later (the gateway's `late`
  path); poll for both rows rather than assuming one write.
- `turns` groups consecutive rows by `turn`; `last_turns` already orders them.
- Windows only builds the `creation_flags` call; CI on other platforms must still compile.
