# P1-14: v2: parallel tool calls

Model: opus
Depends on: none
Feature IDs: SP-16

## Goal
After this task, when a model asks for several tool calls in one turn, v2's agent loop runs them
at the same time instead of one after another. Until V3-2 the v2 loop is the task lane behind the
hub (P1-13), so this is where SP-16 lands in V3-1. Approval questions are still asked one at a
time, in the order the model made the calls, and results go back to the model in that order.

## Touch only these paths
- `packages/core/src/agent.ts`   (change: the `for (const call of calls)` loop in `run`, ~line 921)
- `packages/core/test/agent.test.ts`   (change: new tests)

Why v2 changes (CEO.md rule 4): SP-16 is a V3-1 pick and the agent loop answering V3-1's tasks is
v2's until V3-2 ports it. The change is local to one loop and keeps every existing behaviour
when the model makes one call.

## Must not touch
Everything else under `packages/`, `plugins/`, `src-tauri/`, `connect/`, `v3/`.

## Interfaces
Unchanged: `run()`'s signature, `Step`, `ToolOutcome`, the `on.step` / `on.done` / `on.phase` /
`on.progress` callbacks and their event shapes, `permitted()`, the `ceiling` and `alexia/final`
rules.

## Steps
1. Split the loop into two passes over `calls`, keeping model order:
   - **Gate pass, sequential**: for each call, check `signal.aborted` and `ceiling` as today,
     create the `Step`, emit `on.step`, and settle its permission: `options.guard` then, for an
     `ask`, `options.approve` (one question at a time, as today). Keep the ruling.
   - **Run pass, concurrent**: every call whose ruling allows it starts at once
     (`Promise.all` over `tools.call(...)` with the same arguments `permitted` uses today);
     refused calls resolve immediately to their refusal outcome. Emit `on.phase({kind:'tool',
     name})` for the first running call, `on.done(step)` as each one finishes.
2. After all settle, append the `tool` result messages to `messages`, `added` and the store **in
   the original call order** (the model matched them by `callId`, but stored history order
   must stay deterministic).
3. Refactor `permitted()` into `rule(step)` (gate) and `act(step)` (call) so both passes use the
   same code; `permitted` can remain as `rule` then `act` if other code calls it.
4. A stop (`signal.aborted`) during the run pass: every running call already receives the same
   signal; wait for them, then `finish('stopped')` as today.

## Tests
`packages/core/test/agent.test.ts`, with the file's existing fake tools and providers:
- `independent calls run at the same time`: two tools that each wait 200 ms → the step ends in
  under 350 ms (fake timers or measured), and both results reach the next model request.
- `approvals are asked one at a time in call order`: two `ask` calls → `approve` called twice,
  sequentially, first call first.
- `results keep the model's order`: the second tool finishes first; stored `tool` messages are
  still first-call, second-call.
- `a refused call does not hold up the others`.
- `stop during parallel calls stops all`.
- Every existing agent test still passes unchanged.
