# P1-31: v2 agent: dangling tool ids on a stop

Model: sonnet
Depends on: none
Feature IDs: SP-16

## Goal
**This is a v2 path** (`packages/core`, TypeScript), not v3 Rust.

When the owner presses stop while the gate pass is still going through a turn's calls (for
example during an approval question), every call still gets a tool result. In
`packages/core/src/agent.ts`, the gate loop's first line (`:928`)
`if (options.signal?.aborted) return finish('stopped')` returns with none of the turn's calls
answered: not the ones already gated (their step was pushed, nothing ran), not the rest. The
assistant row stored just before holds every call id, so the session's history has call ids
with no result, and the next turn on a strict provider is refused. It is the same bug P1-24
fixed for the step ceiling. After this task, on that return, every call of the turn gets
`{ role: 'tool', callId, content: 'not run: stopped' }`, pushed and stored like the others,
then `finish('stopped')`.

## Touch only these paths
- `packages/core/src/agent.ts`   (change)
- `packages/core/test/agent.test.ts`   (change)

## Must not touch
Everything under `v3/`, the rest of `packages/core` (`router.ts`, `provider.ts`, the store),
other packages and plugins.

## Interfaces
Unchanged. Uses the existing `Message` shape `{ role: 'tool', callId: string, content: string }`
and `ended: 'stopped'`.

## Steps
1. Add one small helper inside `run` (beside `rule`), used by both early exits:
   `const unanswered = (left: typeof calls, why: string): void` that, for each call in order,
   builds `{ role: 'tool', callId: call.id, content: why }` and does `messages.push`,
   `added.push`, `store.append(session, …)`.
2. P1-24's ceiling block calls `unanswered(calls.slice(gated.length), 'not run: step limit reached')`
   (same behaviour, one copy of the loop).
3. The gate loop's abort check becomes: `unanswered(calls, 'not run: stopped')`, then
   `return finish('stopped')`. All of `calls`, gated ones included: a gated call has not run,
   the run pass has not started.
4. Fire no `on.step` / `on.done` for these (as P1-24). Steps already pushed for gated calls stay
   in `steps` as they are today.
