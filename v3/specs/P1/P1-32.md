# P1-32: Hub run: every exit stops cleanly, Ctrl+C always wins, prune at boot, text-only latency args

Model: sonnet
Depends on: none
Feature IDs: HB-12, SP-09

## Goal
Four review findings in `alexia-hub/src/main.rs`, each fixed with a test:

1. After `boot` succeeds, `run` can return early with `?` (`channels::pairing_codes(&store)?`
   `:269`, `store.sessions()?` `:274`). Those paths skip `host.shutdown()` and
   `watchdog::clean_stop`, so plugin children are left to die with the process and the next boot
   reports a crash ("offline gap") that was not one. After this task every exit from `run` after
   `boot` goes through the one stop sequence.
2. With an offline gap, `run` sleeps 500 ms (`:315`) before it reaches the `ctrl_c` select, so a
   Ctrl+C in that window (or anywhere before the select) is not handled by the hub. After this
   task Ctrl+C is listened for from right after `boot` and always wins.
3. `latency` turns a non-UTF-8 argument into `""` (`:405`, `a.unwrap_or("")`), so
   `latency --html <bad>` writes to an empty path and `--last <bad>` gives a confusing parse error.
   After this task a non-UTF-8 argument is a clean usage error, exit 2.
4. The daily span prune (`:302`) first runs 24 h after start; a hub restarted daily never prunes.
   After this task it runs once at startup, then every 24 h.

## Steps
1. **One stop sequence.** Split `run` after `boot`:
   - Right after `boot`, create `root` and spawn the Ctrl+C listener (step 2) and the
     `ALEXIA_HUB_STOP_ON_EOF` thread as today.
   - Move everything from building providers through spawning the loops into
     `async fn serve(hub: &Hub, layout: &Layout, root: &CancellationToken, tracker: &TaskTracker) -> Res<()>`
     (exact signature is the worker's choice), ending with `root.cancelled().await; Ok(())`.
   - `run` then does `let result = serve(..).await;` and **always** runs the existing stop
     sequence: `root.cancel()`, `tracker.close()`, the 5 s `tracker.wait()`, `host.shutdown()`,
     `watchdog::clean_stop`, `bus.publish(Event::ShuttingDown)`, then prints `Stopped.` and
     returns `result` (so an error still exits 1 with its sentence, after the clean stop).
   - A startup error is an orderly exit, so `clean_stop` is written for it too.
   No `?` may remain between `boot` and the stop sequence outside `serve`.
2. **Ctrl+C always wins.** Spawn, right after `root` exists:
   `tokio::spawn(async move { if tokio::signal::ctrl_c().await.is_ok() { stop.cancel() } })`
   (`stop = root.clone()`). The final `tokio::select!` becomes `root.cancelled().await` inside
   `serve`. The offline-gap announcement moves off the main path: spawn it on `tracker` as a task
   that does `select! { _ = cancel.cancelled() => {}, _ = sleep(500 ms) => bus.publish(Say ..) }`
   with a `root.child_token()`. Keep the existing `ponytail:` comment on the 500 ms pause. Put the
   spawn in a small fn (e.g. `announce_gap(tracker, root, bus, text)`) so it can be unit-tested.
3. **Text-only latency args.** In `latency`, if any element of `rest` is `None`, print the
   sentence above and return `ExitCode::from(2)` before `latency::parse`. Otherwise map with
   `to_owned` (no `unwrap_or`).
4. **Prune at boot.** Run the prune closure once before handing it to `every` (build it once,
   call it, then pass it), so the first prune happens at startup and the next ones every 24 h.
   `every`'s "first after one period" stays as it is for the 10-minute invalidate.

## Tests
In `tests/cli_p1.rs` (binary, as the owner runs it; reuse `hub`, `run_with`, `out`, `err`):
- `run_error_after_boot_still_stops_cleanly`: open the data dir's store once (e.g. run
  `alexia-hub pair` so migrations run), then with `rusqlite` do
  `ALTER TABLE sessions RENAME TO sessions_gone` so `store.sessions()` fails. Run `run` with
  `ALEXIA_HUB_STOP_ON_EOF=1`. Assert exit code 1, the store error on stderr, `Stopped.` on
  stdout, and kv `_core`/`hub_clean_stop` present (read with `rusqlite` from the `kv` table).
  Before the fix the kv row is missing.
- `run_prunes_old_spans_at_boot`: with `alexia_store::Store::open` on the data dir's db, record
  one `SpanRow` with `at` 31 days ago and one with `at` now (`record_spans`); drop the store; run
  `run` with `ALEXIA_HUB_STOP_ON_EOF=1` (stdin closed at once). Assert the old row is gone and the
  new one stays.
- `latency_rejects_non_text_args`: `latency --html <non-UTF-8>`, where the argument is built
  with `std::os::windows::ffi::OsStringExt::from_wide(&[0xD800])` on Windows and
  `std::os::unix::ffi::OsStrExt::from_bytes(b"\xff")` elsewhere (`#[cfg]` both). Assert exit 2,
  the sentence on stderr, and no file written in the data dir.
- `run_without_channel_says_so_and_stops` passes unchanged.

In `src/main.rs`, a `#[cfg(test)] mod tests`:
- `gap_announcement_never_delays_stop`: build a `Bus`, subscribe, `TaskTracker`, `root`; call
  `announce_gap(.., "gap".into())`; it returns at once (not `async`). Cancel `root`,
  `tracker.close()`; `tracker.wait()` finishes within 100 ms (`tokio::time::timeout`), and the
  subscriber got no `Event::Say`. A second case without cancelling receives the `Say` within 2 s.
  (Real time; the hub has no tokio `test-util`, and adding it means touching `Cargo.toml`.)
