# P1-22: Core: tool rows on the wire, catalog temp file

Model: sonnet
Depends on: none
Feature IDs: SP-03, MO-04

## Goal
The chat lane works on sessions that hold tool turns. `wire()`
(`v3/crates/alexia-core/src/openai.rs:153`) turns every stored row into
`{"role", "content"}`: a `Role::Tool` row goes out as `"role": "tool"` with no `tool_call_id`,
and an assistant row's `calls` are dropped, so strict providers answer 400 for any history with
tool turns (v2's imported history has them). Also `Catalog::write`
(`v3/crates/alexia-core/src/catalog.rs:190`) leaves its `.<pid>-<n>.tmp` file behind when the
rename fails.

**The fix chosen for `wire`: leave tool turns out on this path.** `OpenAiCompat::chat` refuses
any request with `tools` (`openai.rs:258`, "tools are not sent on this path"), so every request
it sends has no tool definitions. Sending `tool_calls` / `"tool"` rows without `tools` is itself
rejected by some OpenAI-compatible providers, so mapping `call_id`/`calls` onto the wire would
trade one 400 for another. On this path: `Role::Tool` rows are skipped; an assistant row with
calls keeps only its text, and is skipped when it has no text. V3-2's agent loop, which sends
tools, maps them in full.

## Interfaces
Used, unchanged (`alexia_store`):

```rust
pub enum Role { System, User, Assistant, Tool }
pub struct ToolCall { pub id: String, pub name: String, pub arguments: String }
pub struct MessageBody { pub content: Content, pub calls: Option<Vec<ToolCall>>,
                         pub call_id: Option<String>, /* … */ }
```

Private, in `openai.rs`:

```rust
/// One stored row as an OpenAI chat message on the no-tools path, or `None` when the row is
/// a tool exchange only (a `Tool` row, or an assistant row with calls and no text).
fn wire(role: &Role, body: &MessageBody) -> Option<Value>;
```

## Steps
1. `wire` returns `Option<Value>`:
   - `Role::Tool` → `None`.
   - `Role::Assistant` with `calls` non-empty and no text (`Content::Text(t)` with
     `t.trim().is_empty()`, or `Content::Parts` with no non-blank `Part::Text`) → `None`.
   - Everything else → `Some(json!({"role", "content"}))` as today; `calls` and `call_id` are
     never put on the wire.
2. `chat` (`openai.rs:268`): `messages.extend(req.messages.iter().filter_map(|(r, b)| wire(r, b)))`.
3. Above `wire`, a `ponytail:` comment: tool turns are left out because this path sends no
   tools; V3-2 maps `calls` → `tool_calls` and `call_id` → `tool_call_id`.
4. `Catalog::write` (`catalog.rs:190`): if `std::fs::write(&tmp, ..)` or `std::fs::rename`
   fails, `let _ = std::fs::remove_file(&tmp);` and return the error, e.g.
   `let r = std::fs::write(&tmp, bytes).and_then(|()| std::fs::rename(&tmp, &self.cache));
   if r.is_err() { let _ = std::fs::remove_file(&tmp); } r`.
