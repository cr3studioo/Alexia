# P1-12: Approvals and voice notes

Model: opus
Depends on: P1-11
Feature IDs: CH-07, CH-05

## Goal
After this task a question a run needs answered (an approval gate, a price check) appears in the
chat the turn came from as a message with Approve and Deny buttons, and the owner's tap answers
it (CH-07). A voice note is turned into text through whatever provides `voice.transcribe` before
the turn starts, and the reply comes back as a voice note when the owner's setting says so,
through `voice.render` (CH-05). With nothing installed that can do either, Alexia says so in a
sentence and carries on in text.

## Interfaces
As stubbed in P1-02:

```rust
// ask.rs
pub(crate) type Channels = Arc<std::sync::RwLock<Vec<Arc<dyn Channel>>>>;
pub(crate) struct Asker { channels: Channels, store: Arc<Store> }
impl Asker { pub(crate) fn new(channels: Channels, store: Arc<Store>) -> Asker; }
#[async_trait::async_trait]
impl alexia_core::Ask for Asker {
    async fn confirm(&self, origin: &Origin, question: &Question, cancel: CancellationToken) -> bool;
}
// voice.rs
pub(crate) async fn hear(media: &dyn Media, inbound: Inbound) -> Inbound;
pub(crate) fn wants_voice(store: &Store, inbound: &Inbound) -> bool;
pub(crate) async fn speak(media: &dyn Media, text: &str) -> Option<OutFile>;
```

`gateway.rs` (P1-11) already calls all three; only their bodies change here.

Setting: kv `_core/voice_replies` = `"never" | "mirror" | "always"`, default `"mirror"` (v2's
Telegram setting of the same name and values).

## Steps
1. **confirm**: `Origin::Channel { channel, chat }` → the channel whose `name()` matches →
   `ask(chat, text, cancel)` where text is `question.text` plus `"\n\n" + detail` when present.
   `Some(true)` → true; `Some(false)`, `None`, an error, no such channel, or another `Origin`
   (Desktop, Scheduler) → false, unless the origin is a scheduler job: then ask in the channel's
   primary chat. Give up after 10 minutes (v2 `ANSWER_WAIT`) → false and edit the message to
   "— no answer, so I didn't".
2. **hear**: for each `InFile` whose mime starts with `audio/`: `media.transcribe` → the text
   is appended to the content as if typed (v2 does the same). `Ok(None)` or an error (logged) →
   the text `"[a voice note I couldn't listen to: nothing installed here turns speech into
   text]"` is appended instead, so the brain answers honestly. The audio file stays in `files`
   so `wants_voice` can see it.
3. **wants_voice**: `"always"` → true; `"mirror"` → the inbound had an audio file; `"never"` →
   false.
4. **speak**: `media.speak(text)` → the `OutFile` (must be `audio/ogg`), else `None`; the gateway
   falls back to text. Texts over 1 000 characters are always sent as text (a three-minute voice
   note is not a reply).

## Tests
`tests/ask_voice.rs` (through the public `Gateway` API with fakes, as in P1-11's tests, since
these modules are crate-private):
- `approval_appears_in_the_turns_chat_and_yes_is_true`: a fake brain calls the gateway's
  `asker().confirm(..)`; the fake channel's `ask` was called for that chat; answering
  `Some(true)` → the brain sees true.
- `deny_and_timeout_are_false` (timeout with `tokio::time::pause`).
- `desktop_origin_is_false`.
- `voice_note_is_transcribed_before_the_brain`: fake media returns "hello" → the brain's turn
  text is "hello".
- `no_transcriber_is_honest`: fake media `Ok(None)` → the turn text contains "couldn't listen".
- `mirror_replies_by_voice_to_voice`: outbound `voice: true` with the ogg file.
- `never_and_long_replies_are_text`.

## Notes for the worker
- Security: an approval is answered only by an owner's press (P1-10 enforces it in the
  channel); `confirm` must never return true on anything but `Some(true)`.
- `voice.transcribe` / `voice.render` are capability names; the hub's `Media` implementation
  (P1-17) calls them through `McpHost::call_capability`. The gateway never sees which plugin.
