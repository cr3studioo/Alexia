# P1-11: Gateway loop: ack, merge, steer, drafts, spans

Model: opus
Depends on: P1-02, P1-03
Feature IDs: CH-03, CH-04, CH-08, CH-09, SP-14, SP-09

## Goal
After this task `Gateway::run` is the heart of V3-1. For every owner message it fires the
reaction before doing anything else (CH-03), merges messages sent in quick succession into one
turn (CH-09), lets a new message steer a running task instead of queuing behind it (CH-08),
streams the brain's draft at Telegram's real rate with the stage shown while nothing is written
yet (CH-04, SP-14), delivers the reply, and records every stage of the turn as spans (SP-09).

## Touch only these paths
- `v3/crates/alexia-gateway/src/gateway.rs`   (fill the stub)
- `v3/crates/alexia-gateway/tests/gateway.rs`   (create)

## Must not touch
`channel.rs`, `ask.rs`, `voice.rs`, `channels/`, `lib.rs`, other crates.

## Interfaces
`Gateway` as stubbed in P1-02. Uses `Channel`, `Media`, `Inbound`, `InKind` (P1-02);
`Brain`, `Turn`, `DraftFrame`, `Phase`, `Reply`, `BrainError`, `Bus`, `Event::{Received, Acked,
Delivered, Say}` (P1-01, P0-03); `Store::{channel_session, new_channel_session, primary_chat,
record_spans}` (P1-03); `voice::{hear, wants_voice, speak}` and `ask::Asker` (P1-02 stubs, P1-12).

Spans the gateway writes (`SpanRow.name`), all relative to the turn's first receipt:

| name | from → to |
|---|---|
| `ack` | receipt → reaction answered by the service (parallel to the rest) |
| `merge` | first receipt → turn handed to the brain |
| `hear` | voice note → text (only when there was one) |
| `brain` | handed to brain → `Reply` (an envelope; the brain's own spans break it down) |
| *each `Reply.spans` entry* | as the brain reported them, shifted to the turn's clock |
| `speak` | text → voice note (only when replying by voice) |
| `deliver` | `send` called → returned |

`turn` = `"<channel>:<chat>:<first message id>"`, `lane` = `Reply.lane` (or `"command"`).

## Steps
1. **One poll task per channel**: loop `next(cancel)`. For each owner `Inbound`, before anything
   else, `tokio::spawn` the reaction (`react(chat, msg, cfg.ack_emoji)`), timing it and
   publishing `Event::Acked { ms }`. Then send the `Inbound` to that chat's actor (an `mpsc`,
   created on first sight). The poll loop never awaits a brain, a store write or a reaction.
   On `Error::Unauthorized` the channel's poll task ends (logged); others back off inside the
   channel.
2. **One actor per chat** (a task owning that chat's state; no shared locks):
   - **Idle**, message arrives → collect for `merge_ms` from the first receipt (more messages
     extend nothing: the window is fixed), then start a turn with the texts joined by `"\n"` and
     the files concatenated.
   - **Running, nothing visible yet** (no `Delta` has reached the draft), message arrives →
     cancel the turn, wait for it to return, start a new one with all messages merged (CH-09).
     The session holds nothing from the cancelled turn (brains store only on success).
   - **Running, text visible, lane `Task`** → steer (CH-08): cancel the running turn (the
     bridge stops v2's task), keep what was drafted as a sent message ending "…" so it isn't
     lost, then start a new turn with the new message.
   - **Running, text visible, lane `Chat`** → queue it; it starts when this turn is delivered.
   - `InKind::Stop`, or the text `/stop` → cancel the running turn, send "Stopped.".
   - `/new` → `new_channel_session`, reply "New conversation.". `/help` → three lines listing
     `/stop`, `/new`, `/help`. Other `/x` go to the brain as text (v2 has its own commands).
   - Then `voice::hear(media, inbound)` (P1-12) before building the `Turn`.
3. **Draft pump** (per turn): receive `DraftFrame`s. Keep the full text; send `draft(Some(..))`
   at most every `draft_every_ms`, starting at 300 ms. On `Error::RateLimited { retry_after_ms }`
   wait that long and double the interval (cap 2 000 ms); after 10 clean sends halve it again
   (floor `draft_every_ms`). While no text has arrived, the draft shows the phase: Choosing /
   Asking → "Choosing a model…", Thinking → "Thinking…", Tool → "Working…", Retrying / Backup →
   "Trying another model…" (v2's words in `plugins/telegram/status.js`, copy them). `typing()`
   every 4 s until the first draft is shown. `Restart` clears the text.
4. **Deliver**: `send(chat, Outbound { text, files, voice })` (voice decided by
   `voice::wants_voice`, the file made by `voice::speak`, span `speak`; P1-12 fills both), then `draft(None)`. `BrainError::Unavailable(s)` → send `s`;
   `NeedsTask` cannot reach here (Lanes handles it); `Other` → "Something went wrong on my side.
   I've noted it." and `tracing::error!` the error; `Cancelled` → nothing.
5. **Record**: one `record_spans` call per turn after delivery; `Event::Received` when the turn
   starts, `Event::Delivered { lane, spans }` after. Delete the turn's downloaded files.
6. **Say**: subscribe to the bus; `Event::Say { text, .. }` → `send` to each channel's
   `primary_chat`. Handle `RecvError::Lagged` by continuing.
7. **Shutdown**: on `cancel`, stop polling, cancel running turns, wait at most 3 s, return.

## Tests
`tests/gateway.rs`, with a scripted fake `Channel` (records every call with a timestamp), a fake
`Brain` (scripted frames and delays), a fake `Media`, an in-memory store, `tokio::time::pause`
where the test is about timing:
- `ack_before_brain`: brain takes 5 s → `react` called within 10 ms of `next()` returning
  (real time, not paused); `Event::Acked` published.
- `ack_never_waits_on_a_busy_chat`: a turn running in chat A, a message to A and to B → both
  reacted within 10 ms.
- `quick_messages_merge`: two messages 200 ms apart → one brain call with both texts.
- `message_before_visible_text_restarts_merged`.
- `message_during_visible_task_steers`: first turn cancelled, its draft sent ending "…", second
  turn has only the new text.
- `message_during_visible_chat_queues`.
- `stop_cancels`, `slash_new_makes_a_new_session`.
- `drafts_are_paced_and_back_off`: 50 deltas over 1 s → ≤ 5 draft calls at 300 ms; a
  `RateLimited { 1000 }` → next draft ≥ 1 s later and the interval doubled.
- `phase_shows_before_text`.
- `spans_cover_the_turn`: recorded rows include `ack`, `merge`, `brain`, the brain's spans and
  `deliver`, all with the same `turn`.
- `say_goes_to_primary_chat`.
- `unavailable_sentence_is_sent`.
- `shutdown_within_3s`.

## Notes for the worker
- The 300 ms goal is spent almost entirely on one HTTPS round trip to Telegram. Everything the
  gateway adds must be microseconds: no store write, no bus publish and no lock before the
  reaction is spawned.
- Actors talk over channels; don't hold `std::sync` locks across `.await`.
- v2's own behaviour for the same situations is in `plugins/telegram/index.js` (`Line`,
  `Draft`, `Presence`); match its wording where a person reads it.
