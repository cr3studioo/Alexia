# P1-03: Store: migration 2, channel chats, spans, tries_since

Model: opus
Depends on: P0-07
Feature IDs: SP-09, CH-01, D212

## Goal
After this task the store has migration 2: `channel_chats` maps a channel's chat to its session
and marks the owner's primary chat, and `spans` holds every timed stage of every turn for the
latency dashboard. The router can read recent tries without SQL leaving the store. These are the
only schema changes in V3-1.

## Interfaces
Migration 2 (index 1 of `MIGRATIONS`):

```sql
CREATE TABLE channel_chats (
  channel    TEXT NOT NULL,
  chat       TEXT NOT NULL,
  session_id INTEGER NOT NULL REFERENCES sessions (id) ON DELETE CASCADE,
  is_primary INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY (channel, chat)
);
-- SP-09. One row per timed stage. `turn` groups the stages of one message.
CREATE TABLE spans (
  turn   TEXT NOT NULL,
  at     INTEGER NOT NULL,      -- when the turn was received (ms)
  origin TEXT NOT NULL,         -- JSON Origin
  lane   TEXT NOT NULL,         -- 'command' | 'chat' | 'task'
  name   TEXT NOT NULL,
  start  INTEGER NOT NULL,      -- ms
  ms     INTEGER NOT NULL
);
CREATE INDEX spans_at ON spans (at);
CREATE INDEX spans_turn ON spans (turn);
```

```rust
// types.rs
#[derive(Clone, Debug, PartialEq, Serialize, Deserialize)]
pub struct SpanRow { pub turn: String, pub at: Ms, pub origin: String, pub lane: String,
                     pub name: String, pub start: Ms, pub ms: i64 }
#[derive(Clone, Debug, PartialEq)]
pub struct TryRow { pub at: Ms, pub provider: String, pub model: String, pub outcome: String,
                    pub status: i64, pub waited_ms: Option<i64> }

// db.rs, impl Store
/// The session for this chat, created (titled "<channel>") on first sight. The first chat ever
/// seen on a channel becomes its primary.
pub fn channel_session(&self, channel: &str, chat: &str) -> Result<SessionId>;
/// Point the chat at a fresh session (`/new`). Returns it.
pub fn new_channel_session(&self, channel: &str, chat: &str) -> Result<SessionId>;
pub fn primary_chat(&self, channel: &str) -> Result<Option<String>>;
/// Exactly one primary per channel.
pub fn set_primary_chat(&self, channel: &str, chat: &str) -> Result<()>;
pub fn record_spans(&self, rows: &[SpanRow]) -> Result<()>;                // one transaction
/// The newest `n` turns' rows, oldest turn first, rows in `start` order.
pub fn last_turns(&self, n: u32) -> Result<Vec<SpanRow>>;
pub fn tries_since(&self, at: Ms) -> Result<Vec<TryRow>>;                  // oldest first
/// Requests counted by `record_request` in the `"minute"` or `"day"` bucket that holds `at`
/// (the same bucket arithmetic `record_request` uses). 0 when there is no row.
pub fn request_count(&self, provider: &str, span: &str, at: Ms) -> Result<u64>;
/// Spans older than `before` are deleted (the dashboard keeps 30 days).
pub fn prune_spans(&self, before: Ms) -> Result<u64>;
```

## Steps
1. Append migration 2. The runner (P0-04) already bumps `user_version` per migration.
2. Implement the methods with bound parameters only. `channel_session` is one transaction:
   select, else create the session and insert the row (`is_primary = 1` if the channel has no
   row yet).
3. Nothing reads or writes kv `_core.channel_sessions` (INTERFACES.md §2.4's interim map); the
   table replaces it before any code used it.
4. Tests.

## Tests
`tests/channels.rs` (`Store::open_in_memory()` and a temp-file store):
- `migration_2_applies`: a fresh store has `user_version` 2 and both tables.
- `upgrade_from_1`: a file created at user_version 1 (build it with migration 1's SQL by hand)
  opens and becomes 2 with its sessions intact.
- `channel_session_is_stable`: two calls → the same id; another chat → another id.
- `first_chat_is_primary`, `set_primary_moves_it`: exactly one `is_primary = 1` per channel.
- `new_channel_session_replaces`: after it, `channel_session` returns the new id; the old
  session still exists.
- `spans_round_trip_and_order`: three turns of rows → `last_turns(2)` returns the newer two,
  oldest turn first.
- `prune_spans_deletes_old`.
- `tries_since_filters`: two `record_try` rows either side of `at`.
- `request_count_reads_buckets`: three `record_request` calls → minute and day counts are 3;
  an `at` a day later → 0; an unknown span → `Error::Invalid`.
- `delete_session_cascades_channel_chat`.
- `env_secret_wins` (in `tests/channels.rs` to keep one new test file): set the variable for
  `_core`/`provider_groq` → `secrets::get` returns it; `env_name` maps as documented.

## Notes for the worker
- `Store` is one connection behind a mutex; don't hold the lock across an `.await` (there are
  none in the store, keep it that way).
- `origin` is stored as JSON text so the store never depends on `alexia-core`'s `Origin`.
- The importer refuses a store that already has sessions; a channel row creates a session, so
  P0's import must run before the first Telegram message. P1-17 prints that.
