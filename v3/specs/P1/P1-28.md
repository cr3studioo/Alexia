# P1-28: Telegram stays inside the gateway; one base64

Model: sonnet
Depends on: P1-10, P1-17
Feature IDs: none

## Goal
`alexia-gateway/src/channels/mod.rs` has `#[doc(hidden)] pub mod telegram`, and
`channels/telegram/mod.rs` has `pub mod api`, so the gateway's own integration tests
(`tests/telegram_api.rs`, `tests/telegram_channel.rs`, `tests/types.rs`) can reach the adapter.
That also makes `alexia_gateway::channels::telegram::api::Api` public crate API: the hub could
call Telegram directly, and invariant check 1 would not notice (it only catches a quoted id).
After this task any crate other than `alexia-gateway` that names a `channels::<module>` path
fails `node v3/ci/invariants.mjs`, so the only way into a channel from outside is
`channels::{secret_keys, configured, pairing_codes}` (INTERFACES.md §2.4).

While in the Telegram adapter: P1-10 hand-wrote a base64 encoder (`telegram/mod.rs`, `fn
base64`, for a photo's `data:` URL). P1-17 added the `base64` crate to
`[workspace.dependencies]`; the adapter uses it instead, so v3 has one codec.

Why a check and not `pub(crate)`: `pub(crate)` would move ~1 350 lines of fake-server
integration tests into `src/`, where the path check scans them; the check is a dozen lines and
also covers every future channel.

## Touch only these paths
- `v3/ci/invariants.mjs`   (change: one new hit function, its call in `run`, its self-tests)
- `v3/crates/alexia-gateway/Cargo.toml`   (change: `base64.workspace = true`)
- `v3/crates/alexia-gateway/src/channels/telegram/mod.rs`   (change: `fn base64` → the crate)
- `v3/Cargo.lock`   (change)

## Must not touch
Every other `src/` file, every test file (the gateway's tests keep reaching the adapter; the
new check exempts `v3/crates/alexia-gateway/`), `v3/specs/INTERFACES.md` (§7's row for this
check is already written).

## Interfaces
`invariants.mjs`, next to `pluginHits`:

```js
/** Hits for check 1b: a `channels::<module>` path outside alexia-gateway (INTERFACES.md §7). */
export function channelHits(path, text)
// For every non-comment line of a .rs file not under `v3/crates/alexia-gateway/`, a hit for
// /\bchannels::(?!secret_keys\b|configured\b|pairing_codes\b)[a-z_]+/ :
//   `${path}:${line}: reaches into a channel adapter (use channels::{secret_keys, configured, pairing_codes})`
```

`run` calls it for every `.rs` file of every crate (`src/` and `tests/`), not only `src/`.

## Steps
1. `invariants.mjs`: `channelHits` as above; call it in `run`'s per-file loop for every file
   (outside the `src/` branch). Self-tests:
   - `expect('the hub reaching the telegram api', channelHits('v3/crates/alexia-hub/src/main.rs', 'use alexia_gateway::channels::telegram::api::Api;'))`
   - `expect('a hub test reaching the adapter', channelHits('v3/crates/alexia-hub/tests/t.rs', 'let t = channels::telegram::Telegram::new(a, s, c);'))`
   - `ok('the hub calling configured', channelHits('v3/crates/alexia-hub/src/main.rs', 'let c = channels::configured(store, &layout);'))`
   - `ok('pairing_codes and secret_keys', channelHits('v3/crates/alexia-hub/src/main.rs', 'channels::pairing_codes(&s); channels::secret_keys()'))`
   - `ok('the gateway own tests', channelHits('v3/crates/alexia-gateway/tests/telegram_api.rs', 'use alexia_gateway::channels::telegram::api::Api;'))`
   - `ok('a comment', channelHits('v3/crates/alexia-hub/src/main.rs', '// channels::telegram is private'))`
   Update the file's header comment (the list of checks) with 1b.
2. `telegram/mod.rs`: delete `fn base64`; at its one call use
   `base64::engine::general_purpose::STANDARD.encode(&bytes)` (`use base64::Engine;`).
   `alexia-gateway/Cargo.toml`: `base64.workspace = true`, with a comment line like the
   existing ones ("photo `data:` URLs (P1-10)").

## Notes for the worker
- Rebase on the merged P1-10 and P1-17 first: P1-10 writes the adapter and its encoder, P1-17
  adds `base64` to `[workspace.dependencies]`. The lock already has `base64 0.22.1`; adding it
  to the gateway changes only that crate's dependency list in `Cargo.lock`.
- The regex is deliberately on `channels::` followed by a lowercase name, so a type such as
  `alexia_gateway::Channel` or a local variable `channels` is not a hit.
