# P1-16: Hub watchdog

Model: sonnet
Depends on: P1-02
Feature IDs: HB-12

## Goal
After this task the hub comes back by itself: `alexia-hub install` registers a Windows Task
Scheduler task that starts the hub at boot (so after a Windows Update reboot) and restarts it if
it crashes; the hub keeps a heartbeat, and when it starts after an unclean stop it tells the owner
how long it was gone. Inside the hub, a long-running service that fails is restarted with backoff
instead of taking the hub down. Using Task Scheduler is the platform's own supervisor: no extra
service binary, no Windows service code.

## Interfaces
```rust
pub const TASK_NAME: &str = "Alexia hub";
/// kv `_core/hub_alive` (Ms, every minute) and `_core/hub_clean_stop` (Ms, on clean shutdown).
pub const HEARTBEAT_MS: u64 = 60_000;

/// At boot: if the last heartbeat is older than 3 minutes and later than the last clean stop,
/// the sentence to say ("I was offline from 14:02 to 14:31."), local time, day added when it
/// isn't today. `None` otherwise.
pub fn offline_gap(store: &Store, now: Ms) -> Option<String>;
/// Writes `hub_alive` now and every HEARTBEAT_MS until cancelled.
pub async fn heartbeat(store: Arc<Store>, cancel: CancellationToken);
pub fn clean_stop(store: &Store, now: Ms);

/// Run `f` until cancelled; when it returns or errors, log and run it again after 1 s doubling
/// to 60 s (reset after 10 minutes up). For the gateway, catalog refresh and bridge loops.
pub async fn supervise<F, Fut>(name: &'static str, cancel: CancellationToken, f: F)
where F: FnMut(CancellationToken) -> Fut, Fut: Future<Output = Result<(), String>>;

/// The Task Scheduler XML for `exe` (boot trigger + logon trigger, restart on failure every
/// minute up to 999 times, no execution time limit, run whether the user is logged on or not,
/// highest privileges off, `run` as the argument, working dir = exe's folder).
pub fn task_xml(exe: &Path, user: &str) -> String;
/// `install`: writes the XML to a temp file and runs
/// `schtasks /Create /TN "Alexia hub" /XML <file> /RU <user> /RP` (schtasks prompts for the
/// password itself) and `schtasks /Run`. `uninstall`: `schtasks /Delete /TN "Alexia hub" /F`.
pub fn install() -> Result<(), String>;
pub fn uninstall() -> Result<(), String>;
```

## Steps
1. Heartbeat, `clean_stop`, `offline_gap` over kv (P0-04 API).
2. `supervise` as above; it never panics on `f`'s error and logs the error's sentence at warn.
3. `task_xml`: Task Scheduler 1.2 schema. `schtasks /XML` expects the file as UTF-16 LE with a
   BOM: write it by hand with `encode_utf16`. `user` = `%USERDOMAIN%\%USERNAME%`.
4. `install` explains failures in sentences: not elevated → "Run this from an Administrator
   terminal: Task Scheduler needs it to start the hub at boot."; `schtasks` missing → the
   platform sentence. On non-Windows both return "Only on Windows for now."
5. Never pass or read the Windows password: `/RP` with no value makes schtasks prompt in the
   owner's terminal.

## Tests
In-file:
- `no_gap_on_first_boot`, `no_gap_after_clean_stop`, `gap_after_crash_is_a_sentence`
  (heartbeat 40 minutes ago, no clean stop).
- `supervise_restarts_with_backoff` (`tokio::time::pause`: a closure failing 3 times then
  waiting for cancel is called 4 times, gaps 1 s, 2 s, 4 s).
- `supervise_stops_on_cancel`.
- `task_xml_has_triggers_and_restart`: contains `<BootTrigger>`, `<LogonTrigger>`,
  `<RestartOnFailure>`, `<Arguments>run</Arguments>`, and the exe path XML-escaped.
