# P1-13: V2Bridge: v2 core as the task lane

Model: opus
Depends on: P1-02, P1-03
Feature IDs: CH-06, CH-07, CH-08, SP-14, HB-12 (the child half)

## Goal
After this task the hub can hand a task to v2 core and stream its answer back. `V2Bridge` starts
v2 core on the PC as a child process (`node packages/core/dist/src/entry.js` from the owner's
checkout, with its own v2 data folder), finds its loopback address and token, and implements
`Brain` over v2's own `/api/chat` (server-sent events), `/api/approve` and `/api/stop`. v2 is not
changed: the bridge is a client of the API v2's desktop window already uses. It is deleted at
V3-2 when the Rust agent loop replaces it.

This settles INTERFACES.md §8.2: **v2 core runs on the PC for V3-1**, beside the hub, so the
bridge is loopback only and works when the Mac sleeps.

## Touch only these paths
- `v3/crates/alexia-hub/src/bridge.rs`   (fill the stub; tests in a `#[cfg(test)] mod tests` in
  the same file, since a binary crate's modules can't be reached from `tests/`)

## Must not touch
`main.rs` (P1-17 wires it), other hub modules, every library crate, `packages/` (v2 is used as
it is).

v2's side (read, don't change): `packages/core/src/serve.ts` `handle()` (token header
`x-alexia-token`, host must start `127.0.0.1`), `reply()` for `/api/chat`, `/api/approve`
`{allowed}`, `/api/stop`; `packages/core/src/entry.js` prints `Alexia (<role>) is at <url>`;
the token is substituted for `__TOKEN__` in `packages/ui/index.html`, served at `GET /`.

## Steps
1. **Spawn**: `Command::new(node).arg(root/packages/core/dist/src/entry.js)` with cwd `root`,
   env `ALEXIA_DATA_NAME=<data_name>`, stdout piped, stderr into `tracing` at debug,
   `CREATE_NO_WINDOW` on Windows (`std::os::windows::process::CommandExt::creation_flags
   (0x0800_0000)`, no `unsafe`), `kill_on_drop(true)`. Read stdout lines until one matches
   `is at (http://127\.0\.0\.1:\d+/)` (30 s timeout → log "v2 core did not start." and retry).
2. **Token**: `GET <url>` and take the UUID that replaced `__TOKEN__` in the page (match the
   first `[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}`). Keep it in memory only;
   never log it.
3. **reply**: POST `/api/chat` with `{text, files}`; `files` are the turn's image parts as v2
   `Upload { name, data (base64 without the data: prefix), type }` and `InFile`s read from disk
   (documents ≤ 20 MB). **423** (v2 is answering something else) → wait 500 ms and retry up to
   10 s, then `BrainError::Unavailable("I'm still finishing the last task.")`. Read the SSE body
   with `Response::chunk()` and map each `data:` event (v2's names, from the `say({…})` calls in
   `serve.ts`):
   - `delta` → `DraftFrame::Delta`, appended to the reply text; `restart` → `Restart`, text
     cleared;
   - `phase {kind}` → `DraftFrame::Phase` (`reading`/`choosing` → Choosing, `thinking` →
     Thinking, `writing` → Writing, `tool` → Tool, `retrying` → Retrying, `backup` → Backup);
   - `step {n, name}` → `Phase(Tool)` and a span `tool:<name>` from this step's start to the next
     event (SP-14, SP-09);
   - `ask "<why>"` → `ask.confirm(origin, Question { text: why, .. })` then POST `/api/approve
     {allowed}` (CH-07);
   - `paused`, `paid` (v2 asking whether to spend money) → treated as an `ask`; a "yes" is never
     sent (D212): POST `/api/approve {allowed:false}` and add the sentence "I only use free
     models." to the reply;
   - `error "<sentence>"` → `BrainError::Unavailable(sentence)`;
   - `note`, `switch`, `attached`, `learn`, `learned` → ignored except `switch`, which becomes
     the reply's `model`.
   The stream ending is the end of the reply.
4. **cancel**: on `cancel`, POST `/api/stop` and drop the stream; return `Cancelled` (CH-08: the
   gateway then sends the steering message as a new turn, which v2 sees after the stopped task
   in the same conversation).
5. **Store**: append the user turn and the final reply to the v3 session (`Turn.session`), so v3
   has the whole conversation even though v2 keeps its own copy. Append nothing on cancel or
   error.
6. **Context**: v2's conversation holds only task-lane turns. When the v3 session has chat-lane
   turns since the last task, prefix the text with "(Earlier in this chat:)\n" plus the last 6
   turns, each `"You: …"` / `"Alexia: …"`, 300 characters each at most.
   `// ponytail: quoted context; V3-2's agent reads the v3 session directly.`
7. Spans: `"bridge"` (POST sent → stream ended), `"bridge-first-byte"` (POST → first `delta`),
   and one `tool:<name>` per step.

## Tests
In-file tests against a fake v2 on `127.0.0.1:0` (tokio `TcpListener`, raw HTTP/1.1 and SSE),
attached through `V2Config.attach`; one test spawns a tiny fake "entry.js" through a script:
- `attach_mode_reads_no_child`.
- `deltas_become_draft_and_reply`.
- `phase_and_step_frames_map`: the step becomes a `tool:<name>` span.
- `ask_goes_to_asker_and_answer_is_posted`: fake asker says yes → the fake v2 received
  `{allowed:true}`.
- `paid_is_always_refused`.
- `busy_423_retries_then_sentence`.
- `cancel_posts_stop`.
- `token_from_index_page` and `token_never_logged` (capture `tracing` output with a test
  subscriber; it contains no UUID).
- `chat_context_is_prefixed_once`.
- `child_restarts_after_exit`: `V2Config.root` points at a temp folder whose
  `packages/core/dist/src/entry.js` is a script that prints the line and exits after 1 s, run by
  the real `node` if present (skip the test with a printed reason when `node` is not on PATH).

## Notes for the worker
- The token scrape and the stdout line are v2 internals, not a contract. That's acceptable only
  because the bridge lives for one phase; say in the report exactly which lines of v2 it depends
  on.
- v2's `/api/chat` answers one question at a time for the whole app; the gateway runs one task
  turn at a time per chat, and the owner has one chat, so 423 is rare. Don't build a queue.
- The child's v2 runs its own v2 plugins (memory, voice…) against its own data folder. Its
  Telegram plugin must be switched off by the owner (PHASE.md *Owner needs*); the bridge never
  touches v2's plugins.
