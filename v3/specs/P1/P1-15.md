# P1-15: Latency dashboard

Model: sonnet
Depends on: P1-02, P1-03
Feature IDs: SP-09

## Goal
After this task `alexia-hub latency` shows where every second of the last N turns went: a text
table in the terminal, a self-contained HTML page with one stacked bar per turn, and a `--check`
mode that turns V3-1's done-when into an exit code. It reads only the `spans` table, so it works
on a stopped hub. The hub opens no port for it (PHASE.md, INTERFACES addition 4).

## Touch only these paths
- `v3/crates/alexia-hub/src/latency.rs`   (fill the stub; in-file `#[cfg(test)] mod tests`)

## Must not touch
`main.rs` (P1-17 adds the subcommand and calls `latency::run`), other modules, library crates.

## Interfaces
```rust
pub struct Options { pub last: u32 /* default 50 */, pub html: Option<PathBuf>, pub check: bool }
/// Parses `latency [--last N] [--html FILE] [--check]` (after the subcommand word).
pub fn parse(args: &[String]) -> Result<Options, String>;
/// Prints the table; writes the page if asked; returns the exit code (0, or 1 when `--check`
/// fails, with one line per failure on stderr).
pub fn run(store: &Store, opts: &Options) -> i32;

pub struct TurnView { pub turn: String, pub at: Ms, pub lane: String, pub total_ms: i64,
                      pub ack_ms: Option<i64>, pub stages: Vec<(String, i64, i64)> /* name, start offset, ms */,
                      pub unaccounted_ms: i64 }
/// Groups `last_turns(n)` rows into turns. Offsets are from the turn's first receipt (`at`).
pub fn turns(rows: &[SpanRow]) -> Vec<TurnView>;
```

Definitions (used by the table, the page and `--check`):
- `total_ms` = end of `deliver` − `at`.
- `unaccounted_ms` = `total_ms` minus the length of the union of every stage interval except
  `ack` (it runs alongside) and `brain` (an envelope whose parts are the brain's own spans).
- `--check` fails a turn when `ack_ms` is missing or ≥ 300; when `lane == "chat"` and any stage
  is named `bridge`; when `unaccounted_ms > total_ms / 20`; and fails overall when fewer than
  `last` turns exist ("Only 31 turns recorded; the check needs 50.").

## Steps
1. `turns()` and the definitions above.
2. Text table: one line per turn — time, lane, total, ack, then the three biggest stages
   (`first-byte 1.8s · writing 0.9s · recall-wait 0.1s`); then a summary per stage name over all
   turns: count, p50, p90, max, and share of total time. Seconds with one decimal under 10 s.
3. HTML page: one file, no external scripts or fonts. A heading with the date range and counts
   per lane, the summary table, then one row per turn with an inline SVG stacked bar (stages
   positioned by offset, `ack` drawn as a thin marker above the bar), a legend with a fixed
   colour per stage name, and a `<details>` per turn listing every stage. Colours as CSS custom
   properties with a `prefers-color-scheme: dark` set. Works at phone width (bars scale to 100%
   width). Text is HTML-escaped; nothing from a message is in `spans` anyway.
4. Never print message text, session ids or chat ids; `turn` ids are shown as their last
   segment only.

## Tests
In-file:
- `groups_and_offsets`: rows for two turns → two views, offsets from `at`.
- `unaccounted_is_union_not_sum`: overlapping stages are not double-counted; `ack` and `brain`
  excluded.
- `check_passes_good_turns`, `check_fails_slow_ack`, `check_fails_chat_with_bridge`,
  `check_fails_gaps`, `check_fails_too_few`.
- `html_is_self_contained`: no `src="http`, no `<script src`, contains one `<svg` per turn.
- `parse_args`.
