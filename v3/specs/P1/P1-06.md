# P1-06: Router::hedged with a latency budget

Model: opus
Depends on: P1-05, P1-03
Feature IDs: D212 (hedged free requests), SP-07, MO-03, MO-04

## Goal
After this task `Router::hedged` answers a chat request by racing the two best free candidates,
keeping whichever produces a first byte first and cancelling the other. If neither speaks within
the channel's budget it starts the next candidate too, and failures fall through the ranked
list, so "the slowest free tier we happened to try" becomes "the fastest free tier right now".
It never picks a paid model (D212) and never a local one (D213). Every try is recorded.

## Interfaces
```rust
pub struct Router { /* providers by id, catalog, store */ }
impl Router {
    pub fn new(providers: Vec<Arc<dyn Provider>>, catalog: Arc<Catalog>, store: Arc<Store>) -> Router;
    /// D212 + SP-07. Starts the best two candidates at once; whichever sends a first chunk wins
    /// and the other is cancelled. Each time `budget.first_byte_ms` passes with no first chunk
    /// from anyone, one more candidate starts (at most 4 running). A candidate that fails is
    /// replaced by the next. Chunks from the winner only are forwarded to `out`.
    pub async fn hedged(&self, req: &ChatRequest, budget: Budget, out: mpsc::Sender<ChatChunk>,
                        cancel: CancellationToken) -> Result<ChatDone, ProviderError>;
    /// The ranked list `hedged` would use now, for the dashboard and tests.
    pub fn ranked(&self, now: Ms) -> Vec<Candidate>;
}
```

Store calls used: `tries_since`, `request_count`, `record_try`, `record_usage`, `record_request` (P0-04, P1-03).
`Try.source` is `"chat"`; `outcome` uses v2's strings (`"ok"`, `"busy"`, `"refused"`,
`"unreachable"`, `"timeout"`, `"lost-race"` for the cancelled loser).

## Steps
1. **Ranking** (a port of the part of v2's Automatic that matters for chat; cite
   `packages/core/src/router.ts` `sunk`/`STRIKE_HALF_LIFE`, `ranking`, and `pool.ts`
   `remaining`/`spent`):
   - drop a candidate whose provider has no minute or day headroom:
     `store.request_count(provider, "minute"|"day", now)` against `catalog.row(provider)`'s `rpm`/`rpd`.
   - a failure in `tries` sinks a model with a one-hour half-life (v2's `sunk`).
   - then median `waited` (first byte) of its last 10 successful tries, lower first; untried
     models go after tried-and-fast ones and before tried-and-slow ones (median > budget).
   - routers last (v2 D159); then larger `size_b` first; then id order.
2. **Hedging**: two `tokio::spawn`ed attempts, each with a child `CancellationToken` and its own
   `mpsc` channel. `tokio::select!` on: first chunk from either, failure of either (start the
   next candidate), the budget timer (start one more), `cancel`. When a winner sends its first
   chunk, cancel the rest and forward the winner's channel to `out` until it ends.
3. At most 4 attempts running, at most 6 started per call. All failed → the last error, or
   `Busy` if every one was busy. A loser cancelled after the winner was chosen is recorded
   with outcome `lost-race` and does count toward `record_request` (it was sent).
4. `record_usage` for the winner with `writing_ms` = first byte → done.
5. A request is never sent to two models of the same provider at once (one account's rate
   limit would be hit twice for no gain): the second slot takes the best candidate from a
   different provider when one exists.

## Tests
`tests/router.rs`, with fake providers whose first-byte delay, chunks and failure are
scripted, and `tokio::time::pause()` where timing matters:
- `faster_of_two_wins_and_loser_is_cancelled`: A answers at 800 ms, B at 200 ms → B's text
  only, A's cancel token fired, two tries recorded (`ok`, `lost-race`).
- `budget_starts_a_third`: A and B silent; budget 500 ms → C starts at 500 ms and wins.
- `failure_starts_the_next`: A returns `Busy` at once → C starts immediately.
- `never_two_from_one_provider`: top two are both from provider X → second slot is Y.
- `recent_failure_sinks`: a model with a failure 5 minutes ago ranks below one without.
- `fast_median_ranks_first`.
- `exhausted_day_is_skipped`: rpd reached → not started.
- `all_fail_returns_busy`.
- `cancel_stops_everything`: cancel mid-race → `Cancelled`, every attempt's token fired.
- `no_paid_ever`: a catalog containing only paid models (free = false) → nothing started,
  `Unavailable`-style `ProviderError::Other` with the sentence "No free model can answer right
  now.".
