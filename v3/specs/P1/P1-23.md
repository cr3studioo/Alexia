# P1-23: Gateway: spawned tasks on the tracker

Model: opus
Depends on: none
Feature IDs: CH-01, CH-03

## Goal
`Gateway::run` returns only when nothing it started can still call a channel. Today three tasks
use bare `tokio::spawn` outside the run's `TaskTracker`
(`v3/crates/alexia-gateway/src/gateway.rs`): the reaction in `spawn_ack` (`:234`), the SORRY
send in `Actor::start` when `channel_session` fails (`:558`), and the typing call in
`Pump::run` (`:968`). The 3 s shutdown wait (`tracker.wait()`) does not see them, so they can
call `react` / `send` / `typing` after `run()` has returned, i.e. after the hub thinks the
gateway is stopped. After this task all three run on the tracker.

## Touch only these paths
- `v3/crates/alexia-gateway/src/gateway.rs`   (change)
- `v3/crates/alexia-gateway/tests/gateway.rs`   (change)

## Must not touch
`ask.rs`, `voice.rs` (P1-12), `channels/**` (P1-10, P1-21), `channel.rs`, `lib.rs`,
`Cargo.toml`, every other crate.

## Interfaces
No public signature changes. `Gateway::run(self, cancel: CancellationToken) -> Result<()>`
keeps its contract: "Runs until `cancel`, then stops polling, cancels running turns and waits at
most 3 s." Private change:

```rust
struct Shared {
    cfg: GatewayConfig,
    store: Arc<Store>,
    bus: Bus,
    brain: Arc<dyn Brain>,
    media: Arc<dyn Media>,
    /// Every task the gateway starts, so `run` can wait for all of them.
    tracker: TaskTracker,
}
```

## Steps
1. In `run`, create `let tracker = TaskTracker::new();` before building `Shared`, and store a
   clone in `Shared.tracker`. The `poll`/`say` spawns keep using it.
2. `spawn_ack` (`:234`): `g.tracker.spawn(async move { .. })`.
3. `Actor::start` (`:558`): `self.g.tracker.spawn(async move { ch.send(&chat, &plain(SORRY)).await })`.
4. `Pump` gets a `tracker: TaskTracker` field, set in `Pump::new` from `t.g.tracker.clone()`;
   the typing spawn (`:968`) becomes `self.tracker.spawn(..)`.
5. Leave `tokio::spawn(ctx.run())` (`:580`) and the brain spawn (`:799`) as they are: the actor
   awaits the turn's handle on cancel and the pump aborts the brain after 3 s, so both are
   already inside the wait. Add a one-line comment at each saying so.
6. `tracker.spawn` after `tracker.close()` is allowed and is waited for; no change to the
   close/wait order is needed.

## Tests
In `v3/crates/alexia-gateway/tests/gateway.rs`:
- Give `FakeChannel` two fields: `delay: Mutex<Duration>` (default `Duration::ZERO`) and
  `in_flight: AtomicUsize`. `react` and `typing` increment `in_flight`, sleep `delay`, `note`,
  then decrement. Existing tests keep a zero delay and are unchanged.
- `no_channel_call_after_run_returns`: delay 800 ms; one script that holds 60 s and respects
  cancel; `cfg(20)`. Push one message, wait until `brain.calls() == 1` and `in_flight >= 1`,
  then cancel and await `run` (≤ 30 s). Right after it returns: `in_flight == 0` and the log
  contains `What::React("1")` and `What::Typing`. Record `calls().len()`, sleep 1.5 s, and
  assert the log did not grow. Fails today: `run` returns while the slow `react` / `typing`
  are still in flight.
- `shutdown_within_3s` and every existing test still pass.

The SORRY path needs a failing store to reach; it is not tested here (same one-line change).

## Notes for the worker
- The ack must still never wait on the actor (CH-03, `ack_never_waits_on_a_busy_chat`): the
  tracker only changes who waits at shutdown, not when the task starts.
- A reaction slower than the 3 s wait still outlives `run`; that is the documented bound, and
  `run` logs "some tasks did not stop within 3 s". The test's 800 ms delay is inside it.
- Real time throughout (no `tokio/test-util`); keep every bound generous.
