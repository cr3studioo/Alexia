# P1-34: alexia-hub secret import-v2: copy v2's secrets into v3's store, once

Model: opus
Depends on: none
Feature IDs: SP-18 (secrets in the OS keychain), CH-01, MO-04 (the bot token and free provider keys the hub needs)

## Goal
On the Windows PC v2 keeps every secret in **one** Credential Manager generic credential (D153,
D187): service `dev.alexia.app`, account `_core.vault`, so its target name is
`_core.vault.dev.alexia.app`. v3 keeps one entry per secret under service `alexia`, account
`<owner>.<key>` (`alexia-store/src/secrets.rs`). Today the owner retypes every key with
`alexia-hub secret set`. After this task one command does it:

```
alexia-hub secret import-v2 [--overwrite]
```

It reads v2's entry (read only), maps each v2 name to the owner and key v3 actually reads, and
writes the ones v3 does not have yet. It **copies, never moves**: the v2 entry is never written
or deleted, so v2 keeps working. It prints names only, never a value.

## Interfaces
In `alexia_store::secrets` (names are the worker's choice where not given):

```rust
/// v2's vault, decoded. Its Debug prints names only, never a value.
pub struct V2Vault { /* account -> value, private */ }
impl V2Vault {
    /// The blob as Credential Manager holds it: UTF-16LE JSON
    /// `{"secrets": {"<owner>.<key>": "<value>", ..}, "looked": [..], "moved"?: "all"}`
    /// (v2 `packages/core/src/secrets.ts` `Kept` / `readKept`). A trailing NUL is allowed.
    pub fn parse(blob: &[u8]) -> Result<V2Vault>;
    pub fn names(&self) -> Vec<&str>;
}
/// (owner, key) for a v2 account: `renames` first (v2 account -> v3 `_core` key), else split at
/// the first dot. None when v3 cannot hold it (`account()`'s rules).
pub fn v3_name(v2_account: &str, renames: &[(&str, &str)]) -> Option<(String, String)>;
pub struct V2Report {
    pub copied: Vec<String>,      // "<owner>.<key>" written
    pub kept: Vec<String>,        // v3 already had one; untouched (no --overwrite)
    pub not_in_v2: Vec<String>,   // an expected v3 name v2 had nothing for
    pub unusable: Vec<String>,    // v2 names v3 can't hold, or whose value isn't non-empty text
    pub failed: Vec<String>,      // the write failed (name only)
}
/// Writes through `set`; never reads or writes v2. `expected` are the v3 names the hub uses.
pub fn import_v2(vault: &V2Vault, renames: &[(&str, &str)], expected: &[(String, String)],
                 overwrite: bool) -> V2Report;
/// The one Credential Manager read: `Ok(None)` when the entry is absent.
/// cfg(windows) only; elsewhere returns Err("Importing v2 secrets works only on Windows.").
pub fn read_v2_vault() -> Result<Option<Vec<u8>>>;
```

In `alexia_gateway::channels`:

```rust
/// (v2 account, v3 `_core` key) for every channel secret v2 kept under a plugin's name.
/// Today: ("telegram.bot_token", "telegram_bot_token").
pub fn v2_secret_names() -> &'static [(&'static str, &'static str)];
```

CLI: `alexia-hub secret import-v2 [--overwrite]`. Output, one line per name, tab-separated:
`copied\t<owner>.<key>`, `kept\t<owner>.<key> (v3 already has one; --overwrite replaces it)`,
`not in v2\t<owner>.<key>`, `unusable\t<v2 name>`, `failed\t<owner>.<key>`, then a count line.
No v2 entry: `No v2 secrets found on this PC.` and exit 0. Not Windows: the sentence above,
exit 1. Any `failed`: exit 1 after printing everything. Bad flag: usage, exit 2.

## Steps
1. **The format, from the source.** v2's shell (`src-tauri/src/vault.rs`) writes the entry with
   `keyring::Entry::new("dev.alexia.app", "_core.vault").set_password(..)`; core
   (`packages/core/src/secrets.ts`, `kept()`, `WHOLE = 'vault'`, `account()`) puts the JSON in it.
   `windows-native-keyring-store` 1.1 stores a password as UTF-16LE with no NUL
   (`to_wstr_no_null`) under target `<user>.<service>`. Do **not** read the live entry to check
   this; the owner's by-hand run is the check.
2. **The read.** In `secrets.rs`, one small `#[cfg(windows)]` fn:
   `keyring::Entry::new("dev.alexia.app", "_core.vault")?.get_secret()` (raw bytes; **not**
   `get_password`, whose `BadEncoding` error carries the blob). `NoEntry` → `Ok(None)`. Any other
   error → `Error::Keychain("The v2 keychain entry could not be read.")`, with no keyring text.
   A `#[cfg(not(windows))]` twin returns the not-supported error. Nothing else touches it.
3. **The parse.** Even byte length, else error. `u16::from_le_bytes` pairs, drop one trailing
   `0`, `String::from_utf16`. Then `serde_json::from_str::<serde_json::Value>` and walk it by
   hand: `secrets` must be an object, else error. Every error is a fixed sentence
   (`"The v2 secrets entry is not in the shape v2 writes."`): **never** include a serde_json or
   UTF-16 error's text, because serde_json's messages quote the value (`invalid type: string
   "…"`). Non-string or empty values become `unusable` by name. `looked`/`moved` are ignored.
4. **The mapping.** `v3_name`: if the account is in `renames`, `("_core", <v3 key>)`; else owner =
   text before the first dot, key = the rest; `None` unless `account(owner, key)` accepts it.
   So `_core.provider_<id>` → `_core`/`provider_<id>` (what `free::key_for` reads),
   `telegram.bot_token` → `_core`/`telegram_bot_token` (what `channels::telegram_token` reads),
   and a plugin's `<id>.<key>` → `<id>`/`<key>` (what the MCP host hands that plugin,
   `secrets::get(&m.id, key)`). The hub and the store name no plugin; the one rename lives in
   `channels/mod.rs`, the only folder allowed to name a service (invariants 1 and 1b).
5. **The import.** For each v2 name: map; "v3 has one" is the backend (keychain or memory map),
   **not** the `ALEXIA_SECRET_*` env override (split `get` into a private `stored()` the import
   uses). Has one and not `overwrite` → `kept`. Else `set` → `copied` or `failed`. A failed
   write's error is dropped (name only), so its text can't carry the value. Then each `expected`
   name that v2 did not supply → `not_in_v2`. Sort each list.
6. **The hub.** `main.rs`: `([Some("secret"), Some("import-v2"), flags @ ..], _)` with `flags`
   empty or `[Some("--overwrite")]`, else usage. `expected` = `secret_keys()` as `_core` names
   plus, like `import()`, every scanned manifest's `password_keys()` as `<id>.<key>`.
   `renames` = `channels::v2_secret_names()`. Print the report, then
   `"<n> copied, <n> kept, <n> not in v2."`. Add the usage line.
7. **INTERFACES.md.** §2.6 the new line; §2.4 `channels::v2_secret_names`; the secrets section
   the four new items above.

## Tests
`tests/v2_secrets.rs`, with `secrets::MEMORY_BACKEND_ENV` set (no test reaches Credential
Manager: everything goes through `V2Vault::parse` on bytes built in the test). Every fake value
is built at runtime from two halves, e.g. `let v = format!("{}{}", "fake-", "k3y-91");`, so the
whole value never appears as one literal. Use made-up plugin ids (`zeta.api_key`), not real
ones. A helper encodes JSON to UTF-16LE bytes.
- `parse_utf16le_with_and_without_trailing_nul`: both give the same names.
- `parse_rejects_odd_length_bad_json_and_missing_secrets`: odd byte count, not JSON, `{}` and
  `{"secrets": "x"}` all fail, and **the error text contains no part of the blob** (put a fake
  value in the bad JSON and assert `!err.to_string().contains(..)`).
- `maps_v2_names_to_v3`: `_core.provider_groq` → (`_core`, `provider_groq`); the rename →
  (`_core`, `telegram_bot_token`) with a renames list built in the test; `zeta.api_key` →
  (`zeta`, `api_key`); `nodot`, `Bad.Key`, `zeta.` → `None`.
- `copies_skips_and_overwrites`: v3 already has one name; without `overwrite` it is `kept` and
  its old value stays; with `overwrite` it is `copied` and holds the v2 value; a v2-absent
  expected name is `not_in_v2`; an empty and a non-string value are `unusable`.
- `copy_leaves_the_source_alone`: the `V2Vault` and its blob are unchanged after the import
  (the import takes `&V2Vault`; assert names and a re-parse of the same bytes are identical).
- `no_value_in_report_or_debug`: `format!("{report:?}")`, every report line, and
  `format!("{vault:?}")` contain no fake value.
- `env_override_is_not_a_stored_secret`: with `ALEXIA_SECRET__CORE_PROVIDER_CEREBRAS` set and
  the backend empty, the import copies it (it is not `kept`).

The memory backend is one map per test process and tests run in parallel: give each test its
own owner ids and keys so no two tests share a name.

`alexia-hub/tests/cli.rs` or `cli_p1.rs` is not touched; the binary path reads the real
Credential Manager on Windows, so it has no automated test. A unit test in `main.rs` checks
only that `secret import-v2 --bogus` is a usage error (exit 2) if it can do so without reading
the keychain; otherwise skip it.

## Notes for the worker
- **Never print, log, return in an error, or `Debug` a value.** That includes `tracing` at any
  level, test failure messages (`assert!(!s.contains(v), "a value leaked")`, never `assert_eq!`
  on a string holding one), and `?` on a serde_json or keyring error. A hand-written
  `impl Debug for V2Vault` lists names only.
- Never call `get_password` on the v2 entry and never `set`/`delete` it. The only call on
  `dev.alexia.app` is the one `get_secret`.
- Values are plain `String`s and are not zeroized; `zeroize` is not a dependency and this runs
  once. Leave a `ponytail:` comment saying so.
- `ALEXIA_KEYCHAIN` (the Mac Alexia Dev service name) is not read here: it is a v2 build
  variable for the Mac and must never be referenced from v3.
- Running this twice is safe by design (`kept`), so "once" is the owner's choice, not a guard.
