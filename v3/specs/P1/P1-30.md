# P1-30: Approvals: test the 10-minute give-up and scheduled jobs

Model: sonnet
Depends on: P1-28
Feature IDs: CH-07

## Goal
`ask.rs` gives up on an unanswered approval after 10 minutes (`ANSWER_WAIT`): it cancels the
channel's ask, sends "— no answer, so I didn't" and answers no. Nothing tests that, because
`alexia-gateway` has no `tokio` `test-util` feature, so `tokio::time::pause` is not available
and `deny_and_timeout_are_false` only tests a cancelled run, not the timeout. The
`Origin::Scheduler` path (ask in the first channel's primary chat) is untested too. After this
task both are tested, with paused time for the timeout. No product code changes.

## Touch only these paths
- `v3/crates/alexia-gateway/Cargo.toml`   (change: a `[dev-dependencies]` section)
- `v3/crates/alexia-gateway/tests/ask_voice.rs`   (change)

## Must not touch
`src/` (all of it, including `ask.rs`: if a test shows a bug, stop and report it), other

## Interfaces
None. `alexia-gateway/Cargo.toml` gains:

```toml
# Paused time for the approval timeout (P1-30).
tokio = { workspace = true, features = ["test-util"] }
```

## Steps
1. Add the dev-dependency above. `test-util` pulls in no new crate; if `v3/Cargo.lock`
   changes anyway, stop and report (P1-17 owns the lock while it runs).
2. New test `unanswered_approval_gives_up_after_ten_minutes`, as
   `#[tokio::test(flavor = "current_thread", start_paused = true)]` (paused time needs the
   current-thread runtime): `start(Setup { answer: Answer::Hang, .. })`; spawn
   `h.asker.confirm(&in_chat("x"), &question(), CancellationToken::new())`; wait until
   `h.ch.asks()` has one entry. Then `tokio::time::advance(Duration::from_secs(9 * 60 + 59))`
   and a `yield_now`: the confirm is still pending and nothing was sent to "x". Advance 2 s
   more: the confirm returns `false`, and `h.ch.sent()` holds `("x", text "— no answer, so I
   didn't")`. `h.stop().await`.
   With paused time the harness's 30 s waits (`reply_in`, `stop`) auto-advance; that is fine,
   they are upper bounds.
3. New test `scheduled_job_asks_in_the_primary_chat`: a store where
   `channel_session("fake", "chat-p")` and `set_primary_chat("fake", "chat-p")` are set before
   the gateway starts (add an optional `primary: Option<&'static str>` to `Setup`, applied in
   `start` beside `voice_replies`). `confirm(&Origin::Scheduler { job: JobId(..) }, ..)` with
   `Answer::Yes` → `true`, and `h.ch.asks()` is `[("chat-p", "Delete the old backups?")]`.
   Without a primary chat (default `Setup`) the same call → `false` and no ask.
