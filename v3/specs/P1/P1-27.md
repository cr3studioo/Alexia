# P1-27: De-flake call_at_idle_deadline_never_gone

Model: sonnet
Depends on: none
Feature IDs: none

## Goal
`call_at_idle_deadline_never_gone` (`v3/crates/alexia-mcp/tests/supervise.rs:512`, new in
P0-22) fails under a loaded `cargo test --workspace` and passes when rerun. After this task it
fails only for the bug it exists to catch: an idle stop that overtakes a call.

**Why it flakes (reproduced while planning):** six copies of the test run beside 30 CPU
burners (what parallel Orca builds do to the PC) failed 3 of 6 times, each with
`loop N, gap … ms: (… Err(Gone) …)` and the newest event `Stopped { reason: Heartbeat }`,
followed by `Crashed`. It is not the idle stop. The watcher's ping deadline is the heartbeat
itself (`supervise.rs` `watch`: `conn.request("ping", .., w.heartbeat)`, 500 ms in this test),
so a starved fixture that answers a ping late is killed as hung (`host.rs` `reap`,
`heartbeat: true`, no grace), and the calls in flight get `Gone`. P0-22 already raised the
heartbeat from 50 ms to 500 ms for the same reason; no fixed number is safe on a loaded
machine, and a larger one multiplies the run time (50 loops × a heartbeat each). Unloaded, 32
parallel copies and 8 parallel whole-binary runs all passed.

**The fix: a loop the heartbeat killed proves nothing about the idle stop, so it is not
counted.** The product behaviour (kill a plugin that misses a ping) is right and is tested
elsewhere (`hang_is_killed_by_heartbeat`); this test only asks whether an idle stop can
overtake a call.

## Touch only these paths
- `v3/crates/alexia-mcp/tests/supervise.rs`   (change: this one test, and a helper if needed)

## Must not touch
`v3/crates/alexia-mcp/src/` (the ping deadline is not changed for a test; production's
heartbeat is 15 s), other tests in the file, other test files, other crates. If you find a
failure with no `Stopped { reason: Heartbeat }` in the same loop, that is the real bug this
test guards: stop and report it with the events, do not loosen the test around it.

## Interfaces
None.

## Steps
1. In this test's `Timings`, set `crash_limit: u32::MAX` so heartbeat kills under load never
   switch the plugin off (`Unhealthy` would fail every later call with a sentence, not `Gone`).
   Keep `heartbeat_ms: HEARTBEAT_MS`, `idle_ms: 100`, `exit_grace_ms: 0` (they are what makes
   an overtaken call show).
2. Loop until 50 **clean** loops, at most 150 attempts. Each attempt notes
   `let from = fx.events.lock().unwrap().len();` before its warm call. After the three calls,
   a heartbeat stop among `events[from..]` (`PluginEvent::Stopped { reason:
   StopReason::Heartbeat, .. }`) makes the attempt void: count it in `void` and go on,
   whatever the calls returned. Otherwise the attempt is clean, and a failed call panics with
   the same message as today plus `void` so far. Keep `gap` from the clean-loop index, so the
   sweep still covers −70..+50 ms around the tick.
3. After the loop: `assert_eq!(clean, 50, "only {clean} clean loops in 150 ({void} voided by
   heartbeat stops: the machine is too loaded to test the idle deadline)")`;
   `assert!(fx.count(started) > 1)` as today; replace `assert_eq!(fx.count(crashed), 0)` with
   `assert_eq!(fx.count(crashed), fx.count(heartbeat_stop))` (every crash is one the heartbeat
   caused, none came from an idle stop).
4. Update the comment above the test to say why heartbeat-voided loops do not count.
