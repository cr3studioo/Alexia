## Goal
After this task `alexia-hub run` on the PC is V3-1: it hosts the v2 plugins, keeps the free
catalog fresh, runs v2 core as the task lane, and answers Telegram through the gateway, fast
lane first. The owner can set the bot token and provider keys (`secret set`), pair
(`pair`), register the watchdog (`install` / `uninstall`) and read the dashboard (`latency`).

**Do not start before P1-10 is merged.** Until then `channels::secret_keys()` and
`channels::configured()` are empty stubs and `channels::pairing_codes` does not exist, so the
`run`, `secret` and `pair` tests have nothing to wire.

## Interfaces
New subcommands (INTERFACES.md §2.6 grows; P1-01 wrote them there):

```
alexia-hub run                         P0's run plus everything below
alexia-hub secret set <key>            reads the value without echo; key ∈ channels::secret_keys()
                                       or "provider_<id>" for an id in free::ladder()
alexia-hub secret clear <key>
alexia-hub secret list                 the allowed key names, never values
alexia-hub pair                        prints "<channel>\t<code>" per channels::pairing_codes(&store)
alexia-hub latency [--last N] [--html FILE] [--check]
alexia-hub install | uninstall         watchdog::install / uninstall
```

```rust
// media.rs: alexia_gateway::Media by capability name.
pub struct McpMedia {
    caps: Arc<dyn alexia_core::chat::Caps>,   // the same Arc FastChat gets (McpHost implements it)
    host: McpHost,                             // only for speak's audio block
    cache: PathBuf,                            // layout.cache()
}
// transcribe: caps.answers("voice.transcribe") false → Ok(None); else
//   caps.call("voice.transcribe", {"file": <path>}, token) → Ok(that text), None → Ok(None) and
//   a warn log (Caps already joins the text blocks and maps isError / a failed call to None).
// speak: host.answers("voice.render").answers false → Ok(None); else host.call_capability(
//   "voice.render", {"text"}) → the first content block of type "audio" with mimeType
//   "audio/ogg", `base64::engine::general_purpose::STANDARD`-decoded to
//   cache/voice/voice-<alexia_store::now_ms()>-<n>.ogg (n: a static AtomicU64 counter, so two
//   notes in one ms never clash) → OutFile { name, mime: "audio/ogg", path }.
//   isError, no audio block or bad base64 → Ok(None) and a warn log.
```

Environment read here: `ALEXIA_V2_ROOT`, `ALEXIA_V2_DATA_NAME` (default `AlexiaBridge`),
`ALEXIA_V2_URL` + `ALEXIA_V2_TOKEN` (attach, tests), `ALEXIA_NODE`, and P0's variables.
`ALEXIA_TELEGRAM_API` and `ALEXIA_FREE_PROVIDERS` are read by the library code.

## Steps
1. `run`, in this order: `Store::open` → `Bus` → `McpHost::new(.., NoUpcalls, sink)` +
   `start(enabled)` (P0's `boot`) → `let providers = free::configured()` and
   `let rows = providers.iter().map(|p| p.row().clone()).collect()` (the same rows, so an
   `ALEXIA_FREE_PROVIDERS` file reaches the catalog too; `free::ladder()` here would not) →
   `Catalog::new(providers as Arc<dyn Provider>, rows, layout.cache().join("v3-free-models.json"))`
   → `Router::new` → `let caps: Arc<dyn Caps> = Arc::new(host.clone())` → `FastChat::new(router,
   caps.clone(), store, Budget::CHAT)` → `V2Bridge::new` (only when `ALEXIA_V2_ROOT` or
   `ALEXIA_V2_URL` is set; otherwise the task brain is a tiny local `Brain` that answers
   "Tasks need v2 core on this PC. Set ALEXIA_V2_ROOT and restart." — defined in `main.rs`) →
   `Lanes::new(fast_chat, task_brain)` → `Gateway::new(GatewayConfig::default(), store, bus,
   lanes, Arc::new(McpMedia { caps, host: host.clone(), cache }))`, `add` each of
   `channels::configured(..)` → `bridge.set_ask(gateway.asker())`.
   Then **spawn** (on one `TaskTracker`, each with a child of the root token):
   `catalog.run`, `bridge.run`, `gateway.run` (log its `Err` with `tracing::error!`),
   `watchdog::heartbeat`, and the two timers of step 3. Not `watchdog::supervise`: `Gateway::run`
   consumes the gateway (an `FnMut` cannot call it twice), `Catalog::run` and `V2Bridge::run`
   return only on cancel, and the bridge already restarts v2 itself with backoff, so supervise
   would wrap nothing. `supervise` stays in `watchdog.rs` for V3-2's loops that can return.
2. On start: if `watchdog::offline_gap(&store, now_ms())` is `Some(s)`, publish `Event::Say {
   text: s, urgency: Normal }` once the gateway is running. Print "No channel is set up. Run
   `alexia-hub secret set …`" listing `channels::secret_keys()` when `configured` is empty, and
   one pairing line per `channels::pairing_codes(&store)` entry ("Send <code> to the <channel>
   bot to pair it."). Print "Import v2 first (`alexia-hub import-v2`)" when the `imports` table
   is empty and there are no sessions (P0-07 refuses after the first message).
3. Every 10 minutes, `fast_chat.invalidate()` (profile or personality edits show up within 10
   minutes; nothing publishes `Event::SettingsChanged` for plugin settings, so the timer is the
   mechanism). Every day, `store.prune_spans(now_ms() − 30 days)`. Use `alexia_store::now_ms`
   (P1-25); write no clock of your own.
4. On Ctrl+C: cancel the root token, close the tracker and wait for it (at most 5 s; the
   heartbeat task must have stopped before `clean_stop`, or a late tick makes a clean stop look
   like a crash), `host.shutdown()`, `watchdog::clean_stop(&store, now_ms())`, publish
   `ShuttingDown`, print `Stopped.` (P0's test hook `ALEXIA_HUB_STOP_ON_EOF` still works).
5. `secret set`: refuse unknown keys with the list of allowed ones; read with
   `rpassword::prompt_password("Paste the value (it won't be shown): ")`, or one line from stdin
   when stdin is not a terminal (tests, pipes); `secrets::set("_core", key, value)`; print
   "Saved." and never the value. Why `rpassword`: hiding typed input on a Windows console needs
   `SetConsoleMode` (unsafe FFI); the crate is the standard small answer. `secret clear` and
   `secret list` likewise refuse unknown keys / print names only.
6. `pair`: `Store::open`, then `channels::pairing_codes(&store)?` → one `"<channel>\t<code>"`
   line each; nothing printed and exit 0 when every channel is paired.
7. `media.rs` as above. Why `base64` (a new workspace dependency): voice notes arrive base64 in
   an MCP audio block; P1-26 (v2 uploads) and P1-28 (photo data URLs) use the same crate, so v3
   has one codec, not one hand-written copy per crate. It is already in `Cargo.lock` (0.22.1).

## Notes for the worker
- Rebase on the merged P1-10 and P1-25 first.
- The in-memory secrets backend is per process, so a test can't set a secret in one `alexia-hub`
  process and read it in another. Test `secret set` for not echoing and for refusing; leave the
  round trip to the library's own tests (P0-06).
- Order matters for one reason: the bridge needs the gateway's asker and the gateway needs the
  bridge (inside `Lanes`); `set_ask` after both exist breaks the cycle. The bridge is an
  `Arc<V2Bridge>`: one clone into `Lanes`, one into the spawned `run`.
- `McpMedia.transcribe` goes through `Caps` (core already maps text blocks and `isError`);
  only `speak` needs the raw `call_capability` result, for the audio block. Do not copy
  `Caps for McpHost`'s logic into the hub.
- Windows: the hub is still a console app; Task Scheduler runs it without a window when started
  at boot (no console attached).
- From the P1-16/P1-19 reviews: `alexia-hub install` pipes schtasks stderr while /RP asks for
  the password: in the by-hand install check, confirm the password prompt is visible (if it is
  not, inherit stderr for /Create). Access-denied detection matches English text only;
  non-English Windows gets the generic message.
