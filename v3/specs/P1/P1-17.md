## Goal
After this task `alexia-hub run` on the PC is V3-1: it hosts the v2 plugins, keeps the free
catalog fresh, runs v2 core as the task lane, and answers Telegram through the gateway, fast
lane first. The owner can set the bot token and provider keys (`secret set`), pair
(`pair`), register the watchdog (`install` / `uninstall`) and read the dashboard (`latency`).

## Interfaces
New subcommands (INTERFACES.md §2.6 grows; P1-01 wrote them there):

```
alexia-hub run                         P0's run plus everything below
alexia-hub secret set <key>            reads the value without echo; key ∈ channels::secret_keys()
                                       or "provider_<id>" for an id in free::ladder()
alexia-hub secret clear <key>
alexia-hub secret list                 the allowed key names, never values
alexia-hub pair                        prints "<channel>\t<code>" per unpaired channel
alexia-hub latency [--last N] [--html FILE] [--check]
alexia-hub install | uninstall         watchdog::install / uninstall
```

## Steps
1. `run`, in this order, each long-running part under `watchdog::supervise` with the root token:
   `Store::open` → `Bus` → `McpHost::new(.., NoUpcalls, sink)` + `start(enabled)` →
   `free::configured()` → `Catalog::new(.., layout.cache().join("v3-free-models.json"))` +
   `catalog.run` → `Router::new` → `FastChat::new(router, Arc::new(host.clone()), store,
   Budget::CHAT)` → `V2Bridge::new` + `bridge.run` (only when `ALEXIA_V2_ROOT` or
   `ALEXIA_V2_URL` is set; otherwise the task brain is a tiny local `Brain` that answers "Tasks
   need v2 core on this PC. Set ALEXIA_V2_ROOT and restart." — defined in `main.rs`) →
   `Lanes::new(fast_chat, task_brain)` → `Gateway::new(GatewayConfig::default(), store, bus,
   lanes, Arc::new(McpMedia{..}))`, `add` each of `channels::configured(..)` →
   `bridge.set_ask(gateway.asker())` → `gateway.run` → `watchdog::heartbeat`.
2. On start: if `watchdog::offline_gap` is `Some(s)`, publish `Event::Say { text: s, urgency:
   Normal }` once the gateway is running. Print "No channel is set up. Run `alexia-hub secret set
   …`" listing `channels::secret_keys()` when `configured` is empty, and the pairing line from
   `channels::pairing_codes` when unpaired. Print "Import v2 first (`alexia-hub import-v2`)" when
   the `imports` table is empty and there are no sessions (P0-07 refuses after the first message).
3. Every 10 minutes and on `Event::SettingsChanged`, `fast_chat.invalidate()`. Every day,
   `store.prune_spans(now − 30 days)`.
4. On Ctrl+C: cancel the root token, `host.shutdown()`, `watchdog::clean_stop`, publish
   `ShuttingDown`, print `Stopped.` (P0's test hook `ALEXIA_HUB_STOP_ON_EOF` still works).
5. `secret set`: refuse unknown keys with the list of allowed ones; read with
   `rpassword::prompt_password("Paste the value (it won't be shown): ")`, or one line from stdin
   when stdin is not a terminal (tests, pipes); `secrets::set("_core", key, value)`; print
   "Saved." and never the value. Why `rpassword`: hiding typed input on a Windows console needs
   `SetConsoleMode` (unsafe FFI); the crate is the standard small answer.
6. `media.rs` as above.

## Tests
`tests/cli_p1.rs` (spawning the binary, `ALEXIA_SECRETS_IN_MEMORY=1`, temp data dir):
- `secret_list_names_keys_only`: `secret list` prints at least one `provider_` key and the
  channel key(s), one per line, and nothing else.
- `secret_set_reads_stdin_and_never_prints_it`: pipe a value for the first listed key; exit 0,
  "Saved.", and neither stdout nor stderr contains the value.
- `secret_set_refuses_unknown_key`.
- `latency_with_no_turns_check_fails`: exit 1, "Only 0 turns recorded".
- `run_without_channel_says_so_and_stops`: with `ALEXIA_HUB_STOP_ON_EOF=1`, stdout contains
  "No channel is set up".
- P0's `tests/cli.rs` and `tests/v2_plugins.rs` still pass.

## Notes for the worker
- The in-memory secrets backend is per process, so a test can't set a secret in one `alexia-hub`
  process and read it in another. Test `secret set` for not echoing and for refusing; leave the
  round trip to the library's own tests (P0-06).
- Order matters for one reason: the bridge needs the gateway's asker and the gateway needs the
  bridge (inside `Lanes`); `set_ask` after both exist breaks the cycle.
- Windows: the hub is still a console app; Task Scheduler runs it without a window when started
  at boot (no console attached).
