# P2-58: Gateway: a waiting file message is not overtaken by steers; tests wait for events

Model: sonnet
Depends on: P2-38
Feature IDs: CH-08, CH-09; review follow-up from P2-07

## Goal
Steering carries `Content` only, so a message with files goes the normal way, into
`self.queued` while a visible chat turn runs. A text the owner sends after it is steered
straight into the running turn, so it is answered before the file message that came first.
After this task no message is steered while an earlier one is still waiting, and messages are
answered in the order they arrived.

`tests/gateway.rs` waits a fixed 1 s, or 1.5 s, in several places (about lines 658, 767, 911 and
1257). That is slow, and still flaky on a loaded machine. After this task those tests wait for
the event they expect, with a long deadline.

- `v3/crates/alexia-gateway/tests/gateway.rs` (change)

## Must not touch

## Steps
1. `gateway.rs`, the steering branch (about line 467): steer only when `self.queued` is empty
   (and the existing conditions hold). Otherwise the message goes the normal path, which queues
   it after the waiting one. Comment why.
2. Check the CH-08 tasky branch (about line 499). There, `next` is the unread steers plus the new
   message. If anything is queued, it must come first. Today the tasky path does not queue, so
   this may already hold. Prove it with a test rather than change it.
3. `tests/gateway.rs`: replace each fixed `sleep(Duration::from_secs(1))` and the 1.5 s one with
   an `eventually`-style wait on the condition that test asserts next (a sent message, a draft,
   a brain call count), deadline 10 s. A sleep that proves something does *not* happen may stay,
   shortened to 200 ms, with a comment saying so.

## Tests
- `file_message_not_overtaken_by_steer`: a steerable brain mid-turn and visible, a message with
  a file (queued), then a text. The brain's next turn has the file message, and the text comes
  after it, not steered into the first turn.
- `steer_still_works_with_empty_queue` (the P2-07 case, unchanged)
- The existing tests, rewritten as in step 3.

Each new test must fail without its fix.
