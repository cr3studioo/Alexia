# P2-45: McpHost::manifests, the agent's source of plugin commands and skills

Model: sonnet
Depends on: P2-23
Feature IDs: SP-01 (plugin commands), plugin skills; phase review 4 finding 2

## Goal
After this task core can ask the host which plugins are enabled and what their manifests declare
(commands, skills folders) without spawning anything. Today `McpHost::plugins()` returns
`PluginStatus`, which has neither the manifest nor the folder, so `commands::list` (P2-25) and
`Skills::load` (P2-38) have no source. P2-20 then puts the host into `AgentParts`.

## Touch only these paths
- `v3/crates/alexia-mcp/src/host.rs` (change)
- `v3/crates/alexia-mcp/tests/manifests.rs` (create)

## Must not touch
`serve.rs`, `conn.rs`, `supervise.rs`, `wasm.rs`, every other crate, INTERFACES.md (the review-4
planner already wrote §2.2 `manifests`).

## Interfaces
```rust
impl McpHost {
    /// Every loaded plugin that is enabled and not refused, by id: its folder and manifest.
    /// Reads what `start`/`reload` loaded; spawns nothing.
    pub fn manifests(&self) -> Vec<PluginDir>;
}
```

## Steps
1. In `host.rs`, beside `plugins()` (about line 253): lock `inner.plugins` once, keep slots that
   are `enabled` and whose state is not `Refused`, clone `slot.dir` (`PluginDir { path, manifest }`),
   in the map's id order. Reuse the existing `lock()` helper; no new state.
2. After `reload` the next call returns the reloaded manifest (the slot's `dir` is what reload
   replaces); after `set_enabled(id, false)` the plugin is gone from the list.

## Tests
`tests/manifests.rs`, with temp plugin folders and non-resident manifests (see how

`manifests_lists_enabled_only`, `refused_plugin_not_listed`, `disabled_drops_out`,
`reload_shows_new_manifest`, `manifests_spawns_nothing` (`pid()` stays None).
