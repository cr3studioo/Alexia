# P2-27: Parallel helpers

Model: opus
Depends on: P2-20
Feature IDs: AC-07

## Goal
After this task the model can split a big job across sub-agents: a builtin tool `helpers.run`
starts up to 4 child runs at once, each with its own goal, session and a 12-step ceiling, under
the same permissions and approvals as the parent, and returns their answers together. Helpers
cannot start helpers.

## Touch only these paths
- `v3/crates/alexia-core/src/helpers.rs`
- `v3/crates/alexia-core/tests/helpers.rs` (create)

## Must not touch
Everything else.

## Interfaces
```rust
pub struct Helpers { /* Weak<Agent> */ }
impl Helpers { pub fn new(agent: &Arc<Agent>) -> Arc<Helpers>; }
impl Builtin for Helpers {
    /// `helpers.run {tasks: [{goal: string}] (1..=4)}` → one section per helper:
    /// "Helper 1 (<goal>): <answer or why it stopped>".
}
```

## Steps
1. Each helper: a new session titled "Helper: <goal>" (deleted after 30 days with runs), a Task
   with `parent = ctx.run`, `origin = ctx.origin` (approvals go to the owner where the parent
   came from), `background = ctx.background`, `max_steps = limits.helper_steps`.
2. Run them in a `JoinSet`; the parent's cancel cancels all; one failing doesn't stop the others.
3. A helper's tool list excludes `helpers.run` (depth 1).
4. The parent's trace notes "Started 3 helpers"; each helper has its own `runs` row with `parent`.

## Tests

`helper_cannot_spawn_helpers`, `parent_cancel_stops_helpers`, `one_failure_others_answer`,
`approvals_go_to_parent_origin`, `more_than_four_refused`.
