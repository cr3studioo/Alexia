# P2-69: OpenAI wire: blank assistant text is empty; a call is answered only by the tool turns right after it

Model: sonnet
Depends on: none
Feature IDs: SP-01; review follow-ups from P2-53

## Goal
Two edges in `wire_messages` (`alexia-core/src/openai.rs:222`):
- An assistant turn whose calls are all unanswered gets the note "I called … and got no
  answer." only when `plain(&body.content).is_empty()` (line 245). Content of `" "` or `"\n"` is
  not empty, so the turn goes out as a blank assistant message, which some providers refuse.
- `answered` (line 238) counts a `Tool` turn anywhere later in the history. OpenAI-compatible
  providers want each `tool_calls` message followed directly by its `tool` messages. A call
  answered only after a later user or assistant turn is kept, and its result then goes out as a
  `tool` message in the wrong place, which a strict provider rejects.

After this task blank content counts as empty, and a call counts as answered only by the run of
`Tool` turns that directly follows its assistant turn. A result outside that run is sent as the
"A tool answered: …" user note, as an unknown result is today.

## Steps
1. Line 245: `plain(&body.content).trim().is_empty()`.
2. `answered(id)`: look only at `messages[at + 1..]` up to the first turn that is not
   `Role::Tool`.
3. `seen`: clear it at every non-`Tool` turn, before an assistant turn adds its kept calls. A
   `Tool` turn whose id is not in `seen` then becomes the user note, as today.
