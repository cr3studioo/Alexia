# P2-53: OpenAI wire: unanswered calls, odd delta shapes, nameless calls

Model: sonnet
Depends on: none
Feature IDs: SP-01; review follow-up from P2-04

## Goal
Three edges in `OpenAiCompat` that P2-04's reviewer found. After this task:
- an assistant turn's tool call that no later tool turn answers is not sent, so a strict
  provider never sees a call without a result (the mirror of P2-04's result-without-a-call rule);
- a streamed `delta.tool_calls` that is a single object instead of an array is read, not dropped;
- a streamed call that never got a name is not silently lost: the loop gets it and reports it.

## Touch only these paths
- `v3/crates/alexia-core/src/openai.rs` (change)
- `v3/crates/alexia-core/tests/openai.rs` (change)

## Must not touch
Every other file, including `router.rs` and `catalog.rs` (P2-17 is running). No public
signature changes.

## Interfaces
None new.

## Steps
1. `wire_messages()` (about line 222): first collect the call ids that a later `Role::Tool` turn
   answers. On each assistant turn, send only the answered calls in `tool_calls`. If none are
   left, send the turn without `tool_calls`. If its content is then empty too, send the text
   `I called {names} and got no answer.` so no empty assistant message goes out. Keep the
   existing "A tool answered: …" path for a result without a call.
2. The stream reader (about line 521): accept `delta.tool_calls` as an array, or as one object
   (read as `[object]`). Anything else is ignored, as today.
3. The assembly (about line 550): a piece with arguments but no name is emitted with the name
   `unnamed_tool`, so the agent loop's unknown-tool path tells the model, plus one
   `tracing::warn!` with the provider id and index (never the arguments). A piece with neither
   a name nor arguments is still skipped.
