# P2-23: Hot reload of plugins

Model: opus
Depends on: P2-22
Feature IDs: EX-12

## Goal
After this task a plugin updates without a hub restart: when its folder's `plugin.json` or entry
files change (an update, a rebuild), the host finishes the calls in flight, stops the old process,
re-reads the manifest, and the next call spawns the new version. Tools are re-listed
(`ToolsChanged`). A manifest that no longer parses keeps the old version running and says why.

## Touch only these paths
- `v3/crates/alexia-mcp/src/{host.rs, supervise.rs}`
- `v3/crates/alexia-mcp/tests/reload.rs` (create)

## Must not touch
`serve.rs`, `conn.rs`, `wasm.rs`, other crates.

## Interfaces
`McpHost::reload(&self, id) -> Result<(), Error>` (P2-02), `PluginState::Reloading`,
`PluginEvent::ToolsChanged`.

## Steps
1. The folder watcher that already detects removal (V3-0) also compares, every scan, the
   manifest's mtime+size and the `version` field; a change → `reload(id)`.
2. `reload`: state `Reloading`; new calls wait (bounded by `call_ms`) for the swap; in-flight
   calls run to completion or `call_ms`; then stop (not a crash, `StopReason::Disabled`), parse
   the new manifest, re-create declared tables (`create_tables` is idempotent), `Loaded`,
   `ToolsChanged`.
3. Parse failure: old process kept, `PluginStatus.sentence` = the reason, event `Refused` not emitted.
4. A resident plugin is respawned at once; a lazy one on its next call.

## Tests
`manifest_change_reloads`, `in_flight_call_finishes`, `bad_manifest_keeps_old`,
`resident_respawns`, `tools_changed_emitted`, `reload_is_not_a_crash` (crash count unchanged).

## Done when
- `cargo fmt --all --check` passes in v3/
- `cargo clippy --workspace --all-targets -- -D warnings` passes in v3/
- `cargo test --workspace` passes in v3/
- `node v3/ci/invariants.mjs` passes from the repo root
- `cargo test -p alexia-mcp --test reload` passes 20 times in a row

## Notes for the worker
- No new file-watching dependency: the host already polls; reuse its scan.
