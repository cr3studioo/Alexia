# P2-80: Resume: a live job's age counts from its last step; every ending closes its questions; audit rows name their own run

Model: sonnet
Depends on: none
Feature IDs: SP-13, AC-08, TR-08; review follow-ups from P2-26

## Goal
Three edges in `alexia-core/src/resume.rs`:
- **Age** (`resume.rs:47`). `now_ms() - row.started_at > MAX_AGE_MS` ends a run that started more
  than 7 days ago, even when it took a step an hour ago. AC-08 is jobs that run for days; the age
  that matters is since the run last moved (`touched_at`).
- **Questions left open** (`resume.rs:60`, `:68`). `end_with` ends the run but leaves its pending
  approvals pending; only `start` closes them. A run ended at boot keeps an open question in the
  approvals inbox forever.
- **Audit run id** (`resume.rs:189`). `answer_dangling` picks the first live run of the session
  (`.find(|r| r.session == session)`), so with two live runs in one session (a helper beside its
  parent) the audit row names the wrong run.

After this task a run that moved in the last 7 days is resumed, every run ended at boot has no
pending question, and each "restarted" audit row names the run that made the call.

## Steps
1. Age from `row.touched_at`; the note says "it had not moved for more than 7 days".
2. Move the "close the run's pending approvals" loop out of `start` into a helper called by both
   `start` and `end_with`. A store error in it is logged and does not stop the boot.
3. `answer_dangling(store, row, why)`: use `row.run` for the audit row instead of searching the
   live runs.

## Tests
- `old_run_that_moved_lately_resumes` (`started_at` 10 days ago, `touched_at` 1 hour ago: resumed)
- `stale_run_is_ended` (`touched_at` 8 days ago: ended with the note)
- `ended_run_closes_its_questions` (a run whose session is gone, with a pending approval: after
  `resume_all` the approval is answered `false` via `"restart"`)
- `audit_names_its_own_run` (two live runs in one session, the second has a dangling call: the
  audit row's `run` is the second)
