# P2-62: New plugins start unreviewed; the GPU watcher hands the hub what it needs

Model: opus
Depends on: P2-55, P2-57
Feature IDs: TR-01, MO-09, D213; phase review 5 findings 6 and 7

## Goal
Two findings, both in how the host and the GPU watcher meet the rest of the hub:
- `McpHost::tools` sets `reviewed` from a denylist (`_core.unreviewed`) that no v3 code writes;
  only the v2 import fills it. Any plugin dropped into a plugin folder, a third-party MCP-compat
  server included, is `reviewed: true`, and its own `readOnlyHint` lets its calls run unasked in
  *Ask before anything risky*. That is fail-open.
- `gpu::Watch::run` takes sync `Fn()` callbacks and no process list. INTERFACES §2.6 step 11
  needs async `Runtime::stop_all`, `McpHost::stop` for the plugins on the GPU and
  `LocalJobs::set_paused`. P2-38 would have to spawn detached tasks and run nvidia-smi a second
  time to find the pids. And a stopped lazy plugin respawns on its next call while the game is
  still running.

After this task a plugin id the host has never seen starts unreviewed, the owner's word
(`McpHost::set_reviewed`) changes that, `Watch` sends `GpuEvent`s with the process list over an
mpsc channel, and `McpHost::hold` keeps the GPU plugins stopped until `release`.

## Steps
1. Reviewed, fail closed. Where the host learns a plugin id (`start`, and a new folder found by
   hot reload), read kv `_core`/`known_plugins` (a JSON array of ids):
   - absent (first run ever): write every id found now as known; add none to `_core.unreviewed`.
     What the owner installed before the first run is trusted, as v2's bundled set was;
   - present: each id not in it is appended to `_core.unreviewed` and to `known_plugins`;
   - unreadable or malformed: write nothing, warn once. `tools()` already treats an unreadable
     `unreviewed` list as "everyone unreviewed"; treat an unreadable `known_plugins` the same way
     in `tools()` (fail closed).
   Write both lists in one `kv` transaction if the store has one, else `unreviewed` first.
2. `set_reviewed(id, true)` removes the id from `_core.unreviewed`; `false` adds it. A read error
   is returned, not swallowed.
3. Hold: `hold(ids)` records the ids in a held set, then `stop`s each. While an id is held,
   `call_tool` and `call_capability` for it return `CallError::Off { sentence: "<name> is paused
   while a game runs." }` before any spawn; a resident plugin is not respawned by supervision.
   `release()` clears the set; the next call spawns as usual. Check the set under the same lock
   that decides to spawn, so a call racing `hold` cannot spawn after the stop.
4. `gpu.rs`: `pub enum GpuEvent`; `Watch::run(self, cancel, events)` sends
   `StepAside { procs }` with the list it just decided on, once per game start, and `GameOver`
   once when it ends. A closed receiver ends `run`. No `spawn_blocking` change beyond what is
   there.
