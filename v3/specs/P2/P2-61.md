# P2-61: One file URI decoder; compute/run never opens a network path; undo stays in its plugin

Model: opus
Depends on: P2-51
Feature IDs: TR-01, TR-06, AC-11; phase review 5 findings 3, 4 and 5

## Goal
Three reviewers' findings about paths and a confused deputy:
- `alexia-mcp/src/serve.rs` `inside()` calls `fs::canonicalize` on a path a plugin supplies
  (`inputs[].path`) and on the worker's `resource_link` URI before the roots check. On Windows
  `\\host\share\x` or `file:////host/share/x` makes the OS open SMB to that host, which can leak
  the owner's NTLM hash. Its `file_uri_path` also ignores the URI's host. P2-50 fixed this only
  in core's `tools.rs`.
- There are three `file://` decoders (`permissions.rs` `normalised`, `tools.rs` `file_uri_path`,
  `serve.rs` `file_uri_path`) with different rules for the host, drive-relative `/x` and UNC. So
  the permission gate can judge a different path from the one the acting code opens.
- A plugin's `_meta["alexia/undo"]` keeps its target unchanged when it names another installed
  plugin's `<id>__tool` or a core builtin (`schedule.cancel`, `helpers.run`, ...). One plugin can
  plant an "undo" that runs another plugin's tool or a core builtin.

After this task there is one decoder, `alexia_mcp::file_uri_path`, and one network-path test,
`alexia_mcp::is_network_path`. All three places use them. compute/run refuses a network path
before any filesystem call. An undo target is always the returning plugin's own tool.

## Steps
1. `uri.rs`: `file_uri_path` takes the rules P2-51 put in `permissions::normalised`: scheme
   matched case-insensitively, the one-slash form `file:/C:/x` and `file:/x`, host empty or
   `localhost` (else `None`), percent-decoded (a broken escape kept as written), `/C:/x` read as
   `C:/x` (with `\` on Windows). A UNC result and a drive-relative `/x` are returned as decoded,
   not refused: refusing them is the opening code's job (step 3, 5). `is_network_path`: two
   leading separators in any mix of `/` and `\`, or `\\?\UNC\` (case-insensitive). Pure, no
   filesystem call, no `cfg` other than the `\` conversion.
2. `permissions.rs`: `normalised` calls `alexia_mcp::file_uri_path` for the `file:` branch and
   keeps its `~` and variable branches. Delete its own `percent_decoded` if nothing else uses it.
   A UNC or drive-relative result is still judged (it looks absolute), so it stays out of scope
   and asks: the gate does not fail open on what the opener refuses.
3. `serve.rs`: delete `percent_decode` and `file_uri_path`, use the shared one. `inside()` first
   returns `None` for `is_network_path(path)`, before `canonicalize`. Do the same for each root.
   The `resource_link` URI goes through `file_uri_path`, so another host is refused too.
4. `serve.rs`: update the comment over `inside()`: the containment check is still compute's own
   (roots, not the owner's scope), but the decoder is now shared.
5. `tools.rs`: delete its `file_uri_path`, use the shared one plus `is_network_path`, and keep its
   own extra rule that on Windows only a drive-letter path is local. Behaviour is P2-50's.
6. `tools.rs` undo (about line 197): the target is always `namespaced(&plugin, &u.tool)`, the
   returning plugin's own tool. Drop the undo (with one `tracing::warn!`, plugin id and target
   name only) when `u.tool` already contains the separator (`__`) or equals a builtin's tool
   name. `callable()` stays as the last check.
