# P2-30: Scheduled jobs

Model: opus
Depends on: P2-01, P2-03
Feature IDs: AC-09

## Goal
After this task "Every Monday at 9, check my school portal" becomes a job: the model calls the
builtin `schedule.add`, the scheduler fires it at the right local time through the brain
(`Origin::Scheduler`), and the answer reaches the owner's chat with `Event::Say`. Jobs survive
restarts (they are rows). `schedule.list` and `schedule.cancel` manage them, and `schedule.add`'s
result carries its undo (`schedule.cancel {id}`). The proactivity engine (watches, quiet hours,
V3-3) builds on this.

## Interfaces
```rust
#[serde(tag = "kind", rename_all = "snake_case")]
pub enum Trigger { At { at: Ms }, Every { period_ms: u64, from: Ms },
                   Daily { hour: u8, minute: u8 }, Weekly { weekday: u8 /* 1 = Monday */, hour: u8, minute: u8 } }
pub struct Job { pub id: JobId, pub trigger: Trigger, pub prompt: String, pub urgency: Urgency,
                 pub origin: Origin, pub created_at: Ms, pub next_at: Option<Ms> }
pub struct Scheduler { /* store, bus, brain */ }
impl Scheduler {
    pub fn new(store: Arc<Store>, bus: Bus, brain: Arc<dyn Brain>) -> Arc<Scheduler>;
    pub fn add(&self, trigger: Trigger, prompt: &str, urgency: Urgency, origin: Origin) -> Result<JobId>;
    pub fn cancel(&self, id: JobId) -> Result<bool>;
    pub fn jobs(&self) -> Result<Vec<Job>>;
    /// Sleeps until the next due job (re-checks every minute and on add/cancel), fires it, sets next_at.
    pub async fn run(self: Arc<Self>, cancel: CancellationToken) -> Result<()>;
    /// The builtin tools, for the agent's Tooling.
    pub fn tools(self: &Arc<Self>) -> Arc<dyn Builtin>;
}
/// Next fire time after `now` in local time (chrono `Local`), DST-safe.
pub fn next_after(trigger: &Trigger, now: Ms) -> Option<Ms>;
```

## Steps
1. Dependencies: `alexia-store`, `alexia-core`, `chrono` (workspace, P2-01), `serde`, `tokio`.
2. Firing: a Turn with `origin = Scheduler { job }`, session = the job origin's channel session,
   content = the prompt; the reply → `Event::Say { urgency, job }`; `job_ran` with run id and
   outcome. A miss while the hub was off fires once at start (not once per missed period).
3. Builtin tools: `schedule.add {kind, at?, every_minutes?, hour?, minute?, weekday?, prompt, urgency?}`
   with a clear description for the model; `schedule.list {}`; `schedule.cancel {id}`.
   `schedule.add` is not read-only (asks in *risky*), `schedule.list` is read-only.
