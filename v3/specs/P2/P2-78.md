# P2-78: Tooling: a plugin's file link is sent only from where the plugin may write

Model: opus
Depends on: P2-67
Feature IDs: TR-01, TR-06, SP-10; phase review 6 finding 7

## Goal
`produced()` (`alexia-core/src/tools.rs:288`) turns any `file://` `resource_link` that names an
existing file into a `Produced`, and the gateway uploads it to the owner's chat. Nothing checks
the path against the plugin's own folder, the scope roots or the never-touch list. A sandboxed
WASM plugin (only `/data` preopened) or an unreviewed one can make core read and send any local
file, for example `alexia.db` or a key under `~/.ssh`. For WASM this is a sandbox escape.

After this task a file link becomes a produced file only when it is inside the plugin's own data
folder, `layout.uploads()` or a scope root, and never when it is on the never-touch list or a
network path. Anything else is "[file: <name> — not sent]" and a warning.

## Touch only these paths
- `v3/crates/alexia-core/src/tools.rs` (change)
- `v3/crates/alexia-core/tests/tools.rs` (change: add tests)

## Must not touch
Every other file, including `src/permissions.rs` (its `never_touch`, `scope` and containment
helpers are reused as they are), `alexia-mcp` and `v3/specs/INTERFACES.md`.

## Interfaces
None public. `outcome_of(result)` keeps its signature for builtins; the hosted-tool path calls a
crate-private `outcome_from(result, allowed: &Allowed)` where `Allowed` holds the roots below.

## Steps
1. In `McpTooling::call` for a hosted tool, build the allowed roots: the plugin's own data
   folder (from `host.manifests()` / the layout the host uses for that plugin), `layout.uploads()`,
   and `permissions::scope(store, root)`'s roots. Read what is available from the existing
   fields; if `McpTooling` lacks the store or layout, take them from what the host already holds
   rather than adding a constructor argument.
2. `produced()` gets the allowed set: refuse a network path (`alexia_mcp::is_network_path`),
   resolve the path, refuse it if `permissions::never_touch`, and accept it only if it is within
   one of the roots (the same containment permissions uses). Refused links keep the text
   "[file: <name> — not sent]" and a `tracing::warn!` with the plugin id and no path contents.
3. A builtin's links (core's own tools) keep today's behaviour.

## Tests
- `link_inside_plugin_dir_is_sent` (a temp plugin folder, a file in it: one `Produced`)
- `link_outside_roots_is_not_sent` (a temp file outside every root: no `Produced`, text says not sent)
- `link_to_database_is_not_sent` (a link to the data dir's `alexia.db`: refused even if the
  data dir is under a scope root)
- `network_link_is_not_sent` (`file://host/share/x`: refused, no filesystem call needed)

Each new test must fail without its fix.
