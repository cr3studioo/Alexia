# P2-34: Local vision, local embeddings, the local checker model

Model: opus
Depends on: P2-31, P2-32, P2-33, P2-21
Feature IDs: MO-06, MO-07, TR-02 (where the checker runs), SP-17, D213

## Goal
After this task three GPU jobs work on demand on the hub, each unloaded after 10 minutes idle and
stopped for games:
- **Vision (MO-06).** With a vision model installed and `_core.vision` = `"local"` (the default
  when one is installed), pictures in a task never leave the PC: before a request goes to a cloud
  model, each image part is replaced by the local model's description and OCR text
  (`see_before_cloud`). Plugins get the same as the host capability `vision.describe`.
- **Embeddings (MO-07).** The host capability `text.embed` (`{texts:[…]}` → `{vectors:[[…]]}`)
  served by llama-server `--embedding`, for memory plugins now and V3-3's memory later.
- **The checker model (TR-02).** The smallest installed instruct model `gpu::fit` accepts becomes
  the `Checker`'s model (`Job::Check`), with a draft model for speculative decoding when one is
  installed and fits (SP-17).

## Steps
1. Model choice per job from `hf::installed`: vision = has an mmproj; embed = embedding arch;
   check = smallest instruct that `fit` says `Fits`. Owner pins (`_core.models`, P2-17) win.
2. Descriptions are cached per image hash for the session (an image sent twice is described once).
3. No local model for a job → the job is unavailable; vision then falls back to sending the image to
   a cloud vision model only if `_core.vision == "cloud"`, else the turn says it cannot look at
   pictures right now.
