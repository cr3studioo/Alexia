# P2-32: GPU: fit, load cap, steps aside for games

Model: opus
Depends on: P2-01
Feature IDs: MO-02, MO-08, MO-09, D213

## Goal
After this task the hub knows what the 4060 Ti can hold and keeps out of the owner's way: `fit`
says whether a GGUF fits (and how many layers go on the GPU) while leaving a headroom the owner
sets (MO-08, default 1.5 GB); a watcher sees a game start (a graphics process the owner did not
start through Alexia, from a game library folder) and makes everything Alexia runs on the GPU step
aside until it ends (MO-09). Nothing restarts by itself after the game: the next call respawns.

## Touch only these paths
- `v3/crates/alexia-core/src/gpu.rs`
- `v3/crates/alexia-core/tests/gpu.rs` (create)

## Must not touch
`local.rs`, everything else.

## Steps
1. Port `packages/core/src/fit.ts` and `nvidia.ts` (cited). `nvidia-smi` missing → `None`/empty,
   never an error the owner sees more than once.
2. The hub (P2-38) wires `step_aside` to `Runtime::stop_all` and `McpHost::stop` for every plugin
   whose pid shows up in `processes()` (INTERFACES §8.8's design, brought forward because MO-09 is
   a V3-2 pick). This module only detects.
3. Steam: `HKCU\Software\Valve\Steam\SteamPath` + `steamapps\common` and `libraryfolders.vdf`;
   Epic: `%ProgramData%\Epic\EpicGamesLauncher\Data\Manifests\*.item` `InstallLocation`.
   Read without unsafe code (`reg query` output is fine).
