# P2-67: Core: test folders cleaned up; the registry export file is unique per call

Model: opus
Depends on: P2-61, P2-62
Feature IDs: MO-09; review follow-ups (disk; P2-57)

## Goal
Two leaks of temp files in `alexia-core`:
- Its tests leave folders in `%TEMP%` that are removed before a test and never after:
  `tests/catalog.rs:82`, `chat.rs:170` (the `temp("host")` folder at line 546; the catalog cache
  file is already removed by `World`'s drop), `hf.rs:99` (model files), `local.rs:106`,
  `permissions.rs:76`, `prompt.rs:36`, `tools.rs:49` (a copy of the `mcp-fixture` executable
  per test).
- `gpu.rs` `reg_export` (line 358) writes `temp_dir()/alexia-reg-<pid>.reg`. Two calls in one
  process at once (`game_dirs` from two threads, or two tests in one test binary) export into
  the same file: one reads the other's half-written export, or a file the other just deleted,
  and finds no Steam folder.

After this task core's tests leave nothing in `%TEMP%`, and each `reg_export` call has its own
file.

## Steps
1. `tests/scratch/mod.rs`: the same `Scratch` as P2-65 step 1 (copy it from
   `alexia-store/tests/scratch/mod.rs` if merged): folder
   `temp_dir()/alexia-test/core-<tag>-<pid>-<n>`, `Deref<Target = Path>`, `remove_dir_all` on
   drop with up to 5 retries 100 ms apart on Windows.
2. Each helper in *Goal* returns a `Scratch`. Bind it before the `Store`, `McpHost`, `Catalog` or
   child process that uses it, so it drops last. Where a helper's folder is held by a `World` or
   `Env` struct, make the `Scratch` its last field (fields drop in declaration order).
3. `catalog.rs`'s `cache(name)` returns the cache file path inside a folder: return
   `(Scratch, PathBuf)`.
4. `gpu.rs` `reg_export`: add a process-wide `static N: AtomicU64` and name the file
   `alexia-reg-<pid>-<n>.reg`. Everything else stays (the file is still deleted after reading).
