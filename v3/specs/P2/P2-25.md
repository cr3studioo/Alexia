# P2-25: Commands

Model: opus
Depends on: P2-20, P2-45
Feature IDs: SP-01, AC-10, AC-11, AC-12, MO-10, MO-12 (`/status` spend)

## Goal
After this task a message starting with `/` is handled by core without a model: v2's built-ins
that still mean something on the hub, every plugin's declared commands (first installed wins the
bare word, `/<plugin>.<name>` always works), and P2's new ones. A built-in v2 had that v3 does not
serve answers with one honest sentence rather than pretending.

## Touch only these paths
- `v3/crates/alexia-core/src/commands.rs`
- `v3/crates/alexia-core/tests/commands.rs` (create)

## Must not touch
Everything else.

## Interfaces
```rust
pub struct CommandInfo { pub name: String, pub summary: String, pub alias: Option<String>,
                         pub plugin: Option<PluginId>, pub shadowed: bool }
pub fn list(manifests: &[Manifest]) -> Vec<CommandInfo>;      // v2 `commands()`
/// Called by `Agent::reply` for Lane::Command. Appends the turn and the answer to the session.
pub async fn run(agent: &Agent, turn: &Turn, cancel: CancellationToken) -> Result<Reply, BrainError>;
```
Built-ins: `/new` (new channel session + `conversation_ended`), `/help`, `/status` (mode, what
is running, spend this month, always $0.00 unless a provider charged), `/providers` (v2's check),
`/approvals` (pending list with ids), `/approve <id>`, `/deny <id>`, `/undo`, `/activity [text]`,
`/compare <question>`, `/models` (pins per job). `/local`, `/combined`, `/cloud`, `/nsfw`, `/sfw`,
`/cheap`, `/best`: "That setting is not in v3 yet." (TR-10 is V3-4; v3 is free-only).

## Steps
0. Manifests come from `agent.host().manifests()` (P2-45, phase review 4 finding 2): `list` takes
   their `manifest`s; `/new` calls `agent.host().conversation_ended()`; `/status` reads
   `agent.host().plugins()` for what is running. Nothing in this task touches `agent.rs` or mcp.
1. Port `packages/core/src/commands.ts` (`commands`, `run`, `standing`, `/providers`), cited.
   Plugin commands run as v2 runs them (read `run()`'s `call` hook: the plugin's tool by name).
2. `/approve`/`/deny`: `store.approval_answer(id, …, via = "<channel>:<chat>")` and publish
   `Event::Answered { approval: id, answer }` (bus variant added by P2-01) so the
   waiting asker (P2-29) resolves.
3. `/undo` → `undo::undo_last(agent, session)`; `/activity` → `trace::activity`; `/compare` →
   `compare::compare` (stubs until P2-28/P2-36 land; their tasks make them real).
4. `/new` from a channel: `store.new_channel_session`.
