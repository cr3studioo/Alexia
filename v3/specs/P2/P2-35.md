# P2-35: Subscriptions through their official CLIs

Model: opus
Depends on: P2-17
Feature IDs: MO-05, D212

## Goal
After this task, once the owner turns it on, a job can be answered by a subscription the owner
already pays for, through the vendor's own signed-in CLI on the PC: Claude Code (`claude -p
--output-format stream-json`) or OpenAI Codex (`codex exec --json`). It is a `Provider` that
answers text (no tool calls: the CLI runs its own), so it fits `Job::Plan` and `Job::Code` pins,
not tool steps. Alexia never signs in for the owner, never reads or copies the CLI's tokens, and
never starts a paid plan (D212). Off by default.

## Touch only these paths
- `v3/crates/alexia-core/src/subscription.rs`
- `v3/crates/alexia-core/tests/subscription.rs` (create)

## Must not touch
Everything else.

## Interfaces
```rust
pub enum Cli { ClaudeCode, Codex }
pub struct SubscriptionCli { /* cli, exe path, timeouts */ }
impl SubscriptionCli {
    /// `ALEXIA_CLAUDE_CLI` / `ALEXIA_CODEX_CLI`, else the name on PATH. None if not installed.
    pub fn find(cli: Cli) -> Option<SubscriptionCli>;
    /// `claude --version` / `codex --version` and a no-op sign-in check; a sentence if not signed in.
    pub async fn check(&self) -> Result<(), String>;
}
impl Provider for SubscriptionCli {   // id "subscription:claude-code" | "subscription:codex"; models() one entry, free: true, tools: false
}
```

## Steps
1. Spawn with `CREATE_NO_WINDOW`, the prompt on stdin (never argv: it can be long and private),
   working dir an empty temp folder (the CLI must not wander the PC; its own tool permissions are
   left at their most restrictive flags), stream its JSON events to `ChatChunk::Text`.
2. Cost is reported as 0 (`ChatDone.cost`): the plan is already paid. A rate-limit message from the
   CLI is `ProviderError::Busy`.
3. The hub registers it with `Router::set_provider` only when the owner pinned it
   (`alexia-hub models use plan subscription:claude-code`, P2-38).
