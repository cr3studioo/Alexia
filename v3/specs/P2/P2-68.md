# P2-68: Router: notes per run, keychain keys cached, unreadable pins said out loud

Model: opus
Depends on: P2-20
Feature IDs: TR-04, MO-14; review follow-ups from P2-17 and P2-59

## Goal
Three edges in `alexia-core/src/router.rs`:
- `known_secrets` (line 685) calls `free::key_for` for every catalog row, and `key_for` is a
  synchronous Credential Manager read. `race` calls it on every non-local request, so the chat
  lane (`FastChat` → `hedged`) and every task step block a tokio worker on N keychain reads per
  turn.
- `notes` (line 121) is one queue for the whole `Router`. Two runs stepping at once (parallel
  helpers, a scheduled job beside a chat task) each `take_notes()` the other's "Skipped the
  pinned model …" and "Removed … before sending." lines, so a note shows in the wrong run, or in
  none.
- `pins` (line 635) turns a `_core`/`models` value that does not parse into "no pins" with no
  word: every pin the owner set is dropped silently. (A pin that parses but names nothing usable
  is already skipped with a note in `step`; that stays.)

After this task a turn reads the keychain at most once a minute, a run only ever gets its own
notes, and a broken pins value is a warning.

## Steps
1. Keys cache: a `Mutex<Option<(tokio::time::Instant, Arc<Vec<String>>)>>` field (tokio's
   `Instant`, so paused time drives it in tests). `known_secrets` returns the
   cached list when it is younger than `KEYS_FRESH` (a `const` of 60 s, with a comment: a key the
   owner adds is matched by the generic patterns of `redact_request` until the next read). On a
   miss, read the keys inside `tokio::task::spawn_blocking`, so `known_secrets` becomes
   `async`; `race` awaits it. Two racing misses may both read; that is fine.
2. Notes per run: `notes` becomes `Mutex<HashMap<Option<RunId>, Vec<String>>>`. `step` files
   its notes under `ask.run`; `take_notes(run)` removes and returns that entry only.
3. If P2-20's `agent.rs` calls `take_notes()`, pass the run's id. Change nothing else there.
4. `pins`: when the value exists but does not parse, `tracing::warn!` once per call that the
   pins could not be read and are ignored (no value in the message), then return empty as
   today. Do not rewrite or delete the stored value.

## Tests
- `notes_stay_with_their_run` (two `step`s with different `run`, each with an unusable pin;
  `take_notes(Some(a))` has only a's note, `take_notes(Some(b))` only b's)
- `keys_read_once_per_minute` (an `ALEXIA_SECRET__…` override or the in-memory backend holding a
  key; two steps in a row with the key changed between them: the second still redacts the
  first key, so it came from the cache; with paused time advanced past 60 s the new key is
  used)
- `unreadable_pins_warned` (kv `_core`/`models` = `"oops"`; `pins()` is empty and a warning is
  logged; the kv value is unchanged)
- The existing `take_notes` assertions in `router_steps.rs` use `take_notes(None)` or the run
  they stepped with.

Each new test must fail without its fix.
