# P2-01: Core P2 types, module stubs, dependencies, INTERFACES.md

Model: opus
Depends on: P1-18
Feature IDs: SP-01 (all of P2's shared shapes), phase review 3 findings 2, 3, 6, 11, 12 (the spec half)

## Goal
After this task every P2 module of `alexia-core` exists as a stub with its final public
signature, the run types every P2 task shares are real, every new dependency is in the lock file,
and INTERFACES.md describes P2 (PHASE.md *INTERFACES.md additions*, items 1–10). Later tasks fill
one module each and never edit `lib.rs`, `Cargo.toml` or `Cargo.lock`.

                      pub annotations: Option<alexia_mcp::types::ToolAnnotations>,
                      /// false for an MCP-compatibility server nobody reviewed (wire-protocol §7)

pub struct ToolOutcome { pub text: String, pub ok: bool, pub files: Vec<Produced>,

pub struct ToolCtx { pub session: SessionId, pub run: RunId, pub origin: Origin, pub background: bool,

/// What the loop may call. `McpTooling` (P2-18) and a test fake.
#[async_trait] pub trait Tooling: Send + Sync {
    /// Re-asked every step, on purpose: a plugin can vanish between steps.
    async fn list(&self) -> Vec<ToolSpec>;
    /// A failure is an outcome (`ok: false`), never an Err.
    async fn call(&self, name: &str, args: Map<String, Value>, ctx: ToolCtx) -> ToolOutcome;
}
/// A tool core itself offers (skills, schedules, helpers, undo). Several implementations.
#[async_trait] pub trait Builtin: Send + Sync {
    fn specs(&self) -> Vec<ToolSpec>;
    /// None: not one of mine.
    async fn call(&self, name: &str, args: &Map<String, Value>, ctx: &ToolCtx) -> Option<ToolOutcome>;
}
pub struct Step { pub n: u32, pub name: String, pub args: Map<String, Value>, pub outcome: Option<ToolOutcome> }

pub struct LiveRun { pub run: RunId, pub session: SessionId, pub origin: Origin, pub started_at: Ms,

/// Review 12: the one "ms since an Instant, capped at u32::MAX" helper.

`Limits { max_steps: 24, background_steps: 200, helper_steps: 12 }` (`max_spend_usd` removed:

task that fills it (P2-12 permissions, P2-13 checker, P2-14 redact, P2-15 trim, P2-16 prompt,

are written so `agent.rs` can call them before they are filled: `see_before_cloud` returns its
