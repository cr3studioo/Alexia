# P2-46: Permissions fail closed: kv read errors, unannotated deletes, ~ and file:// paths

Model: opus
Depends on: P2-42
Feature IDs: TR-01; phase review 4 findings 3, 4 and 5

## Goal
Phase review 4 found three more places where `alexia-core` permissions fail open. After this
task a store error never makes a spoken boundary disappear. A spoken "don't delete anything"
stops a delete tool that has no annotations. A path written as `file:///…`, `~/…`, `$HOME/…` or
`%APPDATA%\…` goes through the never-touch and scope checks the same way as an absolute path.

## Touch only these paths
- `v3/crates/alexia-core/src/permissions.rs` (change)
- `v3/crates/alexia-core/tests/permissions.rs` (change)

## Must not touch
Every other file. No public signature changes (INTERFACES §2.3 `permissions` already describes
the new behaviour).

## Interfaces
None new. The behaviour of `scope()`, `paths_in()` and the private `is_destructive()` changes as
described below.

## Steps
1. `scope()` (about permissions.rs:418): `get` must tell "absent" apart from "could not read". On
   any `kv_get` Err for `scope`, `mode` or `boundaries`, return a closed Scope: mode
   `PermissionMode::AskEveryTime`, no roots, `everywhere: false`, and one synthetic boundary with
   `Blocks::Everything`. Give it a fixed `said` sentence, for example "Alexia could not read your
   permissions, so it asks before everything.". Log one `tracing::warn!` that names the key and
   never a value. Absent keys keep today's defaults.
2. `is_destructive()` (about line 104): a call is destructive when `!reviewed`, or when it is not
   `read_only` and `annotations.and_then(|a| a.destructive_hint) != Some(false)`. MCP's default for
   `destructiveHint` is true, and v2's own comment says "and so does not knowing", but v2's code
   read a missing hint as safe. Add a comment that names this deliberate divergence and its reason.
3. `paths_in()` (about line 327): normalise each string before `looks_absolute`:
   - a `file://` URI is percent-decoded to its path (`file:///C:/x` → `C:\x` on Windows, `/x`
     elsewhere). A host other than empty or `localhost` is ignored.
   - a leading `~`, `~/` or `~\` becomes the private `home()`.
   - `$HOME`, `$VAR`, `${VAR}` and `%VAR%` at the start expand from the environment. An unset
     variable is left as written, so the string stays non-absolute.

   Reuse `env_path`/`home()`, which are already in this file.
4. Check every caller of `is_destructive`. In *Ask before anything risky* mode, an unannotated call
   that is not read-only now asks first. That is intended. Say so in the commit message.
