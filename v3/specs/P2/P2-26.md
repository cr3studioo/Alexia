# P2-26: Resume after restart; jobs that run for days

Model: opus
Depends on: P2-20
Feature IDs: SP-13, AC-08

## Goal
After this task a task that was running when the hub stopped (update, crash, Windows Update
reboot) carries on when the hub starts again, from its last finished step. The conversation is
the state (v2), so resuming is: answer any call that was in flight with "not run: Alexia restarted
before it finished", tell the owner, and re-enter the loop with the steps already counted.
Background jobs get the larger ceiling (`Limits.background_steps`), so a job that runs for days is
bounded by steps, not by restarts.

## Interfaces
```rust
/// For every `live_runs` row: fix dangling calls, say "Picking up where I stopped: <task>." to the
/// run's origin (`Event::Say`), and spawn `agent.run` with the same RunId and `steps` so far.
/// Rows older than 7 days, or whose session is gone, are ended with a note instead
/// (`Trace::resume(.., row.steps)` then `end` with that note). Returns how many resumed.
pub async fn resume_all(agent: Arc<Agent>, tracker: &TaskTracker, cancel: CancellationToken) -> usize;
/// The dangling-call fix on its own (v2 P1-24 / P1-31 rule).
pub fn answer_dangling(store: &Store, session: SessionId, why: &str) -> Result<u32>;
```

## Steps
1. `Task` from the row: `messages` = session history; `run = Some(id)`; `steps_done =
   Some(row.steps)`; `max_steps = None` (the loop's ceiling bounds the total, steps done
   included); `background` and `parent` from the row; origin parsed from JSON. `Agent::run` then
   uses `Trace::resume`, which keeps the surviving `live_runs` row (phase review 4 finding 1:
   `live_begin` is a plain INSERT, so the old row must not be inserted again).
2. An approval that was waiting when the hub stopped is asked again (the step it guarded never ran).
3. The draft goes nowhere visible for a resumed run (`DraftSink` drained); the reply is delivered
   with `Event::Say` to the origin, like a scheduled job's.
