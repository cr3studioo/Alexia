## Goal
After this task `alexia-hub run` is the only Alexia core on the PC. It builds everything in the
exact order of INTERFACES §2.6, steps 1 to 11 (phase review 4 finding 7):
1. store → bus
2. host with `NoUpcalls`, not started yet
3. providers, catalog, router (with each signed-in subscription CLI registered, see step 2a
   below) → `ChannelSet` → `Asker` → `Checker`
4. `McpTooling` with no builtins (`vec![]`)
5. `Agent` (with `host` in `AgentParts`)
6. `add_builtin` for `Helpers` and `UndoTool`, then `Scheduler::new(.., agent)` and
   `add_builtin(scheduler.tools())` (a `Weak<Scheduler>`, P2-60)
7. `host.set_upcalls(agent)`, then `host.start`
8. `Skills` from `layout.skills()` plus `host.manifests()` → `add_builtin`
9. `Runtime` → `LocalJobs` → `agent.set_local_jobs`
10. `Lanes(FastChat, Agent)` → `Gateway::with_channels`
11. `scheduler.run` → `resume_all` → `gpu::Watch` sending `GpuEvent`s to a receiver loop that
    pauses local jobs, `stop_all`s the runtime and `McpHost::hold`s the GPU plugins (P2-62) →
    catalog news as one `Say`

`bridge.rs` is deleted, together with every `ALEXIA_V2_*` read, `NoTaskBrain`, and P2-06's

`allow(dead_code)` and `V2Bridge::ready`) and finding 8 (the bridge's unredacted log lines). The

## Steps
1. Wire `run` as §2.6 says, one statement per arrow, in that order. Each long-running piece is a
   tracker task under the root token (the existing pattern). Do not reorder steps 2, 5 to 8:
   - `Helpers::new`, `UndoTool::new` and `Scheduler::new` need `Arc<Agent>` (review 5 #2:
     the scheduler cannot be built before the agent, so its builtins are added in step 6).
   - `Agent` needs `Arc<dyn Tooling>`.
   - `host.start` must come after `set_upcalls`, so that residents get the agent's offers.
   - `Skills` needs `host.manifests()`, which is only filled after `start`.
   2a. (Phase review 6 finding 10.) In §2.6 step 3, for each `SubscriptionCli::find(cli)` whose
   `check()` passes, `router.set_provider(Arc::new(cli), false)` (not local). Without this no
   `subscription:<cli>` pin (MO-05, P2-48's `models use`) can ever be used. A CLI that is missing
   or signed out is skipped with one `tracing::info!`, never an error. `check()` runs the CLI;
   use it as P2-35 wrote it (it has its own timeout) and add nothing around it.
2. Delete `bridge.rs`, its `mod`, `V2Config::from_env`, `NoTaskBrain` and the bridge's `set_ask`.
   Remove the dependencies from `Cargo.toml` that are no longer used.
3. `invariants.mjs` check 11: fail on `V2Bridge`, `ALEXIA_V2_ROOT`, `ALEXIA_V2_URL`,
   `ALEXIA_V2_TOKEN` or `/api/chat` anywhere in `v3/crates/*/src`.
