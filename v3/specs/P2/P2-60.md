# P2-60: Scheduler tools hold a Weak<Scheduler>; no wiring cycle

Model: opus
Depends on: P2-56
Feature IDs: AC-09; phase review 5 finding 2

## Goal
`Scheduler::new` takes the brain (the Agent), and `Scheduler::tools()` needs that
`Arc<Scheduler>`. INTERFACES §2.6 step 4 used to put the scheduler's builtins into
`McpTooling::new` before the Agent exists: a cycle, so P2-38 could not follow the order. Forcing
it with `Arc`s would also leave a strong cycle, Agent → tooling → ScheduleTools → Scheduler →
Agent, and nothing would ever drop. The review-5 planner has already rewritten §2.6: step 4 is
`McpTooling::new(host, vec![])`, and step 6 builds `Scheduler::new(.., agent)` and then calls
`tooling.add_builtin(scheduler.tools())`. After this task `ScheduleTools` holds a
`Weak<Scheduler>`, as Helpers and UndoTool hold `Weak<Agent>`, so P2-38 can wire it that way.

## Steps
1. `struct ScheduleTools(Weak<Scheduler>)`; `tools()` passes `Arc::downgrade(self)`.
2. Each `ScheduleTools` method upgrades first. If the scheduler is gone, the call returns a tool
   error with the text `Scheduled jobs are not running.` (a `ToolOutcome` the model reads), never a
   panic. `specs()` needs no scheduler and still lists the three tools.
3. Keep `answer_origin` and the undo `schedule.cancel {id}` as they are.
4. Update the comment on `Scheduler::new`: the brain is the Agent (§2.6 step 6), and the only way
   back from the Agent to the scheduler is this `Weak`.

## Tests

- `brain_holding_tools_is_no_cycle` (a fake brain that holds the `Arc<dyn Builtin>` from
