# P2-73: Agent: slash commands only from the owner's chat; attached files are read; scheduled runs are background

Model: opus
Depends on: P2-21, P2-25, P2-68
Feature IDs: TR-01, AC-09, AC-10; phase review 6 findings 1 (high), 2 (high) and 11

## Goal
Three gaps in `Agent::reply` (`alexia-core/src/agent.rs:974-1010`):
- **Commands from anyone (high).** Any turn whose text starts with `/` goes to
  `commands::run`, whatever its origin. A scheduled job fires its prompt through
  `Brain::reply` with `Origin::Scheduler`, and P2-21 runs "a slash command typed into a plugin's
  conversation" as a command. A model-made job `{prompt: "/approve 7"}` (prompt injection) or a
  plugin's sampling text can then answer a pending approval, undo a call, or run a plugin command,
  which P2-25 runs as a direct tool call with no gate.
- **Files dropped (high).** `reply` stores only `turn.content` and never reads `turn.files`.
  The gateway hands documents and photos to the brain (`alexia-gateway/src/gateway.rs:836`,
  "which reads them during `reply`") and deletes them after the turn. Today only `bridge.rs`
  reads them (`uploads`, `bridge.rs:552`), and P2-38 deletes the bridge. After P2-38 every photo
  and document would be silently ignored.
- **Scheduled runs in the foreground (low).** `reply` hard-codes `background: false`, so a
  scheduled job gets the 24-step foreground ceiling instead of `Limits.background_steps`.

After this task only a turn from a channel (the owner's chat) can run a command, every attached
file reaches the model or is named as unreadable, and scheduled runs are background runs.

## Steps
1. `Agent::reply`: take `Lane::Command` only when `turn.origin` is `Origin::Channel { .. }`.
   From any other origin a `/…` text is an ordinary task turn (the model reads it as text).
2. `commands::run` (the one function every caller routes through, P2-21's included): when
   `turn.origin` is not `Origin::Channel`, refuse `/approve`, `/deny`, `/undo` and every plugin
   command with a one-line reply ("Commands are only taken from your own chat.") and run
   nothing. Read-only built-ins that change nothing (`/help`, `/commands`) may still answer.
   Check how P2-21's `upcalls.rs` reaches commands: if it calls `commands::run`, the guard
   covers it; if it has its own path, leave a note for the coordinator instead of editing it.
3. Files: a private `async fn attach(turn: &Turn) -> Content` used by `reply` before the user
   turn is stored:
   - `image/*` up to 20 MB (the bridge's `MAX_DOCUMENT`): read and appended as
     `Part::Image { url: "data:<mime>;base64,<…>" }` beside the turn's text.
   - text-like (`text/*`, `application/json`, `application/xml`, `.md`, `.csv`) up to 200 KB of
     valid UTF-8: appended as a text part `"<name>:\n<contents>"`.
   - anything else, too big, or unreadable: a text part `"(The owner attached <name>, <mime>,
     which Alexia cannot read yet.)"` and a `tracing::warn!` without the contents.
   Reading uses `tokio::fs` (no blocking read on a worker). The stored user message holds the
   result, so a resumed run (P2-26) sees the same content after the gateway deleted the files.
4. `background: matches!(turn.origin, Origin::Scheduler { .. })`.

## Tests
- `scheduled_slash_text_is_not_a_command` (a turn `"/approve 1"` with `Origin::Scheduler` and a
  pending approval: the approval stays pending, the model was asked)
- `channel_slash_text_is_a_command` (the same text from `Origin::Channel` reaches
  `commands::run`; P2-25's tests keep passing)
- `commands.rs`: `owner_commands_refused_from_desktop` (`commands::run` with `Origin::Desktop`
  and `/approve 1`: refusal text, approval still pending)
- `photo_reaches_the_model_as_an_image` (a temp PNG in `turn.files`; the scripted provider's
  request has an image part with its data URL)
- `text_file_inlined_and_binary_named` (a `.txt` file's text is in the request; a `.bin` file is
  named as unreadable)
- `scheduled_turn_runs_in_background` (`Origin::Scheduler`: the run is background and its
  ceiling is `Limits.background_steps`)

Each new test must fail without its fix. Temp files go through `tests/scratch` if P2-67 has
landed, otherwise into a folder the test removes.
