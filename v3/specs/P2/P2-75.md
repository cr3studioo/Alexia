# P2-75: Agent loop edges: a stop mid-gate is recorded, the asked model is kept, a failed answer is not lost, helpers cannot start helpers

Model: opus
Depends on: P2-73, P2-27
Feature IDs: TR-08, AC-07; review follow-ups from P2-20; phase review 6 finding 5

## Goal
Four edges in the loop in `alexia-core/src/agent.rs`:
- **Stop in the gate pass** (`agent.rs:577-596`). When the cancel fires between two calls of the
  gate pass, `unanswered` gives every call a tool turn, but the calls already gated (pushed to
  `self.steps`, some of them asked and answered by the owner) keep `outcome: None` and get no
  audit row. TR-08 wants one audit row per call the model made.
- **Asked equals answered** (`agent.rs:546`). `self.trace.model(&done.model, &done.model, ..)`
  writes the answering model twice, so the trace never shows that a step fell back from the
  model it asked first.
- **An error after text** (`agent.rs:534`). A router `Err` that is not a cancel, after `Delta`s
  were already drafted, returns `Refused` with no `DraftFrame::Restart` and stores nothing of
  what was written. The owner sees half an answer, then a refusal on top of it.
- **Helpers start helpers** (finding 5, `agent.rs:436`). `go()` always offers
  `p.tools.list()`. P2-27 step 3 wants a helper's tool list without `helpers.run`, and P2-27 may
  not touch `agent.rs`.

After this task every model call has an outcome and an audit row, the trace says which model was
asked and which answered, a failed answer is cleared before the refusal, and a child run never
sees `helpers.run`.

## Steps
1. Stop in the gate pass: before `unanswered`, give each already-gated step its outcome (its
   refusal if the gate refused it, otherwise the `STOPPED` text, not ok) and write its audit row
   the way the run pass does, with the gate's fields and decision `"stopped"` for the ones that
   were allowed. Then `unanswered` covers only the calls never gated. No call gets two tool turns.
2. Asked model: keep the first ranked candidate (already read for the trim window) and pass its
   model as `asked`; `answered` stays `done.model`.
3. Error after text: in the `Err(e)` arm, when `heard.text` is not empty, send
   `DraftFrame::Restart` and store the partial text as an assistant row with `stopped: Some(true)`
   (as the cancel arm does), then return the refusal.
4. Helpers: in `go()`, when `self.task.parent.is_some()`, drop the tool named `helpers.run` from
   `available` before it is offered. A one-line comment says why (AC-07: one level of helpers).

## Tests
- `stop_mid_gate_records_every_call` (two calls, the first asks and is approved, the cancel fires
  while the second is gated: both steps have an outcome, the audit has two rows, the history has
  one tool turn per call)
- `trace_keeps_asked_model` (the first candidate fails, the second answers: the trace row has
  `asked` = first, `answered` = second)
- `error_after_text_restarts_draft` (a provider that sends text then errors: the draft got
  `Restart`, the history has the partial text marked stopped, the reply is a refusal)
- `child_run_has_no_helpers_run` (a builtin named `helpers.run` in the tooling; a task with
  `parent: Some(..)`: the provider's request lists no `helpers.run`; without a parent it does)

Each new test must fail without its fix.
