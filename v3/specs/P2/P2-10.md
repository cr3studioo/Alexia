# P2-10: Secrets: no echo, read errors kept, in-memory only for tests

Model: opus
Depends on: none
Feature IDs: TR-03; phase review 3 findings 7, 9 and 10

## Goal
After this task three ways a secret could leak or be lost are closed:
1. `alexia-hub secret set <pasted token>` no longer prints what was typed where the key goes.
2. `secrets::import_v2` never overwrites a v3 secret it failed to read.
3. `ALEXIA_SECRETS_IN_MEMORY` cannot silently turn the real hub's `secret set` into a no-op.

## Touch only these paths
- `v3/crates/alexia-store/src/secrets.rs`, `tests/{secrets.rs, v2_secrets.rs}`
- `v3/crates/alexia-hub/src/main.rs` (`known_key`, `secret_set`, `run` start-up line only)
- `v3/crates/alexia-hub/tests/cli_p1.rs`

## Must not touch
Anything else in `main.rs`; other crates.

## Interfaces
```rust
pub mod secrets {
    pub const MEMORY_BACKEND_ENV: &str = "ALEXIA_SECRETS_IN_MEMORY";
    /// True while the in-memory backend is on (tests only).
    pub fn in_memory() -> bool;
}
```

## Steps
1. `known_key`: "That is not a known key. Known keys: …" without quoting the input.
2. `import_v2`'s `stored()`: a keychain read `Err` goes to `failed` (name only) and `set` is never
   called for it, with or without `--overwrite`.
3. In-memory backend: keep it (the e2e tests run the real binary with it), but `secret set` and
   `secret clear` refuse while it is on ("Secrets are in memory for tests, so nothing would be
   saved. Unset ALEXIA_SECRETS_IN_MEMORY."), exit 1; `run` prints one stderr line saying secrets
   are in memory. Values set through `ALEXIA_SECRET_*` keep working.

## Tests
- cli: `secret_set_unknown_key_does_not_echo` (stdin and argv both checked for the input text in
  stdout/stderr); `secret_set_refuses_in_memory`.
- store: `import_read_error_is_failed_not_overwritten` (a backend fake whose `get` errors).
