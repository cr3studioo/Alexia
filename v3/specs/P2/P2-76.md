# P2-76: One permission gate: undo and plugin commands go through the agent's gate

Model: opus
Depends on: P2-75, P2-77, P2-25, P2-28
Feature IDs: TR-01, TR-02, TR-08, AC-11; phase review 6 finding 4

## Goal
The gate (`permissions::rule` → the checker in *Watch and warn me* → `Ask` → the audit fields) is
the private method `Run::gate` (`alexia-core/src/agent.rs:718`). Two other paths call tools
without it:
- P2-28's undo sends the inverse call "through the same permission gate", and its spec lists
  `rule` and `Ask` but leaves out the checker.
- P2-25's plugin commands call tools directly.

Each has, or will grow, its own partial copy, and copies drift. After this task there is one
gate, and undo and plugin commands call it.

## Touch only these paths
- `v3/crates/alexia-core/src/agent.rs` (change: lift the gate)
- `v3/crates/alexia-core/tests/agent.rs` (change only if a gate test moves)
- `v3/crates/alexia-core/src/undo.rs` (change: call the gate, delete its own copy)
- `v3/crates/alexia-core/tests/undo.rs` (change: add one test)
- `v3/crates/alexia-core/src/commands.rs` (change: plugin commands call the gate)
- `v3/crates/alexia-core/tests/commands.rs` (change: add one test)

## Must not touch
Every other file, including `src/permissions.rs`, `src/checker.rs` and
`v3/specs/INTERFACES.md` (the function is `pub(crate)`, not public API).

## Interfaces
```rust
// agent.rs, crate-private
pub(crate) struct GateAsk<'a> {
    pub step: &'a Step,
    pub spec: Option<&'a ToolSpec>,
    pub run: &'a RunId,
    pub session: SessionId,
    pub said: &'a [String],   // what the owner said this run, for the checker
}
/// The one gate: rule → checker (Watch and warn me) → Ask. Returns the existing `Gate`
/// (refused outcome, gate, decision, why, plugin) for the caller's audit row.
pub(crate) async fn gate(agent: &Agent, ask: GateAsk<'_>, cancel: &CancellationToken) -> Gate;
```
`Gate` becomes `pub(crate)` with its fields. `Run::gate` becomes a thin call to it, sending the
run's phase as today.

## Steps
1. Move the body of `Run::gate` into `gate(..)`. What it read from `self` (`said`, `run`,
   `task.session`, the tallies on `Agent`) comes through `GateAsk` and `agent`. Keep
   `self.phase(Phase::Asking)` in `Run`, sent when the returned decision came from an ask
   (or pass a callback; pick the smaller diff).
2. `undo.rs`: replace its own `rule` + `Ask` sequence with `gate(..)`, so the checker applies in
   *Watch and warn me*. The audit row it writes uses the returned `Gate` fields.
3. `commands.rs`: a plugin command's tool call goes through `gate(..)` first; a refusal is the
   command's reply.

## Tests
- `undo.rs`: `undo_asks_checker_in_watch_mode` (mode Watch and warn me, a checker fake that
  blocks: the inverse call does not run, the audit row says `checker`)
- `commands.rs`: `plugin_command_is_gated` (a plugin command whose tool is unreviewed or destructive
  in Ask mode: the owner is asked; on Deny the tool is not called)
- The existing `agent.rs` gate tests pass unchanged.

Each new test must fail without its fix.
