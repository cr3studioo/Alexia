# P2-70: Gateway: a question that could not be sent is not a denial; Desktop runs ask the primary chat; test folders cleaned up

Model: opus
Depends on: P2-58, P2-64
Feature IDs: AC-10, TR-01; review follow-ups from P2-29 (and disk); phase review 6 finding 3

## Goal
- In `Asker::confirm` (`alexia-gateway/src/ask.rs:163`) an error from `ch.ask` (the question
  could not be sent: network, Bot API refusal) is settled as `settle(id, false, ch.name())`.
  The `approvals` row then says the owner denied it in that channel, which they never did, and
  the "— Denied from …" logic treats it as an answer. The outcome must stay "no" (fail closed);
  the record must say what happened.
- Two `ponytail:` comments in `confirm` (the timeout note and the end of the function) say an
  answer by a chat's own buttons gets no "Approved here" edit because `Channel::ask` returns no
  `MsgRef`. Telegram already edits the question itself on a button press
  (`channels/telegram/mod.rs:574`, "<question> — approved"). The comments are wrong.
- `Asker::target` (`ask.rs:72`) returns `None` for `Origin::Desktop`, so `confirm` is false and
  every gated call in such a run is auto-denied. P2-21 runs plugin `alexia/tools` tasks with
  `Origin::Desktop` and expects the question in the owner's primary chat; Desktop-origin scheduled
  jobs fall back to it too (P2-64). (Added by the phase review 6 planner.)
- Gateway tests leave folders in `%TEMP%`: `tests/gateway.rs:861` (`alexia-steer-file-*`, never
  removed) and `tests/telegram_channel.rs:232`.

After this task a question that never reached the owner is recorded as unsent and answered no,
with no "Denied from" note, a Desktop run's question goes to the primary chat, the comments say
what the code does, and gateway tests leave nothing in `%TEMP%`.

## Steps
1. `confirm`, the `Err(e)` arm of `buttons`: `tracing::warn!` as today, then
   `self.settle(id, false, "unsent")`, and return `false` without a note (the channel just failed
   to send; a note would fail too). If someone answered first (`settle` returns their answer),
   that answer stands, as for every other path.
2. The end-of-function note ("— Approved/Denied from {via}") skips `"unsent"` as it does the
   channel's own name.
3. Rewrite both `ponytail:` comments: a button press is shown by the channel itself (Telegram
   edits the question); `Asker` adds a follow-up only for an answer from elsewhere or a timeout.
   Keep the `ponytail:` marker on the timeout one: the timeout note still follows the question
   instead of editing it, because `Channel::ask` returns no `MsgRef`.
4. `target()`: `Origin::Desktop` uses the same primary-chat lookup as the `Scheduler` fallback
   (share the code; do not copy it).
5. `tests/scratch/mod.rs`: the same `Scratch` as P2-65 step 1 (folder
   `temp_dir()/alexia-test/gateway-<tag>-<pid>-<n>`). Use it for the two temp folders above.
