# P2-64: After the wiring: one Job Object, scheduled approvals in their own chat, a stricter plugin-name check

Model: sonnet
Depends on: P2-38, P2-63

## Goal
Three low findings in files that P2-34, P2-29 and P2-38 own until they are merged:
- `alexia-core/src/local.rs:483-610` is a second hand-written Job Object FFI, with its own
  kernel32 struct layouts and `#[allow(unsafe_code)]` in core. INTERFACES §1.2 says only
  alexia-mcp's job code opts out, and `alexia_mcp::job::Job` already does this (today it is
  reachable only as `alexia_mcp::testing::Job`).
- A scheduled turn carries `Origin::Scheduler { job }`, so the Asker sends its approval questions
  to the first channel's primary chat (`alexia-gateway/src/ask.rs:61`), not to the chat that
  created the job. The job row stores that origin (`alexia-scheduler/src/lib.rs:278`).
- `v3/ci/invariants.mjs:58` matches a plugin id only as a whole quoted literal. An id inside a
  string passes, such as the planned `"subscription:claude-code"` (P2-35) beside
  `plugins/claude-code`, and so does an id in a `format!` piece. The check is weaker than §0.1.

After this task core has no unsafe code, a scheduled job's question goes to its own chat (the
primary chat only as the fallback), and check 1 also catches ids inside string literals.

## Steps
1. `alexia-mcp/src/lib.rs`: `pub use job::Job;`. Keep the `testing` re-export (tests use it).
2. `local.rs`: delete `mod job` with its `#[allow(unsafe_code)]`, kernel32 declarations and
   struct layouts; use `alexia_mcp::Job`. `alexia_mcp::Job::assign` takes a pid
   (`child.id()`); a child with no pid (already exited) is not assigned, as the old code did by
   failing. The non-Windows no-op stays the one in `job.rs`.
3. `ask.rs` `target()`: for `Origin::Scheduler { job }`, read the job row (`store.jobs()`, which
   still lists a one-shot while its turn runs) and use its stored origin: a `Channel` origin asks
   in that channel and chat, if that channel is in the set. Only when the row is missing, its
   origin is `Desktop` or `Scheduler`, or its channel is not configured, fall back to the first
   channel's primary chat, as today. A store error is logged and falls back.
4. `invariants.mjs` check 1: besides the whole quoted literal, flag an id inside a string
   literal (`"…"`, `'…'`, `` `…` ``, `r"…"`, `r#"…"#`) when it is bounded by a non-`[a-z0-9-]`
   character on both sides **and** either contains a `-` or sits right after `:`, `/`, `\` or
   `__` (namespaced tool names such as `memory__recall`). A plain one-word id inside prose
   (`"saved to memory"`) is not flagged: ids like `memory`, `voice` and `media` are ordinary
   words. A line ending in `// invariant: plugin id …` is allowed. The existing
   `v2 import` and `bot api term` exceptions stay.
5. Run the check; mark each real exception it now finds with the comment from step 4, and fix any
   line that is a real violation by asking for the capability instead. List both in the PR note.
