# P2-65: Store: test folders cleaned up, a keychain probe per process, a plain leftover kept until its key proves right

Model: opus
Depends on: P2-54
Feature IDs: TR-03, TR-09; review follow-ups (disk; P2-52; P2-54)

## Goal
Three edges in `alexia-store`:
- Its tests leave `alexia-*` folders in `%TEMP%` on every run. Each helper (`tests/channels.rs:10`,
  `tests/import.rs:15`, `tests/store.rs:10`, `tests/p2.rs:11`, `tests/encrypt.rs:21`) removes
  the folder before a test and never after. Across all crates that is thousands of folders and
  tens of GB on the PC.
- `windows_credential_manager_round_trip` (`src/secrets.rs:366`) uses the fixed account
  `_v3test.probe`. Two worktrees testing at once write, read and delete the same Credential
  Manager entry, so one sees the other's value and fails.
- P2-54 shreds `alexia.db.plain` on `Store::open` only after the encrypted file opened with the
  right key: while the key is missing the leftover may be the owner's only readable copy. That is
  right. `encrypt`'s "already encrypted" refusal (`src/encrypt.rs`, the `is_encrypted` branch)
  shreds the leftover without that check, so an `alexia-hub encrypt` run while the key is lost
  destroys the only readable copy.

After this task store tests leave nothing in `%TEMP%`, the probe cannot race another worktree,
and no path shreds a plain leftover before the key has opened the encrypted database.

## Steps
1. `tests/scratch/mod.rs`: `pub struct Scratch(PathBuf)`, the pattern already in
   `alexia-mcp/tests/manifest.rs:298` (`Scratch`), with three changes:
   - every folder is under one parent, `std::env::temp_dir()/alexia-test/`, named
     `store-<tag>-<pid>-<n>` (`n` from a static `AtomicU64`), so a run that was killed leaves
     one place to look;
   - `Drop` calls `remove_dir_all`; on Windows, if that fails, it retries up to 5 times 100 ms
     apart (an SQLite handle can close a moment late), then gives up silently;
   - `impl Deref<Target = Path>`, so callers can keep `dir.join(..)`.
   Keep it that small: each test file that uses it says `mod scratch;`, and anything unused
   would be a `dead_code` error under `-D warnings`.
2. Each helper listed in *Goal* returns a `Scratch` instead of a `PathBuf`. In each test, bind the
   `Scratch` before any `Store` that lives in it, so it is dropped last. `tests/encrypt.rs`'s
   `setup` returns `(MutexGuard, Scratch)`.
3. `src/secrets.rs` test: the account is `format!("_v3test.probe.{}", std::process::id())`.
4. `src/encrypt.rs`, the "already encrypted" branch of `encrypt`: shred the leftover only when
   `Store::open(path)` succeeds (which is the key proving right; `open` shreds it itself then).
   On any `open` error keep the leftover and `tracing::warn!` once that it was kept because the
   key is missing or wrong, naming the file, never its content. Then refuse as today.
