# P2-14: Redaction before cloud

Model: opus
Depends on: P2-01
Feature IDs: TR-04, TR-03

## Goal
After this task core has v2's redaction: keys, tokens and passwords are replaced by
`[redacted]` in text, and a whole `ChatRequest` can be redacted before it leaves the machine.
The router applies it to every cloud request (P2-17); the trace and audit apply it before they
write (P2-19); the checker before it asks (P2-13).

## Touch only these paths
- `v3/crates/alexia-core/src/redact.rs`
- `v3/crates/alexia-core/tests/redact.rs` (create)

## Must not touch
Everything else.

## Interfaces
```rust
pub const PLACEHOLDER: &str = "[redacted]";
/// Secret-shaped strings only (keys, tokens, private keys, URLs with credentials).
pub fn redact_secrets(text: &str) -> (String, Vec<String>);
/// Secrets plus v2's personal patterns (card numbers, IBANs, one-time codes …), as v2 `redactText`.
pub fn redact_text(text: &str) -> (String, Vec<String>);
/// Every text part of every message and the system prompt; images untouched. `kinds` deduped.
pub fn redact_request(req: &ChatRequest) -> (ChatRequest, Vec<String>);
pub fn redact_json(v: &Value) -> Value;      // every string leaf through redact_text
pub fn summarise(kinds: &[String]) -> String;
```

## Steps
1. Port `packages/core/src/redact.ts` pattern for pattern (cite each), using `regex` compiled once
   (`std::sync::LazyLock`).
2. Also redact any value currently in the keychain for a known key (`secrets::get` for
   `_core` keys the hub lists): pass them in as `extra: &[String]` on a second function
   `redact_known(text, extra)`; never log them.
3. Tool-call arguments in `MessageBody.calls` are JSON text: redact their string leaves.

## Tests
Port `packages/core/test/redact.test.ts`; plus `request_redacts_system_and_calls`,
`images_untouched`, `known_secret_redacted`, `no_false_positive_on_plain_sentence`.
