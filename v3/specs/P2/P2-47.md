# P2-47: MCP: plugin requests keep their cancel and progress; tools unreviewed until read

Model: opus
Depends on: P2-45
Feature IDs: SP-01 (compute progress as in v2), TR-01 (reviewed); phase review 4 findings 6 and 8

## Goal
After this task, a request a plugin sends to the host keeps the plugin's cancel token and
progress sink:
- `alexia/compute/run` and `alexia/capability/call` pass both to the provider. A cancelled
  compute job stops at once, and v2's compute progress frames reach the caller, as v2's `host.ts`
  does with `signal`/`onProgress`.
- `sampling/createMessage` passes both to `Upcalls::sample`.

Also, a `HostedTool` is unreviewed unless the `_core.unreviewed` list was read and does not
name its plugin.

## Steps
1. `conn.rs` `on_line` (about line 257): pass the token already stored in `incoming` into
   `request(..)`, instead of only racing the request against it. If the request's params carry
   `_meta.progressToken`, make a `ProgressSink` whose frames go back to the plugin as
   `notifications/progress` with that token. Use a small forwarding task that ends when the
   sender is dropped. Keep the existing select, so a cancelled request still gets no answer.
2. `host.rs` `Handler::request` (about line 1284): pass both on. `sampling/createMessage` calls
   `up.sample(&self.id, p, progress, cancel)` instead of today's `None, CancellationToken::new()`.
3. `serve.rs`: `serve` takes a `CallCtx { cancel, progress, .. }`. Use it at about line 165
   (`call_capability_as`) and about line 287 (`compute_call`) instead of `CallCtx::default()`.
   The conversation and meta fields stay default, as today.
4. `host.rs` `hosted()` (about line 1253): set `reviewed: false`. Only the successful read of
   `_core.unreviewed` in `tools()` (about line 333) sets it to true, for ids not on the list. Any
   other path that returns cached tools (`plugin_tools`, reload) then reports unreviewed unless
   that read ran. Check every caller of `hosted()`.
5. `serve.rs` has `inside()`/`file_uri_path()` and `alexia_core::permissions` has
   `{within, file_uri}`. These are two implementations with different rules (review 4 #10). Keep
   both: core depends on mcp, not the other way round, and compute checks containment in a
   plugin's own folder, not in the owner's scope. Add one comment above `inside()` that says so.

## Tests
- `plugin_cancel_reaches_incoming` (tests/conn.rs): the plugin sends `notifications/cancelled`
  and the fake `Incoming` sees its token fire.
- `plugin_progress_token_gets_frames`: frames sent into the sink reach the plugin as
  `notifications/progress` with its token.
- `cancelled_compute_stops_provider` (tests/compute.rs): the caller cancels a slow compute job,
  and the provider gets `notifications/cancelled` well before `capability_ms`.
- `compute_progress_reaches_caller`
- `hosted_tool_unreviewed_until_list_read`

The existing tests' `Incoming` fakes gain the two new parameters. Each new test must fail without
its fix.
