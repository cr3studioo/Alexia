# P2-51: Core safety edges: odd file URIs, skill symlinks, secret-named JSON keys

Model: opus
Depends on: none
Feature IDs: TR-01, TR-04, TR-12; review follow-ups from P2-46, P2-16, P2-14 and P2-11

## Goal
Reviewers found three places in `alexia-core` where a safety check can be walked around, and
two places where INTERFACES.md no longer says what the code does. After this task:
- a path written as `FILE:///…`, `File://…` or `file:/C:/…` meets never-touch and scope the same
  way `file:///…` does, and a string the normaliser cannot read is never silently dropped;
- `skill.read` refuses a file whose real path it cannot work out, instead of reading it anyway;
- a JSON object key that names a secret (`password`, `api_key`, `token`, …) has its value
  redacted in `redact_json` and `redact_request`, as v2's raw-text rule did;
- INTERFACES.md matches the code for check 1's `// invariant: bot api term` exception and for
  what `redact_text` covers.

## Steps
1. `permissions.rs` `normalised()` (about line 331):
   - match the scheme case-insensitively (`file://`, `FILE://`, `File://`);
   - accept the one-slash form `file:/C:/x` and `file:/x` (RFC 8089 allows it) as a local path;
   - an unclosed `${` or `%` returns `None` today, so the string is skipped. Return the string
     as written instead: a non-absolute string stays non-absolute, an absolute one is still
     checked. `None` stays only for a `file://` URI on another host.
2. `prompt.rs` skill read (about line 210): the symlink check runs only when both
   `canonicalize` calls succeed, so a failure reads the file unchecked. On either `Err`, refuse
   with `outside()`. A missing file then says "outside", which is fine: it is not readable
   either. Read from `real`, the canonical path that was checked, not from `path`, so the file
   cannot be swapped between the check and the read.
3. `redact.rs` `walk()` (about line 232): an object key that matches the secret keyword list of
   the "env assignment" rule (`api[_-]?key|secret|token|password|passwd|bearer|credential`,
   case-insensitive, anywhere in the key) has a string value of 12 or more characters replaced
   whole by `PLACEHOLDER`, kind `"secret field"`. Shorter strings, numbers, booleans and null go
   through `walk` as today (v2's rule needed 12 characters too). Arrays and objects under such a
   key are walked, not replaced. Build the key regex from the same keyword list as the
   env-assignment row so the two cannot drift. Comment that this is the parsed-JSON reading of
   that row, as `LOCATION_KEY` is for "location field".
4. INTERFACES.md §2.3 `redact`: `redact_text`'s comment says "card numbers, IBANs, one-time
   codes". The code, and v2's `redactText`, have secrets and locations only, on purpose (see the
   `redact.rs` header). Rewrite the comment to say so. Add to `redact_json`'s comment that a
   secret-named key's value goes whole (step 3).
5. INTERFACES.md §7 check 1: add the second exception the script already has. A line under
   `crates/alexia-gateway/src/channels/telegram/` marked `// invariant: bot api term` may use a
   Bot API word that is also a plugin id (`voice`).

## Tests
- `upper_case_file_uri_meets_never_touch` (`FILE:///C:/Users/x/.ssh/id_rsa` on Windows,
  `FILE:///home/x/.ssh/id_rsa` elsewhere)
- `one_slash_file_uri_meets_never_touch`
- `unclosed_var_absolute_path_still_checked` (`C:\Users\x\.ssh\${oops` meets never-touch)
- `skill_read_refuses_when_canonicalize_fails` (a dangling symlink in the skill dir, or the
  skill dir removed after loading)
- `skill_read_reads_the_checked_path`
- `secret_named_key_redacted` (`{"password":"hunter2hunter2"}`, `{"OPENAI_API_KEY":"…"}`)
- `secret_named_key_short_value_kept` (`{"token": 5}`, `{"password":"x"}`)
- `secret_named_key_in_tool_arguments_redacted` (through `redact_request`)

Each test must fail without its fix.
