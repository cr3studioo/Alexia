# P2-17: Router for task steps: model per job, $0 cap, catalog news

Model: opus
Depends on: P2-04, P2-05, P2-14
Feature IDs: MO-11, MO-12, MO-14, TR-04, D212, D213

## Goal
After this task the agent can ask the router for one task step: `Router::step` picks candidates
for the step's `Job` (the owner's pins per job first, then the ranked free list filtered by what
the request needs), redacts the request before it leaves the machine, hedges like the chat lane,
and never asks a model that is not free. Local providers (llama.cpp, P2-31) are only ever used for
`Vision`, `Check` and `Local` jobs, never `Chat`, `Plan`, `Step` or `Code` (D213). The catalog
reports new free models once (MO-11).

## Touch only these paths
- `v3/crates/alexia-core/src/{router.rs, catalog.rs}`
- `v3/crates/alexia-core/tests/router_steps.rs` (create)

## Must not touch
`openai.rs`, `chat.rs`, `lane.rs`, other crates.

## Interfaces
```rust
pub struct StepAsk { pub job: Job, pub avoid: Vec<String> /* "provider\nmodel" */,
                     pub plugin: Option<String>, pub run: Option<RunId>, pub session: Option<SessionId> }
impl Router {
    /// One step. Pins: kv `_core`/`models` = {"plan": ["<provider>/<model>" | "subscription:<cli>" | "local:<id>"], ...}.
    /// Cloud requests go out redacted (`redact::redact_request`); local ones as they are.
    pub async fn step(&self, req: &ChatRequest, ask: &StepAsk, budget: Budget,
                      out: mpsc::Sender<ChatChunk>, cancel: CancellationToken) -> Result<ChatDone, ProviderError>;
    /// Providers added at run time (local runtime, subscriptions). Replaces one with the same id.
    pub fn set_provider(&self, p: Arc<dyn Provider>, local: bool);
    pub fn remove_provider(&self, id: &str);
    pub fn pins(&self) -> BTreeMap<String, Vec<String>>;
    pub fn set_pins(&self, job: Job, models: Vec<String>) -> Result<()>;
}
impl Catalog {
    /// Models seen for the first time by the last refresh, once; then empty until the next new ones.
    pub fn news(&self) -> Vec<Candidate>;
}
```

## Steps
1. Per-job ranking (port the free half of v2 `router.ts` `shapeOf`/`ranking`): `Plan` and `Code`
   prefer larger `size_b` first, `Step` prefers the fastest median, `Chat` is today's order.
   Pins go first in their order; a pin that cannot answer (no key, not free, needs not met) is
   skipped with one note, never silently replaced by a paid model.
2. MO-12, D212: a candidate is asked only when its catalog price is known to be zero, or it is a
   subscription CLI (P2-35) or local. A `ChatDone.cost > 0` from any provider records a
   `tries` row with outcome `"charged"`, sets that model aside for 30 days and publishes nothing
   itself (the agent turns it into a warning line). `record_usage` attributes `plugin`, `run_id`
   and `session` (v2's per-plugin attribution).
3. Redaction: every message to a non-local provider goes through `redact_request`; the kinds found
   are returned in a note the agent shows ("Removed 1 key before sending.").
4. D213: `local == true` providers are filtered out unless `job ∈ {Vision, Check, Local}`.
5. `Catalog::news` from `seen` (migration 1's table): `first_seen` within the last refresh.
