# P2-07: Steering into a running run

Model: opus
Depends on: P2-06
Feature IDs: CH-08 carried into the agent loop; phase review 3 finding 3

## Goal
After this task a message sent while a task is running is handed to the run, not used to cancel
it. The brain gets a `Steer` on the `Turn`; a brain that can take steering (the agent, P2-20)
says so with `DraftFrame::Steerable`, and from then on the gateway sends later messages from that
chat into the steer channel. Chat-lane turns keep today's cancel-and-restart. Stop still stops.

## Interfaces
```rust
/// Extra user messages for a run already going. Clone shares one receiver.
#[derive(Clone, Default)] pub struct Steer { /* Option<Arc<tokio::sync::Mutex<mpsc::Receiver<Content>>>> */ }
impl Steer {
    pub fn none() -> Steer;
    pub fn channel(capacity: usize) -> (mpsc::Sender<Content>, Steer);
    /// Everything waiting now, without waiting. Empty for `none()`.
    pub async fn take(&self) -> Vec<Content>;
}
pub struct Turn { /* existing */ pub steer: Steer }
pub enum DraftFrame { Delta(String), Restart, Phase(Phase), /** the brain reads `turn.steer` from now on */ Steerable }
```

## Steps
1. Add `Steer`, `Turn.steer`, `DraftFrame::Steerable`; update every Turn literal.
2. Gateway: each running turn keeps its steer sender and a `steerable` flag set when the draft
   stream yields `Steerable`. A new message in that chat while `steerable`: react 👀 at once (the
   ack rule is unchanged), send its content through the sender, and do not cancel. Not
   steerable: today's merge/cancel path.
3. When the reply returns, the gateway drains anything the brain did not take (`steer.take()`)
   and starts a new turn with it, so no message is lost to a race at the end of a run.
4. `Stop` cancels as today, steerable or not.

## Tests
