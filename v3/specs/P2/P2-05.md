# P2-05: Candidates know tools, vision and context; rank by what a request needs

Model: opus
Depends on: P2-01
Feature IDs: MO-11, MO-14 (groundwork), SP-01; phase review 3 findings 1 and 12 (router helper)

## Goal
After this task the router never sends tools to a model that cannot call them, never sends a
picture to a model that cannot see, and never sends a conversation longer than a model's window.
`Candidate` carries `tools`, `vision` and `context` from `ModelInfo`, and `rank` filters by what
the `ChatRequest` needs. Today `catalog.rs:21` drops them.

## Touch only these paths
- `v3/crates/alexia-core/src/{catalog.rs, router.rs}`
- `v3/crates/alexia-core/tests/{router.rs, catalog.rs}`

## Must not touch
`openai.rs` (P2-04), `chat.rs`, `lane.rs`, other crates.

## Interfaces
```rust
pub struct Candidate { /* existing fields */ pub tools: bool, pub vision: bool, pub context: u32 }
/// What a request asks of a model.
pub struct Needs { pub tools: bool, pub vision: bool, pub tokens: u32 }
impl Needs { pub fn of(req: &ChatRequest) -> Needs; }   // tools non-empty; any image part; size estimate (v2 trim.ts PER_TOKEN = 3 chars)
impl Router {
    pub fn ranked_for(&self, now: Ms, needs: &Needs) -> Vec<Candidate>;   // ranked() filtered
}
```
`hedged` uses `ranked_for(now, &Needs::of(req))`. An unknown capability counts as no for
`vision`, and as the provider row's default for `tools` (a row field read from v2's ladder where
it says so; else no). `context` 0 means unknown and passes only requests under 8 192 tokens.

## Steps
1. Carry the three fields through the catalog cache (old cache files without them load as unknown).
2. `Needs::of` and the filter; when the filter empties the list, the error sentence says which
   need could not be met ("No free model that can use tools can answer right now.").
3. Replace `router.rs`'s private `elapsed_ms` with `crate::ms_since` (review 12).
