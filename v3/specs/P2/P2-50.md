# P2-50: Tooling: no UNC paths from file URIs; call() applies list()'s limits

Model: sonnet
Depends on: P2-18
Feature IDs: none (review follow-up to P2-18)

## Goal
The P2-18 review found that `file_uri_path` in `alexia-core/src/tools.rs` still turns some
file URIs into Windows UNC paths (`file:////srv/share/x`, `file:///%5C%5Csrv/share`). Core then
stats them, which makes Windows contact that server over SMB and can leak the user's NTLM
credentials. It also found that `call()` skips two limits that `list()` applies. After this
task only local paths are ever stat'ed, and `call()` refuses what `list()` hides.

## Touch only these paths
- v3/crates/alexia-core/src/tools.rs   (change)
- v3/crates/alexia-core/tests/tools.rs (change)

## Must not touch
Anything else. No public signature changes.

## Interfaces
None new.

## Steps
1. In `file_uri_path` (about tools.rs:214), after percent-decoding, reject (treat as not
   written) any path that starts with two separators (`//`, `\`, `/\`, `\/`) or with `\?\UNC\`,
   and any path that is not absolute with a drive letter on Windows. Never call `metadata`/`stat`
   on a rejected path.
2. In `call()` (about tools.rs:83), apply the same name-length limit (`NAME_LIMIT`) and the same
   hidden-tool rule that `list()` applies (about tools.rs:131): a name `list()` would not offer
   gets the same unknown-tool sentence. An `alexia/undo` that points at a hidden tool is dropped
   from the outcome (no uncallable undo).

## Tests
- `unc_file_uris_are_not_written`: `file:////srv/share/x`, `file:///%5C%5Csrv/share/x`,
  `file:///\srv\share\x` all come back as not written, and no stat happens (assert by giving
  a server name that would hang or fail slowly; the test must finish in under 2 s).
- `call_refuses_a_name_list_hides`: an over-long name and a hidden tool both get the unknown-tool
  sentence.
- `undo_to_hidden_tool_is_dropped`.
Each must fail without its fix.
