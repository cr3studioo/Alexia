# P2-63: One redaction of secrets, in alexia-mcp

Model: opus
Depends on: P2-38, P2-61
Feature IDs: TR-04, TR-03; phase review 5 finding 8

## Goal
v2's `redactSecrets` has two Rust ports: `alexia-mcp/src/process.rs:195` (hand-written matchers,
`•••`, used for plugin stderr and by `chat.rs` for the memory capture) and
`alexia-core/src/redact.rs` (regexes, `[redacted]`, used before every cloud request). They will
drift, and a secret one catches may pass the other: the mcp one already has no "url credentials"
row. After this task the secret rows exist once, as regexes in `alexia-mcp`, with v2's
placeholder `[redacted]`. `core::redact::redact_secrets` calls them, and core keeps only what is
its own: the location rows, the secret-named JSON key rule (P2-51), JSON walking and requests.

## Steps
1. `alexia-mcp/src/redact.rs`: move core's secret rows (api key, github, aws, google, slack,
   telegram, private key, jwt, env assignment, url credentials), the `Keep` handling and the known
   values pass (longest first) here, as `redact_secrets`. `redact` is `redact_secrets(..).0`.
   The key regex P2-51 built from the env-assignment keyword list moves here too, as
   `pub fn is_secret_key(key: &str) -> bool`, built from the same const, so core's JSON key rule
   uses the same words.
2. `process.rs`: delete the hand-written `Rule` matchers, `apply`, `MASK` and helpers; its call
   sites use `crate::redact::redact`. The placeholder in plugin logs becomes `[redacted]`.
3. `alexia-core/src/redact.rs`: delete the secret rows; `redact_secrets(text)` is
   `alexia_mcp::redact_secrets(text, &[])`, `redact_known(text, extra)` passes `extra`. The
   location rows, `redact_text`, `redact_json`, `redact_request*` and `summarise` stay here.
   The kind strings stay exactly as they are (the agent shows them).
4. Before deleting the mcp matchers, run the mcp matchers' existing test inputs through the regex
   version; any input the old code caught and the regexes miss is a regex bug to fix here, with a
   test.
