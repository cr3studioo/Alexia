# P2-44: compute/run: checked path is the path used; copies don't collide or leak

Model: sonnet
Depends on: P2-22
Feature IDs: none (review follow-up to P2-22)

## Goal
Three small holes in `alexia/compute/run` found in the P2-22 review. After this task the file a
worker is given is exactly the file the own-dir/uploads check approved, two outputs with the same
name both survive, and a failed copy leaves nothing behind.

## Touch only these paths
- v3/crates/alexia-mcp/src/serve.rs      (change)
- v3/crates/alexia-mcp/tests/compute.rs  (change)

## Must not touch
host.rs, supervise.rs, any other crate. No public signature changes.

## Interfaces
None new.

## Steps
1. serve.rs about line 264: pass the worker the canonical path that `inside()` checked (about
   line 202), not the raw `i.path`. Keep the resolved path from the check and use only it, so a
   link swapped after the check can't send the worker outside the caller's own dir or uploads.
2. serve.rs about line 316: copies are keyed by file_name, so two resource_links with the same
   name overwrite each other. Give a clashing name a numeric suffix before the extension
   (`out.png`, `out-2.png`, ...), and return the real names.
3. serve.rs about line 318: if any copy fails, remove the `compute/<pid>-<ns>` folder this call
   created before returning the error.

## Tests
- `compute_uses_the_checked_path`: the worker receives the canonical path (assert on what the
  fixture saw), including when the input was given through a symlink or junction inside the
  caller's own dir.
- `same_name_outputs_both_kept`: two resource_links with the same file name give two files.
- `failed_copy_leaves_no_folder`: a resource_link to a missing file makes the call fail and no
  `compute/<pid>-*` folder remains.
Each must fail without its fix.
