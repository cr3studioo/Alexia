# P2-81: Say goes to its run's chat and carries the run's files

Model: sonnet
Depends on: P2-48, P2-70, P2-74, P2-80
Feature IDs: SP-13, AC-08, AC-09; phase review 6 finding 8

## Goal
`Event::Say` (`alexia-core/src/bus.rs:60`) has no origin and no files, and the gateway's `say()`
(`alexia-gateway/src/gateway.rs:273-307`) sends it to every channel's primary chat:
- Resume (P2-26) says "Picking up where I stopped" and delivers a resumed run's reply with
  `Say`. Both go to the primary chat, not to the chat the run came from.
- A scheduled job's answer (`alexia-scheduler/src/lib.rs:355`) goes to every primary chat, not
  the chat that created the job, and the reply's files (`reply.files`) are dropped.

After this task a `Say` with an origin goes only to that channel and chat (the primary chat is the
fallback for none, `Desktop`, or a channel that is not configured), and its files are sent with
it.

## Steps
1. `bus.rs`: add `to` and `files`; fix every literal (core, scheduler, gateway tests, hub).
2. `resume.rs`: `to: Some(origin)` for both the "Picking up" line and the resumed reply, with the
   reply's files.
3. Scheduler `fire`: `to` is the job's stored origin, `files` the reply's files.
4. Gateway `say()`: an `Origin::Channel { channel, chat }` whose channel is in the set → only that
   channel and chat; else the loop over primary chats as today. `Outbound.files` gets the files
   (the same conversion the reply path uses); a missing file is logged and skipped.

## Tests

- `scheduler.rs`: the fired job's `Say` has the job's origin in `to`
- `resume.rs`: the "Picking up" `Say` has the run's origin
