# P2-28: Undo

Model: opus
Depends on: P2-20
Feature IDs: AC-11

## Goal
After this task `/undo` (and a builtin `undo.last` tool the model may call when the owner says
"undo that") reverses the newest undoable thing Alexia did in this conversation: a plugin call
whose result carried `_meta["alexia/undo"]`, or a core builtin that records its own inverse
(scheduling a job). The inverse goes through the same permission gate as any call. Nothing that
did not declare an inverse claims to be undoable.

## Touch only these paths
- `v3/crates/alexia-core/src/undo.rs`
- `v3/crates/alexia-core/tests/undo.rs` (create)

## Must not touch
Everything else.

## Steps
1. `store.last_undoable(session)` → parse `UndoCall` → gate it (`permissions::rule`, `Ask` if it
   says ask) → `tools.call(undo.tool, undo.arguments)` → `mark_undone` on success; its own audit
   row with gate decision and `why = "undo of #<id>"`.
2. A failed inverse leaves the original row undoable and says why.
