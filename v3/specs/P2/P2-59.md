# P2-59: Chat lane redacted: Router::hedged redacts every cloud request

Model: opus
Depends on: P2-17
Feature IDs: TR-04, D212; phase review 5 finding 1

## Goal
The chat lane answers most turns, and today it sends history, recalled memory, the profile and
the new turn to free cloud providers unredacted (`chat.rs:249` calls `Router::hedged`, and
`hedged` sends `req` as it is, `router.rs:227`). v2's `router.ts` redacted every cloud call.
P2-17 redacts only inside `Router::step`, and compare (P2-36) will call the same unredacted race.
After this task redaction lives in the one place every cloud request passes: each non-local
candidate in `hedged`'s race gets `redact::redact_request(req)`, and a local one gets `req` as
it is. `step`, FastChat and compare are all covered without each remembering to redact.

## Steps
1. In `hedged`, build the redacted copy once per call (`redact_request(req)`), only if a
   non-local candidate is in the queue. The race holds both `Arc<ChatRequest>`s. Starting a
   candidate picks the redacted one unless its provider is local (P2-17's `set_provider(p, local)`
   flag). A hedge that starts a third or fourth candidate reuses the same copy.
2. `step` (P2-17) no longer redacts by itself; it relies on step 1, so nothing is redacted twice.
   Keep the note P2-17 shows ("Removed 1 key before sending."): have the race hand back the kinds
   it found (a private field or a private inner fn), and `step` builds the note from them as now.
3. `hedged`'s own result does not change. FastChat shows no note (v2's chat path showed none).
4. If the kinds are non-empty, one `tracing::debug!` with the kinds only, never the text.

## Tests
