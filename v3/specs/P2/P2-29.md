# P2-29: Approvals inbox

Model: opus
Depends on: P2-03, P2-06, P2-08
Feature IDs: AC-10

## Goal
After this task every approval question is a row in `approvals`, so the owner can see every
pending decision in one place (`/approvals` on any channel, `alexia-hub approvals`) and answer it
from anywhere: the buttons in the chat that asked, `/approve <id>` / `/deny <id>` from any chat,
whichever comes first. A question still gives up after 10 minutes (no answer = no).

## Touch only these paths
- `v3/crates/alexia-gateway/src/ask.rs`
- `v3/crates/alexia-gateway/tests/approvals.rs` (create)

## Must not touch
`gateway.rs`, `channels/`, core (`Event::Answered` is added by P2-01).

## Interfaces
`Asker` (P2-06) unchanged on the outside. Inside: `confirm` →
`store.approval_open` → ask with buttons in the origin's chat → `select!` on the button answer,
`Event::Answered { approval == id }` from the bus, the 10-minute timer, `cancel` → the first
answer wins through `store.approval_answer` (false means someone else answered first: use the
stored answer). The question text ends with "(#<id>)" so `/approve <id>` is typeable.

## Steps
1. The Asker already holds the `Bus` (P2-06).
2. On a button answer, also edit the message to say who answered ("Approved here" / "Approved from
   telegram"), as v2's `NO_ANSWER` edit does.
3. A scheduled or resumed run with no chat asks in the primary chat, as today.

## Tests
`row_per_question`, `button_answers`, `slash_approve_from_other_chat_answers`,
`first_answer_wins`, `timeout_is_no_and_recorded`, `cancel_leaves_row_unanswered`.
