# P2-24: WASM plugins in a capability sandbox

Model: opus
Depends on: P2-23
Feature IDs: SP-10, TR-06 (pulled in; owner confirms)

## Goal
After this task a plugin whose manifest says `"entry": {"run": "wasm", "args": ["plugin.wasm"]}`
runs inside the hub through wasmtime, with no process hop, speaking the same MCP JSON-RPC over
WASI stdin/stdout as a process plugin, so the host, the `alexia/*` layer and the agent treat it
like any other. It gets only what it declared: no network, no clock beyond WASI's, a filesystem
that is its own dir and nothing else (and only with `fs.own_dir` in `requires`), memory and fuel
limits. Crashes, hangs and deletion behave as invariant checks 3–5 say.

## Touch only these paths
- `v3/crates/alexia-mcp/src/{wasm.rs, host.rs}`
- `v3/crates/alexia-mcp/fixtures/wasm-hello/**` (create: a tiny Rust MCP server for wasm32-wasip1, not a workspace member)
- `v3/crates/alexia-mcp/tests/fixtures/wasm-hello.wasm` (create, built from the above)
- `v3/crates/alexia-mcp/tests/wasm.rs` (create)

## Must not touch
`serve.rs`, `conn.rs` (reuse it over in-memory pipes), other crates, `v3/Cargo.toml` members.

## Interfaces
```rust
pub mod wasm {
    pub struct Limits { pub memory_mb: u32 /* 128 */, pub fuel_per_call: u64, pub start_ms: u64 }
    pub struct WasmPlugin { /* engine, store, pipes */ }
    impl WasmPlugin {
        /// Instantiate and start `_start` on a blocking thread; stdin/stdout are pipes the host's
        /// `Conn` reads like a child's. Preopens: the own dir only, only if declared.
        pub fn spawn(module: &Path, own_dir: Option<&Path>, limits: Limits) -> Result<WasmPlugin, Error>;
        pub fn kill(&self);
    }
}
```

## Steps
1. `host.rs`: where it spawns a process for `entry.run`, `"wasm"` → `WasmPlugin::spawn`; the
   connection, handshake, heartbeat, idle stop and crash counting are the same code paths.
2. Sandbox: no `inherit_*`; env empty; args `[id]`; preopen own dir as `/data` only when
   `requires` has `fs.own_dir`; `epoch_interruption` for hangs (heartbeat kills), memory limit
   via `StoreLimits`.
3. A trap is a crash (counts toward `crash_limit`); a deleted folder kills the instance (`Removed`).
4. The fixture: `fixtures/wasm-hello/` (~100 lines, serde_json only) answers `initialize`,
   `tools/list`, `tools/call` for `hello`, and a `hang`/`trap`/`read_outside` tool for the
   sandbox tests. Build command in its README:
   `cargo build --release --target wasm32-wasip1 --manifest-path …`; commit the `.wasm` and its
   SHA-256 in the README; `tests/wasm.rs` checks the hash so a stale binary fails loudly.

## Tests
`wasm_plugin_lists_and_calls`, `trap_is_a_crash`, `hang_is_killed_by_heartbeat`,
`no_file_outside_own_dir`, `no_own_dir_without_require`, `memory_limit_enforced`,
`deleted_folder_removes`, `same_events_as_process_plugin`.

- `cargo test --workspace` passes in v3/

## Notes for the worker
- v2 does not know `"run": "wasm"`; such a plugin simply fails to start on v2, which is fine:
  v2's manifests are unchanged and none uses it.
- Security code. Sandbox claims in comments must be exactly what the code enforces.
