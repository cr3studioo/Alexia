# P2-55: MCP: a cancel that beats its request still reaches it; WASM compiles off the runtime

Model: opus
Depends on: P2-52
Feature IDs: SP-10; review follow-ups from P2-47 and P2-24

## Goal
Two concurrency faults in `alexia-mcp`.

`plugin_cancel_reaches_incoming` flakes. The fixture sends a request and its
`notifications/cancelled` back to back. `on_line` registers the token and spawns the handler.
If the cancel is read before the spawned task is first polled, the task's `select!` can pick
`token.cancelled()` and drop the handler future without ever polling it. `Incoming::request` is
then never called, so the handler never sees the cancel. After this task a request that was
cancelled early still reaches `Incoming::request` with a token that is already cancelled, and
the test passes every time.

`WasmPlugin::spawn` waits on a std `mpsc::recv_timeout` for up to `start_ms` while the module
compiles, and the host calls it from async code (`start_guest`, host.rs about line 1418). That
blocks a tokio worker thread for the whole compile. After this task the wait is async.

## Interfaces
- `WasmPlugin::spawn` and `WasmPlugin::spawn_as` become `async fn`, with the same arguments and

  does not change. `host.rs` is their only caller.

## Steps
1. `conn.rs` `on_line`, the `Message::Request` arm (about line 264): make the spawned
   `select!` `biased;` with the request branch first, so the handler future is polled at least
   once before a cancel can win. Comment why. Check that a handler that never yields still
   lets a cancel through: it does, because the next poll after a `Pending` sees the token.
2. `tests/conn.rs` `plugin_cancel_reaches_incoming`: keep it as it is. Add
   `cancel_before_first_poll_reaches_incoming`. Drive `on_line`'s path with a request and its
   cancel delivered in one write, run it 200 times on a current-thread runtime, and require
   `cancel_seen` every time.
3. `wasm.rs` `spawn_as` (about line 274): replace the std channel with a
   `tokio::sync::oneshot` and `tokio::time::timeout(start_ms, ready_rx).await`. The compile stays
   on its own OS thread, as now. On timeout, kill the guest as today.
4. `host.rs` `start_guest` (about line 1389): make it `async` and `.await` the spawn. Its one
   caller (about line 996) is already in async code.
5. Delete `#[allow(clippy::incompatible_msrv)]` on `pipes()` (about line 165). P2-52 made 1.87
   the workspace's rust-version.

## Tests
- `cancel_before_first_poll_reaches_incoming` (tests/conn.rs)
- `slow_compile_does_not_block_runtime` (tests/wasm.rs): on a current-thread runtime, start a
  WASM plugin and, at the same time, a 10 ms ticker. The ticker keeps ticking while the module
  compiles. Use the committed `wasm-hello.wasm`. If its compile is too fast to show the
  difference, a `#[doc(hidden)]` delay hook in `spawn_as` is fine.
- Existing `tests/wasm.rs` and `tests/conn.rs` cases keep passing (they reach the spawn through
  the host).
