# P2-12: Permission modes, scope, never-touch, spoken boundaries

Model: opus
Depends on: P2-01
Feature IDs: TR-01

## Goal
After this task core decides, for every tool call, whether it runs, asks or is blocked, exactly as
v2 does: the never-touch list first (no mode turns it off, D63), then scope (folders the owner
chose), then spoken boundaries ("don't delete anything"), then the mode. `rule()` is what
INTERFACES §2.3 used to call `gate()`.

## Touch only these paths
- `v3/crates/alexia-core/src/permissions.rs`
- `v3/crates/alexia-core/tests/permissions.rs` (create)

## Must not touch
Everything else.

## Steps
1. Port `packages/core/src/permissions.ts` whole (cite functions in comments): `rule`,
   `readOnly`, `isDestructive`, `asVerb`, `plainly`, `neverTouchList` (credential stores, system
   folders, Alexia's own data dir: built from `%APPDATA%`, `%LOCALAPPDATA%`, `%windir%`, the

   Windows and `..` normalised, `within`, `pathsIn`, `heard`/`lifts`/`boundaryAck`.
2. `reviewed == false` → destructive whatever the annotations say (wire-protocol §7).
3. Sentences word for word from v2, so the owner sees the same questions.
