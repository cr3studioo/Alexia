# P2-79: Subscriptions: a clean environment, no Codex shell on tool output, no hang, exact error reading

Model: opus
Depends on: none
Feature IDs: MO-05, TR-01, TR-03; phase review 6 finding 9; review follow-ups from P2-35

## Goal
Edges in `alexia-core/src/subscription.rs`:
- **The hub's environment** (finding 9, `subscription.rs:135-165`). Both CLIs inherit the hub's
  whole environment, including `ALEXIA_SECRET_*` overrides and provider keys. The CLI's own agent
  can read them.
- **Codex's shell** (finding 9). Codex runs `exec --sandbox read-only`. That sandbox still lets
  its agent run shell reads anywhere on disk, and the prompt can carry untrusted tool output
  (prompt injection). That bypasses the gate and the never-touch list. Claude Code already runs
  with `--tools ""`.
- **A hang** (`subscription.rs:405-430`). A read error on stdout breaks the loop, then
  `child.wait()` is awaited with no cancel and no deadline.
- **A full stderr pipe** (`subscription.rs:388`). The stderr reader stops after 64 KiB but keeps
  the pipe open, so a CLI that writes more blocks forever.
- **Loose error reading** (`classify`, `subscription.rs:225`). It matches bare `"401"` and
  `"429"` substrings, so a model answer or a path that contains them reads as busy or signed out.

After this task a CLI sees only the variables it needs, Codex never runs a shell on a prompt
that holds tool output, every wait honours cancel and the deadline, and only real error markers
are classified.

## Steps
1. `command()`: `env_clear()`, then copy only an allowlist from the hub's environment: `PATH`,
   `PATHEXT`, `SYSTEMROOT`, `WINDIR`, `COMSPEC`, `TEMP`, `TMP`, `USERPROFILE`, `HOMEDRIVE`,
   `HOMEPATH`, `HOME`, `APPDATA`, `LOCALAPPDATA`, `PROGRAMDATA`, plus the CLI's own config
   variables (`CLAUDE_CONFIG_DIR` for Claude Code; `CODEX_HOME` for Codex). A `const` list with a
   comment per group. `check()` and `find()` use the same environment.
2. Codex shell: if `codex exec` has a switch that turns its shell tool off (check `codex exec
   --help` / its config `-c` overrides on the PC and write what you found in the PR note), pass
   it. If it has none, `chat` refuses a request that holds any tool turn or tool result with
   `ProviderError::Other("Codex is not used on steps that carry tool output.")`, so the router
   moves on; a request without tool output runs as today.
3. Hang: the stdout read error ends the loop, then `wait()` is inside the same `select!` with
   cancel and the deadline (kill on either).
4. Stderr: keep reading to the end, keep the first 64 KiB, drop the rest (`tokio::io::copy` of the
   remainder into `tokio::io::sink()` is enough).
5. `classify`: match `429`/`401` only as status markers (`"status 429"`, `"http 429"`,
   `" 429 "` at a word boundary with "too many" or "unauthorized" nearby, or a JSON `"status":429`).
   Prefer a word-boundary regex (`regex` is already a dependency).

## Tests

  returns `Cancelled` promptly, the child is killed)

- `bare_numbers_are_not_errors` (an answer containing "4290 files" and "401k": not Busy, not
  signed out)

Each new test must fail without its fix. Fake CLIs follow P2-35's existing test pattern.
