# P2-42: Permissions fail closed: Windows trailing dots, bad boundary entries

Model: sonnet
Depends on: P2-12
Feature IDs: none (review follow-up to P2-12)

## Goal
Two places in `alexia-core` permissions fail open, found in the P2-12 review. After this task a
Windows path segment with trailing dots or spaces is compared the way Windows opens it, and one
malformed spoken-boundary entry no longer drops every boundary.

## Touch only these paths
- v3/crates/alexia-core/src/permissions.rs   (change)
- v3/crates/alexia-core/tests/permissions.rs (change)

## Must not touch
Any other file. No public signature changes.

## Interfaces
No new public items. Behaviour of `key()` (path comparison key) and the boundary parsing inside
`scope()` changes as below.

## Steps
1. In `key()` (about permissions.rs:227, and the lexical tail at about 266-270), on Windows strip
   trailing `.` and ` ` from every path segment before comparing, as Win32 does when it opens a
   path (`C:\Users\me\.aws.\credentials` opens `C:\Users\me\.aws\credentials`). Keep the `.` and
   `..` segments meaning what they mean. Do this only under `cfg(windows)`; other platforms keep
   their current behaviour.
2. In `scope()` (about permissions.rs:428-430) parse the boundaries list element by element: keep
   each entry that parses, skip each one that doesn't with `tracing::warn!` naming its index (never
   its text). A list that is not an array yields no boundaries, also with a warning.

## Tests
- `trailing_dot_segment_is_never_touch` (cfg(windows)): with home as a root, a path through
  `<home>\.aws.\credentials` (where `.aws` does not exist) is never-touch.
- `trailing_space_segment_is_never_touch` (cfg(windows)): same with a trailing space.
- `one_bad_boundary_keeps_the_rest`: a boundaries list with one malformed entry and one good one;
  the good boundary still blocks its action.
Each test must fail without its fix.
