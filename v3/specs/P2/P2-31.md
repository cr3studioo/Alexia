# P2-31: Managed llama.cpp, speculative decoding

Model: opus
Depends on: P2-01
Feature IDs: MO-01, SP-17 (local non-chat jobs only), D213

## Goal
After this task the hub can install the pinned CUDA build of llama.cpp (`b11146`, v2's digests),
start `llama-server` on loopback for one local model, health-check it, stop it after 10 minutes
idle (SP-06's on-demand rule), restart it on crash with backoff, and hand the router an
OpenAI-compatible `Provider` for it (marked local). A draft model can be given for speculative
decoding (SP-17). Nothing here decides which jobs may use it: the router allows only `Vision`,
`Check` and `Local` (D213, P2-17).

## Touch only these paths
- `v3/crates/alexia-core/src/local.rs`
- `v3/crates/alexia-core/tests/local.rs` (create)

## Must not touch
`gpu.rs`, `hf.rs`, `router.rs`, everything else.

## Steps
1. Port `packages/core/src/llama.ts` (assets and digests for `win32-x64-cuda` + its cudart
   companion, and the CPU zip as fallback; argument building; health check `GET /health`; port
   picking; random API key per start; exit handling), cited. Never resolve "latest".
2. Children: `CREATE_NO_WINDOW`, a Job Object (reuse `alexia_mcp`'s pattern by copying the call,
   not the module), bound to `127.0.0.1`, `--api-key`, `--model-draft <path>` when `draft` is set
   and `-ngld` from the same fit.
3. The Provider is `OpenAiCompat` with a `FreeRow` for `http://127.0.0.1:<port>/v1` (free, no
   router flag) built in memory.
4. Download through `reqwest` streaming to a temp file, SHA-256 checked before unzip; zip entries
   with `..` or absolute paths refused.
