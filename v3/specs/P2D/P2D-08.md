# P2D-08: Library: plugins and skills from the shelf

Model: opus
Depends on: P2D-02, P2D-06
Feature IDs: SP-01

## Goal
After this task the Library screen lists the plugins and skills on Alexia's shelf (v2's
registry, `github:cr3studioo/Alexia`), shows updates and pulled entries, and installs or updates
one with progress, landing it in the hub's extensions folder the way P2D-06's folder install
does. INVENTORY L1–L3.

## Touch only these paths
- `v3/crates/alexia-api/src/library.rs`   (change: stub)
- `v3/crates/alexia-api/tests/library.rs`   (create)
- `v3/crates/alexia-hub/tests/contract/library.json`   (change: L1–L3 to `"answers"`)

## Must not touch
Other `alexia-api` modules, `lib.rs`, `alexia-mcp` (use P2D-06's `install_folder`), `packages/`,
`.github/`.

## Interfaces
- `GET /api/library` → serve.ts 2650–2725: `Library::plugins()`, `skills()`, `revoked()`,
  `updates(..)`, `offerable(..)` ported from `library.ts`; on a network failure v2's sentence.
- `GET /api/library/progress?id=` → `{done,total}` or `{done:0}` from `api.library`.
- `POST /api/library/install {id, kind, update, enable}` → serve.ts 2734–2787: download the
  release asset over `reqwest` (rustls), check its sha256 against the registry entry (`sha2`),
  unpack, `McpHost::install_folder` (P2D-06), enable if asked; a skill goes to
  `layout.skills()` with provenance `library` and is pre-authorised (v2 `preauthorise`).
- `pub(crate) struct LibraryState { progress: Mutex<HashMap<String, (u64, u64)>>, cache: .. }`.

## Steps
1. Port `library.ts` (registry URL, entry types, revocation, updates, offerable, extract).
2. Unpacking: v2 shells out to `System32\tar.exe`. Use the `zip` crate for `.zip` assets and
   `%SystemRoot%\System32\tar.exe` (not PATH's tar, v2 `archiver()`) for `.tar.gz`, with
   `CREATE_NO_WINDOW`; refuse entries escaping the folder.
3. Flip L1–L3.

## Tests
- `tests/library.rs` against a local fake registry (a `tokio` HTTP server in the test serving a
  registry JSON and one zipped fixture plugin): `lists_plugins_and_updates`,
  `install_checks_sha256` (a wrong digest refuses and leaves nothing), `progress_reported`,
  `revoked_not_offered`, `zip_slip_refused`, `skill_install_preauthorised`.
- `cargo test -p alexia-hub --test contract`: L1–L3 answer (the contract run points the registry
  at a local fake through `ALEXIA_LIBRARY_REGISTRY`, the same variable v2 reads, if v2 has one;
  otherwise add it here, test-only, and say so in the report).
