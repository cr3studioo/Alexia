# P2D-17: Computer plugin: the typing guard follows the window a plan opens

Model: opus
Depends on: P2D-16
Feature IDs: none (owner A-19 item 5)

## Goal
P2D-16 made typing safe: keys and clicks refuse unless the window in front belongs to the process
the task targets. Its review found three cases where that guard refuses work it should allow, so
plans that open something and then type into it stop on Windows. After this task the guard follows
the window the plan itself brought up, and modern (UWP) apps pass it, while typing into an
unrelated window is still refused.

## Interfaces
1. `front()` on Windows (today null): returns `{ pid, title }` of the foreground window
   (GetForegroundWindow + GetWindowThreadProcessId + window text), through the existing
   PowerShell path. index.js:939 `openUrl` re-targets with it, as on macOS.
2. A plan's `openApp` step (task.js:161) re-targets to the process it opened, the way run_task's
   first open_app does, so later type/key/click steps in that plan target the new app.
3. UWP apps: a window hosted by ApplicationFrameHost.exe counts as the target when its hosted
   CoreWindow child belongs to the target pid (or when the target pid IS that ApplicationFrameHost
   window's process). Same rule in `focus` and in the guard (windows.js:136-145, :490).
4. replay.js:115 type/key/click pass the replayed task's target pid, so replays are guarded too.
5. Unchanged: with a target pid and a foreground window that matches none of the above, the guard
   still refuses and sends nothing.
