# P2D-13: The Tauri shell starts or attaches to the hub

Model: opus
Depends on: P2D-01
Feature IDs: SP-01

## Goal
After this task the desktop app runs on the Rust hub: on start it attaches to the hub already
running on this PC (from Task Scheduler or a console) or starts `alexia-hub run` itself, points
its windows at the hub's port, restarts a hub it started when that hub stops, and never starts
the Node core or the vault. Telegram and the window share that one hub. `pnpm app` bundles the
hub binary and the UI as resources, with no `tauri.conf.json` change (D-P2D-4). INVENTORY T4
(`start-core-again`), gap G8 (Node for plugins).

## Touch only these paths

- `scripts/sidecar.mjs`   (change: build and copy the hub and the UI into `src-tauri/resources/`)

## Interfaces
Hub side (P2D-01, read only here): `%LOCALAPPDATA%\AlexiaHub\window.json` =
`{"port":u16,"pid":u32}` while a hub serves the window; `alexia-hub run` exits 1 with
`Another Alexia hub is already running on this computer.` if one holds `hub.lock`;
`ALEXIA_WINDOW_PORT`, `ALEXIA_UI_DIR`, `ALEXIA_NODE` environment variables; the data folder is
`ALEXIA_V3_DATA` or `%LOCALAPPDATA%\AlexiaHub`.

Shell behaviour (`main.rs`):
1. `find_hub() -> Option<u16>`: read `window.json`; the hub answers if a TCP connect to
   `127.0.0.1:<port>` succeeds within 1 s and process `pid` exists. Then **attach**: navigate the
   windows (not `control`) to `http://127.0.0.1:<port>/`, hold no child.
2. Otherwise **start**: spawn `<resource_dir>/resources/hub/alexia-hub.exe run` with
   `ALEXIA_UI_DIR=<resource_dir>/resources/ui`, `ALEXIA_NODE=<path of the alexia-core sidecar
   binary>` (Tauri's resolved sidecar path, the bundled Node), `ALEXIA_WINDOW_PORT=<free_port()>`,
   `CREATE_NO_WINDOW`; stdout/stderr drained (as today, so the child never blocks); hold the
   child; wait for the port as `start` does today, then navigate.
   Dev fallback when no bundled hub exists (`cargo tauri dev` / an unbundled run before
   `sidecar.mjs`): `ALEXIA_HUB_EXE` environment variable naming the binary; neither → the
   placeholder page says the hub was not found (stderr line, tooltip "Alexia — something went
   wrong").
3. A hub the shell started that stops: restarted with today's back-off. An attached hub that
   stops: after the back-off, `find_hub()` again, else start one.
4. `start-core-again`: a started hub is killed and restarted by the watch; an attached one is
   not killed (it is not ours): the shell re-runs `find_hub()`/start and navigates again.
5. `RunEvent::Exit` (tray Quit): kill the hub only if this shell started it. Closing the window
   hides it, as today.
6. The vault is not opened and no handover is written (D-P2D-5): the hub reads its own
   Credential Manager entries.
7. `@shell` lines: the hub prints none; the reader stays (harmless) and compute-role tray modes
   are not reachable (D-P2D-7).

`scripts/sidecar.mjs` (runs before `tauri build`):
- `cargo build --release --locked -p alexia-hub --manifest-path v3/Cargo.toml` and copy
  `v3/target/release/alexia-hub(.exe)` to `src-tauri/resources/hub/`.
- Copy the UI exactly as the hub serves it (`packages/ui/{index.html, compute.html, app.css,
  *.png, *.svg, *.webp}` and `packages/ui/dist/src/*.js`, after `tsc -b`) to
  `src-tauri/resources/ui/` keeping `dist/src/` (statics.rs reads `dist/src/<name>.js`).
- Keep building and copying the `alexia-core` sidecar (Node) and `alexia-connect` as today.
  Stop copying `alexia.mjs`, `boot.mjs`, `scripts` into resources only if nothing else reads
  them; the final `boot.mjs` existence check is replaced by a check that
  `resources/hub/alexia-hub(.exe)` and `resources/ui/index.html` exist.

## Steps
1. Read `src-tauri/src/main.rs` (whole) and `scripts/sidecar.mjs` (whole).
2. Replace `sidecar()`/`start()`'s Node path with find/attach/start of the hub; keep windows,
   tray, overlay, hotkeys, updater, autostart as they are.
3. Change `sidecar.mjs`.
4. Build on this PC: `pnpm app` (or `pnpm sidecar` then `pnpm tauri build --no-bundle` if NSIS
   is slow), start `src-tauri\target\release\alexia.exe` with no hub running → one hub starts;
   quit; start a hub from a console, start the app → it attaches, no second hub; quit the app →
   the console hub keeps running.
