# P2D-10: Compute screen on a hub with no paired computers

Model: opus
Depends on: P2D-02
Feature IDs: SP-01

## Goal
After this task Settings › Compute and `compute.html` load on the hub and answer every compute
route in v2's shapes: this PC's role (`interaction`), its inventory, its job queue with cancel
and pause, the relay/mailbox settings, Tailscale state and the window close. Pairing another
computer answers v2's refusal shape with a sentence (D-P2D-7); no UI change. INVENTORY R1–R23.

## Touch only these paths
- `v3/crates/alexia-api/src/compute.rs`   (change: stub)
- `v3/crates/alexia-api/tests/compute.rs`   (create)
- `v3/crates/alexia-hub/tests/contract/compute.json`   (change: R1–R23 to `"answers"`)

## Must not touch
Other `alexia-api` modules, `lib.rs`, `alexia-core` (use `LocalJobs`, `Runtime`, `gpu` as they
are), `connect/`, `packages/`.

## Interfaces
Routes, each with the shape `compute/api.ts` gives for an interaction computer with no pairs:
- `GET role` → `{role:"interaction", ...}` as api.ts 491–495; `POST role` → to `interaction`:
  `{ok:true}` no-op; to `compute`: `409 {ok:false, said:"Pairing another computer comes with the
  mesh in a later version."}`; `POST role/cancel` → `{ok:true}`.
- `GET hosts` → `{hosts:[]}` shape of api.ts 512–517; `GET status`, `GET inventory`,
  `GET queue`, `GET job`, `GET jobs` with no `host` or `host=this` → this PC: inventory from
  `gpu` facts and installed models (v2 `compute/inventory.ts` keys), queue/jobs from
  `LocalJobs`; with another host → api.ts's unknown-host refusal.
- `POST select {host}` → `this` accepted, others refused as api.ts.
- `POST setup/install {host?, item}` → this PC: the llama.cpp runtime via `Runtime` (P2-31's pin);
  others refused.
- `POST jobs/cancel {job}`, `POST pause {paused}` → `LocalJobs` cancel / `set_paused`.
- `GET/POST tailscale` → v2's shape from `compute/tailscale.ts` (detect `tailscale.exe` status;
  POST stores the preference only).
- `GET discover`, `POST pair/start`, `GET pair`, `POST pair/cancel`, `POST unpair` → `pair`
  answers "no pairing open"; the rest the 409 sentence above (unpair of an unknown host: api.ts's
  refusal).
- `GET/POST services` → api.ts 664–682 on kv `_core`/`compute_services`.
- `POST window/close` → api.ts 684–690 (`only('compute')`: refused on the interaction computer,
  as v2).
- `compute::state(api)` → what `/api/state` carries under `compute` (api.ts 449–460).
- Fallthrough: `404 {"ok":false,"said":"That compute endpoint or method is not available."}`.

## Steps
1. Read `compute/api.ts`, `types.ts`, `inventory.ts`, `tailscale.ts`, `jobs.ts`, `scheduler.ts`;
   write the interaction-without-pairs answers.
2. Flip R1–R23.
