# P2D-11: Image editor and research viewer

Model: opus
Depends on: P2D-02, P2D-03
Feature IDs: SP-01

## Goal
After this task the image editor opens in the window and every editor call reaches the plugin
that provides `image.edit` with the conversation checked, its pictures and shared files are
served, and the research viewer shows the latest research snapshot of a plugin with a
`research` widget and serves its previews and report. INVENTORY E1–E7.

## Touch only these paths
- `v3/crates/alexia-api/src/editor.rs`   (change: stub)
- `v3/crates/alexia-api/src/research.rs`   (change: stub)
- `v3/crates/alexia-api/tests/editor.rs`   (create)
- `v3/crates/alexia-api/tests/research.rs`   (create)
- `v3/crates/alexia-hub/tests/contract/editor.json`   (change: E1–E7 to `"answers"`)

## Must not touch
Other `alexia-api` modules, `lib.rs`, every library crate, `packages/`, `plugins/`.

## Interfaces
- `POST /api/editor {conversationId, call, args}` → serve.ts 2101–2128: the conversation must
  exist (`context_required` sentence), then the tool of the plugin providing `image.edit`
  (capability resolution through `McpHost`, never an id), called with `alexia/editor` context as
  v2 `plugins.editorCall`; files the tool shares get a token in `api.editor`
  (`/api/editor/file?token=...`, serve.ts 524).
- `GET /api/editor/file?token=` → serve.ts 2073–2079; `GET /api/editor/picture?...` → 2080–2085
  (a picture the conversation owns, via the attachments layer); `POST /api/editor/upload` →
  2086–2095; `POST /api/editor/forget` → 2096–2100.
- `editor::state(api)` → `{installed, conversationId, private}` (serve.ts 1926).
- `POST /api/research {plugin}` → `{snapshot}` from `McpTooling::research(plugin,
  api.session())` (P2D-03) when the plugin's manifest has a `research` widget, else `null`.
- `GET /api/research-file?plugin=&run=&source=&kind=` → serve.ts 3179–3197: realpath inside the
  plugin's own dir and matching run id, else `404` empty.
