# P2D-19: Computer plugin: `elements` sees the window a turn just opened, every time

Model: opus
Depends on: P2D-18
Feature IDs: none (owner A-19 item 5)

## Goal
P2D-15's end-to-end run (v3/ops/reports/P2D-e2e.md on cr3studioo/v3-P2D-15) found that
`cargo test -p alexia-hub --features pc-actions --test pc_actions` passed once and then failed in six
runs in a row at the same place: the turn opens Character Map, `focus` succeeds, then the computer
plugin's `elements` tool (plugins/computer/index.js ~line 660, windows.js `elements`) returns no rows
("Nothing there names itself"), so the test ends at pc_actions.rs:773 with no click. A plain UI
Automation read of a freshly started Character Map on this PC does list "Characters to copy :"
(automation id 104). After this task `elements` with the pid from `open_app` lists Character Map's
controls on every run, and pc_actions passes 5 runs in a row.

## Touch only these paths
- plugins/computer/windows.js   (change)
- plugins/computer/index.js   (change)
- plugins/computer/test/windows.test.js   (change)
- v3/crates/alexia-hub/tests/pc_actions.rs   (change, only if the test itself races, e.g. calls
  elements before the window exists; say so in the report)
- v3/ops/reports/P2D-19.md   (create)

## Must not touch
Any other plugin, packages/, src-tauri/, other v3/ files, plugins/computer/macos.js.

## Steps
1. Reproduce: run pc_actions (from PowerShell in the owner's session, as P2D-12's report says) until
   it fails; capture what `elements` sends to PowerShell and what comes back.
2. Find the cause. Suspects, in order: the P2D-17 window lookup by pid (FrameOf / hosted-pid rule)
   picking a different or zero window for a classic app; `elements` running before the new window
   has its UI Automation tree (it needs a short bounded wait/retry when the pid's window exists but
   reports no children); a stale cache from `warm()` keyed by pid or title from a previous run.
3. Fix it in the plugin. A bounded retry (for example up to 2 s, 200 ms steps, abortable) is fine if
   the cause is timing; a wrong window pick must be fixed at its root.
4. Unit tests with injected PowerShell output for the cause you found.
5. Run pc_actions 5 times in a row; all must pass. Record each run's result in the report.

- if pc_actions.rs changed: cargo fmt --check, cargo clippy -p alexia-hub --features pc-actions
  --all-targets -D warnings pass
- `node v3/ci/invariants.mjs` passes
