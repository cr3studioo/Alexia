# P4-08: TR-05 proven: the mesh refuses what it must

Model: opus
Depends on: P4-05, P4-06
Feature IDs: TR-05

## Goal
"End-to-end encrypted mesh" is shown, not assumed: an adversarial test suite against the real
mesh code proves that only paired devices are heard, revocation takes effect at once, the link
and operations refuse wrong roles and wrong secrets, and nothing secret appears in logs. A short
report says what the encryption is (connect's QUIC/TLS 1.3 with raw public keys bound to endpoint
ids) and what is out of scope.

## Touch only these paths
- `v3/crates/alexia-mesh/tests/security.rs`   (create)
- `v3/ops/reports/P4-mesh-security.md`   (create)

## Must not touch
Any `src/` file. If a test finds a hole, stop, write the failing test, and escalate with it; the
fix is a separate task.

## Interfaces
Uses `Node`, `pair_offer`/`pair_join`, `dial`, `accept_links`, `serve_ops`, `send_op` as P4-04..P4-06 define them.

## Steps
1. Build three ephemeral nodes: hub H, limb L (paired), stranger S (never paired).
2. Write the tests below; each asserts the refusal *and* that the callback on the target was never called.
3. Write the report: what crosses (connect README *What crosses*), what is encrypted, who holds
   which key where (keychain service names), what a stranger on the LAN sees (QUIC handshake
   refused), what relays would see (none configured, D-P4-2), what is not covered (a compromised
   device, the owner's keychain).

## Tests
`tests/security.rs`:
- `stranger_cannot_dial_limb`, `stranger_cannot_send_ops_to_hub`;
- `revoked_limb_is_cut_within_1s` (open link → revoke on H → link `closed` fires within 1 s and a
  new dial fails);
- `wrong_loopback_secret_is_401` (a local process with the wrong bearer on H's connect port);
- `wrong_host_secret_is_refused` (a request straight to L's host service without connect's secret);
- `forged_peer_header_is_ignored` (a body or header claiming another `x-alexia-peer` changes nothing);
- `pair_code_single_use` (re-use after success fails);
- `no_secret_in_logs` (run a pairing and a link with tracing captured at debug: no code, no
  per-launch secret, no host secret, no line content);
- `limb_role_cannot_serve_ops_to_a_limb` (L calling `send_op` to another limb is refused).
