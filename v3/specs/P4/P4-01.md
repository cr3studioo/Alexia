# P4-01: Capabilities for P4

Model: opus
Depends on: none
Feature IDs: HB-06, HB-07, HB-08, HB-09, HB-17, PC-01..PC-20

## Goal
Every capability the P4 plugins provide and the hub calls is written down before anyone builds
it, so plugin tasks (P4-15..P4-29) and hub tasks (P4-37, P4-38) agree on names, arguments and
results without talking to each other. Plugins depend on capabilities, never on plugins (rule 5).

## Touch only these paths
- `docs/spec/capabilities.md`   (change: a new section "P4: devices and the PC")

## Must not touch
`v3/specs/INTERFACES.md` (P3-35 holds it; P4-35 copies this section there later), any code,
`docs/spec/wire-protocol.md` (P3-36).

## Interfaces
Add each capability with: name, who provides it, arguments (JSON Schema shape in prose or JSON),
result (`CallToolResult` text and `structuredContent`), annotations (`readOnlyHint`,
`destructiveHint`, `openWorldHint`), and what happens when absent. Exactly these names:

| Capability | Provided by | Arguments → result | Annotations |

Also state, once, for every device capability: on the hub the same capability may be offered by
several devices; the call may carry `device` (a device id from `alexia-hub devices`) and the host
picks by D-P4-9 (PHASE.md) when it does not.
