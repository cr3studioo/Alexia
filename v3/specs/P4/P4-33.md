# P4-33: Gateway: guests on Telegram

Model: opus
Depends on: P4-03, P4-31, P4-32
Feature IDs: TR-11

## Goal
A family member the owner invited can message the same Telegram bot and talk to Alexia as a
guest. Their chat is recognised by a one-time code, gets its own sessions, never receives the
owner's notices, approvals or follow-ups, and never joins the owner's handoff. Anyone else who
is neither the owner nor a guest is still ignored as today.

## Touch only these paths
- `v3/crates/alexia-gateway/src/gateway.rs`   (change)
- `v3/crates/alexia-gateway/src/channels/telegram/mod.rs`   (change: let a non-owner chat through when it is a guest or sends a code)
- `v3/crates/alexia-gateway/tests/guests.rs`   (create)

## Must not touch
`src/ask.rs` (P3-36), `channel.rs`, other channels, other crates.

## Interfaces
Uses `Store::{guest_claim, guest_of}` (P4-03) and `permissions::guest_of` (P4-31).
- An unknown chat whose first message is `/start <code>` or the bare code: hash it (sha256 hex),
  `guest_claim("telegram", hash, chat)`; on success reply "Hi <name>, I'm Alexia. <owner name>
  invited you. I can chat; I can't see anything of theirs." and from then on the chat is a guest.
  On failure: no reply at all (an unknown chat learns nothing), and at most 5 tries per chat per
  hour are even looked at.
- A guest's message becomes a turn with `Origin::Channel { channel:"telegram", chat }` in a
  session keyed by that chat, never merged with the owner's (no handoff), never `Active`.
- `Say`, approvals (`Asker`), notice buttons and follow (P4-32) never target a guest chat.
- A removed guest (`guest_remove`) is ignored like any stranger from the next message on.
- Generating codes (`/guest add`) is P4-39's; tests insert guests with `guest_add`.

## Steps
1. Find where the Telegram channel filters to the paired owner chat (P1 pairing).
2. Add the guest path beside it with the rules above.
