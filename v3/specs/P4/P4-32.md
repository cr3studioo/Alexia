# P4-32: Gateway: notices and the conversation follow the owner

Model: sonnet
Depends on: none
Feature IDs: HB-06, HB-04

## Goal
The gateway asks the hub "where is the owner?" before saying something unprompted, and sends it
there only (a device's notification when they are at the Mac, else Telegram), instead of to every
channel. And a message from a different face within 30 minutes of the last turn continues the
same conversation, with the reply of a turn still running going to the face the owner moved to
(handoff, D-P4-8).

## Touch only these paths
- `v3/crates/alexia-gateway/src/gateway.rs`   (change)
- `v3/crates/alexia-gateway/tests/follow.rs`   (create)

## Must not touch
`src/ask.rs`, `tests/elicit.rs` (P3-36), `channel.rs`, `channels/**`, other crates.

## Interfaces
```rust
/// Where the owner is now, as an origin to deliver to (`Origin::Channel { channel, chat }`,
/// e.g. `{ "device", "<device id>" }` or `{ "telegram", "<chat>" }`), or None to deliver as before.
pub type Follow = Arc<dyn Fn() -> Option<Origin> + Send + Sync>;
impl Gateway {
    pub fn set_follow(&self, follow: Follow);
}
pub const HANDOFF_MS: i64 = 30 * 60 * 1000;
```
- `Say` with `to: None`: if `follow()` names a configured channel and chat, deliver there only;
  if that send fails, deliver as before (every primary chat). `to: Some(..)` is unchanged.
  `Urgency::Urgent` goes to the followed face **and** Telegram's primary chat.
- Handoff: the gateway keeps (session, last face, last turn time). A turn from another face of
  the owner (not a guest: P4-33 marks those) within `HANDOFF_MS` joins the same session; the
  session's in-flight run, if any, delivers its final reply to the new face, and the old face
  gets one line "Continued on <face>." (`face` = channel name, or the device id for "device").
  `/new` on any face starts a fresh session as today.
- A device face is a channel named `device` registered by the hub (P4-37). The gateway does not
  know devices; it only uses the channel set.

## Steps
1. Read how `Say` is delivered and how a channel's chat maps to a session today.
2. Add the follow hook and the handoff table (in memory; on restart, sessions resume per chat as today).
