# P4-05: Pair a device with a code or a QR

Model: opus
Depends on: P4-04
Feature IDs: HB-18, HB-02, TR-05

## Goal
The hub offers a pairing as one line of text and as a QR of that text; a limb joins with the text.
Under it is connect's direct pairing (SPAKE2 over iroh, one attempt, five minutes), so no
mailbox or third-party service is used (D-P4-2). On success both sides write a `devices` row and
put the other on the allowlist; nothing else trusts the peer.

## Touch only these paths
- `v3/crates/alexia-mesh/src/pair.rs`   (fill)
- `v3/crates/alexia-mesh/src/qr.rs`   (fill)
- `v3/crates/alexia-mesh/tests/pair.rs`   (create)

## Interfaces
```rust
// pair.rs
impl Node {
    /// Hub: POST /v1/pairing/host {"name","payload":Hello,"exclusive":false,"direct":true}.
    pub async fn pair_offer(&self, hello: &Hello) -> Result<PairOffer>;
    /// Hub: waits for the offer to settle (GET /v1/pairing/{id}?wait=true); on `paired` writes
    /// the device (role from its Hello must be `limb`), syncs the allowlist and hints.
    pub async fn pair_wait(&self, offer: &PairOffer) -> Result<DeviceRow>;
    /// Limb: parses the URI and joins with {"code","name","payload","direct":{"endpointId","addresses"}}.
    /// On `paired` writes the hub's row (role must be `hub`) and syncs. Err with a sentence on each failure code.
    pub async fn pair_join(&self, uri: &str, hello: &Hello) -> Result<DeviceRow>;
}
pub struct PairUri { pub endpoint: EndpointId, pub code: String, pub addresses: Vec<std::net::SocketAddr>, pub name: String }
pub fn pair_uri(p: &PairUri) -> String;       // "alexia-pair:1?e=..&c=..&a=..,..&n=<percent-encoded>"
pub fn parse_pair_uri(s: &str) -> Option<PairUri>;
// qr.rs
pub fn qr_text(data: &str) -> String;          // Unicode half blocks, quiet zone 2, dark on light
pub fn qr_svg(data: &str) -> String;
```
Failure sentences (one per connect code): expired → "The pairing code ran out. Start a new one
with `alexia-hub devices pair`."; wrong code → "That code did not match. It can't be used again;
start a new pairing."; unknown/timeout → "Nothing is waiting for that code. Check the PC shows it
and the two computers are on the same network (or Tailscale)."; proof failed → "The other computer
could not prove who it is. Nothing was paired."

## Steps
1. URI build/parse (strict: scheme, version, 64-hex `e`, code shape as connect checks it, ≤ 16
   addresses, name ≤ 128 B). Addresses: connect `/v1/status` `directAddresses` plus extras.
2. QR with the `qrcode` crate, both renderings.
3. Offer/wait/join per connect README *Pairing* and *Pairing without a mailbox*.
4. A `paired` result whose `role` is wrong is refused: revoke at once, sentence "That is not an
   Alexia limb." / "That is not an Alexia hub."
5. A `paired` that raced a cancel (`cancelled: false`) is honoured only if this side did not cancel.

## Tests
`tests/pair.rs` (two ephemeral nodes on loopback):
- `uri_round_trips`, `uri_rejects_bad_shapes` (6 cases);
- `qr_text_decodes` (render, then check module count matches `qrcode`'s version for the data; or
  decode with the crate's test helper if one exists), `qr_svg_is_svg`;
- `hub_and_limb_pair` (offer → join with the URI → both rows exist, each on the other's allowlist,
  `MeshEvent::Paired` on both);
- `wrong_code_fails_once` (alter one word → failed; the right code afterwards also fails);
- `limb_cannot_pair_as_hub` (a joiner whose Hello says `hub` is refused and not allowlisted).

## Notes for the worker
- The code is a secret for five minutes: never log it, never store it. The URI holds it; print
  it only where the CLI shows it to the owner (P4-37).
- Two nodes on one machine need loopback hints: put `127.0.0.1:<port>` in the URI's `a`.
- connect's `ALEXIA_CONNECT_LOOPBACK_HINTS` is debug-only; do not rely on it in non-test code.
