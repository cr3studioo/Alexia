# P4-40: Hub: the fallback's turns come home

Model: opus
Depends on: P4-37, P4-36
Feature IDs: HB-11

## Goal
When the PC is back and the Mac's limb reconnects, the hub collects every turn the Mac answered
while it was away and appends them to the same conversations, in time order and exactly once.
While the hub is up, it keeps the Mac's context fresh (the last 50 messages of each owner chat),
so the next fallback starts with something to go on.

## Touch only these paths
- `v3/crates/alexia-hub/src/fallback.rs`   (create)
- `v3/crates/alexia-hub/src/main.rs`   (change: one line)
- `v3/crates/alexia-hub/tests/fallback_sync.rs`   (create)

## Must not touch
`devices.rs`, `face.rs`, `carry.rs`, `kill.rs`, other crates.

## Interfaces
Uses the limb's hidden tools (P4-36) through `McpHost::call_tool(<device id>, "fallback.turns"|"fallback.ack"|"fallback.context", ..)`
and the store's `fallback_synced` / `fallback_mark` (P4-03).
- On `PeerOnline` for a limb: loop `fallback.turns {after_id}` → for each turn, skip if
  `fallback_synced(device, id)`; else find the owner session for `Origin::Channel { "telegram", chat }`
  (the one the gateway would use; create if none), append the message with its original `at`,
  `fallback_mark`; then `fallback.ack {up_to_id}`. Then one `Say` to the owner: "While the PC was
  off I answered <n> messages from the Mac. They're in your conversation now." (only if n > 0).
- Every 10 min and on each `RunEnded` for a Telegram session: `fallback.context {chat, messages}`
  (last 50, text only, attachments as "[file]") to each online limb that declares the tool.
- Memory: appended turns are then given to P3-16's capture like any new turn (if P3-16 exposes a
  call for that; otherwise note it in the report as a follow-up).
