# P4-04: Mesh node: connect in-process, identity, allowlist, peer events

Model: opus
Depends on: P4-02, P4-03
Feature IDs: HB-02, TR-05

## Goal
One `Node` type starts `alexia-connect` inside the calling process, keeps its identity in the OS
keychain, puts exactly the store's non-revoked devices on the allowlist, and turns connect's
peer events into `MeshEvent`s. The hub and the limb both use it; nothing else in v3 speaks to
connect.

## Touch only these paths
- `v3/crates/alexia-mesh/src/node.rs`   (fill)
- `v3/crates/alexia-mesh/src/control.rs`   (fill: a typed client for connect's loopback API)
- `v3/crates/alexia-mesh/tests/node.rs`   (create)

## Must not touch
`connect/`, `src/lib.rs`, `src/types.rs` (P4-02's; if a type is missing, escalate), other crates.

## Interfaces
```rust
pub struct NodeConfig {
    pub keychain: String,             // KEYCHAIN_HUB or KEYCHAIN_LIMB
    pub name: String,                 // shown on the other device
    pub role: Role,
    /// Tests: a fresh key in memory, no keychain (connect's debug-only switch is not used).
    pub ephemeral: bool,
    /// Extra addresses this device is reachable at (Tailscale), D-P4-2.
    pub extra_addresses: Vec<std::net::IpAddr>,
}
pub struct Node { /* Running, port, secret, reqwest client, store, events tx */ }
impl Node {
    pub async fn start(cfg: NodeConfig, store: Arc<alexia_store::Store>) -> Result<Arc<Node>>;
    pub fn endpoint(&self) -> EndpointId;
    pub fn role(&self) -> Role;
    /// `http://127.0.0.1:{port}` and the per-launch secret, for link.rs and ops.rs.
    pub fn loopback(&self) -> (String, String);
    /// Re-reads `devices` and replaces connect's allowlist and hints with it.
    pub async fn sync_allowlist(&self) -> Result<()>;
    pub async fn revoke(&self, device: &DeviceId) -> Result<bool>;   // store + DELETE /v1/allowlist/{id}
    pub async fn connect(&self, device: &DeviceId) -> Result<Reach>; // POST /v1/peers/{id}/connect
    pub async fn status(&self) -> Result<serde_json::Value>;         // GET /v1/status
    pub fn events(&self) -> tokio::sync::broadcast::Receiver<MeshEvent>;
    pub async fn close(self: Arc<Self>);
}
```
`control.rs`: `pub(crate) struct Control { base: String, secret: String, http: reqwest::Client }`
with one method per connect request used here, plus an SSE reader for `GET /v1/events` that
reconnects with backoff and treats `snapshot` as a full replacement (connect README *Events*).

## Steps
1. Identity: `alexia_connect::identity::load_or_create(&cfg.keychain)`, or `SecretKey::generate`
   when `ephemeral`. The key is never logged or returned.
2. Secret: 32 random bytes as hex, held in memory.
3. `alexia_connect::start(Options { .. network: Network::new::<&str>(&[], None)?, pairing: <settings with no mailbox> })`.
4. `PUT /v1/self/addresses` with `extra_addresses`; `sync_allowlist()`.
5. Events task: map endpoint → device via the store; publish `Online`/`Offline` on change, update
   `device_seen`. Ignore unknown event names.
6. `close` closes connect (`Running::close`).

## Tests
`tests/node.rs` (two ephemeral nodes in one process, scratch stores, loopback hints):
- `starts_and_reports_endpoint` (64 hex, port on 127.0.0.1 only);
- `allowlist_is_the_store` (a device row → listed in `/v1/peers`; revoked → gone);
- `paired_peers_connect_and_go_online` (rows written on both sides by hand, hints with the
  other's loopback address → `connect` → both see `Online`);
- `revoke_sends_offline`;
- `nothing_logs_the_secret` (capture tracing output; the secret string never appears).

## Notes for the worker
- Read `connect/README.md` in full: it is the contract. `Options`, `Running`, `identity`,
  `Network` are public in `connect/src/lib.rs`.
- Loopback hints in tests: give each node the other's `127.0.0.1:<port>` from `/v1/status`
  `directAddresses` via `PUT /v1/peers/{id}/hints`.
- Windows: the keychain path is Credential Manager; tests use `ephemeral` and never touch it.
- No `0.0.0.0`, no `localhost` (invariant 13).
