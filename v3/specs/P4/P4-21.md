# P4-21: documents: edits

Model: sonnet
Depends on: P4-01
Feature IDs: PC-07

## Goal
The `documents` plugin already reads almost any document. Now it can also change text in Word
(`.docx`), Markdown, plain text and CSV files: replace a phrase, append a paragraph or a row. By
default it writes an edited copy beside the original, so nothing is lost.

## Touch only these paths
- `plugins/documents/edit.js`   (create)
- `plugins/documents/index.js`   (change: register the tool)
- `plugins/documents/plugin.json`   (change: `provides` + `document.edit`, `requires` + `fs.write_scoped`)
- `plugins/documents/test/edit.test.js`   (create)

## Must not touch
The reading code (`read.js`, `office.js`, `pdf.js`, ...), other plugins, `pnpm-lock.yaml` (use
the zip code the plugin already has in `zip.js`).

## Interfaces
`document.edit {path, edits:[{find, replace, all?:false}] | append:{text} | append_row:[..], in_place?:false}`
→ `{path, changed:<count>}`. Copy name: `<stem> (edited).<ext>`, then ` (edited 2)`. `in_place`
is destructive (annotation set per call is not possible; declare the tool `destructiveHint: true`
and describe that the default makes a copy). `.docx`: edit `word/document.xml` text runs; a
`find` that spans several runs is matched on the paragraph's joined text and rewritten into the
first run, keeping that run's formatting (documented limitation). PDF and others → `isError`
"Alexia can read this kind of file but not edit it yet."

## Tests

`docx_replace_across_runs`, `in_place_overwrites`, `copy_names_increment`, `pdf_refused`,
`outside_roots_refused`.
