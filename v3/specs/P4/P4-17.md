# P4-17: file-courier: files in chunks between devices

Model: sonnet
Depends on: P4-15
Feature IDs: HB-08 (the device side)

## Goal
Each computer can hand a file out in 1 MiB pieces and take one in, checked by SHA-256 at the
end. The hub moves a file by reading chunks from one device's courier and writing them to
another's (P4-38). Reading is limited to folders the owner allowed; writing lands in Downloads
or an allowed folder and never overwrites.

## Touch only these paths
- `plugins/file-courier/**`

## Must not touch
Other plugins, any crate, `pnpm-lock.yaml`.

## Interfaces
`file.stat {path}` → `{size, sha256, name}`; `file.read_chunk {path, offset, length<=1048576}` →
`{data (base64), eof}`; `file.write_chunk {name, folder?, offset, data, last, sha256?}` → `{path}`.
Writes go to `<name>.part` until `last`, then the hash is checked (when given) and the file is
renamed; an existing target gets ` (2)`, ` (3)`. A mismatch deletes the part and returns
`isError` "The file arrived damaged; nothing was kept." Paths are resolved through the host's
roots (`roots/list`) as `fs.read_scoped`/`fs.write_scoped` require; outside → `isError` with a sentence.
Annotations: stat/read read-only; write not destructive.

## Steps
1. Read `docs/spec/capabilities.md` for the scoped fs rules and how other plugins check roots.
2. Implement with `node:fs/promises` handles; parts older than 1 h are cleaned at start.
