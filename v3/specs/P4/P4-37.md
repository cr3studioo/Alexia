# P4-37: Hub: mesh, devices, presence, notices that follow

Model: opus
Depends on: P3-31, P4-05, P4-06, P4-07, P4-11, P4-12, P4-13, P4-32
Feature IDs: HB-02, HB-03, HB-05, HB-06, HB-09, HB-18

## Goal
`alexia-hub run` starts the mesh node, hosts each paired device as a server through the dialer,
keeps track of where the owner is, makes notices follow them, and picks the best device per call.
`alexia-hub devices` pairs, lists, revokes and wakes devices. A device is also a face: its
notifications and replies are the gateway channel `device`.

## Interfaces
CLI:
```
alexia-hub devices                      list: id, name, platform, reach, last seen, plugins on it
alexia-hub devices pair                 prints the QR (terminal), the text, and writes <data>/pair.svg; waits up to 5 min
alexia-hub devices revoke <id>          revoke + remove its server
alexia-hub devices wake <id|hub>        sends WoL to a device's MACs (from its Hello)
```
Wiring in `run`, after step 2 of INTERFACES §2.6 and before `host.start`:
1. `Node::start(NodeConfig { keychain: KEYCHAIN_HUB, role: Hub, name: <computer name>, extra_addresses: <Tailscale 100.x addresses if any> })`.
2. `HostConfig.dial = Some(Arc::new(MeshDial(node)))`: `dial(id, args)` → `node.dial(&DeviceId(id))` → `into_stdio`; unreachable → `DialError::Offline`.
3. For each device row: `host.add_server(ServerEntry { id, name, run: "mesh", args: [endpoint] })` if absent; `set_reviewed(id, true)`.
4. Mesh events: `Online` → `host.restart(id)`, `Event::PeerOnline`; `Offline` → `Event::PeerOffline`; `Paired` → add the server; `Revoked` → `host.remove`.
5. Every 30 s, for offline devices, `node.connect(id)` (cheap when unreachable).
6. `node.serve_ops(..)`: `Presence` → presence table in memory + `Event::Active { via: <device id> }` when `idle_ms < 60 s`; `Face` → an inbound message on `DeviceChannel`; `Kill` → `Event` for P4-39 (logged until then).
7. `host.set_prefer(prefer)` implementing D-P4-9 with `presence::here`.
8. `gateway.set_follow(follow)`: `here()` → `Origin::Channel { channel: "device", chat: id }` for a device; the channel origin for a channel; None.
9. `DeviceChannel` (`name() = "device"`): `send`/`notify` → `call_capability_on("notify.show", device, ..)`; buttons map to `notify.show.buttons`; `next()` yields `Face` messages; `react`/`typing` no-ops.
Hello for the hub: `{ role: hub, platform: "win32", appVersion, wake: own_macs() }`.

### From the P4-11 review (CEO, 2026-11-28)
- `McpHost` honours `run: "mesh"` from any manifest, not only from `add_server` (alexia-mcp host.rs, the mesh branch before the process path). Your Dial adapter must refuse a link for a server that did not come from `add_server` (a folder plugin must not be able to open a device link with its own args). Add a test for that refusal.
- `McpHost` holds the spawn lock while it awaits `dial.dial` and puts no timeout on it. Your adapter must bound every dial (return `DialError::Offline` after a few seconds) so a hung link never blocks that server's calls. Add a test.
