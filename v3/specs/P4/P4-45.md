# P4-45: Bind the clipboard and file-courier tools to their capabilities

Model: sonnet
Depends on: P4-16, P4-17
Feature IDs: none (fixes P4-16 and P4-17)

## Goal
device-clipboard and file-courier declare their capabilities in plugin.json `provides`, but no tool
binds them with `_meta: { "alexia/provides": [...] }` (docs/spec/capabilities.md, "How a capability
reaches a tool"). So every capability call to them answers -32050, as if the plugin were missing.
After this task each capability they declare is bound by exactly one tool, and a test proves it.

## Touch only these paths
- plugins/device-clipboard/index.js   (change)
- plugins/device-clipboard/test/load.test.js   (change)
- plugins/file-courier/index.js   (change)
- plugins/file-courier/test/load.test.js   (change)

## Must not touch
Anything else, including the plugins' other files, plugin.json files, and packages/.

## Interfaces
For every capability `c` in the plugin's plugin.json `provides`, exactly one tool in the plugin's
tools/list carries `_meta: { "alexia/provides": [c] }`. Follow plugins/device-notify/index.js:61
(the tool binds only when its backend is present on this device, so a device without a clipboard
does not claim one). Capability-to-tool mapping: by name (clipboard.get -> the get tool, and so on);
read each plugin's index.js to find them.

## Steps
1. Read docs/spec/capabilities.md "How a capability reaches a tool" and plugins/device-notify/index.js.
2. Add the `_meta` binding to each tool of both plugins.
3. Extend each load.test.js: list the tools (as the existing load test starts the plugin), and
   check that the set of bound capabilities equals plugin.json `provides`, each bound once.

## Tests
- `every_declared_capability_is_bound_once` in each of the two load.test.js files.

## Done when
- `pnpm -s exec vitest run --project unit plugins/device-clipboard plugins/file-courier` passes
- `node v3/ci/invariants.mjs` exits 0
- `pnpm lint` and `pnpm typecheck` pass (do not run the full pnpm test: the machine is low on memory)

## Notes for the worker
On a device without a backend (for the clipboard: no Windows or macOS clipboard command), the
binding may be absent; the test then checks only that what is bound is in `provides`.
