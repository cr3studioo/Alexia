# P4-34: Core: local-only and guests applied in the loop

Model: opus
Depends on: P4-30, P4-31, P3-16
Feature IDs: TR-10, TR-11

## Goal
The agent loop applies the two new rules on every tool call, and a guest's turn runs as a guest:
a short guest prompt instead of the owner's profile, no memory recall or capture (P3-16's
capture is skipped), no skills that read the owner's data, and tools only from the guest list.

## Touch only these paths
- `v3/crates/alexia-core/src/agent.rs`   (change)
- `v3/crates/alexia-core/tests/guest_turns.rs`   (create)

## Must not touch
`prompt.rs` (P3-10 holds it: the guest prompt is a `const` in `agent.rs`), `chat.rs`, `tools.rs`,
`permissions.rs`, `run.rs`, other crates.

## Interfaces
Uses `permissions::{local_only, guest, guest_of, Guest}` (P4-30, P4-31).
- Ruling order for a call: `rule` → `proactive` (scheduler origin) → `local_only` → `guest` (when the turn's origin is a guest).
- `const GUEST_PROMPT: &str` (in `agent.rs`): "You are Alexia, talking with <name>, a guest of
  <owner>. You know nothing about <owner>'s life and must not guess. Be friendly and brief."
  (names filled at run time; owner name from `alexia/host/info`'s display name.)
- For a guest turn: the tool list offered to the model is only `scope.guest_tools`; recall and the
  owner profile are not added; P3-16's capture is not called; the run is not shown in the owner's
  activity feed as the owner's (audit keeps it, marked guest).
- Local-only turns: no change beyond the rule (the router does the rest).

## Steps
1. Rebase on P3-16 first; read how it calls capture and builds the prompt.
2. Insert the two rules where `proactive` is applied (line ~805 today).
3. Branch the turn setup on `guest_of(origin)`.
