# P4-31: Core: the guest rule

Model: opus
Depends on: P4-30, P4-03
Feature IDs: TR-11

## Goal
Core can tell that a turn comes from a guest and has the rule that limits what a guest's turn may
do: only tools the owner listed for guests (none by default), never anything that asks the
owner, never the owner's folders. P4-33 recognises guests at the gateway; P4-34 applies this in
the loop and keeps guests away from memory and the owner's sessions.

## Touch only these paths
- `v3/crates/alexia-core/src/permissions.rs`   (change: `guest`, `guest_of`)
- `v3/crates/alexia-core/src/run.rs`   (change: `Scope.guest_tools`)
- `v3/crates/alexia-core/tests/guest.rs`   (create)
- `v3/crates/alexia-core/tests/{permissions.rs, checker.rs}`   (change: `Scope` literals only)

## Must not touch
`agent.rs`, `chat.rs`, `prompt.rs`, `upcalls.rs`, `brain.rs`, `commands.rs`, other crates.

## Interfaces
```rust
// run.rs
pub struct Scope { /* existing + local_only */ /// (P4-31) kv `_core`/`guest_tools`: tool ids a guest's turn may use. Unreadable → empty.
    pub guest_tools: Vec<String> }
// permissions.rs
#[derive(Clone, Debug, PartialEq, Eq)]
pub struct Guest { pub id: i64, pub name: String }
/// The guest behind an origin, if any: `Origin::Channel { channel, chat }` looked up with
/// `Store::guest_of`. Every other origin → None.
pub fn guest_of(store: &Store, origin: &Origin) -> Option<Guest>;
pub const GUEST_BLOCKED: &str = "That isn't something Alexia does for guests.";
/// (P4-31, D-P4-12) For a guest's turn: Blocked unless the tool id is on `scope.guest_tools` and
/// is read-only or not destructive; never Ask (a guest cannot approve for the owner).
/// Applied after `rule`, `proactive` and `local_only`.
pub fn guest(ask: &CallAsk, scope: &Scope, ruling: Ruling) -> Ruling;
```
Path arguments in a guest call are always Blocked (no folders for guests), whatever the list says.

## Steps
1. `guest_of` with the store API from P4-03.
2. `guest` rule; `scope()` reads `guest_tools`.
