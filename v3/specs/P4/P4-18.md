# P4-18: device-notify: native notifications with a reply

Model: sonnet
Depends on: P4-15
Feature IDs: HB-06 (the device side)

## Goal
Alexia's notices can appear as the computer's own notifications, with up to three buttons and
an optional reply box, so when the owner is at the Mac a notice shows there instead of on
Telegram (D-P4-8). A button or reply comes back to the hub as a face message.

## Touch only these paths
- `plugins/device-notify/**`

## Must not touch
Other plugins, any crate, `pnpm-lock.yaml`.

## Interfaces
`notify.show {title, text, urgency:"low"|"normal"|"high"|"urgent", buttons?:[{label,data}] (≤3), reply?:bool, id?}`
→ `{shown:bool}`. The answer (button `data` or reply text) is returned as a progress-free
second result: the tool waits up to 60 s for an answer when `buttons` or `reply` is set and
returns `structuredContent: {answer?: {data?|text?}}`; after 60 s it returns `{answer: null}`
and the notification stays (the hub then treats any later click as nothing).
- Windows: a toast through PowerShell WinRT (`Windows.UI.Notifications.ToastNotificationManager`,
  AppId of PowerShell), actions and an input box; activation read back through the toast's
  `Activated` event in the same PowerShell process.
- macOS: `osascript` `display dialog` with buttons and `default answer` when buttons or reply are
  asked, else `display notification`. Urgent plays the default sound.
- `low` urgency is never shown as a dialog on macOS (notification only).

## Steps
1. Two backends behind one interface; the runner injectable for tests.
2. Escape all text for PowerShell/AppleScript (no string concatenation into code; pass by stdin/env).
