# P4-23: shell-runner: shell, scripts, installs, finished jobs

Model: opus
Depends on: P4-15
Feature IDs: PC-15, PC-16, PC-17

## Goal
Alexia can run a command or a script on any of the owner's computers (PowerShell on Windows, zsh
on the Mac), install software from the platform's package manager, and watch a long job (a
process, a command, a log file) and say when it finishes. Running anything that is not on a
small read-only list asks first, in every mode; installs always ask.

## Touch only these paths
- `plugins/shell-runner/**`

## Must not touch
Other plugins (`claude-code` runs code tasks; leave it), any crate, `pnpm-lock.yaml`.

## Interfaces
- `shell.run {command, shell?, cwd?, timeout_s?<=600}` → `{exit, stdout, stderr, truncated}`
  (each ≤ 64 KiB). Two tools: `shell_read` (`readOnlyHint: true`) accepts only commands whose first
  word is on the read-only list (`Get-ChildItem, Get-Content, Get-Process, Get-Service, Test-Path,
  ls, cat, pwd, whoami, git status, git log, git diff, df, du, ps, uname, which, where`) **and** that
  contain no `;`, `|`, `&`, `>`, `<`, backtick, `$(` or newline; `shell_run` (`destructiveHint`,
  `openWorldHint: true`) runs anything. `cwd` must be inside the roots.
- `software.install {name, source?}` → winget (`winget install --id <id> -e --accept-package-agreements`
  after `winget search` resolves the id and the tool result shows the publisher) or `brew install`.
  `destructiveHint`, `openWorldHint`. `software.search {name}` read-only.
- `job.watch {pid? | file?, says?}` → `{watch}`; `job.unwatch {watch}`. job.watch never starts a
  command (CEO #21, review of P4-01): `shell.run`/`shell_read` take `watch?: true, says?` to run a command in
  the background and return `{watch}` at once, under their own annotations. A finished
  watch becomes an item of this plugin's `notice.items` provider (P3 §3.6 shape) with urgency
  `normal`, text "<says or the job> finished (exit N)". Command watches are started by `shell.run`
  with `watch: true` (same rules as `shell_run`/`shell_read`). File watches finish when the file has not grown for 60 s or a line
  matches `done_when` regex.
- Environment: children get a minimal environment (PATH, HOME/USERPROFILE, TEMP, LANG) — no
  `ALEXIA_SECRET_*`, no plugin env. Children are killed with their tree on timeout and on cancel.

## Steps
1. Read `docs/spec/capabilities.md` (`proc.spawn`, `notice.items`) and `plugins/claude-code` for
   how a plugin runs a child and reports progress.
2. Implement the read-only classifier first, with tests that try to escape it.
3. Output streaming as `notifications/progress` while running.

## Tests

`ls; rm`, `cat x | sh`, `$(..)`, backticks, newlines, unicode lookalikes, `Get-ChildItem -Path x -Recurse | Remove-Item`),
`timeout_kills_tree`, `cancel_kills`, `env_is_minimal` (a secret-looking variable set in the
parent is absent in the child), `output_cut_with_note`, `cwd_outside_roots_refused`,
`winget_id_resolved_before_install` (runner faked), `watch_pid_finishes_notice`, `watch_file_quiet_60s` (fake clock).
