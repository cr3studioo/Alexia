# P4-41: The window joins the handoff

Model: sonnet
Depends on: P3-16, P4-32
Feature IDs: HB-04

## Goal
Opening Alexia's window on the PC in the middle of a Telegram conversation shows that same
conversation and continues it, and a reply that was still being written goes to the window; the
reverse works too. The window becomes one more face in P4-32's handoff.

## Touch only these paths
- `v3/crates/alexia-api/src/chat.rs`   (change)
- `v3/crates/alexia-api/tests/handoff.rs`   (create)
- (CEO #23) `v3/crates/alexia-api/src/lib.rs` and `v3/crates/alexia-api/Cargo.toml`   (change, only to hold a `Gateway` clone in the api state, and the alexia-gateway dependency if missing)
- (CEO #23) `v3/crates/alexia-hub/src/main.rs`   (change, only the lines that pass the hub's `Gateway` clone to the api and register the window channel)

## Must not touch
`alexia-gateway/**`, other api modules, `packages/ui` (the page already shows whatever session the API says is current).

## Interfaces
Uses `Gateway`'s handoff state from P4-32. If P4-32 did not expose it, add nothing to the
gateway here: escalate. Expected: `Gateway::current_session(within_ms) -> Option<(SessionId, Origin)>`
and `Gateway::moved_to(session, origin)`.
- `GET /api/chat/current` (or whichever route the window uses to pick its session; read `chat.rs`)
  returns the gateway's current owner session when its last turn is within `HANDOFF_MS`.
- A message sent from the window into that session calls `moved_to(session, Origin::Window)`.

## Steps
1. Rebase on P3-16 (it changes `chat.rs`).
2. Find how the window chooses its session today; add the handoff branch.

- (CEO #23) Facts from P4-46 (merged): `Gateway` is `Clone` (routes in a shared Arc), so the hub
  keeps a clone and hands one to the api. An unprompted Say after `moved_to(session, Origin::Window)`
  reaches the window only through a gateway channel named `window`; no such channel exists yet.
  This task registers one: a channel named `window` whose sends land in the session the window
  shows (the api's existing chat event stream). If none is registered, Says go to the chats as
  before, so nothing is lost. `current_session` is None until the chat's first message was seen.
  Read the doc comments on `current_session`, `moved_to` and `followed_face` in gateway.rs.
