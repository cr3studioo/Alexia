# P4-13: Core: one tool across devices, with a `device` argument

Model: opus
Depends on: P4-11
Feature IDs: HB-09, HB-03

## Goal
The model sees each tool once. When the same `<plugin>.<tool>` is offered by the hub's own plugin
and by limbs (or by several limbs), the model gets one tool with an optional `device` argument
listing the devices that have it, and the description says the default is the device the owner
is using. A call with `device` goes there; without it, the hub's preference picks (P4-12).
Tools only one limb has keep the device in their name.

## Touch only these paths
- `v3/crates/alexia-core/src/tools.rs`   (change: building the model's tool list and routing a call)
- `v3/crates/alexia-core/tests/device_tools.rs`   (create)

## Must not touch
`agent.rs`, `chat.rs` (P3-16), `prompt.rs` (P3-10), `upcalls.rs`, `brain.rs` (P3-35/36),
`alexia-mcp/**`.

## Interfaces
Hosted tools from a remote server arrive as `HostedTool { plugin: <device id>, device: Some(<device id>), tool.name: "<plugin>.<tool>" }` (P4-11).
Local tools are `HostedTool { plugin, device: None, tool.name }` and are exposed today as `<plugin>__<tool>`.
- Merge key: `(<plugin>, <tool>)`, where a local tool's key is `(plugin, name)` and a remote one's is the split of `name` at its first `.`.
- Merged name: the local form `<plugin>__<tool>`; schema = the local one (else the first remote's)
  plus `"device": {"type":"string","enum":["hub", <device ids>],"description":"Which computer. Leave out for the one the owner is using."}`.
  The enum lists only devices whose server is not `Stopped` at list time, plus `hub` when local.
- Unmerged remote tool: name `<device id>__<plugin>.<tool>` as today's namespacing already gives.
- Routing: strip `device`; `"hub"` → local plugin; a device id → that remote server's tool;
  absent → `McpHost::call_capability_on`-style preference: first of `prefer(cap, providers)` where
  `cap` is the tool's first `alexia/provides` entry, else the local one.
- Annotations of a merged tool: the most cautious of the merged ones (destructive or open world if any is).
- Permissions see the real target (`CallAsk.tool` = the resolved `<device>__<plugin>.<tool>` or local id).
