# P4-14: Limb: its plugins' upcalls go to the hub

Model: opus
Depends on: P4-09, P3-35
Feature IDs: HB-03, HB-09

## Goal
A plugin running on the Mac can still ask for a model (`sampling/createMessage`), call a
capability another device provides (`alexia/capability/call`), run compute (`alexia/compute/run`),
ask the owner (elicitation, P3-35/36) and read host facts, exactly as on the hub. The limb's
`Upcalls` forwards those to the hub as server → client requests over the link (D-P4-4). Storage
and settings stay on the device. With no hub connected, each answers a sentence error.

## Touch only these paths
- `v3/crates/alexia-limb/src/upcalls.rs`   (create)
- `v3/crates/alexia-limb/tests/upcalls.rs`   (create)

## Must not touch
`serve.rs`, `main.rs`, `cli.rs` except one line in `main.rs` to install `Forward` instead of
`NoUpcalls` (allowed), `alexia-mcp/**`, `alexia-core/**`.

## Interfaces
```rust
/// The limb's Upcalls: forwards over the current link, if any.
pub struct Forward { /* the active link's request sender, swapped when a new link arrives */ }
impl Forward { pub fn new() -> Arc<Forward>; pub fn attach(&self, peer: serve::PeerRequests); pub fn detach(&self); }
#[async_trait::async_trait] impl alexia_mcp::Upcalls for Forward { /* every method of the trait as it is after P3-35 */ }
```
`serve::PeerRequests` is the handle P4-09's `serve` uses to send requests to the hub; if P4-09 did
not expose one, add a `pub fn requests(&self) -> PeerRequests` in `serve.rs` (allowed: one function).
Mapping:
- `sample` → `sampling/createMessage` to the hub, params unchanged, progress forwarded, cancel → `notifications/cancelled`.
- `elicit` → `elicitation/create` to the hub (the hub's host already handles it from a plugin: P3-35).
- capability call / compute run → `alexia/capability/call` / `alexia/compute/run` to the hub.
- `host_facts` → cached `alexia/host/info` from the hub at link start; device name added.
- `roots` → the limb's own scope (folders the owner chose on this device, kv `_limb`/`roots`).
- `offers` → what the hub offered at the last `initialize`, minus anything absent now.
- No link → `RpcError` -32050 "The PC isn't reachable right now, so this can't be done on the Mac."

On the hub side, nothing new: the limb is a plugin to `McpHost`, so these requests are served by
the hub's `Upcalls` like any plugin's (with the limb's server id as `plugin`).
