# P4-09: Limb: the device's plugins served to the hub

Model: opus
Depends on: P4-06
Feature IDs: HB-03, HB-02, HB-05

## Goal
`alexia-limb` becomes a real program. It keeps its own small store, hosts the plugins the owner
enabled on this device with the same `McpHost` the hub uses, and serves all their tools to its
paired hub as **one MCP server** over the link (D-P4-4). It reports presence to the hub every
30 s. It can pair, unpair, list and enable plugins from the command line.

## Touch only these paths
- `v3/crates/alexia-limb/src/main.rs`   (fill)
- `v3/crates/alexia-limb/src/cli.rs`   (create: argument parsing and the commands)
- `v3/crates/alexia-limb/src/serve.rs`   (create: the MCP server face)
- `v3/crates/alexia-limb/src/service.rs`   (create: stub `pub fn install()`/`uninstall()` returning "not yet", P4-10 fills)
- `v3/crates/alexia-limb/tests/limb.rs`   (create)

## Must not touch

`alexia-mesh/**`, other crates.

## Interfaces
CLI (`alexia-limb <cmd>`; plain sentences on stdout, exit 1 with a sentence on failure):
```
run                      start: store, McpHost (NoUpcalls until P4-14), Node (KEYCHAIN_LIMB, role limb),
                         accept_links, presence loop. Ctrl+C stops cleanly.
pair "<alexia-pair:1?..>" join the hub; prints "Paired with <hub name>."
unpair                   revoke the hub (store + allowlist)
status                   endpoint id, hub, reach, enabled plugins, their states
plugins [enable|disable <id>]   list found plugins / switch one (kv `_limb`/`enabled`)
install | uninstall      service::install / uninstall (P4-10)
```
Data: `Layout::new(alexia_store::data_dir().join("limb"))` (never the hub's own folder, which
the fallback brain uses on a Mac, D-P4-6). Plugin folders: `<limb data>/extensions` then
`ALEXIA_PLUGINS_DIR` if set.

`serve.rs`:
```rust
/// Serve one link as an MCP server (revision 2025-11-25) until it closes.
pub async fn serve(link: alexia_mesh::link::Link, host: alexia_mcp::McpHost, facts: Facts) -> ();
pub struct Facts { pub device_name: String, pub platform: &'static str }
```
- `initialize` → `serverInfo { name: "alexia-limb", version }`, capabilities `{ tools: { listChanged: true } }`.
- `tools/list` → every enabled plugin's tools as `<plugin>.<tool>`, `inputSchema`, `annotations`,
  `_meta` copied (`alexia/provides` included), plus the limb's own `device.presence` (read-only,
  provides `device.presence`). Hidden tools stay hidden.
- `tools/call` → `McpHost::call_tool(plugin, tool, args, ctx)`; `isError` passed through;
  progress forwarded; `notifications/cancelled` cancels.
- `PluginEvent::ToolsChanged` → `notifications/tools/list_changed` to the hub.
- `ping` answered. Anything else → method not found.
- Presence: every 30 s while a hub link is open, `presence::idle_now()` → `send_op(hub, Presence)`.

## Steps
1. `cli.rs` with a hand-written parser like the hub's.
2. `run`: open store and host (`HostConfig` with the limb layout), start enabled plugins, start
   the node and `accept_links`; one link at a time (a new one replaces the old).
3. `serve.rs` with `alexia_mcp::jsonrpc` types for framing; requests handled concurrently.
4. `device.presence` builtin.
