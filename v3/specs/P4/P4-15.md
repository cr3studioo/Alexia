# P4-15: Ten plugin skeletons and the lockfile

Model: sonnet
Depends on: P4-01
Feature IDs: none (enables HB-06, HB-07, HB-08, HB-17, PC-03..PC-20)

## Goal
The ten new P4 plugins exist as empty, loadable folders with their manifests' `provides` set
from P4-01, so each later task fills one folder and never touches `pnpm-lock.yaml`.

## Touch only these paths
- `plugins/{device-clipboard, file-courier, device-notify, window-deck, file-finder, pc-care, shell-runner, browser-pilot, screen-ink, screen-look}/{package.json, plugin.json, index.js, test/load.test.js}`   (create)
- `pnpm-lock.yaml`   (change: only what `pnpm install` writes)

## Must not touch
Other plugins, `packages/`, any crate.

## Interfaces
`package.json` as `plugins/task-list/package.json` (`@alexia/plugin-<id>`, private, module,
AGPL-3.0-only, `@alexia/sdk: workspace:*`). `plugin.json`: `manifest_version: 1`, `id`, `name`,
`summary`, `version: "0.1.0"`, `license`, `entry {run:"node", args:["index.js"]}`,
`alexia_protocol: 3`, `mcp_protocol: "2025-11-25"`, `requires` and `provides` below.

| id | name | summary | provides | requires |
|---|---|---|---|---|
| device-clipboard | Clipboard | Your clipboard on this computer, its history, and copying between your devices. | clipboard.get, clipboard.set, clipboard.history | proc.spawn, fs.own_dir |
| file-courier | File courier | Moves files between your computers, in pieces, checked at the end. | file.stat, file.read_chunk, file.write_chunk | fs.read_scoped, fs.write_scoped |
| device-notify | Notifications | Shows Alexia's notices on this computer, and takes your reply. | notify.show | proc.spawn |
| window-deck | Windows | Opens, arranges and closes apps and windows, and remembers layouts. | window.list, window.arrange, window.layout.save, window.layout.apply, app.quit | proc.spawn, fs.own_dir |
| file-finder | Find and tidy | Finds files instantly and keeps folders tidy, asking before it moves anything. | file.search, folder.tidy | proc.spawn, fs.read_scoped, fs.write_scoped, fs.own_dir |
| pc-care | Computer care | Volume, brightness, dark mode, disk space, startup apps, and sleep or restart when you ask. | system.get, system.set, system.care, power.do | proc.spawn |
| shell-runner | Shell | Runs commands and scripts, installs software, and tells you when long jobs finish. | shell.run, software.install, job.watch, notice.items | proc.spawn, fs.read_scoped, fs.own_dir |
| browser-pilot | Browser | Reads and works in your own browser through Alexia's extension. | browser.tabs, browser.read, browser.click, browser.fill, browser.open | net.listen, fs.own_dir |
| screen-ink | Screen ink | Draws arrows, boxes and her own cursor on your screen to show you things. | screen.draw, screen.clear, cursor.show | proc.spawn |
| screen-look | Look at my screen | Looks at your screen, reads any text on it, and helps with what you're doing. | screen.look, screen.help, screen.text | computer.screenshot, image.ocr, vision.describe |

`index.js`: the SDK's `plugin()` with no tools, SPDX first line, a comment naming the task that fills it.

## Steps
1. Create the forty files.
2. `pnpm install` at the repo root; commit the lockfile change it makes and nothing else.
3. `node v3/ci/invariants.mjs`: none of the ten ids may appear quoted in any crate.

## Tests
`test/load.test.js` per plugin (node:test, like `plugins/task-list/test/load.test.js`): manifest
parses, `id` equals the folder name, `provides` matches the table, `index.js` imports.

## Done when
- `pnpm check` passes at repo root (known LATER failures aside)
- `node v3/ci/invariants.mjs` exits 0
- `CARGO_TARGET_DIR=D:/alexia-target/P4-15 cargo run -p alexia-hub -- plugins` with
  `ALEXIA_PLUGINS_DIR=<repo>\plugins` lists the ten ids, none refused
- `cargo fmt --all --check` and `cargo test --workspace` unaffected (no Rust changed)

## Notes for the worker
- A capability a plugin *requires* that nothing provides yet is fine: the manifest says why.
  Check `docs/spec/manifest.md` for whether `requires` must list only host capabilities; if a
  `requires` entry above is refused by the host, move it to the plugin's own runtime check and say so.
- `screen-look` requiring `vision.describe`: the host answers it (P2-34) when a model is set.
