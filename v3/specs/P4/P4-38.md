# P4-38: Hub: the clipboard follows, files move between devices

Model: sonnet
Depends on: P4-37, P4-16, P4-17
Feature IDs: HB-07, HB-08

## Goal
Copy on the Mac, sit down at the PC, paste: when the owner moves to another device within two
minutes of copying, the hub carries the clipboard text over (if they turned "clipboard follows
me" on). And "send the report on my Mac to the PC" is one tool: the hub reads the file in pieces
from one device and writes it on the other, checked at the end.

## Touch only these paths
- `v3/crates/alexia-hub/src/carry.rs`   (create)
- `v3/crates/alexia-hub/src/main.rs`   (change: one line to start it and add the builtin)
- `v3/crates/alexia-hub/tests/carry.rs`   (create)

## Must not touch
`devices.rs`, `face.rs` (use their pub API), other crates.

## Interfaces
- Setting kv `_core`/`clipboard_follows` (bool, default false; set with `alexia-hub devices clipboard on|off`, added to the CLI in `main.rs`).
- On a presence change A → B (from P4-37's presence state; subscribe to `Event::Active`): if on,
  `clipboard.get` on A; if `at` is within 120 s, not `sensitive`, `kind == "text"`, and differs from B's
  `clipboard.get`, then `clipboard.set` on B. Never logs text.
- Builtin tool `devices.send_file {from, path, to, folder?}` (a core `Builtin`, like the scheduler's
  tools): `file.stat` on `from`, then `file.read_chunk` / `file.write_chunk` 1 MiB at a time with the
  sha256, progress reported; result "Sent <name> (<size>) to <to>: <path>". Annotations: not
  read-only, not destructive, not open world (it stays on the owner's devices). `from`/`to` are
  device ids or `hub`.

## Steps
1. Read P4-37's `devices.rs` pub API; subscribe to the bus.
2. Implement both; register the builtin.

## Tests
