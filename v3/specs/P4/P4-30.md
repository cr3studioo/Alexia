# P4-30: Core: the local-only rule

Model: opus
Depends on: none
Feature IDs: TR-10

## Goal
Core knows a "local-only" switch (kv `_core`/`local_only`, D-P4-11) and enforces it in the two
places that decide what leaves the computer: the router never picks a cloud provider for any
job, and the permission rules block every outward-facing tool. With no local model installed,
a turn answers a plain sentence instead of quietly going to the cloud. This task writes the rules
and their tests; P4-34 calls them in the loop and P4-39 adds the switch.

## Touch only these paths
- `v3/crates/alexia-core/src/router.rs`   (change: honour local-only)
- `v3/crates/alexia-core/src/permissions.rs`   (change: `local_only`, reading the flag in `scope`)
- `v3/crates/alexia-core/src/run.rs`   (change: `Scope.local_only`)
- `v3/crates/alexia-core/tests/local_only.rs`   (create)
- `v3/crates/alexia-core/tests/{permissions.rs, checker.rs}`   (change: `Scope` literals gain the field, nothing else)

## Must not touch

## Interfaces
```rust
// run.rs
pub struct Scope { /* existing */ /// (P4-30, TR-10) kv `_core`/`local_only` is true. Unreadable → false.
    pub local_only: bool }
// permissions.rs
/// The sentence for a tool local-only blocks.
pub const LOCAL_ONLY_BLOCKED: &str = "Local-only mode is on, so Alexia won't {doing}: it would reach outside your computers.";
/// (P4-30, D-P4-11) Narrows a ruling when `scope.local_only`: an `openWorldHint: true` tool is
/// Blocked; everything else unchanged. Applied after `rule` and after `proactive`.
pub fn local_only(ask: &CallAsk, scope: &Scope, ruling: Ruling) -> Ruling;
/// The flag itself, for callers without a Scope (router, hub).
pub fn is_local_only(store: &Store) -> bool;
// router.rs
pub const NO_LOCAL_MODEL: &str = "Local-only mode is on and no model is installed on this computer, so Alexia can't answer. Install one in Models, or turn local-only off.";
```
Router: when `is_local_only(store)` (read per request; cheap kv read, or cached with
`SettingsChanged`), only providers registered with `set_provider(.., local: true)` are
candidates for every job (chat, steps, vision, check), hedging is off, and an empty candidate
list yields an error whose text is `NO_LOCAL_MODEL`. Subscription CLIs (`claude`, etc.) are cloud.

## Steps
1. Find where the router builds its candidate list for a job; filter there.
2. `scope()` reads `local_only` like it reads `silent`.
3. `local_only()` mirrors `proactive()`'s shape; Blocked stays Blocked.

## Tests
