# P4-06: The link: MCP over the mesh, and the hub's operations

Model: opus
Depends on: P4-04
Feature IDs: HB-02, HB-03, TR-05

## Goal
The hub can open a long-lived, two-way, newline-delimited JSON-RPC stream to a paired limb, and
hand its two ends to `McpHost` as if they were a plugin's stdin and stdout. The limb accepts that
stream from its paired hub only. Small hub operations (kill, presence, face) let a limb tell the
hub things without waiting to be asked. This is the whole transport of D-P4-5.

## Interfaces
```rust
// link.rs
/// One duplex JSON-RPC line stream. Lines in and out, keepalives hidden.
pub struct Link { pub rx: tokio::sync::mpsc::Receiver<String>, pub tx: tokio::sync::mpsc::Sender<String>, pub closed: CancellationToken }
impl Node {
    /// Hub → limb: POST {bridge}/{endpoint}{LINK_PATH}, streaming body both ways. Err(Unreachable)
    /// within 15 s if the peer cannot be reached; Err(Refused) on connect's refusal codes.
    pub async fn dial(&self, device: &DeviceId) -> Result<Link>;
    /// Limb: serve the host service on 127.0.0.1 (random port), register it with connect
    /// (`PUT /v1/host`, operation `link` POST LINK_PATH, with a host secret), and hand each
    /// accepted link to `on_link`. A request whose `x-alexia-peer` is not a paired *hub* gets 403.
    pub async fn accept_links(self: &Arc<Self>, on_link: impl Fn(DeviceId, Link) + Send + Sync + 'static) -> Result<()>;
}
/// The same two ends as OS pipes, typed as tokio's `ChildStdin`/`ChildStdout` (as `alexia-mcp`'s
/// wasm guest does), for `McpHost`'s `Dial` (P4-11). Pumps run until either side closes.
pub fn into_stdio(link: Link) -> std::io::Result<(tokio::process::ChildStdin, tokio::process::ChildStdout)>;

// ops.rs
pub enum HubOp { Kill { from: DeviceId }, Presence { from: DeviceId, idle_ms: u64, locked: bool }, Face { from: DeviceId, text: String, reply_to: Option<String>, data: Option<String> } }
impl Node {
    /// Hub: register the three hub operations with connect and deliver each request to `on_op`.
    pub async fn serve_ops(self: &Arc<Self>, on_op: impl Fn(HubOp) + Send + Sync + 'static) -> Result<()>;
    /// Limb: send one operation to its hub. Err(Unreachable) if the hub cannot be reached in 5 s.
    pub async fn send_op(&self, hub: &DeviceId, op: &HubOp) -> Result<()>;
}
```
A node that is both a link server and an ops server registers one host service holding all its
operations (connect keeps one registration). Frame rules: each JSON-RPC message is one line;
every 5 s of silence each side writes `"\n"`; empty lines read are dropped before `rx`; a line
over 16 MiB closes the link with a warn (no content logged).

## Steps
1. Hub side: hyper client over TCP to connect's loopback port, `Authorization: Bearer <secret>`,
   a streaming request body fed from `tx` and a response body read into `rx` line by line.
2. Limb side: a hyper http1 server on 127.0.0.1; check `Authorization` (host secret) and
   `x-alexia-peer` against `devices` (role hub, not revoked); stream both ways.
3. Keepalive timers on both sides; `closed` fires when either body ends or errors.
4. `into_stdio`: OS pipe pairs (`std::io::pipe`), two pump tasks.
5. Ops: JSON bodies ≤ 64 KiB; `face.text` ≤ 4096 chars.

## Tests
`tests/link.rs` (two paired ephemeral nodes, pairing rows written directly):
- `lines_both_ways` (100 lines each way, in order);
- `link_survives_60_s_idle` (paused or real 60 s with keepalives; the link is still open and
  connect reports the peer `direct`). Use real time with a 60 s cap; mark `#[ignore]` only if CI
  time forbids, and then add a 20 s version that is not ignored;
- `hub_drop_closes_limb_side` and the reverse;
- `unpaired_peer_gets_refused` (a third node with no row → `Refused`);
- `limb_refuses_a_limb` (a peer row with role limb dialling → 403);
- `into_stdio_round_trip`;
- `ops_reach_the_hub` (each of the three, and a malformed body → 400, no callback).
