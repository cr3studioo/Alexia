# P3-35: Hosts offer elicitation to plugins: a plugin form becomes an owner prompt

Model: opus (security-related: the only way a plugin's email is ever sent)
Depends on: P3-05 (merged: this task changes `alexia-mcp/src/host.rs` and
`src/bin/mcp-fixture.rs`, which P3-05 also changes), P3-24 (merged: the plugins that use it)
Feature IDs: DY-06 (sending email for you, always asks; D214)

Part 1 of 2. This task is the host side: the types, what `initialize` offers, which tool call
an elicitation belongs to, and the end of that call ending the question. **P3-36** puts the
question in front of the owner (window chat and Telegram) and sends the answer back.

## Goal
`google-account` and `microsoft-account` `mail.send` (P3-24) ask the owner through MCP form
elicitation (`elicitation/create`) and send only on an explicit accept. Anything else (decline,
cancel, timeout, no elicitation offered) means not sent. The plugins need two things from the
host. First, an `initialize` that clearly offers form elicitation, and only to plugins the owner
trusts. Second, a question that ends when the tool call that raised it ends, so a late yes can
never send mail after the model was told the call failed. After this task the host has both. It
also tells core which tool call (which conversation) an elicitation belongs to, so P3-36 can ask
in that chat.

**Which host.** P3 runs plugins through the v3 hub (`v3/crates/alexia-mcp`, wired in
`alexia-hub/src/main.rs` with `host.set_upcalls(agent)`). That is what this pair of tasks
changes. v2's `packages/core/src/supervisor.ts:287-291` declares only `{ roots, sampling }`.
It stays as it is: PHASE.md keeps `packages/core` out of P3, and on v2 every send correctly
ends with "Not sent: Alexia could not ask you here, and only your yes sends mail." So v2 keeps
working and never sends.

**What is there today (read before starting).** `alexia-core/src/upcalls.rs:810-818` already
offers `elicitation: {}` to every plugin. `Agent::elicit` (`upcalls.rs:1010-1030`) accepts one
boolean field and puts it to `Ask::confirm` on the owner's primary chat. Three problems:

- The gateway waits up to 10 minutes (`ANSWER_WAIT`). The host gives a `tools/call` only 120 s
  (`Timings::call_ms`). The plugin waits 5 minutes (`ASK_MS`). So a yes given in minute 3
  sends the mail, although the model was already told at minute 2 that the call failed.
- "No answer", "nowhere to ask" and "denied" all come back as `accept {field: false}`.
- The question text (the whole email) is stored in `approvals.text`.

This task fixes the first problem. P3-36 fixes the other two.

## Interfaces
```rust
// alexia-mcp/src/types.rs. 2025-11-25 shape. An older plugin reads {"form":{}} as "elicitation
// offered", and the SDK 2.0 that @alexia/sdk uses requires `form` (its elicitInput throws
// "Client does not support form elicitation." without it).
#[derive(Clone, Debug, Default, Serialize, Deserialize)]
pub struct ElicitationCaps {
    #[serde(skip_serializing_if = "Option::is_none")] pub form: Option<Empty>,
    /// Never offered in P3: Alexia does not open links a plugin hands it.
    #[serde(skip_serializing_if = "Option::is_none")] pub url: Option<Empty>,
}
pub struct ClientCapabilities {
    pub roots: Option<Empty>,
    pub sampling: Option<Empty>,
    #[serde(skip_serializing_if = "Option::is_none")] pub elicitation: Option<ElicitationCaps>,
}

// alexia-mcp/src/lib.rs
/// The `tools/call` an `elicitation/create` arrived during: the newest call to that plugin
/// still in flight when the request came. None when no call was in flight.
#[derive(Clone, Debug)]
pub struct During {
    /// That call's `CallCtx.conversation` (a `SessionId` as a decimal string), if it had one.
    pub conversation: Option<String>,
    /// Cancelled when that call ends however it ends: answered, timed out, cancelled, or the
    /// plugin gone.
    pub ended: CancellationToken,
}
pub trait Upcalls: Send + Sync {
    // .. unchanged ..
    /// `cancel` fires when the plugin cancels its request (`notifications/cancelled`) or the
    /// connection ends.
    async fn elicit(
        &self,
        plugin: &PluginId,
        params: serde_json::Value,
        during: Option<During>,
        cancel: CancellationToken,
    ) -> Result<serde_json::Value, jsonrpc::RpcError>;
}

// alexia-core/src/brain.rs (re-exported from the crate root by the existing `pub use brain::*`)
/// How long the owner has to answer a plugin's question. Below `Timings::call_ms` (120 s) with
/// margin, so the answer always reaches the plugin while its tool call is still alive.
pub const ELICIT_WAIT: std::time::Duration = std::time::Duration::from_secs(100);

/// A plugin's yes/no form, put to the owner.
#[derive(Clone, Debug)]
pub struct Elicitation {
    /// The run whose tool call asked (so the window watching it can show it), else
    /// `RunId(format!("elicit-{plugin}-{ms}"))`.
    pub run: RunId,
    /// The plugin's id.
    pub plugin: String,
    /// The plugin's manifest name.
    pub name: String,
    /// The form's `message`, exactly as the plugin sent it.
    pub message: String,
    pub wait: std::time::Duration,
}
impl Elicitation {
    /// What the owner reads. Always names the plugin, by name and id (two plugins can share
    /// a name): `"{name} ({plugin}) asks:\n\n{message}"`.
    pub fn prompt(&self) -> String;
}

/// MCP's three answers. Accept only on the owner's own yes.
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum Elicited { Accept, Decline, Cancel }
impl Elicited {
    /// "accept" | "decline" | "cancel": the only thing ever logged about an answer.
    pub fn as_str(self) -> &'static str;
}

pub trait Ask: Send + Sync {
    async fn confirm(&self, origin: &Origin, question: &Question, cancel: CancellationToken) -> bool;
    /// Default, for the test fakes: `confirm` with `prompt()` as the text, inside
    /// `tokio::time::timeout(e.wait, ..)`. true → Accept, false → Decline, elapsed or
    /// `cancel` → Cancel. The gateway overrides it (P3-36).
    async fn elicit(&self, origin: &Origin, e: &Elicitation, cancel: CancellationToken) -> Elicited { .. }
}
```

**Who is offered elicitation (`Agent::offers`):** `elicitation: Some(ElicitationCaps { form:
Some(Empty {}), url: None })` only for a plugin that is **reviewed**: its id is not on kv
`_core`/`unreviewed`, read fail-closed the way `McpHost::tools` reads it (`host.rs:350-375`).
An unreadable or malformed list means nobody is offered. Everything else gets `elicitation:
None`:

- **MCP servers added with `add_server`** (kv `_core`/`servers`, "MCP server. Not an Alexia
  plugin. Not reviewed by us."). They start unreviewed (`host.rs:1474`), so they are offered
  elicitation only after the owner marks that server reviewed in Settings › Plugins, and from
  its next start.
- **Any folder plugin the owner marked unreviewed.**
- **Limbs** (V3-4) and anything else that is not an `McpHost` plugin. They are not hosted here,
  so they are never offered.

The v3 host runs no remote (network) MCP server today. One added later is an `add_server`
entry and falls under the same rule. `elicit` checks the rule again on every request (a server
marked unreviewed since it started is refused with `MISSING_REQUIRED_CLIENT_CAPABILITY` and
nobody is asked).

## Steps
1. `types.rs`: `ElicitationCaps`, and change the field. Fix the two `ClientCapabilities`
   builders (`NoUpcalls`, `upcalls.rs`) and `tests/compute.rs`.
2. `lib.rs`: `During`, and the new `Upcalls::elicit` signature. `NoUpcalls::elicit` is
   unchanged in what it answers.
3. `host.rs`: keep per plugin a list of the calls in flight, each `(seq, conversation, ended)`,
   pushed in `call_tool_within` before the `tools/call` request and removed by a drop guard
   that also cancels `ended`, so a timeout, a cancel, an error or a crash all end it. In
   `Handler::request`, `"elicitation/create"` passes the newest entry's `During` (or None) and
   the request's own `cancel` (the one sampling already gets). `call_capability_as` goes
   through `call_tool_within` too, so check it is covered. Do not change any timing.
4. `brain.rs`: the types and the default `Ask::elicit`.
5. `upcalls.rs`: `offers` per the rule above. `elicit` keeps today's routing (P3-36 replaces
   it). Its one change: the `confirm` it awaits gets a token that is cancelled when
   `cancel` or `during.ended` fires, so the question never outlives the call. Then it answers
   `{"action":"cancel"}`. The refusal of any form other than one boolean field, and of
   `mode: "url"`, stays as it is.
6. `mcp-fixture.rs`: mode `ask`. Tool `ask {message, wait_ms?}` sends `elicitation/create`
   with a one-boolean form (`send`) and returns the host's answer as JSON text. Tool `caps`
   returns the `capabilities` its `initialize` received. Tool `ask_late {message, after_ms}`
   returns at once and sends the elicitation `after_ms` later, outside any call.
7. INTERFACES.md: the four places listed in *Touch only these paths*. Change the §3 line
   "`+ "elicitation":{}` when there is somewhere to ask" to
   `+ "elicitation":{"form":{}}` for a reviewed plugin (P3-35).

## Notes for the worker
- The plugins' side is `plugins/google-account/mail.js` `askToSend` (and the same function in
  `plugins/microsoft-account/mail.js`). Read it: the form is
  `{mode:"form", message, requestedSchema:{type:"object", properties:{send:{type:"boolean"}},
  required:["send"]}}`, sent with a 5-minute SDK timeout. Only `accept` with
  `content.send === true` sends. `plugins/mail-desk/voice.js` never elicits itself. It calls
  the account plugin's `mail.send`, which asks.
- Why the call must end the question: `conn.request("tools/call", .., timeout)` gives up at
  `call_ms`, and the model hears "the plugin did not answer in time". If the question stayed
  open, a later yes would still send the mail. This is a real send of the owner's mail, so
  test the end of the call, not just the happy path.
- `ELICIT_WAIT` is 100 s on purpose. A longer wait needs the call's deadline to move while a
  question is open (a change to `conn.rs`), which is not this task. Leave a `// ponytail:`
  line where the wait is used.
- Nothing about an elicitation is logged here: no `tracing` call with `params`, and no message
  text in any error.
- 16 GB RAM: `CARGO_BUILD_JOBS=1`, per-crate tests while working. `alexia-mcp/tests/supervise.rs`
  can hang under load (P2D L7). If it does in the final run, run it alone and say so.
- Windows: the fixture runs in a Job Object like any plugin. Kill nothing yourself.
