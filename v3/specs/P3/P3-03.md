# P3-03: Ten plugin skeletons and the lockfile

Model: sonnet
Depends on: P3-02
Feature IDs: none (makes room for the plugin tasks)

## Goal
The ten new plugin folders exist, each a valid plugin that loads, says hello and offers no
tools yet, and `pnpm-lock.yaml` knows them. After this, each plugin task touches only its own
folder, so they can run side by side without fighting over the lockfile.

## Touch only these paths
For each id in `google-account`, `microsoft-account`, `day-planner`, `mail-desk`, `task-list`,
`page-watch`, `notes-library`, `screen-memory`, `study-desk`, `errand-kit`:
- `plugins/<id>/package.json`   (create)
- `plugins/<id>/plugin.json`   (create)
- `plugins/<id>/index.js`   (create)
- `plugins/<id>/test/load.test.js`   (create)

And:
- `pnpm-lock.yaml`   (change, by `pnpm install` only)

## Must not touch
Existing plugins, `packages/`, any crate. No dependency beyond `@alexia/sdk`, except
`errand-kit`, which also takes `pdf-lib` (pinned exact version, for P3-30's form filling).

## Interfaces
`package.json` as `plugins/commitments/package.json`: `"name": "@alexia/plugin-<id>"`,
`"private": true`, `"type": "module"`, `"license": "AGPL-3.0-only"`, `@alexia/sdk:
workspace:*`.

`plugin.json`: `manifest_version: 1`, `id`, `name`, `summary` (one sentence, below),
`version: "0.1.0"`, `license: "AGPL-3.0-only"`, `entry: {run: "node", args: ["index.js"]}`,
`alexia_protocol: 3`, `mcp_protocol: "2025-11-25"`, `requires: []`, `provides: []`.

| id | name | summary |
|---|---|---|
| google-account | Google | Your Google calendar, mail and contacts, read for you; anything sent asks first. |
| microsoft-account | Microsoft 365 | Your Outlook calendar, mail and contacts, read for you; anything sent asks first. |
| day-planner | Day planner | Plans your day, finds time, tells you when to leave and what to bring to a meeting. |
| mail-desk | Mail desk | Sorts your inbox, watches for what matters, tracks parcels and bills. |
| task-list | Tasks | Your to-dos and reminders, by time, place or person. |
| page-watch | Page watch | Watches pages you care about and tells you when they change. |
| notes-library | Notes and documents | Reads the notes and documents in folders you choose, so she can find them later. |
| screen-memory | Screen memory | Remembers the text that was on your screen, off until you turn it on. |
| study-desk | Study desk | Study sessions, and notes from your lectures and meetings. |
| errand-kit | Errands | Plans trips, prepares bookings and fills forms; anything submitted asks first. |

`index.js`: the SDK's `plugin()` with no tools, `// SPDX-License-Identifier: AGPL-3.0-only`
first line, a doc comment saying which task fills it.

## Steps
1. Create the forty files.
2. `pnpm install` at the repo root; commit the lockfile change it makes and nothing else.
3. Run `node v3/ci/invariants.mjs`: none of the ten ids may appear quoted in any crate (check 1).

## Tests
- `test/load.test.js` per plugin (node:test, like `plugins/commitments/test`): the manifest
  parses, its `id` equals the folder name, `provides` is an array, and `index.js` imports
  without throwing.
- `pnpm check` runs them.

## Done when
- `cargo fmt --all --check` passes in v3/
- `cargo clippy --workspace --all-targets -- -D warnings` passes in v3/
- `cargo test --workspace` passes in v3/
- `pnpm check` passes at repo root (known `compute-connect.test.ts` failure aside)
- `node v3/ci/invariants.mjs` prints ok
- With `ALEXIA_PLUGINS_DIR=<repo>\plugins`, `alexia-hub plugins` lists the ten ids (none refused)

## Notes for the worker
- No Rust changes. If you run the cargo checks, `CARGO_BUILD_JOBS=1` (16 GB RAM).
- The ids are long on purpose (PHASE.md D-P3-10): check 1 flags any crate line that quotes a
  plugin id, and short ids like `watch` or `tasks` are words the scheduler uses.
- `docs/spec/manifest.md` is the manifest's authority; `plugin.schema.json` validates it.
- Invariants: no plugin id in a crate, no user paths, 127.0.0.1 only, no secrets in files.
