# P3-39: A watch may only poll a reviewed, read-only capability, and never unlocked

Model: opus (security: a model-made job that runs a capability on its own, again and again)
Depends on: none (found by the P3 phase review, finding 1)
Feature IDs: PR-16 (website change watch), PR-26 (how much she does without asking)

## Goal
`schedule.add` with `kind: "watch"` takes any `cap` and any `args` from the model
(`alexia-scheduler/src/lib.rs` `trigger_of`). Every N minutes the scheduler then calls that
capability through `Sources::poll` → `HostSources::poll` → `McpHost::call_capability`. That call
passes no permission gate: not `permissions::rule`, not `permissions::proactive` (D-P3-6), and
no audit row. A model that read an injected page or email can set up `shell.run`,
`folder.tidy`, `browser.open`, or `memory.recall {unlocked: true}`, which puts locked facts into
the scheduled turn's prompt. Each then runs unasked and repeatedly. INTERFACES §3.6 only
envisions `page.text`.

After this task, a watch is accepted only when the capability resolves to tools that are
reviewed, `readOnlyHint: true` and not destructive. This is checked when the watch is made and
again before every poll. `unlocked` never reaches the polled capability, for new watches and
for rows already stored.

## Interfaces
```rust
// alexia-scheduler/src/lib.rs, trait Sources
/// (P3-39) Whether `cap` may be polled by a watch: Ok when every enabled provider's tool for
/// `cap` is from a reviewed plugin, `readOnlyHint: true` and not `destructiveHint: true`.
/// Err is the sentence the model is told. The default refuses (fail closed), so a Sources
/// that does not know is never polled.
async fn watchable(&self, cap: &str) -> std::result::Result<(), String> {
    Err(format!("{cap} can't be watched here."))
}

/// The argument a watch may never pass (P3-15: only core's own reads unlock memory).
pub(crate) const UNLOCKED: &str = "unlocked";
```
Creation (`ScheduleTools`, `schedule.add` with `kind: "watch"`). `trigger_of` removes
`unlocked` from the watch's `args`. Then, before `Scheduler::add`,
`s.sources.watchable(&cap).await`. On Err the job is not stored and the model gets an error
outcome with that sentence, for example "shell.run can't be watched: a watch may only read
something, and that changes things." `ScheduleTools::add` becomes async, or the check moves into
`call` before it. Pick whichever changes less.

Poll (`watch::changed`): first `args.remove(UNLOCKED)`, then `sources.watchable(cap)`. On Err,
return None without calling `poll`, and `tracing::warn!(job, cap, "a watch was not polled: its
capability may not be watched")`, with no args and no text. The job stays, so it polls again
once the owner reviews the plugin. Rows stored before this task go through the same gate.

Hub (`HostSources::watchable`):
- Collect the enabled providers of `cap` from `host.plugins()` (enabled and `provides` holds
  `cap`, Refused or Unhealthy included).
- None → Err "Nothing installed can be watched for {cap}." Core's own answers are never
  watchable, because they have no annotations.
- Otherwise `host.tools()` (already listed and cached for the agent). Each of those providers
  must have a listed tool with `cap` in `provides` and pass `reviewed && read_only_hint ==
  Some(true) && destructive_hint != Some(true)`. One that fails, or has no listed tool, → Err.
- Every provider is checked, not only the first. That way the provider `call_capability` picks
  (plugin id order, skipping held ones) always passes, whichever it is.
- `openWorldHint` does not matter here: `page.text` reads the web and is the case §3.6 wants.

## Tests
`tests/watch_gate.rs` (scheduler; paused time, a fake `Sources` whose `watchable` answers from a
set and which records every `poll(cap, args)`, the store in memory). Each fails on today's code:
- `unwatchable_cap_refused_at_creation`: `schedule.add {kind: "watch", cap: "shell.run", ..}`
  through `Scheduler::tools()` → an error outcome with the fake's sentence, and no job row.
- `watchable_cap_accepted`: `page.text` → a job row, as today.
- `unlocked_stripped_at_creation`: `args: {url: "u", unlocked: true}` → the stored trigger's
  args are `{url: "u"}`, and the first poll saw no `unlocked`.
- `old_row_with_unlocked_is_stripped`: a job row written straight to the store (as a row from
  before this task) with `args.unlocked: true` → `poll` never sees `unlocked`.
- `gate_rechecked_every_poll`: a watch made while watchable, then the fake says Err (the
  plugin was unreviewed) → the next due time passes with no `poll` call and no turn. Ok again
  → it polls again.
- `default_sources_never_poll`: `NoSources`-style fake without `watchable` → refused at
  creation, and an existing row is never polled.

`proactive.rs` unit tests, with the file's own fake-plugin rig (Node `SERVER`, extended so a
tool may carry `annotations`, and `set_reviewed`):
- `watchable_reviewed_read_only`: one provider, `readOnlyHint: true` → Ok.
- `not_read_only_refused`: `readOnlyHint` missing or false → Err. `readOnlyHint: true,
  destructiveHint: true` → Err.
- `unreviewed_refused`: the same read-only tool after `host.set_reviewed(id, false)` → Err.
- `every_provider_checked`: two providers of one cap, the second not read-only → Err.
- `no_provider_refused`: nothing provides `test.page` → Err.
