# P3-24: Replies in your voice and sending email (always asks)

Model: opus
Depends on: P3-20, P3-21, P3-23
Feature IDs: DY-05, DY-06

## Goal
She can draft a reply that sounds like the owner, learned from their own sent mail, and send
it, but only after the owner says yes to that exact message every time (D214: anything that
leaves the owner's devices asks; DY-06 defaults to always ask). Drafts are kept on this PC in
the mail desk's own folder until approved. Nothing is put into Gmail's or Outlook's drafts
silently. The account plugins gain `mail.send`, marked outward-facing.

## Interfaces
- `mail.send {to, subject, text, replyTo?}` in both account plugins: annotations
  `readOnlyHint: false, destructiveHint: true, openWorldHint: true`. **`destructiveHint: true`
  on purpose**: then "Ask before risky" asks too, and a spoken "don't send anything" boundary
  blocks it. In Full trust the core would run it, so the tool **also** requires an
  `approved_draft` argument: a token that only `send_draft` puts in after the owner's yes
  (below); without it the tool refuses with "Sending needs your yes on the draft first." The
  new scopes mean the owner reconnects once; the status says so.
- A "sent mail sample" read: `mail.list` with `query: "in:sent"` (Gmail) or the SentItems folder
  (Graph), at most 200 recent messages, used only by `voice.js`.
- `mail-desk`:
  - `voice.js`: from the sample, a short style card (greeting and sign-off habits, typical
    length, formality, language per recipient domain), built by one sampling call over at most
    30 trimmed sent messages, stored in the plugin's kv, rebuilt weekly. Never stores the
    messages themselves.
  - `draft_reply {mail_id, intent}` (not read-only, not destructive, not open-world: it writes
    only the plugin's own folder): reads the mail, writes a draft with the style card, saves it
    as a file in its own dir and a row in `drafts` (`id`, `mail_id`, `to`, `subject`, `text`,
    `state`), returns the draft text and its id.
  - `send_draft {draft_id}` (`openWorldHint: true`, `destructiveHint: true`): asks the owner
    through the host's elicitation ("Send this to <to>? <subject>" with the text), and only on
    an explicit yes calls `mail.send` with `approved_draft` set to a one-time token it keeps for
    60 s. No yes (no, timeout, no way to ask) → not sent, the draft stays.
