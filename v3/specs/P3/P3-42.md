# P3-42: A tool that does not say openWorldHint counts as reaching outside

Model: opus (security: D214 / D-P3-6, outward-facing tools always ask on her own)
Depends on: P4-30, P4-31 (both own `alexia-core/src/permissions.rs`; P4-30 adds `local_only`, which reads the same hint)
Feature IDs: PR-26 (how much she does without asking), DY-06 (sending always asks, D214)

## Goal
MCP's default for `openWorldHint` is **true**. `permissions::proactive` reads
`ask.annotations.and_then(|a| a.open_world_hint) == Some(true)`, so a reviewed tool that leaves
the hint out (or has no annotations at all) counts as not outward-facing. Put on the owner's
silent list, it then runs unasked from a scheduled turn. D-P3-6 says outward-facing tools always
ask. P4-30's `local_only` (merged before this task) blocks "an `openWorldHint: true` tool" and
has the same gap. After this task, one helper decides "reaches outside": anything but an explicit
`openWorldHint: false`. `proactive` and `local_only` both use it.

Checked against the code (`946173c1`): real, at `permissions.rs:115`. The same `== Some(true)`
test is in `commands.rs:988` (`/silent allow`) and `alexia-hub/src/main.rs:1283`
(`alexia-hub silent allow`). Those two only decide whether the tool goes on the silent list.
Once `proactive` is fixed, a hint-less tool on the list still asks (rule 1 comes before rule 3),
so they no longer open anything. They are left out of this task because `commands.rs` belongs to
P4-39 and `main.rs` to P4-37..P4-40. What they still get wrong is a sentence, "she may use it
without asking", for a tool she will still ask about. That goes into LOG.md as a LATER line (see
Notes).

## Interfaces
```rust
// permissions.rs
/// (P3-42) MCP's default for `openWorldHint` is true: only an explicit `false` keeps a tool
/// inside the owner's computers. No annotations at all reaches outside too.
pub fn reaches_out(annotations: Option<&ToolAnnotations>) -> bool {
    annotations.and_then(|a| a.open_world_hint) != Some(false)
}
```
`proactive` rule 1 becomes `if reaches_out(ask.annotations) || !ask.reviewed`. `local_only`
blocks when `reaches_out(ask.annotations)`. Keep P4-30's sentence and its
Blocked-stays-Blocked order. The doc comment on `proactive` changes to "outward-facing (anything
but `openWorldHint: false`)". Nothing else in `rule`, `read_only` or `is_destructive` changes.

Alexia's own builtins: the scheduler's (`alexia-scheduler/src/lib.rs` `spec`) already say
`openWorldHint: false`. Check every other builtin `ToolSpec` (`helpers.rs:156` and
`prompt.rs:445` have `annotations: None`; also `undo.rs` and `commands.rs`). For each one a
scheduled turn really uses, decide whether asking is right. A builtin that gets stuck asking in
