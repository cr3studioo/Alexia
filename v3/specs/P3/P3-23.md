# P3-23: Mail desk: triage, inbox watch, packages, bills

Model: sonnet
Depends on: P3-03
Feature IDs: DY-04, PR-14, PR-17, PR-18

## Goal
The `mail-desk` plugin reads new mail through `mail.list`/`mail.read` (whichever account
provides them) and sorts it: what needs the owner, what is waiting on someone else, what can
wait, what is noise. It watches the inbox for what matters (a reply from someone they wrote
to, a message from the school, a known important sender), tracks parcels from shipping mails,
and keeps a list of bills and subscriptions with their due dates. All of it reaches the owner
as notices and as the brief's mail section. It never marks, moves or deletes mail.

## Touch only these paths
- `plugins/mail-desk/**`   (fill: `index.js`, `triage.js`, `parcels.js`, `bills.js`, `plugin.json`, `README.md`, `test/*.test.js`)

## Must not touch
`package.json` (no new dependency), the account plugins, other plugins, crates.

## Interfaces
- `requires`: `mail.list`, `mail.read` ("to read new mail; nothing is marked or moved").
- Settings: `important` (text: addresses or domains always worth a notice), `every` (choice
  15 | 30 | 60 minutes, default 15), `status`.
- Tables: `seen` (`id`, `at`, `class`), `parcels` (`carrier`, `number`, `what`, `state`,
  `eta`, `mail_id`, `at`), `bills` (`payee`, `amount`, `currency`, `due`, `recurring`,
  `mail_id`, `state`).
- Triage (`triage.js`): each new message → class `act` | `reply` | `wait` | `read_later` |
  `noise`, first by rules (important senders → act; replies in a thread the owner started →
  reply; known newsletters by `List-Unsubscribe` → noise), then one sampling call for a batch
  of up to 20 unclassified, returning the class and a ≤ 15-word reason per id. The model sees
  sender, subject and the first 500 characters only.
- Parcels (`parcels.js`): tracking numbers by carrier patterns (Zásilkovna, PPL, DPD, GLS,
  Česká pošta, DHL, UPS, FedEx, Amazon), state from the mail text ("shipped", "out for
  delivery", "delivered", Czech equivalents). No carrier API calls.
- Bills (`bills.js`): due date and amount from invoices and subscription renewals (sampling
  call with the text, then the plugin checks the date parses and the amount is a number).
- `notice_items`: `act` and `reply` mails (Normal, key `mail:<id>`, why "From <sender>: <reason>"),
  parcels out for delivery today (Low) or delivered (Low, once), bills with `dueAt`
  (the scheduler's radar raises them), renewals 3 days ahead (Low).
- `brief.section`: morning: counts per class and the `act` lines; evening: what still needs a
  reply; weekly: bills and renewals of the coming week.
- Tools: `inbox {class?}`, `parcels {}`, `bills {}` (read-only), `bill_paid {id}` (not read-only).

## Steps
Pure parsers with tests first (`parcels.js`, `bills.js` parsing, `triage.js` rules), then the
poll loop (only mails newer than the newest seen; the first run looks back 3 days) and tools.

## Tests
`parcels.test.js`: one fixture line per carrier (hand-written text), state words in both
languages. `bills.test.js`: `invoice_due_and_amount`, `bad_date_rejected`.
`triage.test.js`: `important_sender_is_act`, `reply_in_own_thread`, `list_unsubscribe_is_noise`,
`model_sees_only_500_chars`. `index.test.js`: `never_calls_anything_but_list_and_read`,
`notice_items_shape`.
