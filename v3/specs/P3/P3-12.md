# P3-12: Gateway: notice buttons, feedback, owner activity

Model: sonnet
Depends on: P3-01, P3-04
Feature IDs: PR-06 (urgency shown), PR-07 (feedback "later"), PR-01, ME-17 (activity signal)

## Goal
What she says unprompted arrives in the right chat with a row of buttons: **Thanks**, **Not
useful**, **Later**, **Why?**, and **Done** when it is something to do. A tap (or a reply such
as "later", "done", "stop these" to that message) goes back to the scheduler as
`Event::Feedback`. Every message from the owner, on any channel, and every window message
publishes `Event::Active`, which is how the morning brief knows the owner is up (PHASE.md
D-P3-7). `Say.to` is honoured: a follow-up goes to the chat where it was asked.

## Interfaces
```rust
// channel.rs
pub struct Inbound { /* existing */ pub button: Option<String> /* callback data, P3-12 */ }
#[async_trait::async_trait]
pub trait Channel {
    /* existing */
    /// A message with one row of buttons `(label, data)`. Default: `send` without buttons.
    async fn notify(&self, chat: &ChatRef, text: &str, buttons: &[(String, String)]) -> Result<MsgRef> { .. }
}
```
Button data: `n:<notice id>:<verb>`, verb ∈ `seen|useful|not|later|why|done`. Telegram limits
callback data to 64 bytes; this fits.

Delivery of `Event::Say { text, urgency, notice, to, .. }`:
- `to: Some(Origin::Channel { channel, chat })` naming a configured channel → that chat only.
  `Some(Origin::Window)` or `Some(Origin::Desktop)` → every primary chat (the window shows
  nothing unprompted in P3; the UI is untouched). `None` or anything else → every channel's
  primary chat (today's behaviour).
- `urgency` `High` prefixes "❗ ", `Urgent` "‼️ ". `Low`/`Normal` unchanged.
- `notice: Some(id)` → `notify` with buttons Thanks/Not useful/Later/Why? (+ Done when the
  notice's source is not `"pattern"`), and the sent `MsgRef` remembered as kv `_core`/
  `notice_msg.<channel>.<chat>.<msg id>` = id (keep the newest 500, drop older).
- `notice: None` → `send` as today.

Button or reply → feedback:
- `useful` → `Verdict::Useful`, `not` → `NotUseful`, `done` → `Done`, `seen` → `Seen`,
  `later` → `Later { until: now + 3 h }` (the "Later" press answers "I'll bring it up again at
  <time>."), `why` → no event; the gateway answers in the chat with the notice's `why` (read
  with `store.notice(id)`), and that counts as `Seen`.
- A text message that replies to a remembered notice message and is just "done", "later",
  "not now", "stop", "stop these" or "thanks" (case-insensitive, trimmed, Czech "hotovo",
  "později", "díky" too) → the matching verdict (`stop`/`stop these` → `Mute`), a 👍 reaction,
  and the message does not go to the brain. Anything longer goes to the brain as usual.
- Every accepted owner message (after pairing) → `Event::Active { via: <channel name> }`.
