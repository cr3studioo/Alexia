# P3-08: Scheduler: notice intake, the decider, deadline radar

Model: opus
Depends on: P3-05, P3-07
Feature IDs: PR-01, PR-05, PR-06, PR-09, PR-07 (applied to notices)

## Goal
The engine's heart. Every few minutes the scheduler asks every source what might be worth
saying, files each answer as a notice (deduplicated), and decides for each live notice, by
plain rules, whether to say it now, keep it for the next brief, hold it until later, or drop
it. Deadlines raise their own urgency as they approach (the radar), so they are flagged while
there is still time. There is no daily cap (PR-05). Quiet hours, pauses, snoozes and mutes are
the only brakes. The owner's answers (`Event::Feedback`) and signs of life (`Event::Active`)
feed back in.

## Interfaces
From INTERFACES §2.5 (P3):
```rust
pub enum Decision { SayNow, Brief, Hold { until: Ms }, Wait, Drop }
pub struct DecideCtx<'a> { pub now: Ms, pub now_local: (u8, u8), pub cfg: &'a Proactive,
    pub mutes: &'a [MuteRow], pub last_active: Option<Ms> }
/// D-P3-5: > 7 days → None; ≤ 7 d → Low; ≤ 3 d → Normal; ≤ 24 h → High; ≤ 2 h or past → Urgent.
pub fn radar(due_at: Ms, now: Ms) -> Option<Urgency>;
pub fn decide(n: &NoticeRow, ctx: &DecideCtx) -> Decision;
```
`decide`, in this order:
1. A mute matches (same `source`, and `topic` is None or a case-insensitive substring of
   `text`) → `Drop`.
2. `not_before > now` → `Hold { until: not_before }`.
3. `u` = the higher of the row's urgency and `radar(due_at, now)`.
4. State `said`: if `u == Urgent`, `seen_at` is None, `times_said < 3` and 30 min have passed
   since `said_at` → `SayNow` (urgent things repeat until seen). Otherwise `Wait`. (A said
   deadline that turns `High` or `Urgent` is said again: intake puts it back to `new`, below.)
5. `paused_until > now` and `u < Urgent` → `Hold { until: paused_until }`.
6. `held(now_local, &cfg.quiet, u)` → `Hold { until: quiet end }`.
7. `u >= Normal` → `SayNow`; `Low` → `Brief`.

Intake (`notices.rs`, every `cfg.collect_every_ms`, and once at start):
- `sources.items(now, 14)`; each `(cap, item)` → `notice_upsert` with `source = cap`,
  `urgency = item.urgency.unwrap_or(Low)` raised by `radar(item.due_at)`. Read the live row
  first; when it is `said` and the new urgency is `High` or `Urgent` and above the row's,
  set it back to `new` after the upsert, so the rise is said.
- Also, each pass, every live notice with `due_at` gets `radar` re-applied the same way
  (deadlines rise with the clock even when no source answers).
- A live `new`/`held` notice of a source that answered this round but did not return its key
  for **3 rounds in a row** becomes `done` (the thing went away: a commitment closed, a mail
  answered). Rounds are counted in memory. A restart resets them, which only delays closing.
  A source that returned nothing this round (all providers failed) counts as not answered.

Dispatch, after every intake and on every `Feedback`/`Active`:
- `SayNow` → `Event::Say { text: n.text, urgency: u, job: None, notice: Some(n.id), to: None }`
  and `notice_said(id, "primary", now)`. `Hold` → `notice_set(id, "held", Some(until))`.
  `Drop` → `notice_set(id, "dropped", None)`. `Brief`/`Wait` → nothing (P3-09 reads Brief).
- At most one `Say` per notice per dispatch. Several `SayNow` in one pass go out as one `Say`
  (lines joined, the highest urgency, `notice` = the first id) when there are more than 3, so
  a burst after quiet hours is one message, not ten.

Feedback (`Event::Feedback`):
`Seen` → `notice_seen(id, None)`; `Useful`/`NotUseful` → `notice_seen(id, Some(..))`, and
`NotUseful` also sets the notice `dropped`; `Later { until }` → `held` with `not_before = until`;
`Mute` → `mute_add(source, None, None)` and `dropped`; `Done` → `done`, and when the
notice's source is `notice.items`, `sources.done(&key)` so the plugin closes its side too
(a commitment kept, P3-25).
`Event::Active` → `last_active = at` (kept in memory and in kv `_core`/`last_active`).
