# P3-16: Core: learn from every conversation, one memory, locked memory stays locked

Model: opus
Depends on: P3-00, P3-06, P3-12
Feature IDs: ME-02, ME-15, ME-13 (core's half)

## Goal
Every finished exchange with the owner, on every channel and in either lane, is offered to
`memory.capture`, so she learns from every conversation, not only from the chat fast path and
the window as today. One memory serves Telegram, the window and anything later (ME-15): the
capture carries the channel and session so each fact knows where it came from (P3-13).
Private conversations are never captured. Proactive turns (`Origin::Scheduler`) are never
captured. Locked facts (P3-15) are only unlocked for the owner's own chats, never for a
proactive turn.

## Touch only these paths
- `v3/crates/alexia-core/src/agent.rs`   (change: capture after a finished task-lane run; `unlocked` on profile and recall)
- `v3/crates/alexia-core/src/chat.rs`   (change: capture args gain `channel`, `session`; `unlocked`; skip private)
- `v3/crates/alexia-core/tests/capture_everywhere.rs`   (create)
- `v3/crates/alexia-api/src/chat.rs`   (change: the window's capture args gain `channel: "window"`, `session`, and `unlocked: true` where it reads memory)

## Must not touch
`permissions.rs`, `run.rs` (P3-06's), `prompt.rs` (P3-10's), the gateway, the scheduler, the
memory plugin.

## Interfaces
Arguments core sends (INTERFACES §2.3, P3-02):
- `memory.capture`: v2's `{said, answered, at}` plus `channel` (`"telegram"`…, `"window"`,
  `"desktop"`) and `session` (number). `said`/`answered` redacted as today.
- `memory.profile` and `memory.recall`: existing args plus `unlocked: bool`.

```rust
/// (P3-16) Whether memory may hand this turn its locked facts: the window, the desktop, and
/// the primary chat of a channel (`store.primary_chat(channel) == Some(chat)`). Never a
/// Scheduler turn, never a non-primary chat.
pub(crate) fn unlocked(store: &Store, origin: &Origin) -> bool;
/// (P3-16) kv `_core`/`private_sessions` holds `session` (the list P3-00 made atomic).
pub(crate) fn is_private(store: &Store, session: SessionId) -> bool;
```
Capture is skipped when: the origin is `Scheduler`, the session is private, `memory.capture`
has no provider, or the run ended `Failed`/`Stopped` with no answer. It is spawned, never
awaited, as today.

## Steps
1. Add the two helpers in `agent.rs` (or a small `memory_args` section of it) and use them in
   both lanes.
2. After a task-lane run ends `Done` with a reply, spawn the capture call like `chat.rs` does.
3. Window: the api's capture already skips private sessions; add the args.
