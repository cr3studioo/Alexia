# P3-15: Memory: timeline, nightly tidy-up, profile file, import, locked facts

Model: sonnet
Depends on: P3-14
Feature IDs: ME-05, ME-14, ME-04, ME-18, ME-13 (the plugin's half)

## Goal
Memory keeps a timeline of the owner's days (one short entry per day from what was said and
done), tidies itself every night (merging duplicates, closing past dates, re-embedding,
filling people from contacts), writes the pinned profile to a plain Markdown file the owner
can read and edit, imports memories from other assistants' exports, and lets the owner lock a
fact so it is only recalled in their own chats and never reaches a proactive message.

## Interfaces
- **Timeline (ME-05)**: table `days` (`date` "YYYY-MM-DD", `text`, `at`). Written by the nightly
  pass from that day's captured facts, dates and the conversation summaries capture already
  keeps (one sampling call, at most 5 sentences). Tool `timeline {from?, to?}` (read-only).
  `brief.section` tool (`_meta alexia/provides ["brief.section"]`): for `kind: "weekly"`, the
  week's days as lines; for other kinds, empty.
- **Nightly tidy-up (ME-14)**: `garden.js`'s existing sort runs on its own interval today. Add a
  nightly pass at the first `sort` after 02:00 local: merge near-duplicate facts (cosine ≥ 0.92
  and same kind; the older one is superseded, never deleted), close `dates` that are past,
  embed missing vectors, refresh people from `contacts.find`, write the day entry. Writes a
  status line "Tidied at 02:14: merged 3, closed 2." This only writes the plugin's own tables
  (it is on the owner's proposed silent list, PHASE.md *Owner needs* 1).
- **Profile file (ME-04)**: setting `profile_file` (the setting type `docs/spec/manifest.md` gives
  for a file or folder; `text` if it has none; default empty = off). When set,
  pinned facts are written there as Markdown (one bullet each, a header saying edits are read
  back). On start and every sort, if the file changed since it was written (mtime and hash),
  lines added become pinned stated facts, lines removed are unpinned (not forgotten). The path
  must be inside the plugin's own dir or a folder the owner chose (roots); outside → status
  sentence, nothing written.
- **Import (ME-18)**: tool `import_memories {path}` (not read-only, not destructive). Accepts
  ChatGPT's data export (`conversations.json` or the zip's folder: read its "memory" entries
  if present, otherwise the user messages, at most 2000, captured through the normal capture
  pipeline in batches), a Claude memory export (Markdown or JSON list of memories), and a plain
  text or Markdown file of one memory per line. Every imported fact has `src_doc` = "Imported
  from <assistant name>" and `source` stated. Returns counts. The path must be inside chosen
  roots.
- **Locked facts (ME-13)**: column `locked` on facts. Tools `lock {id}`, `unlock {id}`. `recall`
  and `profile` take `unlocked: boolean` (default false). When false, locked facts are left
  out of results entirely (not hinted at). Core sets it (P3-16). `notice_items` never uses
  locked facts. The panel (P3-17) shows them as "🔒 locked".
