# P3-04: Store migration 4 (notices, mutes) and the bus additions

Model: opus
Depends on: P3-00, P3-02
Feature IDs: PR-01, PR-22 (the record of what was said), PR-26 (what was done silently)

## Goal
Core's database gets its one queue of things that might be worth telling the owner
(`notices`), the owner's "not about this" rules (`mutes`), and a way to read what proactive
runs did. The bus gets what P3 needs to talk across crates without depending on each other:
`Say` says which notice it carries and which chat it is for, `Feedback` carries the owner's
answer to a notice, and `Active` says the owner just showed a sign of life. These are the
shared types every later P3 task uses.

## Steps
1. Append migration 4 to `MIGRATIONS` (index 3). Do not edit 1–3.
2. Add the types and methods. `notice_upsert` runs in one transaction: select the live row by
   `(source, key)`, update or insert. Urgency rises only (`low < normal < high < urgent`).
3. `audit_scheduled_since`: `origin LIKE '{"kind":"scheduler"%' AND decision = 'ran' AND at >= ?`.
   Check the stored origin JSON really starts that way (serde tag `kind`, P2-03) and adjust the
   pattern if not.
4. Add the bus variants and `Verdict`; fix the five `Say` literals listed above.

## Tests
`alexia-store/tests/notices.rs`:
- `migrates_to_4`: a fresh file has `user_version == 4` and both tables; a file built by
  running `MIGRATIONS[..3]` by hand (as the existing migration tests do) is moved to 4 by
  `Store::open` with its rows intact.
- `upsert_dedupes_live_rows`: same (source, key) twice → one row, `created` false the second
  time, text refreshed.
- `upsert_never_lowers_urgency`: high then low → stays high.
- `done_row_lets_a_new_one_live`: set state done, upsert same key → a new row.
- `invalid_urgency_refused`, `invalid_state_refused`.
- `said_counts_and_records_via`, `seen_records_feedback`.
- `mutes_expire`: a mute with `until` in the past is not listed.
- `audit_scheduled_since_only_scheduler_ran`: audit rows with window and scheduler origins and
  ran/denied decisions; only scheduler+ran are returned.
Plus: the existing scheduler, gateway and core tests pass with the new `Say` fields.

## Notes for the worker
- 16 GB RAM: `CARGO_BUILD_JOBS=1`; work with `cargo test -p alexia-store` and
  `cargo test -p alexia-core --lib`; the workspace once at the end (every crate rebuilds
  because `bus.rs` changed).
- Why one queue (PHASE.md D-P3-1): the same thing must never be said twice, and the owner's
  "later" or "not useful" must stick across restarts. The bus is never the only record
  (INTERFACES §4), so state lives here.
- The partial unique index needs SQLite ≥ 3.8; the bundled SQLCipher is newer.
- Invariants: no plugin id in any crate (sources are capability names), no user paths,
  127.0.0.1 only, notice text is the owner's data and never goes to a log line.
