# P3-10: Scheduler: follow-through, check-ins, overnight errands, reminders and timers

Model: opus
Depends on: P3-09
Feature IDs: PR-08 (her half: raising your promise when it is due), PR-21, PR-12, DY-08 (time), DY-09 (on this hub's channels)

## Goal
When something is said in a conversation that needs coming back to, she comes back to it,
unprompted, in the chat where it was said: "remind me at 6", "check on me after the exam",
"look into flights overnight", "set a 20-minute timer". One builtin tool, `follow_up`, turns
any of these into a scheduled follow-up with a reason, and a prompt paragraph tells the model
when to use it. Overnight errands run as background turns at night and their results wait for
the morning brief. Check-ins ask how something went after it ended.

## Interfaces
Builtin tool, added to `ScheduleTools` (it already holds `Weak<Scheduler>`):
```
follow_up {
  kind: "remind" | "check_in" | "errand" | "timer",
  what: string,              // in the owner's words, a sentence that still makes sense later
  at?: string,               // local "YYYY-MM-DD HH:MM", for remind / check_in
  in_minutes?: integer,      // for timer and "in 20 minutes"
  urgency?: "low" | "normal" | "high" | "urgent"   // default: timer high, others normal
}
→ text "I'll <come back to it | check in | look into it overnight | ring> <when>." and
  structured {id}; undo = schedule.cancel {id}
annotations: readOnlyHint false, destructiveHint false, openWorldHint false
```
What each kind becomes (rows in `jobs`, origin = the calling turn's origin, so the answer goes
to that chat via `Say.to`):
- `remind`: `Trigger::At` → at that time a notice (source `"follow"`, key `follow:<job id>`,
  text = `what`, why = "You asked me to remind you.", urgency as given) is filed and dispatched
  by P3-08's rules, so quiet hours still apply. No model turn.
- `timer`: `Trigger::At` now + minutes, urgency `High`, text "⏰ <what>". Quiet hours let `High`
  through only if `lets_through <= High`; a timer is something the owner just asked for, so
  `follow.rs` files it with `not_before` None and urgency `Urgent` when it would otherwise be held.
- `check_in`: `Trigger::At` → a scheduled brain turn with prompt "Check in with the owner about:
  <what>. Ask one short question." (PR-21).
- `errand`: `Trigger::At` = tonight at 02:00 local (or `at` if given) → a background brain
  turn with prompt "<what>. Work on this now; your answer goes into the morning brief." Its
  reply is filed as a notice (source `"errand"`, urgency Low) instead of said, so it lands in
  the morning brief (PR-12). Tools it uses obey P3-06 (it only reads or asks).

Prompt paragraph (`prompt.rs`, in the standing instructions):
> When the owner asks you to remind them, to check on them later, to look into something
> while they sleep, or to set a timer, call `follow_up`. When you yourself say you will get
> back to them, call `follow_up` too, so you actually do. Never promise to come back without it.
