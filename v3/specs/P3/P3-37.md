# P3-37: Reminders and timers ring in the chat that asked

Model: sonnet
Depends on: P3-10
Feature IDs: none (finishes P3-10's spec: "come back to the owner later in this chat")

## Goal
follow_up remind and timer notices are said with Say.to None, so they always go to the primary chat
(or the followed face), not the chat the owner asked in. After this task a remind or timer notice
goes to the origin of the turn that set it, like check_in already does.

## Touch only these paths
- v3/crates/alexia-scheduler/src/notices.rs   (change: carry the job's origin into the Say for follow-up notices only)
- v3/crates/alexia-scheduler/src/follow.rs   (change, only if the origin must be stored with the notice)
- v3/crates/alexia-scheduler/tests/follow.rs   (change: tests)

## Must not touch
decide.rs, brief.rs, patterns.rs, other crates.

## Interfaces
Read how check_in passes its job origin (follow.rs about 340-399, lib.rs about 475-568) and how
notices.rs builds a Say from a notice row (the held job reply already keeps its chat in the key,
notices.rs about 43-74). Reuse that mechanism; do not add a store migration.

## Tests
- `remind_rings_in_the_asking_chat`: a remind set from chat A is said to chat A, not to the primary.
- `timer_rings_in_the_asking_chat`: same for a timer.
- `remind_from_the_window_rings_in_the_window`.
- Quiet hours and pause still hold these notices (an existing decide rule; one test that a held remind
  later goes to the asking chat).
