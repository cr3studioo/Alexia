# P3-43: Plugin notice keys are filed by provider, and Done goes only to the plugin that offered it

Model: opus (security: one plugin must not rewrite, take over or hear another plugin's notices)
Depends on: P3-39 (shares `alexia-hub/src/proactive.rs`), P3-41 (shares `alexia-scheduler/src/notices.rs`)
Feature IDs: PR-01 (proactivity engine), PR-13 (notices patterns)

## Goal
Every plugin's items are filed under the one source `notice.items` with the key the plugin
chose. INTERFACES §3.6 says "keys are prefixed by the provider so two providers never collide",
but nothing enforces it, and the plugins' own prefixes are not their ids: `study-desk` and
`task-list` both use `tasks:`, and `google-account` uses `google:`. So a plugin that offers
another plugin's key (say `commitments:12`) can do three things:
- rewrite that notice's text and why, and raise its urgency;
- take over `Notices.provider`, so the owner's "stop" mutes the wrong plugin;
- hear the Done, because `notice.done {key}` goes to every provider
  (`HostSources::done` → `call_capability_all`). That also hands every plugin's keys to every
  other plugin.

After this task, the scheduler files a plugin item under `"<provider>/<key>"`, so two providers
never share a row. Who offered a row can then be read from its key, after a restart too, which
is what P3-38's mute needs. Done goes to that one provider only, with the plugin's own key.

Checked against the code (`946173c1`): real (`proactive.rs` `round_of` and `done`,
`notices.rs` `intake` and `Verdict::Done`). Dropping items whose key does not start with the
plugin id was rejected: it would drop the items of almost every plugin today.

## Interfaces
`Sources::done(&self, key: &str)` keeps its signature. Its key is now the **filed** key
`"<provider>/<plugin key>"`. Plugin ids are `[a-z0-9-]`, so they never contain `/`.
```rust
// notices.rs
/// (P3-43) The key a plugin item is filed under: its provider's id, `/`, the plugin's own key.
pub(crate) fn filed_key(provider: &str, key: &str) -> String;
/// (provider, plugin key) of a filed `notice.items` key; None for a key from before P3-43.
pub(crate) fn split_key(key: &str) -> Option<(&str, &str)>;
```
Rules:
1. **Filing.** In `intake`, each `(provider, cap, item)` with `cap == ITEMS_CAP` is filed with
   `key = filed_key(provider, &item.key)`. `seen`, `closed`, `missed`, `self.provider` and
   `stop_waiting` all use the filed key. Other sources (`job`, follow-ups, a `Sources` default
   round whose provider is the cap itself) are unchanged.
2. **Rows from before this task** (`notice.items` rows whose key has no `/`). A live plain row
   K keeps being updated under K, but only when no live row with the filed key exists and exactly
   one provider offers K in this round. Otherwise the item is filed under its filed key. The
   check against `closed` skips an item when the set holds its filed key, or the plain K while a
   plain row K is still known. Plain rows close by the usual vanish rule. Nothing is said twice
   because of the upgrade.
3. **Who offered it.** `provider_of(source, key)`: for `ITEMS_CAP`, `split_key(key)` first, then
   the in-memory map (plain rows). `mute` therefore no longer waits (`stop_waiting`) for a
   filed key after a restart.
4. **Done.** `Verdict::Done` on an `ITEMS_CAP` row calls `s.sources.done(&filed)`, where `filed`
   is the row's key if it has a provider, else `filed_key(p, K)` with `p` from the map. When no
   provider is known, nobody is told. Log the notice id only. The owner's Done is still recorded.
5. **Hub `done(key)`.** `split_key` → `(provider, plain)`. Find that provider's tool with
   `notice.done` in `provides` from `host.tools()`, and `call_tool(provider, tool, {key: plain})`
   within `per_call`. No `/`, an unknown or disabled provider, or no such tool → nobody is
   called, with a warn carrying the plugin id only. `call_capability_all` is no longer used for
   `notice.done`.

## Steps
1. Read `notices.rs` `intake`, `answered_without`, `provider_of`, `mute`, `feedback`, and
   `proactive.rs` `done`.
2. Add `filed_key` / `split_key`, then apply rules 1–4 in `notices.rs`.
3. `lib.rs`: the doc of `Sources::done` becomes "Tell the provider named in `key`
   (`<provider>/<plugin key>`) that the owner said Done; nobody else."
4. `proactive.rs` `done` as rule 5. Update its test: `done("alpha/a:1")` tells alpha `{key:
   "a:1"}` and not beta. `done("a:1")` and `done("zeta/a:1")` tell nobody.

## Tests
`tests/notice_keys.rs`, through a real `Scheduler` with paused time, a fake `Sources` with
several providers that records `done` calls, and the store in memory (copy the harness shape of
`tests/mute_provider.rs`; do not change that file). Each of the first four fails on today's code:
- `same_key_two_providers_two_rows`: `alpha` and `beta` both offer `tasks:1` → two live rows,
  `alpha/tasks:1` and `beta/tasks:1`, each with its own text.
- `impostor_cannot_rewrite`: alpha offers `commitments:12` (Low, text A). Then beta offers the
  same key (Urgent, text B) → alpha's row still has text A and Low, and beta's is its own row.
- `done_goes_to_its_provider_only`: the owner says Done on alpha's notice → the fake's `done`
  was called once, with `alpha/commitments:12`.
- `mute_after_restart_knows_provider`: a new `Scheduler` on the same store, with no round yet,
  then "stop" on alpha's filed row → a mute row `notice.items/alpha` at once (today it waits).
- `old_plain_row_kept`: a live plain row `commitments:12` stored before the first round, which
  alpha alone offers → the same row is updated, no second row, nothing said again.
- `old_plain_row_unknown_done_tells_nobody`: Done on a plain row with no known provider →
  recorded done, and `done` never called.
- `job_notices_unchanged`: a `job` notice is filed and closed as before.
