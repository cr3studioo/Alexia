# P3-06: Act silently: the proactive permission rule and the owner's list

Model: opus
Depends on: P3-02
Feature IDs: PR-26, PR-05, DY-06 (always asks), D214

## Goal
When Alexia acts on her own (a turn with `Origin::Scheduler`), she runs a tool without asking
only if it just reads, or if the owner put that exact tool on their "do it without asking"
list. Anything outward-facing (`openWorldHint: true`) always asks, in every permission mode,
even Full trust. This is D214 in code, so no proactive feature can turn "act silently" into
"send things". The list starts empty. Only the owner fills it (P3-31 adds the CLI and `/silent`).

## Touch only these paths
- `v3/crates/alexia-core/src/run.rs`   (change: `Scope.silent`)
- `v3/crates/alexia-core/src/permissions.rs`   (change: read `_core`/`silent` in `scope()`, add `proactive`)
- `v3/crates/alexia-core/src/agent.rs`   (change: apply `proactive` after `rule` for Scheduler-origin tasks)
- `v3/crates/alexia-core/tests/silent.rs`   (create)

## Must not touch
`permissions::rule` itself (the interactive behaviour is unchanged), `undo.rs` (undo is only
offered to the owner in a chat), `checker.rs`, the scheduler crate, the hub.

## Interfaces
```rust
// run.rs
pub struct Scope { pub mode, pub roots, pub everywhere, pub boundaries, pub data_dir,
    /// (P3-06) kv `_core`/`silent`: tool ids ("<plugin>__<tool>") the owner allows a
    /// proactive run to use without asking. Unreadable → empty.
    pub silent: Vec<String> }

// permissions.rs
/// The sentence for a proactive Ask.
pub const PROACTIVE_ASK: &str = "Alexia wants to {doing} on her own. Allow it?";
/// (P3-06, D214) For a turn whose origin is `Origin::Scheduler`, after `rule`:
/// Blocked stays Blocked. Then, in order:
/// 1. `ask.annotations.open_world_hint == Some(true)` or `!ask.reviewed` → Ask.
/// 2. `read_only(ask)` → keep `ruling` (Run, or Ask if `rule` asked, e.g. outside scope).
/// 3. `scope.silent` contains `ask.tool` and `ruling` is Run or Ask → Run.
/// 4. otherwise → Ask(PROACTIVE_ASK with {doing}).
pub fn proactive(ask: &CallAsk, scope: &Scope, ruling: Ruling) -> Ruling;
```
Note rule 3: a silent-listed tool still never escapes the never-touch list or a spoken
boundary, because those come back as Blocked from `rule`, and Blocked stays Blocked.

In `agent.rs`, where `permissions::rule(..)` is called (around line 794): when
`matches!(self.task.origin, Origin::Scheduler { .. })`, pass the result through
`permissions::proactive` before the checker step. Helpers (AC-07) started from such a task
inherit its origin, so they are covered. The audit row's `gate` for a narrowed ruling is
`"proactive"`.

The Ask goes where any Ask from a scheduler turn goes today (the asker: the approvals inbox
and the primary chat, `ask.rs:215`).

## Steps
1. Add the field, read it in `scope()` and `closed_scope()` (empty there).
2. Write `proactive` with the four rules, and unit tests for each in `permissions.rs`.
3. Wire it into the agent's gate and record `"proactive"` as the gate.

## Tests
`tests/silent.rs`, with the agent driven by the scripted provider as `tests/agent*.rs` do:
- `scheduler_turn_reading_runs`: a reviewed `readOnlyHint` tool runs with no Ask.
- `scheduler_turn_writing_asks_when_not_listed`: a non-read-only tool → an Ask with the
  proactive sentence; denied → not run; audit gate `proactive`.
- `scheduler_turn_listed_tool_runs`: the same tool on `_core.silent` → runs, no Ask.
- `open_world_always_asks_even_full_trust_and_listed`: mode FullTrust, tool on the list,
  `openWorldHint: true` → Ask.
- `unreviewed_plugin_asks`.
- `never_touch_still_blocks_listed_tool`.
- `window_turn_unchanged`: the same calls from `Origin::Window` follow `rule` alone (no
  regression in the interactive path).
