# P3-34: computer.screenshot reports the front window and lock state

Model: opus
Depends on: P3-19
Feature IDs: ME-06

## Goal
`computer.screenshot` says, next to the picture, which window was in front while it was taken
(app, title, whether it covered its monitor, whether it showed a title bar) and whether the
session was locked. Screen memory (P3-19) decides every moment from exactly that, and today the
computer plugin reports none of it, so every moment is dropped as `unknown_window`. After this
task, on Windows, an ordinary unlocked window is reported in full and screen memory can keep it;
a locked session, a secure desktop, a probe that failed or a window that changed during the
capture is reported so that screen memory drops the moment. macOS reports what it can, and what
it cannot is left out, which screen memory treats as unknown.

## Interfaces

### The screenshot result (what screen memory reads)
`computer.screenshot` keeps its two `content` parts exactly as they are (the `Saved <path>
(<w>x<h>) …` text and the `resource_link`), and adds:

```js
structuredContent: {
  path: string,          // the PNG's absolute path, the same one the text and the link carry
  width: number,         // pixels, from desktop.screenshot
  height: number,
  locked: boolean,       // always present; true whenever this plugin is not sure it was false
  front?: {              // omitted when the window in front is unknown or changed during the capture
    app: string,         // Windows: Get-Process ProcessName (e.g. "KeePassXC", "LockApp"; no ".exe")
                         // macOS: NSRunningApplication.localizedName
    title?: string,      // Windows: GetWindowText, '' when the window has none
                         // macOS: AXTitle of the focused window; omitted (never '') when unknown
    fullscreen?: boolean,// the window covers its whole monitor; omitted when unknown
    titleBar?: boolean,  // the window shows a caption; omitted when unknown
  },
}
```

No other keys in `front`, and no `pid`: the window title is not repeated in the model-facing
text, and the text does not change at all. When `locked` is `true`, `front` is omitted.

Screen memory reads it as (from `plugins/screen-memory/capture.js` `frontOf` and `filter.js`
`decide`, P3-19): `locked === true` → dropped `locked`; no `front` → `unknown_window`; `app`
missing or `title` not a string → `unknown_window`; `app` in its lock-screen list (`lockapp`,
`logonui`, `loginwindow`, `screensaverengine`, `credentialuibroker`, `consent`) → `locked`;
`fullscreen` not a boolean → `unknown_window`; `fullscreen === true && titleBar !== true` →
`full_screen`. So every "unknown" here is reported by **leaving the key out**.

### The backends (`windows.js`, `macos.js`; both import only `node:` modules, as now)

```js
/** The PowerShell (Windows) or JXA (macOS) source the probe runs. Pure: returns a string. */
export const screenStateScript = () => string

/** Windows: the probe's raw JSON, turned into the state. Pure. */
export function windowsState(raw) -> { locked: boolean, front?: Front }
/** macOS: the same, for the JXA probe's raw JSON. Pure. */
export function macState(raw) -> { locked: boolean, front?: Front }

/**
 * Run the probe once. Never rejects: a spawn error, a non-zero exit, a script the scanner
 * blocked, output that is not JSON, or an aborted signal all give { locked: true }.
 */
export const screenState = (signal) => Promise<{ locked: boolean, front?: Front }>
```

`Front` is the `front` object above. The new probe is a separate `run(...)`, never merged into
the existing `screenshot` script.

**Windows raw probe output** — one compressed JSON line, all keys always present:

```js
{
  desk: string,   // name of the input desktop (OpenInputDesktop + GetUserObjectInformation UOI_NAME);
                  // "" when OpenInputDesktop returns 0
  quns: number,   // SHQueryUserNotificationState's state; -1 when the call fails
  hwnd: number,   // 1 when GetForegroundWindow returned a window, 0 when it returned zero
  pid: number,    // the owner as frontScript computes it (HostedPid for a UWP frame, else PidOf); 0 if none
  name: string,   // Get-Process -Id pid ProcessName, "" when not found
  title: string,  // GetWindowText(foreground, 512 chars)
  style: number,  // GetWindowLong(foreground, GWL_STYLE = -16), as a signed 32-bit int; 0 if none
  win: [number, number, number, number] | null,  // GetWindowRect: left, top, right, bottom
  mon: [number, number, number, number] | null,  // GetMonitorInfo(MonitorFromWindow(fg, MONITOR_DEFAULTTONEAREST = 2)).rcMonitor
}
```

**`windowsState(raw)`**, in this order:
1. `raw` not an object → `{ locked: true }`.
2. `locked` is `true` when any of: `raw.desk !== 'Default'` (the lock screen, the UAC and
   Windows Hello secure desktop are `Winlogon`; a disconnected session gives `""`);
   `raw.quns === 1` (`QUNS_NOT_PRESENT`: screen saver, locked, or switched user);
   `raw.hwnd !== 1`. Then return `{ locked: true }`.
3. `raw.pid > 0` and `raw.name` a non-empty string, else `{ locked: false }` (no `front`).
4. `front.app = raw.name`, `front.title = String(raw.title)` when `raw.title` is a string.
5. `front.fullscreen`: `true` when `raw.quns` is 2 (`QUNS_BUSY`), 3 (`QUNS_RUNNING_D3D_FULL_SCREEN`)
   or 4 (`QUNS_PRESENTATION_MODE`), or when both rects are arrays of four finite numbers and
   `win[0] <= mon[0] + 2 && win[1] <= mon[1] + 2 && win[2] >= mon[2] - 2 && win[3] >= mon[3] - 2`;
   `false` when both rects are valid and that test fails and `quns` is not 2–4; omitted otherwise.
6. `front.titleBar = (raw.style & 0x00C00000) === 0x00C00000` (`WS_CAPTION`) when `raw.style` is
   a non-zero finite number; omitted otherwise.

A maximized ordinary window covers its monitor too (its rect overhangs by the border); it has a
caption, so it is `fullscreen: true, titleBar: true` and screen memory keeps it. That is correct.

**macOS raw probe output** — one JSON line:

```js
{
  locked: boolean | null,  // CGSessionCopyCurrentDictionary()["CGSSessionScreenIsLocked"] === 1;
                           // null when that call or the dictionary is unavailable
  name: string | null,     // frontmostApplication.localizedName
  trusted: boolean,        // AXIsProcessTrusted (the existing trusted() helper)
  title: string | null,    // AXTitle of AXFocusedWindow (or AXMainWindow); null when not trusted or none
  full: boolean | null,    // AXFullScreen of that window; null when not trusted, none, or unreadable
}
```

**`macState(raw)`**: not an object → `{ locked: true }`. `raw.locked !== false` → `{ locked: true }`
(unknown lock state is locked). No non-empty `name` → `{ locked: false }`. Otherwise
`front = { app: name }`, plus `title` only when `raw.title` is a string (an empty or null title is
**omitted**, so a window macOS would not name is unknown), plus, only when `raw.full` is a boolean,
`fullscreen: raw.full` and `titleBar: !raw.full` (a native full-screen window hides its title bar;
a windowed one has one).

### `plugins/computer/moment.js` (new; imports nothing)

```js
/**
 * One screenshot's state from a probe before and a probe after it. Pure.
 * locked: before.locked || after.locked, or true when either is missing.
 * front: kept only when not locked and both probes have a front with the same app, title,
 * fullscreen and titleBar (each compared with ===, a missing key equal only to a missing key);
 * otherwise omitted.
 */
export function sameMoment(before, after) -> { locked: boolean, front?: Front }
```

### `index.js`, the `screenshot` handler

```js
const before = await desktop.screenState(signal)
const size = await desktop.screenshot(to, signal)
const after = await desktop.screenState(signal)
// …noted, prune, unchanged…
return {
  content: [ /* the same two parts, unchanged */ ],
  structuredContent: { path: to, width: size.width, height: size.height, ...sameMoment(before, after) },
}
```

The tool's description, annotations and arguments do not change.

## Steps
1. Read `plugins/screen-memory/filter.js` (`decide`) and `capture.js` (`frontOf`) once more; they
   are the contract. Read `windows.js` `FOREGROUND`, `frontScript` and `screenshot`.
2. `windows.js`: add `screenStateScript()`. It is `FOREGROUND` plus one more `Add-Type -Namespace
   Alexia -Name Screen2 -MemberDefinition @' … '@` block (a new type name; `Alexia.Screen` is
   already used by the elements script) with `RECT`/`MONITORINFO` structs and `[DllImport]`s
   for `GetWindowRect`, `MonitorFromWindow`, `GetMonitorInfo` (user32), `OpenInputDesktop`,
   `GetUserObjectInformation` (CharSet Unicode), `CloseDesktop` (user32) and
   `SHQueryUserNotificationState` (shell32). Same P/Invoke shape as `FOREGROUND`; no native
   module. Write it one statement per line, with named variables, like `screenshot`, and wrap
   each probe (desktop, quns, foreground, rects) in its own `try { } catch { }` that leaves the
   default (`""`, `-1`, `0`, `$null`), so one failing call never loses the rest. Close the desktop
   handle it opened. It calls nothing that changes state: no `SwitchDesktop`, no focus, no input.
   It prints exactly one `ConvertTo-Json @{…} -Compress` line with every key from the raw shape.
3. `windows.js`: add `windowsState(raw)` exactly as in Interfaces, and `screenState(signal)` =
   `run(screenStateScript(), signal)`, `JSON.parse`, `windowsState`, with every failure caught to
   `{ locked: true }`.
4. `macos.js`: add `screenStateScript()` (JXA in the style of `front` and `windows`, reusing the
   file's `trusted()` and attribute helpers; `ObjC.import('CoreGraphics')` and
   `ObjC.deepUnwrap($.CGSessionCopyCurrentDictionary())` for the lock flag, inside `try`, `null`
   on any failure), `macState(raw)` and `screenState(signal)` exactly as in Interfaces.
5. Create `moment.js` with `sameMoment` and import it into `index.js`. Change only the
   `screenshot` handler as shown. If `screenState` were ever to reject, the screenshot still
   succeeds and reports `locked: true` without `front` (it never rejects, but catch anyway).
6. Add the tests below. Run the unit tests on this Windows PC; the live test runs for real here.
7. Write `screen-check.mjs` but do not run its `full` or `lock` modes: do **not** lock the

## Notes for the worker
- **Why this matters**: screen memory keeps OCR text of the screen. Every wrong "known, unlocked,
  windowed" costs the owner a password or a private chat in a database; every wrong "unknown" costs
  only an empty recall. So: when unsure, report `locked: true` or leave `front` (or one of its
  keys) out. Never fill a gap with a default like `false` or `''` (Windows' real empty title from
  `GetWindowText` is the one exception: it is an answer, not a gap).
- The probe is a separate spawn before and after the picture, not part of the `screenshot` script.
  That script's shape is what keeps Windows' AMSI scanner from refusing it (see its comment); do
  not change it. If the scanner blocks the new probe script, `screenState` gives `{locked:true}`,
  screen memory drops every moment, and the live test fails: rewrite the probe in the same plain,
  one-statement-per-line style until it passes, and say so in your report.
- Two probes cost two more PowerShell spawns (each with an `Add-Type` compile, around a second).
  Screen memory takes one screenshot every few minutes and the person's own screenshot is rare, so
  that is fine; do not merge the probes into one script to save it.
- `GetForegroundWindow` returns zero briefly while windows switch; that reports `locked:true` and
  screen memory drops that one moment. Correct, not a bug.
- DPI: PowerShell runs without DPI awareness, so `GetWindowRect` and `rcMonitor` are both scaled
  the same way; do not call `SetProcessDPIAware`. The 2-pixel slack covers rounding.
- `app` stays `ProcessName` without `.exe`, the same as `desktop.front()`. Screen memory's
  `appKey` strips `.exe`, so its default skip list (`KeePassXC.exe`, …) and its lock-screen list
  (`lockapp`, `logonui`, `consent`, …) already match.
- macOS is not tested for real in this task (no Mac here); its pure `macState` and its script's
  content are. Keep `desktop.front()` on both OSes as it is.
- Alexia.md *Memory* and P3-19 (`v3/specs/P3/P3-19.md`) explain screen memory; PHASE.md's risk
  note on ME-06 is why this is opus.
