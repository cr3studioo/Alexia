# P3-07: Scheduler: watches, quiet hours, pause

Model: opus
Depends on: P3-04
Feature IDs: PR-07, PR-01, PR-16 (the watch mechanism), DY-08 (time)

## Goal
The scheduler can watch a capability and fire when its answer changes ("tell me when the
timetable page changes"), knows when not to interrupt (quiet hours that hold anything below
their urgency until they end, and a "not now" pause), and reads its settings from one kv value.
It also lays out the module files the rest of the P3 engine fills, so the later scheduler
tasks each own one file.

`Scheduler::with_parts` (the test constructor with an injected `Clock`) gains a
`sources: Arc<dyn Sources>` argument; update its callers in `tests/scheduler.rs` only by
passing `Arc::new(NoSources)` (the one edit allowed in that file).

`next_after` for `Watch` is `now + every_ms` (`every_ms` below 60_000 is raised to 60_000).

Watch firing (`watch.rs`): instead of a brain turn, call `sources.poll(cap, args)`. Compare the
sha256 hex of the text with kv `_core`/`watch.<job id>`. The first poll stores it and says
nothing. A change stores the new hash and fires the job's prompt as a normal scheduled turn,
with the new text appended as "What changed:\n<text, at most 4000 chars>". `None` (error)
changes nothing.

Quiet hours here mean **holding a `Say`**: the scheduler's own `Say`s (job replies) pass through
`quiet::gate(&Proactive, urgency, now) -> Option<Ms>` (Some = hold until). A held job reply
is stored as a notice (`source "job"`, key `job:<id>:<at>`, state `held`, `not_before` = the end
of quiet hours) so P3-08's dispatcher says it later. Until P3-08 lands, held ones simply wait
in the table. `paused_until` in the future holds everything but `Urgent` the same way.

## Steps
1. `quiet.rs`: `held`, `gate`, `Proactive` with serde defaults and `load`/`save`.
2. `watch.rs`: the poll and compare. Its `fire` branch is called from `lib.rs::fire` for
   `Trigger::Watch`.
3. `lib.rs`: the variant, `with_sources`, `NoSources`, the mod lines and stub files, and the
   quiet gate in front of the `Say` publish.
4. `schedule.add`'s tool schema accepts `{"kind":"watch","cap":..,"args":{..},"every_ms":..}`
   so the agent can set up "tell me when X changes" (PR-16; P3-27 provides the page cap).

  holds a `Normal` one.
