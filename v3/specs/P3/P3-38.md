# P3-38: "Stop" on a plugin notice mutes that plugin, not every plugin

Model: sonnet
Depends on: none (found by P3-33)
Feature IDs: none (fixes the phase's own spec: muting is per source)

## Goal
Every notice a plugin offers through `notice.items` is filed with `source = "notice.items"`
(the capability, `ITEMS_CAP`). Which plugin offered it is kept only in memory
(`self.provider`, `alexia-scheduler/src/notices.rs`). So when the owner answers "stop" /
mute on one plugin's notice, `Verdict::Mute` calls `mute_add("notice.items", …)` and
`decide::mutes` then drops **every** plugin's notices. After this task, muting a plugin notice
mutes only the plugin that offered it, and that still holds after a hub restart.

## Touch only these paths
- `v3/crates/alexia-scheduler/src/notices.rs`   (change)
- `v3/crates/alexia-scheduler/src/decide.rs`   (change)
- `v3/crates/alexia-scheduler/src/brief.rs`   (change, only if the brief's mute filter needs the same rule)
- `v3/crates/alexia-scheduler/tests/mute_provider.rs`   (create)

## Must not touch
`alexia-store/**` (no schema change: P4-03 owns migration 5), `alexia-core/**`, `alexia-hub/**`,
`plugins/**`, other scheduler files.

## Interfaces
Use the existing store API only: `mute_add(source, topic, until, at)`, `MuteRow { source, topic,
until, .. }`, `NoticeRow { source, key, text, .. }`.
Rule: a mute made from a plugin notice is stored with `source = "notice.items/<provider>"`
(`<provider>` = the plugin id that offered it). `mutes(mute, n, now)` covers `n` when the
sources are equal (as today), **or** when `n.source == ITEMS_CAP` and `mute.source ==
format!("{ITEMS_CAP}/{p}")` where `p` is the provider of `n`. Where the provider of a filed notice
comes from after a restart must be decided from the code: if a notice's key already carries the
plugin id, use it; otherwise keep the provider map rebuilt from each round's items (every round
reports `(provider, cap, item)`) and treat a notice with no known provider as not covered by a
per-provider mute. A mute row whose source is plain `notice.items` (old rows) keeps today's
meaning. If none of this can work without a store change, stop and report: do not change the
store.

## Steps
1. Read `notices.rs` (`intake`, `Verdict::Mute`, `self.provider`), `decide.rs::mutes` and
   `decide`, and `brief.rs` where it filters muted notices.
2. Implement the rule above; give `mutes` the provider it needs (an extra argument or a lookup
   passed in `DecideCtx`), and update its callers inside the allowed files.
3. `/notices` and `/mute` are out of scope (core).

## Tests

other scheduler tests build a `Scheduler` with fake sources):
- `mute_on_one_plugin_keeps_the_other`: plugins `alpha` and `beta` each offer one item; mute
  alpha's notice; next round, beta's notice is still said and alpha's is dropped.
- `mute_survives_restart`: same, with a new `Scheduler` on the same store after the mute.
- `old_plain_mute_still_mutes_all`: a mute row with source `notice.items` drops both.
- `non_plugin_source_unchanged`: a mute on a `job` notice works as before.
