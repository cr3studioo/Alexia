# P3-30: Errand kit: travel planner, bookings, forms and paperwork

Model: sonnet
Depends on: P3-03
Feature IDs: DY-13, DY-14, DY-15

## Goal
The `errand-kit` plugin brings three skills and two tools. **Travel planner**: a skill that
plans a trip (dates, route, places, a day-by-day plan, a packing list) with web research and
the calendar, saved as a note. **Bookings**: a skill that prepares a booking (what, where,
options with prices and links) and stops at the point of paying or submitting: the owner books,
or says yes to each outward step (AC-06 "ask every time"). **Forms and paperwork**: fills PDF
forms from what she knows (memory, the owner's answers), saves a filled copy next to the
original, and keeps a checklist of paperwork with deadlines that reach the scheduler.

## Touch only these paths
- `plugins/errand-kit/**`   (fill: `index.js`, `forms.js`, `paperwork.js`, `skills/travel/SKILL.md`, `skills/booking/SKILL.md`, `skills/forms/SKILL.md`, `plugin.json`, `README.md`, `test/*.test.js`)

## Must not touch
`package.json` (P3-03 already added `pdf-lib`), other plugins, crates.

## Interfaces
- Manifest `skills` (the folders above; format `docs/spec/skills.md`). Each skill says which
  capabilities it uses (`web.research`, `calendar.events`, `calendar.create`, `memory.recall`,
  `tasks.add`) and, in **bold**, that it never pays, books or submits anything without the
  owner's yes to that exact step.
- `requires`: `fs.read_scoped`, `fs.write_scoped` ("to read a form and save the filled copy
  next to it").
- Tools:
  - `form_fields {path}` (read-only): the PDF's fillable fields (name, type, options, current
    value).
  - `fill_form {path, values}` (not read-only, not destructive): writes `<name> (filled).pdf`
    beside the original (never overwrites: " (2)" on a clash), returns the path and which
    fields were left empty. Flat PDFs without fields → "This form has no fillable fields; I can
    list what it asks for instead." (and `form_fields` returns the text through
    `document.extract` if present).
  - `paperwork_add {what, due?, docs?}`, `paperwork_done {id}`, `paperwork {}` (read-only):
    a checklist (`items`: what, due, state, docs JSON).
- `notice_items`: open paperwork with `due` (radar raises), key `errands:<id>`.
  `notice.done` closes `errands:<id>`.

## Steps
`forms.js` over `pdf-lib` (fields, fill, save-as-new) with a fixture PDF generated in the
test itself (pdf-lib can create a form), `paperwork.js` pure; then skills and tools.

## Tests
`forms.test.js`: `lists_fields_of_generated_form`, `fills_and_saves_beside_never_overwrites`,
`flat_pdf_says_no_fields`, `outside_roots_refused`. `paperwork.test.js`: `dated_item_is_notice`,
`done_own_key_only`. `skills.test.js`: each SKILL.md parses and contains the never-pays line.
