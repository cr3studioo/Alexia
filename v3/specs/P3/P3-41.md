# P3-41: A bad mutes read or a bad proactive setting holds notices instead of saying them

Model: opus (security-related: the owner's brakes, "stop" and "not now", must not fail open)
Depends on: none (found by the P3 phase review, findings 3 and 4)
Feature IDs: PR-07 (knows when not to interrupt), PR-13 (notices patterns: what the owner said sticks)

## Goal
Two reads of the owner's brakes fail open today. After this task both fail closed.
1. **Mutes** (`alexia-scheduler/src/notices.rs` `dispatch`). The code is
   `s.store.mutes(now).unwrap_or_else(|_| Vec::new())`. When the read errors, `decide` runs with
   no mutes, and every muted notice is said. `brief.rs` reads the same table with `?`, which is
   correct.
2. **`_core/proactive`** (`alexia-scheduler/src/quiet.rs` `Proactive::load`). A DB read
   error, a value that is not an object, or one malformed field replaces the whole struct with
   `Proactive::default()`. That silently lifts the owner's `paused_until` and puts the default
   (off) quiet hours in place of theirs.

After this task:
- A mutes read error skips that dispatch pass. Nothing is said or dropped, and the pass is
  tried again in a minute.
- `Proactive::load` parses field by field, so the readable fields survive.
- When the brakes themselves (`quiet`, `paused_until`) cannot be read, everything below Urgent
  is held, for notices and for job replies alike, until they can.
- A `Proactive` from a failed read can never be saved over the stored value.

Checked against the code (`946173c1`): both findings are real. One part of finding 4 is not real
today. "A later `/quiet` save writes the defaults over" does not happen: core's `/quiet`,
`/pause` and `/resume` edit `_core.proactive` key by key in one `kv_update`, and nothing in
production calls `Proactive::save`. The refusal in `save` is still added, so that stays true.

## Interfaces
```rust
// quiet.rs
/// How soon a pass that could not read the owner's brakes is tried again.
pub const UNREADABLE_RETRY_MS: Ms = 60_000;

pub struct Proactive {
    // ... the seven fields, unchanged ...
    /// (P3-41) `quiet` or `paused_until` could not be read (a DB error, a value that is not an
    /// object, or that field malformed). Everything below Urgent is held while it is set.
    /// Never stored.
    #[serde(skip)]
    pub unreadable: bool,
}

impl Proactive {
    /// Field by field. A missing field takes its default. A malformed field takes its default
    /// and is logged by name only (never its value). A malformed `quiet` or `paused_until`,
    /// a non-object value, or a read error sets `unreadable`. Never fails.
    pub fn load(store: &Store) -> Proactive;
    /// Err(Invalid) when `self.unreadable`: a config from a failed read is never written back.
    pub fn save(&self, store: &Store) -> Result<()>;
}

/// `gate_in`, first: `cfg.unreadable && urgency < Urgent` → `Some(now + UNREADABLE_RETRY_MS)`.
```
`decide_from` rule 5 (the owner's pause): also `ctx.cfg.unreadable && u < Urgent` →
`Hold { until: now + UNREADABLE_RETRY_MS }`, before quiet hours.
`dispatch`: `let Ok(mutes) = s.store.mutes(now) else { warn; return Some(now + UNREADABLE_RETRY_MS) };`.
That comes before anything is decided, said, held or dropped. The warn line carries the error
kind only.

`Proactive { .., ..Proactive::default() }` literals elsewhere (`tests/brief.rs`,
`alexia-hub/tests/week.rs`) keep compiling, because the new field is `pub` and has a default.

## Steps
1. `quiet.rs`: add the field, then rewrite `load`:
   - `kv_get` Err → `Proactive { unreadable: true, ..default }`.
   - `Ok(None)` → default.
   - `Ok(Some(Value::Object(m)))` → start from the default. For each of the seven fields
     present in `m`, `serde_json::from_value` it. On failure keep the default, warn with the
     field name, and set `unreadable` if the field is `quiet` or `paused_until`.
   - Any other value → `unreadable`.
   - `paused_until: null` is valid (no pause).
2. `save` refuses an unreadable config. `gate_in` holds on it as above. Job replies go through
   `Scheduler::hold_until` → `quiet::gate_in`, so they hold too, and `lib.rs` does not change.
3. `decide.rs` rule 5 as above.
4. `notices.rs` `dispatch`: the mutes read as above. Leave the rest of the function alone.
5. Replace the unit test `load_ignores_bad_json` (it asserts today's fail-open behaviour) with
   the field-by-field ones below.

## Tests
Unit, in `quiet.rs`:
- `load_keeps_readable_fields`: `{"brief_fallback": [8,30], "evening": "x"}` → `brief_fallback`
  (8,30), `evening` the default, `unreadable == false`.
- `bad_pause_is_unreadable`: `{"paused_until": "soon", "brief_fallback": [8,30]}` →
  `unreadable`, `brief_fallback` still (8,30).
- `bad_quiet_is_unreadable_and_keeps_pause`: `{"quiet": "never", "paused_until": T}` →
  `unreadable`, `paused_until == Some(T)`.
- `not_an_object_is_unreadable`: `"x"` and `[1]` → `unreadable`.
- `unreadable_never_saved`: `save` of an unreadable config is Err, and the stored value is
  unchanged.
- `gate_holds_below_urgent_when_unreadable`: `gate_in(unreadable, Normal, now)` ==
  `Some(now + UNREADABLE_RETRY_MS)`. With Urgent → None.

`tests/fail_closed.rs`, through a real `Scheduler` with paused time, a fake `Sources` and the
store in memory (copy the harness shape of `tests/mute_provider.rs`; do not change that file).
Each fails on today's code:
- `mutes_read_error_says_nothing`: a mute on source `job`, then a live Normal notice of that
  source. Make the read fail with `store.transaction(|tx| { tx.execute_batch("ALTER TABLE mutes RENAME TO mutes_off")?; Ok(()) })`.
  A dispatch pass → no `Event::Say` and the row still `new`. Rename it back → the next pass
  drops it as muted, and it is never said.
- `kv_read_error_holds_notices`: `_core.proactive` unreadable (rename `kv` the same way, in a
  test that needs no other kv) → a Normal notice is not said while it lasts. An Urgent one is.
- `bad_quiet_field_keeps_the_pause`: `_core.proactive` = `{"paused_until": <tomorrow>,
  "quiet": "never"}` → a Normal notice is held, not said (today the pause is lifted and it is
  said). Fix the value with a good `quiet` → still held by the pause until `paused_until`.
- `bad_brief_field_changes_nothing_else`: `{"paused_until": <tomorrow>, "evening": "x"}` → the
  pause holds and `unreadable` is false.
- `job_reply_held_when_unreadable`: a job fires while `quiet` is malformed → its Normal reply
  is filed held, not said (through `hold_until`, unchanged).
