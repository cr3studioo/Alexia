# P3-20: Google: calendar, mail reading, contacts

Model: opus
Depends on: P3-03
Feature IDs: DY-01, DY-17 (contacts), PR-09 (calendar deadlines)

## Goal
The `google-account` plugin connects the owner's Google account with OAuth (their own Desktop
client, loopback redirect on 127.0.0.1 with PKCE), and provides the calendar (read, and
create events that ask first), Gmail reading (never marking read) and contacts, through the
P3 capabilities, so the day planner, the mail desk, memory and the scheduler can use them
without knowing it is Google. Its `notice.items` offers today's and tomorrow's events with
deadlines in their titles ("Deadline", "Due", "Odevzdat", "Termín").

## Touch only these paths
- `plugins/google-account/**`   (fill: `index.js`, `oauth.js`, `calendar.js`, `mail.js`, `contacts.js`, `plugin.json`, `README.md`, `test/*.test.js`)

## Must not touch
`package.json` (no new dependency: `fetch` and `node:crypto` are enough), other plugins, crates.

## Interfaces
- `requires`: `net.request` ("to talk to Google: googleapis.com, oauth2.googleapis.com,
  accounts.google.com"), `net.listen` ("for one moment, on 127.0.0.1 only, so Google can hand
  back your sign-in").
- Settings: `client_id` (text), `client_secret` (password), `refresh_token` (password, hidden
  from the form, written by the plugin), `calendars` (text: calendar ids, default `primary`),
  `connect` (action button "Connect Google"), `status`.
- OAuth (`oauth.js`): PKCE S256; scopes `calendar.events`, `calendar.readonly`,
  `gmail.readonly`, `contacts.readonly` (P3-24 adds `gmail.send` and `gmail.compose`). The
  listener binds `127.0.0.1` port 0, accepts exactly one request on the redirect path whose
  `state` matches, answers a plain "You can close this tab" page, closes. It opens the browser
  through the host (elicitation URL, as other plugins open links) and never logs the URL's
  query. Tokens: access token in memory only; refresh token as the `password` setting.
- Capability tools (`_meta alexia/provides`), shapes from INTERFACES §3.6:
  `calendar.events` (read-only), `calendar.create` (`openWorldHint: true`, `destructiveHint:
  false`: it writes to Google, so a proactive run always asks, D214), `mail.list`, `mail.read`
  (both read-only; Gmail's `format=metadata` for list, `full` for read, text/plain preferred,
  HTML stripped; never `modify`), `contacts.find` (read-only).
- `notice_items` (`notice.items`): events in the next `horizon_days` whose title matches the
  deadline words → items with `dueAt` = event start, key `google:event:<id>`; all-day events
  today → one item "Today: <titles>" (Low).
- Errors are sentences: "Google is not connected. Open Plugins › Google › Connect." /
  "Google refused the sign-in; connect again." Never the HTTP body.

## Steps
1. `oauth.js` with a fake token endpoint in tests (PKCE verifier/challenge, state check,
   refresh).
2. `calendar.js`, `mail.js`, `contacts.js`: request builders and response mappers, pure,
   tested on recorded-shape JSON written by hand (no real data in fixtures).
3. `index.js`: tools, settings, status. `README.md`: how to make the Desktop OAuth client
   (console steps), which scopes and why, how to disconnect.

## Notes for the worker
- No Rust. Cargo checks, if run: `CARGO_BUILD_JOBS=1`.
- PHASE.md D-P3-9 and *Owner needs* 4: the owner makes the client; the README walks them
  through it. A personal client shows Google's "unverified app" screen; say so in the README.
- Security: the loopback listener is the only port; it binds `127.0.0.1`, never `0.0.0.0` or
  `localhost`, and closes after one request or 5 minutes. Tokens never in a table, a log, a
  tool result or a prompt.
- Invariants: no plugin names, no user paths, secrets only in `password` settings (Credential
  Manager), no mail or event text in logs.
