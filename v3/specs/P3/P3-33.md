# P3-33: On this PC: the real hub, the owner's week begins

Model: sonnet
Depends on: P3-00..P3-32
Feature IDs: all of P3 (the end-to-end check, and the start of the owner's week)

## Goal
The real `alexia-hub run`, built from this branch, runs on this PC with the real plugins and
whatever accounts the owner has connected, and shows the engine working: a forced brief
arrives in the owner's Telegram chat, the notice log shows what each source offered, the
silent list is empty until the owner fills it, and `v3/ops/reports/P3-week.md` is ready for the
owner to fill one line a day. That week, signed off, is what accepts the phase.

## Touch only these paths
- `v3/ops/reports/p3-e2e.ps1`   (create)
- `v3/ops/reports/P3-e2e.md`   (create)
- `v3/ops/reports/P3-week.md`   (create)

## Must not touch
Code, specs, the owner's real v3 data (the script uses a **copy** of `%LOCALAPPDATA%\AlexiaHub`
in a scratch folder through `ALEXIA_V3_DATA` unless the owner says to use the real one),
`main`, releases, Alexia Dev's build variables (CLAUDE.md).

## Interfaces
`p3-e2e.ps1` steps, each printing PASS/FAIL/SKIPPED with a reason, writing a log under
`%TEMP%\p3-e2e\`:
1. Build: `cargo build -p alexia-hub --release` (`CARGO_BUILD_JOBS=1`).
2. Data: copy the hub's data folder to scratch (the database is encrypted; the key is in
   Credential Manager and works for the copy).
3. Start `alexia-hub run` with `ALEXIA_PLUGINS_DIR=<repo>\plugins` (after `pnpm install`), and
   wait for `window.json`.
4. `alexia-hub plugins`: every P3 plugin is loaded (none refused); print which are enabled.
5. `alexia-hub silent list` prints nothing (the list starts empty, D-P3-6).
6. `alexia-hub brief --now morning`; wait up to 120 s for the owner's Telegram chat to receive
   it. The script cannot read Telegram: it waits for the owner to type `y` (seen) or `n`, and
   records the answer. With no owner at the keyboard: SKIPPED, not PASS.
7. `alexia-hub notices --last 20`: printed into the log (the owner's data stays in `%TEMP%`,
   **not** in the report; the report records only counts per source and state).
8. Stop the hub (Ctrl+C equivalent), check it exited 0 and `window.json` is gone.

`P3-e2e.md`: the table of steps with results and counts (no notice text, no names), the
commit it was built from, what was SKIPPED and why.

`P3-week.md`: a table for seven days the owner fills, one row a day: date | brief arrived when
I picked up the phone? (y/n, time) | a promise she followed through? | a deadline flagged
before it was urgent? | anything annoying or wrong? | anything she did on her own that
surprised me?. Above it, three lines on how to give feedback (the buttons, `/quiet`, `/mute`,
`/silent`) and the phase's acceptance rule: the week passes when each of the first three
columns has at least one "y" and the last column has no surprise the owner objects to.

## Steps
1. Write and run the script; fix nothing in code (report failures to the coordinator).
2. Write both reports. Ask the coordinator to tell the owner the week can start.

## Tests
The script is the test. It must run twice in a row on this PC without leaving a hub or a
plugin process behind (`Get-Process alexia-hub, node` after step 8 shows none started by it).

## Done when
- `cargo fmt --all --check` passes in v3/
- `cargo clippy --workspace --all-targets -- -D warnings` passes in v3/
- `cargo test --workspace` passes in v3/
- `pnpm check` passes at repo root (known failure aside)
- `powershell -File v3/ops/reports/p3-e2e.ps1` ends with no FAIL
- `P3-e2e.md` and `P3-week.md` exist and contain no notice text, names or addresses

## Notes for the worker
- 16 GB RAM: `CARGO_BUILD_JOBS=1`; nothing else compiling while the release build runs.
- CLAUDE.md: never merge, push to main, or release. This task writes reports only.
- Only one hub per PC (D-P2D-3): if the owner's hub is running, the scratch hub exits on the
  lock. The script stops and asks the owner to quit Alexia first, rather than killing their
  hub.
- Invariants: no plugin id in a crate (nothing changes code), no user paths in the reports,
  127.0.0.1 only, no secrets or private data in the reports or logs committed.
