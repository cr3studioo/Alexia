What I built (fix round, try 2; the earlier file.stat / file.read_chunk / file.write_chunk work stands):
- Each transfer has its own part, `<name>.<random>.alexia-part` (long names cut), created with 'wx' and recorded in the ledger (id, folder, name, path, file id)
- A first piece returns `transfer`; later pieces send it. Without it a piece is taken only when one transfer can be meant, else refused

- Pieces of one name run in turn and ledger changes are serialized; cleaning deletes only a part whose file id still matches
- A failed removal of the part name after linking no longer makes a second copy
- inside() accepts children like `..cache`; Windows reserved names (CON, nul.tar.gz, COM1.txt ...) get a plain sentence
- test/index.js imports every test file
