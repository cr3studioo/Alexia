Problems or doubts:
- v2 has no id-based chat filter. It drops non-chat rows via `max_completion_tokens === 0`
  (parse) and Ollama's `completion` capability, and v3 `ModelInfo` carries neither field. So
  `chats` is a word list (embed*, rerank*, *guard, whisper, tts, image, flux, ocr, moderation,
  safety...). The drop cases in the test are real provider ids, not from v2's tests. v2's tests
  only give the keep side and `bge-m3`.
- v2 `routes` also reads the display name, which `ModelInfo` does not have. `openrouter/free` and
  `openrouter/pareto-code` (routers by name only in v2's test) are listed as known ids.
- Seed differs from the spec's "no cache and every fetch fails". It is per provider and keyless
  rows only, so ovhcloud (no list) is always there as in v2. nara and cloudflare-ai seeds are
  left out because `Provider` cannot say whether a key exists and they have no list (ponytail note).
- Usability is read from `models()` returning NeedsKey, because the trait has no `usable()`.
  No-list rows that require a key (github, nara, cloudflare) are therefore never candidates.
