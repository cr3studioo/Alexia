Problems or doubts (reviewer please look):
- "Front window" cannot be cropped: computer.screenshot gives no window rectangle and the spec limits the capabilities. The whole screen is
  read and sent; `whole_screen` only changes wording; only the front window is judged private. Fix needs a rect in computer.screenshot's `front`.
- Across devices: computer.screenshot's path is only readable on the device that took it. If the hub routes it elsewhere than screen-look
  (explicit `device` while the owner is elsewhere), the answer is "could not be opened here" and that file is not deleted there.
- Box coordinates are screenshot pixels. On Windows the picture starts at the virtual screen's origin (and the capture is not DPI aware),
  so with a monitor left/above the primary, or scaling, screen-ink may draw offset. Not tested with screen-ink.
- Judgment calls: sign-in titles count as private (as in screen-memory); a title that changes constantly may be refused as unnamed.
- No live end-to-end run: the owner's screen was never captured, and no real vision or sampling model was called.
