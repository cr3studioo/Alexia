# P2-47 report

Status: done

What I built:
- `conn.rs`: `Incoming::request` now gets the plugin's cancel token and, when params carry
  `_meta.progressToken`, a `ProgressSink`. A forwarder task sends its frames back as
  `notifications/progress` under the plugin's token. It holds `Weak<Shared>`, sends queued
  frames first, and ends when the sender drops or the request ends (the token is cancelled
  once the request finishes). The existing select stays, so a cancelled request gets no answer.
- `host.rs`: `Handler::request` builds a `CallCtx { cancel, progress, .. }` for `alexia/*` and
  gives both to `up.sample`. `hosted()` now starts with `reviewed: false`. Only `tools()`, after
  reading `_core.unreviewed`, sets it. `hosted()` has one caller (`plugin_tools`); the other
  callers of `plugin_tools` only read `provides`/meta.
- `host.rs`: new `#[doc(hidden)] serve_ctx_for_test` (`serve_for_test` now calls it with the default context).
- `serve.rs`: `serve(host, id, call, ctx)`; `call_capability_as` and `compute_call` use `ctx`.
  Added the comment above `inside()` on why it is not `alexia_core::permissions`.
- `mcp-fixture.rs`: compute tool `crunch` (op `demo.slow`). It sends progress, can be cancelled,
  and writes `cancelled.txt` as proof. greet `ask-cancel` / `ask-progress` drive the conn tests.
