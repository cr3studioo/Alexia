# P1-08 report

Status: done

What I built:
- `Caps` trait plus its `McpHost` impl: `answers(cap).answers`; `call_capability` returns the text blocks joined, or `None` on any error or `isError`.
- `FastChat` (`Brain`): spawns recall when the turn arrives, builds the cached prefix (v2 no-tools floor, display name from kv `_core/display_name`, profile, personality, the `[[task]]` line, then "Today is …"), and waits for recall until 250 ms after `reply` started. Then one `router.hedged`.
- History is the last 20 turns, user/assistant text only, tool turns dropped. Each turn is rebuilt as a bare `MessageBody` so its bytes stay the same from turn to turn. Recall notes go only into the new user message and are never stored.
- Marker handling: text is held while it could still be `[[task]]` (or until 8 chars that can't be). `NeedsTask` sends no frames and stores nothing. `Phase(Writing)` goes out at the first flush, and `Reasoning` becomes `Phase(Thinking)` once.
- Spans: prompt, recall-wait, first-byte, writing, store. Errors: Cancelled maps to Cancelled; every other router error maps to the busy sentence.
- After the reply is stored, `memory.capture` runs fire-and-forget with `said`/`answered` redacted and `at`.

Problems or doubts:
- `tokio::time::pause` can't be used: alexia-core's tokio has no `test-util`, and Cargo.toml is not on my touch list. So slow_recall uses real time: recall takes 60 s, and the test asserts the request was sent between 240 ms and 10 s after `reply` started (the generous-bounds rule), not within 300 ms.
- "Today is" uses the UTC day (no tz crate), so near midnight it can differ from v2's local day. This is marked with a `ponytail:` comment.
- Profile and personality fetches are not time-bounded (the spec doesn't ask for it). A slow memory plugin can delay the first turn after `invalidate`.
- A `Phase(Thinking)` frame is still sent when a reasoning model ends up answering `[[task]]`. No text frames are sent.
