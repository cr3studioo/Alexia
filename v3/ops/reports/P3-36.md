What I built:
- `Agent::elicit` (core): finds the calling run (newest `live_runs` row of `During.conversation`'s session) and its origin. Desktop or unparsable origin → `owner_origin`; no run → `elicit-{id}-{ms}` + `owner_origin`. Calls `Ask::elicit` with `ELICIT_WAIT`. Maps Accept/Decline/Cancel to exactly the three JSON shapes. One `tracing::info!(plugin, outcome)` per request.
- `Asker::elicit` (gateway): window if `Origin::Window` and attached, else `target(origin)`, else `Cancel` at once (no row, nothing sent). Row text is `"{name} ({plugin}) asks you to confirm something."`, detail NULL. A prompt over 3,500 chars is `send`, then a short `ask` that names the plugin. A send/ask error is `Cancel` (`via = "failed"`).
- `in_window` / `in_chat` take a deadline and return `(answer, via)`. `confirm` passes `ANSWER_WAIT` and behaves as before (Stop = no via `window`; a withdrawn confirm leaves its row unanswered).
- Window Stop is a private `WindowReply::Stopped`: `false` for confirm, `Cancel` (row `via = "cancelled"`) for an elicitation. `WindowQuestions::ask` signature unchanged.
- An elicitation's cancel token settles its row `cancelled`, so no later `/approve` can answer it. Timeout note: "— no answer, so nothing was done".
- `docs/spec/wire-protocol.md`: `initialize` comment, capability table, Elicitation section (offer, one boolean field, no url, 100 s, answer table).
