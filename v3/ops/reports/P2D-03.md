# P2D-03 report

Status: done

What I built:
- `Origin::Window` (`{"kind":"window"}`). Slash commands run from it, including owner-only ones (`commands::run`, `owner_only`). The scheduler's `session_of(Window)` is `channel_session("window","main")`. Everywhere else it acts like Desktop.
- `ToolProgress` (run.rs) with `line()`. `ToolCtx.progress` is now `Sender<ToolProgress>`. `tools::progress_of` ports v2 `onprogress`: preview kept only if it starts `data:image/`, `stagesOf` (anything malformed drops the whole strip), `plan` only with stages, `controlsOf`.
- Research snapshots: a port of v2 `ResearchRuns` (owner order, sequence and runId checks, settled on close, cap of 50), keyed by (plugin, session), plus `McpTooling::research()`. Snapshots are checked field by field like v2's zod `ResearchUpdate`. Unknown keys are dropped, and the conversationId must match the session.
- `DraftFrame::{Step, Note, Ask}`, `StepFrame`, `StepOutcomeFrame`. The agent sends Step(args) at the gate, Step(progress) through a bounded queue per call (`try_send`, so a slow window loses a report and the tool never stalls), and Step(outcome) for every call, refused ones included. Every run note is also a `Note` frame. "Stopped before starting." is sent when a run is cancelled before any model was asked.
- Gateway: `WindowQuestions` (attach, detach, attached, ask, answer, cancel_open; one open question at a time, the next waits). `Asker::with_window` and `window()`. A Window run that is attached is asked in the window, with the same `approvals` row (via "window"). One that is not attached is asked in the primary chat. If the window detaches mid-question, the same row goes to the primary chat; it is never a yes. The Telegram pump ignores Step, Note and Ask.
