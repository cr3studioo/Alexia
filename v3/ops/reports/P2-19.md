## Fix round
- `Trace::number` now always returns `base + step.n`. The old guess collided (steps_done=2, n=1,2,3 gave 3,4,3, so two audit rows got step 3 and `record` overwrote a body). New test `resumed_steps_get_distinct_numbers_and_bodies` checks audit steps and body steps are 3,4,5 with three distinct bodies; `resume_keeps_live_row_and_counts_on` still expects 3 for the first step after a resume at 2.
- `Trace::resume` now errors (`Refused`, "Run <id> has no live row to resume.") when no `live_runs` row exists, instead of running silently without one. The spec says resume only touches the surviving row, so it does not recreate it. It checks `live_runs()` first because `live_touch` reports no row count and the store is out of scope. New test `resume_without_live_row_is_an_error`.
