Status: done

What I built:
- `patterns.rs`: `record_active` (kv `_core`/`activity`, first/last minute per local date, newest 90 days); `routine` (median of ≥ 5 days, weekdays and weekends apart); four pure detectors: `routine_finding`, `automations`, `skills`, `dismissed`; `find` (reads the store, leaves private sessions out); `offer` (Low notices, source `pattern`, key `pattern:<kind>:<12-hex sha256>`); `pass`; the loop `run`.
- `lib.rs`: `Scheduler::run` starts the pattern loop beside the notice loop and the brief clock, and waits for it on shutdown.
- The loop records every bus `Active` (a `Lagged` bus is warned and goes on), wakes every minute, and runs the pass in the hour before `cfg.weekly` when none ran since. It also runs once at start when it never ran and a message is ≥ 7 days old. The last pass is kept in kv `_core`/`patterns.last`.

Problems or doubts:
- Rules I picked where the spec is open:
  - Routine: offered when both `brief_earliest` and `brief_fallback` are ≥ 45 min from the weekday start.
  - Word overlap is shared words ÷ the larger set.
  - The weekday is 1 = Monday .. 7 = Sunday, as in `Trigger::Weekly`.
- A run body has no session or user message. A run's first message is the newest user message ≤ 2 min before the run starts, in the audit rows' session when there is one. Runs with a Scheduler origin in audit, and runs from private chats, are skipped. Tool names come from `steps[].name`.
- An automation or skill key hashes the example's normalised words (plus the weekday for automations), so rewording keeps the key.
- A finding is not re-offered while its notice is live, and not within 60 days of a `dropped` or `done` row with its key. Treating `done` like `dropped` goes beyond the spec, which names only dropped.
- The dismissed detector leaves out source `pattern` itself and sources already muted.
- The pass runs synchronously on the loop's task (reads every recent session). That is fine at one owner's scale.
- Tests back-date messages with `store.transaction` and SQL `UPDATE messages SET at`, because `append` stamps the real clock. This uses only the store's public API.
