What I built:
- `supervise.rs`: `CrashLog` (window, doubling backoff capped at `max_backoff_ms`, `Verdict { Retry, Unhealthy }`), `Busy` (calls in flight + last use), vanish check, and one watcher task per process (exit, ping every `heartbeat_ms`, lazy idle stop, folder check), ended by the run's `CancellationToken`.

Problems or doubts:
- Idle uses the host's own last-call time, not `Conn::quiet_ms()` as the spec says: the heartbeat's ping answers reset `quiet_ms` every `heartbeat_ms`, so it could never reach `idle_ms`.
- A call that lands between the idle check and the stop is killed after `exit_grace_ms` (Gone). Marked `ponytail:` in `supervise.rs`.
- The unhealthy sentence is v2's: "… stopped 3 times in a minute …". It says "a minute" whatever `crash_window_ms` is.
- The list_changed-during-tools/list fix has no test: the fixture cannot send that notification mid-list, and the fixture is outside my paths.
- The test fixture lives in `<root>/bin` with `entry.run = "../../bin/…"`, so the plugin folder can be deleted on Windows while the process runs (P0-11's tests copy the exe into the folder, which Windows would lock).
- A start failure is counted as a crash but sends no `Crashed` event (there was never a `Started`).
