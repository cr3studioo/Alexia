# P0-22 report

Status: done

What I built:
- `Busy::enter` takes `&Arc<Busy>` and returns an owned `BusyGuard`. `ensure_running` enters it
  while the spawn lock is held (live process and fresh spawn) and returns `(Arc<Conn>, BusyGuard)`.
- `stop_with(Idle)` checks again under the spawn lock (no calls in flight, last use >= idle_ms)
  and does nothing if the plugin is busy again. `stop_with` now returns `bool` (crate-private).
- The watcher returns only when the idle stop really happened. Otherwise it keeps pinging.
- Removed the old `ponytail:` comment that accepted the race.

Tests added:
- call_at_idle_deadline_never_gone (new): 50 loops. Each loop starts with the plugin stopped,

  50 ms after the first idle tick. Every call must return its result. The test also asserts that
  some idle restarts happened and that nothing crashed.

Problems or doubts:
- Regression check: on the old code the race window is too small to hit unaided. With a 30 ms
  sleep put between ensure_running and busy.enter, the new test fails on loop 0 with
  Gone after an Idle stop. That needs exit_grace_ms = 0 in the test. With the default grace,
  the old code still answered the overtaken call and only killed the process afterwards.
- The new test takes about 55 s (50 loops of about 1 s each).
- tests/conn.rs junk_is_skipped_and_logged failed once in a full-workspace run under load.
  It passed 5/5 alone and in the next full run. That file only tests Conn and the stderr log, and
  this change does not touch either. It is a flaky test outside this task's paths.
- A heartbeat ping still times out after heartbeat_ms (500 ms in the test, as in the rest of the
  suite). A very loaded machine could kill the process through the heartbeat. That is not this race.
