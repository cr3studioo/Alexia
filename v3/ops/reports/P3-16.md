# P3-16 report

Status: done

What I built:
- `agent.rs`: `unlocked(store, origin)` (window, desktop, a channel's primary chat; never Scheduler or another chat), `is_private(store, session)`, `memory_args`, and one `capture(...)` both lanes use. It sends `{said, answered, at, channel, session}`, redacted as before, and skips Scheduler turns, private sessions, empty answers and the case where no provider answers. It is spawned and never awaited.
- Task lane: `Agent::reply` captures after `RunEnd::Answered`. It does not capture after Ceiling, Stopped or Refused, or for `Origin::Window`, because the api's window route already captures that exchange and would otherwise send it twice.
- The task lane's `memory.profile` read carries `unlocked`.
- Chat lane (`chat.rs`): profile and recall carry `unlocked`, and capture goes through the shared helper. The cached system prompt is now kept per lock state, so a profile read for the primary chat is never reused for another chat.
- CEO note: a model's own tool call to a plugin that provides any `memory.*` capability has `unlocked` forced to false. Core recognises such plugins by capability, through a new `Caps::provided_by(&PluginId)` method (default: empty; `McpHost` reads the manifest's `provides`), not by plugin id.
- api `chat.rs`: the window's `memory.capture` args gain `channel: "window"` and `session`.
