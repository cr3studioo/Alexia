# P2D-16 report

Status: done

What I built:
- `windows.js` `focus(pid)`: `AppActivate` replaced by a P/Invoke sequence in the existing PowerShell + Add-Type path. It restores the window if minimised, then `AttachThreadInput` to the foreground thread, `BringWindowToTop`, `SetForegroundWindow`, `SetFocus`, detach. If the window is still not in front: Alt down, `SetForegroundWindow`, Alt up. Then `GetForegroundWindow` + `GetWindowThreadProcessId`. It resolves only when the foreground pid is `pid`; otherwise it rejects with "Could not bring that window to the front." No SystemParametersInfo.
- Guard: `type(text, signal, pid)`, `key(combo, signal, pid)` (including `{WIN}`) and `click(x, y, button, double, signal, pid)` put a foreground-pid check at the start of the same PowerShell script, before any input line. On a mismatch they print `{"refused":true}`, exit, and reject with "The window in front is not the one I was working in, so I did not type." (or "click"). With no pid, the script is the v2 one.
- `index.js`: the `click`, `type` and `key` tools take an optional `pid`; `run_task` passes its target pid to click/type/key. The `click` and `type` tools now turn a rejection into a refusal; before, a thrown error escaped the handler. The `focus` tool already answered with the rejection text, so it never says "Focused" when focus failed.
