Status: done (fix round 2: the approval token is gone; mail.send asks the owner itself)

What I built:
- Removed `mail.approval`, the `approved_draft` token and `mail_approval` everywhere: manifests, code, tests. No plugin can approve a send for the owner.
- `mail.send` (tool `mail_send`, google-account and microsoft-account) asks the owner **itself, every time**: it checks and freezes the message (bare recipients, one-line subject, text), sends MCP `elicitation/create` (form, one `send` boolean) showing "To / Subject / text", and sends exactly that frozen message only on `accept` with `send: true`. Nothing else in the answer is read, and arguments changed during the ask are not used.
- Decline, cancel, accept without `send: true`, a timeout (the host's own, or the plugin's 5-min clock; a yes after that is ignored), a host with no form elicitation, or an elicit that throws: `isError` with a plain sentence (`NOT_SENT`: "Not sent: you said no." and so on) and `structuredContent {sent:false, reason}`. Nothing reaches Google or Microsoft.
- Microsoft reply: `/reply` now carries the shown subject and recipients, with the shown text as `comment`. Graph quotes the original under it, so the question adds "Outlook adds the message you are answering below your text, quoted." The request is built from the frozen message before the ask.
- mail-desk `send_draft` asks nothing. It calls `mail.send` once with the exact draft (to, subject, text, replyTo) and reports the account's answer ("… The draft is kept." on anything short of a send). Draft state turns `sent` only on a confirmed send.
- Kept from round 1: annotations (destructive + open-world), scopes and reconnect status, sent sample, voice card, local drafts.
