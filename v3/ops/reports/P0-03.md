Problems or doubts:
- Deviation from §3.3 (spec wins): optional fields that §3.3 left without
  `skip_serializing_if` (`ToolAnnotations.*`, `InitializeResult.instructions`,
  `ListToolsResult.nextCursor`, `ProgressParams.total/message`, `CancelledParams.reason`,
  `CreateMessageParams` options) now skip `None`. Otherwise core would send `"total":null` /
  `"reason":null` to plugins, which the MCP schema/zod (`optional`, not `nullable`) rejects, and
  the tool round-trip test could not hold. INTERFACES.md §3.3 should be updated to match.
- `AlexiaCall::parse` knows its methods through a 20-name const list beside the enum; adding a
  variant means adding its name there too, or it parses as `Ok(None)`.
- `NoUpcalls.host_facts` returns an empty `display_name` as specified; v2's HostInfo schema wants
  min length 1, so the host must fill a real name before answering `alexia/host/info`.
