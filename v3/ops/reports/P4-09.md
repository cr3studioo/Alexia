# P4-09 report

Status: done

What I built:
- `alexia-limb` CLI (`cli.rs`): `run`, `pair "<uri>"`, `unpair`, `status`, `plugins [enable|disable <id>]`,
  `install|uninstall`. Hand-written slice-match parser like the hub's; sentences on stdout, exit 1 + sentence on failure, usage → exit 2.
- Data under `data_dir()/limb`; plugin folders `<limb>/extensions` then `ALEXIA_PLUGINS_DIR`; enabled list in kv `_limb`/`enabled` (absent = none).
- `run`: store, McpHost (NoUpcalls), Node (KEYCHAIN_LIMB, role limb), `accept_links` (a new link cancels the old),
  a 30 s tick that sends presence to the linked hub and re-syncs the enabled list from kv (so `plugins enable` reaches a running limb). Ctrl+C closes link, node and host.
- `serve.rs`: MCP server over the link. initialize / ping / tools/list / tools/call, method-not-found otherwise; requests concurrent;
  `notifications/cancelled` cancels the call (no answer sent); progress re-tokened to the hub's token; `isError` passed through;
  host events → `notifications/tools/list_changed`. Builtin `device.presence` (read-only, provides `device.presence`).
- `service.rs`: `install`/`uninstall` return "not available yet" (P4-10).

Problems or doubts:
- `Facts` has a third field `changes: broadcast::Sender<()>` beyond the spec's two: `serve(link, host, facts)` has no other way
  to hear the host's events (the EventSink is fixed at `McpHost::new`). `serve::sink(changes)` builds that sink.
- list_changed fires on ToolsChanged, Removed, Unhealthy, Refused and Stopped{Disabled} (disable emits Stopped, not ToolsChanged).
- "Hidden tools stay hidden" read literally: `alexia/compute`/`alexia/editor` tools are left out of tools/list, but a
  tools/call by name still routes (the cancel test uses the hidden `crunch`). If the hub needs them listed for compute, flip the filter.
- Tests include the bin's modules with `#[path]` (a bin crate has no lib); they build mcp-fixture via `$CARGO build -p alexia-mcp` when absent, as alexia-core's tests do.
- `status` shows plugins on/off from a folder scan, not live process states (those live in the running `run` process).
- `pair`/`unpair`/`status` start their own Node; while `run` is up that is a second connect with the same key. A new pairing reaches a running limb only after restart.
- Device name is `hostname` output.
