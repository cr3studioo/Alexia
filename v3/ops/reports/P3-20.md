# P3-20 report: Google calendar, mail reading, contacts

Status: done

What I built:
- `oauth.js`: PKCE S256, a `state` check, a one-shot listener on `127.0.0.1` port 0 (one good request or 5 minutes, then it closes), code exchange, refresh, an access token kept in memory only, and errors as sentences that never include the HTTP body.
- `calendar.js` / `mail.js` / `contacts.js`: pure request builders and mappers in the INTERFACES §3.6 shapes. Every Gmail request is a GET with `format=metadata` or `format=full`, prefers text/plain and strips HTML. Contacts do a People API warmup search. `noticeItems` handles the deadline words (EN/CZ, accents optional) and makes one Low "Today: …" item.
- `index.js`: tools `calendar_events`, `calendar_create` (openWorld, not destructive), `mail_list`, `mail_read`, `contacts_find`, `notice_items` (all bound with `alexia/provides`), and `connect` for the action button. The settings status line is kept up to date.
- `plugin.json`: requires `net.request` and `net.listen`, provides the six capabilities, and declares the spec's settings. `README.md` covers making the Desktop client, the unverified-app screen, the scopes and why each is needed, and disconnecting.
