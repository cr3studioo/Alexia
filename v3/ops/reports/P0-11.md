# P0-11 report

Status: done

What I built:
- `McpHost` (`v3/crates/alexia-mcp/src/host.rs`): scans `plugin_dirs` in order (first folder wins), refuses incompatible manifests with v2's sentence, creates declared tables, spawns resident plugins at start and lazy ones on first use.
- Spawn + §3.2 handshake: `process::spawn` (password secrets for redaction), `Conn::start(.., proc.stderr.clone(), ..)`, `initialize` within `start_ms`, protocolVersion mismatch → process stopped, state Refused with v2's `mcpRefusal` sentence; then `notifications/initialized`, `Started`.
- `tools()`: concurrent per plugin (`JoinSet`), follows `nextCursor`, caches, `provides`/`hidden` from `_meta`; a failing plugin is left out.
- `call_tool`: Off for unknown/disabled/refused, `alexia/call-context` + `ctx.meta`, progress/cancel/`call_ms` passed to `Conn::request`.
- `stop`/`set_enabled`/`shutdown`: the `Conn` is dropped before `process::stop`, so a clean stop is quick.
- Incoming handler: roots/sampling/elicitation via `Upcalls`, `alexia/*` → METHOD_NOT_FOUND, `tools/list_changed` drops the cache and emits `ToolsChanged`.
- Stubs as specified: `call_capability` (Off), `answers` (from `provides[]`, final), `settings_changed`, `conversation_ended`, `purge` (Err "isn't available yet").

Files changed: `v3/crates/alexia-mcp/src/lib.rs`, `v3/crates/alexia-mcp/src/host.rs` (new), `v3/crates/alexia-mcp/tests/host.rs` (new), this report.

Problems or doubts:
- A manifest that fails to parse has no id, so no `Refused` event can be sent; it is only logged (`tracing::warn`) with its folder path.
- If a `tools/call` is still in flight during `stop`, its `Arc<Conn>` keeps stdin open and the plugin is killed after the grace period (marked `ponytail:`).
- A plugin that fails to start stays `Stopped` with a "didn't start: …" sentence, and the next call retries right away. Backoff is P0-12.
- `tools/list` uses `start_ms` as its timeout, because the hub's `tools` command is bounded by it.
- Folder watching and the `Removed` event are left for P0-12 (vanish).
- The fixture copy follows tests/conn.rs: the manifest needs a folder-relative `entry.run`, so the binary is copied into each plugin folder instead of using the absolute `CARGO_BIN_EXE` path.
