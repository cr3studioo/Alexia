# P4-23 report (fix round, try 3)

Status: done

What I built:
- 1 (security, -C): `readOnly(command, { shell })` now checks every named parameter of a read-only cmdlet against an allowlist for that cmdlet (Get-ChildItem, Get-Content, Get-Process, Get-Service, Test-Path, and in PowerShell the aliases ls, cat, ps, pwd and where). A parameter passes only when it is the start of an allowed name and not the start of `computername`, `cn`, `cimsession` or `session`. Matching ignores case. Quotes are taken off and a `-Name:value` is cut at the colon, so `-C`, `-c:pc`, `"-C"`, `-Ci`, `-Se`, `-S`, `--%` and a bare `-` are all refused. The shell defaults to PowerShell, the stricter reading. `shell.js` passes the real shell, so `ls -la` and `ps -C node` still pass in zsh.
- 2 (cwd): with no cwd, a command runs in the first open root, which goes through the same `within` check. With no root open it refuses: "No folder has been opened on this computer, so there is nowhere I may run a command. Open a folder first." `homedir()` is gone.
- 3 (winget source): `winget show` and `winget install` both get `--source <chosen row's source>`, and so do the publisher look-ups for near hits. `parseWingetTable` takes the source only when the header has a Source column. If the source is unknown or not a plain name, nothing is installed.
- 4 (done_when): `doneWhenPattern` refuses more than 200 characters, and refuses a group followed by `*`, `+` or `{` that holds a quantifier or a `|`, with a plain sentence. It skips escapes and character classes when it scans.
- README and the `cwd` description in index.js now match.

Problems or doubts:

- `-S` (Recurse alias) and `-D` are refused or ambiguous on purpose, because `-S` starts `-Session`.
- The nested-quantifier check is conservative: `(a?)+` is refused too. Backreferences are not analysed. The 200-character cap limits the rest.
- A winget with only one source set up prints no Source column, so installs there are refused. This is safe, but it may need `winget source list` later.
