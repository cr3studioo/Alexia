What I built:
- `record.js`: events → steps (click → `press` with `match`/`name`/`role`/`window`/`title`; typed field value → `type` coalesced per field; shortcut → `key`; password → `text:"<ask>"`), the indicator (screen.draw red dot + "Recording", redrawn every 2 s, else notify.show, else refuse), the session (10 min / 200 step caps, ends if the dot can no longer be drawn), a JSON-lines process reader, and `parts()` (a plan cut at its password steps).
- `windows.js` `recordScript`/`recording`: PowerShell watcher. Polls focus, mouse-up → `AutomationElement.FromPoint`, a field's `ValuePattern` value on leaving it (never if `IsPassword`), Enter/Tab/Esc/F-keys, letters only while Ctrl/Alt/Win is held (not AltGr = Ctrl+Alt). Stops at its time limit or when the plugin process is gone.
- `macos.js` `recordScript`/`recording`: JXA, `NSEvent` global monitor + `AXUIElementCopyElementAtPosition`, `AXSecureTextField` never read, keys only with Cmd/Ctrl or named keys.
- `index.js`: `record_start {goal}`, `record_stop {name?}` → `{steps, name}` saved like `save_plan` (`check()` applied), `record_cancel`. `replay_plan` runs a plan in parts: at a `<ask>` step it stops and the owner types the password, then presses Continue (same hold as Take over). The password never passes through Alexia.

Problems or doubts:
- Outside the touch list, approved by the coordinator: plugin.json `requires` gains `screen.draw` and `notify.show`. Core refuses capability calls not in `requires`. The schema has no "optional" flag, but service requirements never block install.
- Spec caps a recording at 200 steps, but replay.js `MAX_STEPS` is 60. A recording over 60 steps is refused at record_stop ("Nothing was saved: …60 is the most").
- A click into a text field is saved as a coordinate `click` (pressing a field does nothing in replay); a moved window misses it. Marked `ponytail:`.
- Windows polls focus instead of a UIA `FocusChanged` handler: PowerShell script blocks crash on UIA's thread. The Mac script is untested on a real Mac (only parsed here). The Windows script was run live, but no events were driven through it.
- Typed text is the field's final value, so a field that already had text gets the whole value typed again on replay.
