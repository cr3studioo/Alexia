Problems or doubts:
- Window/Desktop origin: the tests prove `Say.to` is the origin, not that the window shows it. gateway.rs `say_targets` sends such a `Say` to each channel's primary chat (nothing unprompted in the window in P3), and because `to` is set it now skips the followed face (HB-06), which `to: None` used before. check_in already behaves this way; a fix belongs in the gateway.
- An Urgent timer asked in a channel chat now goes only there: no extra copies via the followed face or other messengers.
- A `low` urgency reminder still waits for the brief, which goes to the usual chat (decide.rs/brief.rs are out of scope).
- Reminders and timers are no longer pooled when more than 3 fall due at once: one message each, as held job replies do.
