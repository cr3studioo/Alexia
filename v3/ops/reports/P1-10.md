Status: done

What I built:
- `Telegram` channel (`channels/telegram/mod.rs`): long poll with one receipt `at` per batch;
  owners/pairing by a one-time six-digit code (rotated on use, sets the primary chat, replies
  "Paired. I'm listening."); strangers and group chats get nothing.
- v2 `Acks` offset rule: saved `telegram_offset` = oldest unfinished update, else newest + 1;
  dropped/Stop/button updates finish at once; `send()` finishes every open update of its chat.
- Content: text/caption, largest photo <= 10 MB as a `data:` image part, voice/audio as
  `<id>.ogg` InFile, documents as InFile with a sanitised basename.
- Stop -> `InKind::Stop`; `ask()` with Approve/Deny buttons resolved from the poll loop
  (owner only; others told "Only the owner can answer this."); cancel removes buttons -> None.
- `draft()` one id per chat per reply, tail 4096; `send()` v2 chunking (paragraph, line,
  word), files as documents, one ogg + `voice` as a voice note.
- Poll errors: Conflict logged once, 10 s doubling to 5 min; Unauthorized stops polling and
  returns `Error::Unauthorized`; Unreachable/Service 1 s doubling to 30 s; 429 waits retry_after.
- `channels::{secret_keys, configured, pairing_codes}` (token from `_core/telegram_bot_token`).

Problems or doubts:
- Pairing calls `store.channel_session("telegram", chat)` before `set_primary_chat`, because
  the store refuses a primary for a chat it has never seen (found by the test).
- The receipt-time test asserts |at - fake reply| <= 5 ms, as the spec asks; it may be tight on
  a very loaded machine.
- Stop has no `from`: it counts as the owner's when its private chat id is a paired user id
  (in a private chat the chat id is the user id).
- A photo/voice/document that fails to download drops the whole message (logged at warn),
  with no reply to the owner. No base64 crate, so a small encoder is inline; codes and draft ids
  come from std's seeded SipHash (marked ponytail), not a CSPRNG.
- Limits count UTF-16 units (Telegram's unit), which is stricter than "characters".
