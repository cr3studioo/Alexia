What I built:
- `Telegram` channel (`channels/telegram/mod.rs`): long poll, one receipt `at` per batch;
  pairing by a one-time six-digit code (rotated on use, sets the primary chat, replies
  "Paired. I'm listening."); strangers and group chats get nothing.
- v2 `Acks` offsets: saved `telegram_offset` = oldest unfinished update, else newest + 1;
  `send()` finishes every open update of its chat.
- Content: text/caption, largest photo <= 10 MB as a `data:` image part, voice/audio as
  `<id>.ogg` InFile, documents as InFile with a sanitised basename.
- Stop -> `InKind::Stop`; `ask()` Approve/Deny resolved from the poll loop (owner only);
  `draft()` one id per chat per reply, tail 4096; `send()` v2 chunking, files, voice notes.
- Poll errors: Conflict logged once, 10 s doubling to 5 min; Unauthorized stops polling;
  Unreachable/Service 1 s doubling to 30 s; 429 waits retry_after.
- `channels::{secret_keys, configured, pairing_codes}`.
Files changed: channels/mod.rs, channels/telegram/mod.rs, tests/telegram_channel.rs, this report.

## Fix round 1
- Asks are keyed by (chat id, ask message id) and the press must carry that ask's number;
  `ask_seq` starts at the current time in ms, so a button from an earlier run never matches.
  The ask is registered right after `sendMessage` returns (a press needs the message first).
- A photo/voice/document that fails to download is still passed on: its text/caption plus
  "[The attachment couldn't be read.]", no files, so the owner gets a reply.
- A press on a stale or unknown ask is answered "This question has expired." and the message
  is left alone (no button removal, no approved/denied edit).
- Five wrong pairing guesses rotate the code and log at info "… Waiting to be paired — send
  <code> to the bot" (same place as the first code; `alexia-hub pair` reads the new one too).
  The miss count is in memory (marked ponytail): a restart grants five more.
- New tests: press_from_an_earlier_run_does_not_answer_a_new_ask,
  unknown_press_leaves_the_message_alone, failed_download_still_reaches_the_owner,
  pairing_code_changes_after_five_misses (21 in telegram_channel).
