Status: done

What I built:
- `Telegram` channel (`channels/telegram/mod.rs`): long poll, one receipt `at` per batch; pairing
  by a one-time six-digit code (rotated on use, sets the primary chat, replies "Paired. I'm
  listening."); strangers and group chats get nothing.
- v2 `Acks` offsets: saved `telegram_offset` = oldest unfinished update, else newest + 1.
- Content: text/caption, largest photo <= 10 MB as a `data:` image part, voice/audio as
  `<id>.ogg` InFile, documents as InFile with a sanitised basename.
- Stop -> `InKind::Stop`; `ask()` Approve/Deny from the poll loop (owner only); `draft()` one id
  per chat per reply, tail 4096; `send()` v2 chunking, files, voice notes. Poll errors back off
  (Conflict 10 s..5 min, logged once; Unreachable/Service 1..30 s; 429 retry_after;
  Unauthorized stops). `channels::{secret_keys, configured, pairing_codes}`.

## Fix round 1
- Asks keyed by (chat, ask message id) and the press must carry that ask's number (`ask_seq`
  starts at now in ms); a stale/unknown press gets "This question has expired.", message untouched.
- A failed attachment download still reaches the owner as text + "[The attachment couldn't be read.]".
- Five wrong pairing guesses rotate the code and log the new one (miss count in memory, ponytail).

## Fix round 2

  keyed by test name + pid (no two tests shared one), so the likely cause is the read-back of the
  just-written .jpg on Windows. Fixed by removing it: `Api::download` (api.rs, approved by the
  coordinator) now returns the bytes; the photo is base64'd from memory. `cache()` in the test
  also gives every call its own folder (pid + counter).
- Disk leak: a photo is no longer written at all (spec Content said `cache/telegram/<id>.jpg`; only
  the image part is used). Voice/documents are still written, as InFiles the turn cleans up.
- Offset gap: `draft(None)` also finishes the chat's open updates, like `send()` (v2 Acks: a stopped
  message counts as done). gateway.rs untouched.
- Tests: photo leaves no file; new stopped_turn_is_not_replayed_after_restart; api download bytes.
- `cargo test -p alexia-gateway --test telegram_channel` 10 runs in a row: 10/10 PASS (22 tests).
