# P4-41: The window joins the handoff

Status: done

What I built:
- `GET /api/state` (the route the window picks its chat with) first opens the gateway's current session, if the owner's last turn is within 30 min, newer than their last choice in the window, the chat still exists and no window answer is running.
- A window message calls `moved_to(session, Origin::Window)`, whichever chat it is in, so a chat app continues it too. Not for a private conversation (privacy choice of mine, not in the spec).
- `WindowChannel` ("window"): an unprompted Say is written into the window's open chat (after the answer, if one is running) and joins a live stream as `note`; a moved in-flight reply joins the stream as `note` (the brain already records it). `ask` and a not-yet-joined `send` return errors, so questions are a no at once and Says fall back to the chats.
- Hub: registers the channel before `gateway.run`, then `api.join_handoff(gateway clone, &window)`.
- Outside the letter of "Touch only" (coordinator approved A): `lib.rs` has `pub use chat::WindowChannel`, a layer calling `chat::follow_on_state` inside the gate, and `self.chat.chosen()` in `set_session`. The Gateway clone sits in `ChatState`. `Cargo.toml`: `async-trait` moved from dev-dependencies to dependencies (needed to implement `Channel`); `Cargo.lock` unchanged.

Files changed: `v3/crates/alexia-api/{Cargo.toml, src/chat.rs, src/lib.rs, tests/handoff.rs}`, `v3/crates/alexia-hub/src/main.rs`, this report.

Problems or doubts:
- UI (fix needs `packages/ui`): the page does not repaint on focus, but still reads `/api/state` then (and after answers). If the owner moved to another chat elsewhere, the API switches while the old one stays on screen, and the next typed message goes to the new one. A window left open does not show phone messages until it repaints.
- For 30 min after a window message, non-urgent Says go only to the window, even if closed or unwatched: they are in the history, not on the phone, and an idle page does not repaint. Notice buttons are not shown there.
- A scheduled job with window origin creates a ("window","main") primary chat; then Says to all chats are copied into the open window chat too. `Asker` may also pick "window" if no channel registered before it has a primary chat (answer: no): P4-37's device channel must be added before it, or `ask.rs` should skip "window".
- A moved reply that finishes after the window's own answer is only in the history. Its files, and an error text the brain did not record, show only as far as a live stream carries the text.
- The moved turn and the window's turn run at once in one session, so their history rows can interleave (a risk for tool-call ordering).
- A conversation handed over and only then marked private can still be continued from the phone (the gateway has no way to take it back).
- `HANDOFF_MS` is copied into chat.rs (the gateway does not export it). "Newer than the choice" compares the chat service's message time with this PC's clock.
