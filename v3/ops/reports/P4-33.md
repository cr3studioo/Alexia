# P4-33 report

Status: done

What I built:
- Telegram (`channels/telegram/mod.rs`): once paired, a non-owner chat that is a live guest
  (`Store::guest_of`) is passed on with `from_owner: false`. An unknown chat's `/start <code>`
  or bare code is sha256-hashed and `guest_claim`ed; on success it gets the welcome, on failure
  nothing. At most 5 tries per chat per hour are looked at (in memory). The code is never
  logged or stored. A store error is nobody. Unpaired: only the pairing code, as before.
- Gateway (`gateway.rs`): a guest message (re-checked with `permissions::guest_of`, and only
  when the channel's primary chat exists and is not the guest's) goes to a guest actor kept in
  a separate table (`Routes::guests`). It never goes through `route()`, so there is no handoff,
  no change to `last`/`current_session`, no `moved_to` match and no `Event::Active`. The guest
  gets its own `channel_session`. `say_to` refuses any guest chat (named `to`, followed face,
  urgent copy, primary). A store error there counts as a guest, so it fails closed.
- `sha2.workspace = true` added to alexia-gateway's Cargo.toml (+1 Cargo.lock line), in its own
  commit, with the coordinator's approval (not on the touch list).
