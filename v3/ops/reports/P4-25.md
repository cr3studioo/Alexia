# P4-25 report: browser-pilot, the extension

Status: done

What I built:
- `extension/manifest.json`: MV3, permissions tabs/scripting/storage/activeTab (+ alarms), host `<all_urls>`, module service worker, options page, icons. No CSP key, no content_scripts, no remote code.
- `extension/background.js`: WebSocket to `ws://127.0.0.1:<port>`, hello `{hello:1,token,browser,version}`, waits for `{"ok":true}`, then answers `{id,do,args}` with `{id,ok,result|error}`. Reconnect backoff 1 s → 30 s; 25 s `chrome.alarms` ping (`{"ping":1}`, which the plugin ignores) keeps the worker alive and reconnects a woken worker. Close 4001/4003 parks it until the code or port changes. Refuses non-http(s) pages (chrome://, edge://, about:, extensions, file:) and the Chrome/Edge stores. Act switch (`act` in storage, read per request, default off) refuses open/click/fill with a sentence.
- `extension/content.js`: injected on demand; text from a DOM walk that skips inputs/textarea/select (no field values ever), controls with stable `data-alexia-ref` refs (`e<n>`), match by ref, then exact name, then case-insensitive contains, refusing >1 match; fill only on fields (React-safe setter + input/change events); "Alexia" badge for 1.5 s while acting. Re-injection keeps the first copy so refs stay valid.
- `extension/options.html` + `options.js`: code + port, "Alexia may act in this browser" switch, status line, plain words about `<all_urls>`.
- `extension/icon-16/48/128.png`.

Problems or doubts:
