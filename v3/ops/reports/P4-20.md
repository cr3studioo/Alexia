# P4-20: file-finder: instant search, tidy folders
Status: done

## What I built
- `file.search` (bound; only on Windows/macOS): Windows Search via ADODB in PowerShell (`CONTAINS`, then `FREETEXT` if nothing), `mdfind -onlyin` on macOS. Words are cut to letters/digits and `'._-`; SQL values are escaped literals sent on stdin. Results are realpath-checked against the roots, newest first.
- `folder.tidy` (bound, destructive): propose, then `apply: plan_id` once within 1 h. Direct files only; hidden/system files, folders, links and anything under a day old stay; no move replaces a file.
- `folder.tidy_undo`: reverses from table `moves` (row written before each move). plugin.json now declares tables `plans`, `moves`.

## Problems or doubts
- Everywhere (coordinator OK'd the default): a plugin is never told the scope (MCP roots cannot say it), so results and tidying stay inside the roots; a drive chosen as a root covers it. `createFinder` has a tested `everywhere` input that index.js does not wire. Needs a core change.
- "Project" in the Goal (coordinator OK'd): only the Rules are implemented (type and installer age), no project grouping.
- macOS never run: `mdfind` query, `find -flags +hidden` and the two mac-only test paths are unverified (P4-43).
- Folders Windows does not index return nothing, without saying so. `FREETEXT` fallback results are looser than the words asked.
- Search can name files inside never-touch folders (e.g. `.ssh`) if a root contains them and the index has them; core checks only argument paths.
- `destructiveHint` is per tool, so proposing a plan also asks for approval (as capabilities.md says).
- "Young" uses the later of modified and created time. `.key` is not treated as a document (private keys). Video and audio are not tidied.
- A moved file that an app has since rewritten (new file, new size) is skipped by undo. A crash mid-move can leave an empty file at the target; the original stays.
