Problems or doubts:
- `busy` is `Arc<AtomicBool>`, not a bare `AtomicBool`: `BusyGuard` has no lifetime, so it must own a handle to outlive the request (the chat stream, P2D-05).
- Token: no CSPRNG crate is in the allowed deps, so it is SHA-256 over 8 OS-seeded `RandomState` hashes + clock + pid (as core's `random_key`). Swap for getrandom if the dep is allowed.
- A wrong method on a registered path answers v2's empty 404 (`method_not_allowed_fallback`), not axum's 405. Bodies over 64 MiB answer 413 `{ok:false,said}` (v2 had no limit).
- guard.ts quirk not copied: in JS an act like `constructor` finds Object.prototype and skips the guard; the port treats it as undeclared (falls to `otherwise`), which is stricter.
- Window session: kv `_core/window_session` if that chat exists, else the newest chat, else a new one.
- A non-u16 `ALEXIA_WINDOW_PORT` stops `run` with a sentence; a relative `ALEXIA_UI_DIR` is ignored with a warning. On Windows a lock error other than 32 also stops `run`.
- The window port goes to `tracing` (stderr), not stdout: cli.rs `run_starts_and_stops` allows no new stdout lines.
- agent_e2e needs `cargo build -p alexia-mcp --bins` first (existing requirement, not new).
- binds_loopback_only finds this PC's LAN address with a UDP connect to TEST-NET; on a machine with no network route it fails, it is not skipped.
