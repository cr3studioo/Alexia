# P2-82 report

Status: done (the full `cargo test -p alexia-mcp` run is still owed, see below)

What I built:
- `wasm.rs`: a `GiveUp` drop guard, created before the wait on `ready_rx`, holding `engine` and
  `killed`. It is disarmed only on `Ok(Ok(Ok(())))`. Dropping it (timeout, error, or the
  `spawn_as` future dropped mid-wait) sets `killed` and bumps the epoch. The timeout arm has no
  code of its own now. The module thread also checks `killed` right before `_start`, so a
  module given up on while it compiled never runs the guest.
- `wasm.rs`: a test-only hook, `set_end_hook` (`#[doc(hidden)]`, thread-local like
  `set_start_delay`). It reports the module thread's end and its exit code. Without it the test
  has no way to see the thread, which is private.
- `serve.rs` `inside()`: before `canonicalize`, `links_stay_local` walks the path's prefixes.
  For each symlink or junction it reads the target with `read_link` and refuses a network
  target. It follows local targets recursively, up to 40 hops. After `canonicalize` it refuses
  a `\\?\UNC\…` result. `remote()` reuses `crate::is_network_path` for plain paths and treats a
  verbatim (`\\?\` / `\??\`) path as local only on a drive letter. The `ponytail:` comment
  notes the race between the walk and the canonicalize.

Problems or doubts:
- The spec suggests `\\127.0.0.1\nonexistent`. Localhost answers in about 0.1 s, so that test
  would pass without the fix. Instead the test uses a TEST-NET address that is never routed,
  where a followed link costs about 20 s. It picks a fresh address on each run because Windows
  remembers a host that failed and answers instantly for a while. The limit is 10 s.

  spins without reading. So the test checks that the module was stopped (`None`) instead of
  exiting by itself.
