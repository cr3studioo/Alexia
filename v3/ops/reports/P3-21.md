# P3-21 report: Microsoft 365 calendar, mail reading, contacts

Status: done

What I built:
- `oauth.js`: device code flow (`/{tenant}/oauth2/v2.0/devicecode`, then polls `/token` at the given interval, +5 s on `slow_down`, stops on expiry, decline or a newer Connect). Refresh keeps a rotated refresh token. Access token in memory only. Errors are our own sentences, never Microsoft's body. AADSTS 65001/90094/90095/90099/53003/50105 give the DY-02 sentence. The tenant setting is validated before it goes into a URL.
- `calendar.js` / `mail.js` / `contacts.js`: pure builders and mappers to the INTERFACES §3.6 shapes. `calendarView` with `Prefer: outlook.timezone="UTC"`. `@odata.nextLink` is followed only back to graph.microsoft.com/v1.0, so the bearer never leaves Graph. Mail is GET only with `$select`, the body comes as text (HTML stripped if sent), and labels cover UNREAD/INBOX/SENT/DRAFT/IMPORTANT/FLAGGED/OTHER/categories. Contacts use `startswith` on names, an exact email, or a scan of up to 10 pages for a phone number. Birthdays handle Outlook's no-year 1604 and the local-midnight UTC shift.
- `index.js`: tools `calendar_events`, `calendar_create` (openWorld, not destructive), `mail_list`, `mail_read`, `contacts_find`, `notice_items` (keys `microsoft:event:<id>`, `microsoft:today:<day>`), and `connect`. Connect shows the user code and URL in the status line and in the chat (`alexia/card`).
- `plugin.json`: requires `net.request` only, provides the six capabilities, and declares the settings `client_id`, `tenant` (default `common`), `connect`, `status` and `refresh_token` (password, hidden). `alexia_protocol` 7, for the setting `when`.
- `README.md`: Entra app registration (public client flows on, delegated permissions), school accounts and the consent limit, the scopes and why, both account plugins at once, how to disconnect.
